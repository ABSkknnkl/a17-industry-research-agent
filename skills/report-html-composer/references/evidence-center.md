# 来源与证据中心

## 三层结构

1. **正文引用**：每段事实或分析后显示简洁的“来源 N”，点击跳到完整条目。
2. **阅读器导航**：桌面侧栏提供“来源与证据索引”入口；不打断正文，但随时可达。
3. **完整索引**：保留材料名、发布主体、指标、范围、可用日期、报告期、原文定位、报告引用位置和获取方式/层级，并支持页面内筛选。

上述合并展示对应 10 个不可省略的语义字段：材料、发布主体、指标、口径范围、可用日期、报告期、原文定位、报告引用位置、获取方式、来源层级。目录与运行时质量门必须共同守卫它们。

## 证据类型不能混成一个含糊字段

- 数值型证据：指标名、单位、值、报告期、可用日期、主体、口径。
- 文档型证据：标题、发布方、日期、页码/章节、获取方式。
- 模型估算与情景假设：必须显式标识，不能伪装成已披露事实。

现有 `EvidenceSourceEntry` 尚未完全拆分数值与文档证据，因此当前 HTML 先保留全部可用字段，不在模板中猜测缺失字段。后续升级应扩展上游证据契约，而不是在 Agent 5 中解析自然语言补字段。

## 索引体验

- 筛选只隐藏不匹配的行，不改写来源内容。
- 输入为空时恢复全部来源。
- 搜索逻辑在本地运行，不上传查询词和报告内容。
- 打印时隐藏搜索控件，完整索引全部输出。
- 屏幕端来源条目使用宽卡片和两列字段，不把七个字段压进窄表格列；移动端回退单列。
- 每个来源列出它支撑的摘要、章节/小节和图表位置，避免“有来源但不知道支撑哪里”。
- 报告引用位置很多时，屏幕端默认显示引用数量并允许展开完整清单；打印端始终展开，不得截断或删减。
- 无来源时明确写“当前报告未提供可展示的来源元数据”，不得生成占位来源。
- “不得生成占位来源”指不得在完整索引中伪造编号来源行；正文引用处可以显示“来源信息待补充”，用于明确揭示证据缺口。
