1. **改 `backend/.env` 后必须重启后端**：`config.py` 用 `@lru_cache` 的 `get_settings()`，

   实测 `nohup ... & disown` 启动的 uvicorn 在工具调用结束后即被回收（进程消失、
   端口释放、curl exit 7）。上一会话的进程能活 11 小时正是因为用了后台任务机制。
3. **curl 本地服务必须加 `--noproxy '*'`**：环境里设了

4. `ps` 在本环境不可用（operation not permitted，关沙箱也不行），查进程用 `lsof -iTCP:端口`。
5. **【勘误·重要】`npm run type-check` 是空转的假质量门，不能信**
   - `tsconfig.json` 是 solution 风格：`{"files": [], "references": [app, node]}`。
     裸跑 `vue-tsc --noEmit`（即 `npm run type-check`）**不会下钻 references，
     一个文件都不检查，恒返回 0**。

     `npm run type-check` 仍 0 错误；`vue-tsc -b --force` 与

     2 个错在 `ReviewActions.revise.spec.ts(86,21)/(110,21)`，TS2352
     （`ReviewRequest` 转 `Record<string, unknown>` 需先 `as unknown as`）。
     修法：两处 `as Record<string, unknown>` 改成 `as unknown as Record<string, unknown>`。
   - **顺带**：`npm run verify`（= type-check && lint && format:check && test）

   - **正确的检查命令**：

### 3. 发现并修复 Prettier 无法解析的模板（重要坑）
`src/components/ReviewActions.vue` 模板里的
`{{ (risk as Record<string, unknown>).description }}`
会让 **Prettier 的 HTML 解析器把 `<string,` 当成标签**，隐式闭合 `<li>`，
报 `SyntaxError: Unexpected closing tag "li"`（226:11）。
**这是 Prettier 的解析局限，不是 Vue 模板错误** —— vue-tsc / vite build / 组件测试全过。
对照组实验已验证：去掉类型断言的同结构模板 Prettier 正常通过。
**修法**：把断言挪进 `<script setup>` 的 `function riskText(risk: unknown): string`，
模板只留 `{{ riskText(risk) }}`。逻辑用 `||` 保持与原实现一致（`??` 会改变空串行为）。
→ **通用规则：Vue 模板的 `{{ }}` 内不要写带 `<...>` 尖括号的 TS 类型断言。**
