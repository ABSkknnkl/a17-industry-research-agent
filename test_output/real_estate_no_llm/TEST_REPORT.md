## 3. 测试方法

为满足“不调用本项目 LLM”的要求，本次没有请求任何模型供应商接口：

1. 使用人工构造的房地产证据、图表数据集和研究边界代替 Agent 1 的真实采集结果。
2. 使用本地确定性 Python 对象模拟 Agent 2 所需的结构化分析模型输出。
3. 实际运行 Agent 2 的解析、质量校验和结果封装逻辑。
4. 实际运行 Agent 3 的图表匹配、路由、降级、去重和 ECharts 配置生成逻辑。
5. 使用本地确定性 Python 对象模拟 Agent 4 的章节文字输出，同时实际运行 Agent 4 的章节审计、引用校验和 7 章 21 节组装逻辑。
6. 实际运行 Agent 5 的报告融合、来源索引、风险披露和单文件 HTML 导出逻辑。
7. 使用 Playwright Chromium 打开最终 HTML，检查页面错误、控制台错误、章节和图表渲染数量。

本次测试不覆盖 Agent 1 的 SkillHub 联网采集，也不评价真实大模型的金融分析质量；它验证的是在上游结构化数据与模型输出合规时，Agent 2—5 能否正确连通并完成报告交付。

## 5. 发现并修复的小型缺陷

### 现象

首次成功运行时，4 张图表全部被 Agent 4 放进第一章，尽管 Agent 2/3 已分别给出了第二章、第三章和第五章的推荐位置。报告能够生成，但图文对应关系不专业。

### 根因

Agent 3 内部的 `ChartCandidate.chapter_hint` 只用于生成阶段的数量控制和审核决策包，没有写入下游使用的 `ChartReference`。Agent 4 因而只能依据“本章是否能引用该图表证据”筛选图表，无法知道图表原本推荐给哪个章节。第一章允许引用的证据范围较宽，因此可能提前接收全部图表。

完整断点为：

`ChartCandidate.chapter_hint` → **生成 ChartReference 时丢失** → Agent 4 提示词没有章节目标 → 图表集中在前部章节。

### 修复

1. 在 `ChartReference` 增加可选的 `recommended_chapter_id`，格式限制为 `CH-00` 形式。
2. Agent 3 生成 ready 图表引用时，将 `candidate.chapter_hint` 传入该字段。
3. Agent 4 使用 planned 图表时同样保留候选章节提示。
4. Agent 4 构建逐章提示词时，仅暴露“未指定章节”或“推荐给当前章节”的图表，同时继续执行证据子集校验。

### 回归结果

- 修复前新增的两个测试按预期失败：一个报字段不支持，一个报推荐章节缺失。
- 修复后 Agent 3/4 相关 21 个定向测试全部通过。
- 完整后端测试集在可启动 Chromium 的环境中全部通过。
- 重跑报告后图表按第二、三、五章正确分布，第一章不再堆积图表。
