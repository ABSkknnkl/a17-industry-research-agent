# 产业链研究共享包设计

## 目标与依赖

A1 调度本包，A2/A3 消费同一 bundle。Pydantic 管契约，JSON 和 SQLite 管证据与版本，
httpx 和 PyMuPDF 管原文。模型与搜索通过注入协议提供；本包不导入业务 Agent。

## 2026-10-30 比赛版修改

保留 T0—T3 和 evidence_v2 生产适配，新增 profile_guided 策略。重点行业用版本化结构政策，
新主题走 explore；不因比赛目标把所有候选标为 verified。

模型辅助核验记 model_assisted。独立代码政策检查产品类别、应用范围与组织角色，生成可追溯的
MembershipDecision，再派生 participates_in。原始 offers 不因映射缺失被改成 contradicted。
模型抽出的 is_a/part_of 只能作为待审线索，不自动成为政策词表。

画像既包含结构，也包含分类与默认组织方式。工艺、品牌、渠道、场景、服务分开表达；
内部／外部是默认方式，不能据此推导具体企业。首批 notebook/liquor 为 draft，
来源字段明确引用内部迁移依据，未声称原始行业知识已经人工确认。

获取资料按 structure/company/gap 分配真实搜索与读取额度；失败尝试也计数。
抽取／核验首批资料以后，再对准入缺口补查，不使用先到先得的 14 文档全局限制。
相同 URL 在一个作业中不重复获取。段落窗口保留原始文档，引用仍按全量存档文本定位。

视图模型是语义投影：支持企业、画像产品类别、工艺说明、应用场景分别显示，
全部归属及断言进入可展开详情。未据证实的主体不因版式需要填入。
只输出有来源依据的工艺边，不从 offers 推导具体客户供货。

## 兼容与回滚

schema 2.1 新增字段均有旧数据读取默认值；旧 manifest 默认 explore，不伪造画像版本。
新模式通过请求级 data_fetch_options 持久化策略，独立于引擎环境开关。
profile_snapshot 与 manifest、归属记录的版本须一致。回退 legacy 不删除 v2 产物。

旧 chart-generator 画像继续支持 legacy，本轮未修改；新版语义政策只由共享包维护。
其余历史画像的迁移须先完成笔记本真实样板内容验收，不能只复制企业名单。

## 输入与输出边界

画像 ID 使用允许列表和包资源读取，拒绝路径穿越。输出 SVG/HTML 的来源文本转义；
不执行网页脚本。原有 HTTP(S) 大小、跳转和超时限制保留。研究来源不可信，模型抽取不能
改变应用配置、调用命令或把候选关系提升为人工认证。网络端点和凭证沿用项目配置，不新增密钥。

## 已知限制

- 笔记本／白酒画像没有本轮联网补证，均为待审结构政策；还不是比赛完成品。
- 分类以精确词表为主，陌生型号／新产品会落 unknown，需定向补查或审阅后扩表。
- 组织别名只支持有原文依据的中英文括注；缺少显式依据时宁可保留未合并主体。
- 服务流程最多一轮验证后补查；不是无限知识发现。初始来源读取仍可能分布不均。
- service 的流程编排与内嵌抽取函数偏长，后续可拆成独立阶段对象，当前通过行为测试控制风险。
- presentation_ready 不自动置真；覆盖候选阈值与人工内容／视觉审阅不同。
- 本轮没有执行真实模型、豆包或生产 A1—A3，没有声称业务验收或未知行业认证通过。

## 验证方式

共享包测试使用假模型、假搜索、文件临时目录和本地 HTTP 服务；API 策略测试通过假 A1
验证持久化请求传参，并在 data_fetch 审核点停止。对历史原文可做后续重放；真实联网测试
必须另行按用户执行安排，不混称为离线验证。
