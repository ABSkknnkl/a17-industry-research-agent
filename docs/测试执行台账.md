## 四、缺陷台账（任务书 §7.3 固定 8 字段）

### 缺陷 D-01 · 存储层 run_id 路径穿越（阻断性 · 安全）

| 字段 | 内容 |
|---|---|
| **被测对象** | `backend/app/core/storage.py::StorageManager.get_run_dir / delete_run` |
| **故障等级** | **阻断性故障**（可导致任意目录创建/删除，属 N23–N25 安全判据） |
| **复现输入** | ① `get_run_dir("../outside")`　② `get_run_dir("<绝对路径>/abs_run")`　③ `delete_run("../outside")`（目标目录含 `keep.txt`） |
| **实际现象** | ① 不报错且**在 base_dir 之外创建了目录**；② 不报错且在**任意绝对路径**创建目录；③ 不报错且 **`shutil.rmtree` 删除了 base_dir 之外的目录**（`keep.txt` 一并消失） |
| **原始快照片段** | `data/runs/` 未被污染（测试使用 `tmp_path` 沙箱）；现象记录于测试文件 `backend/tests/agents/real_core/test_adapter.py` 三个失败用例 |
| **根因分类** | **E · 业务逻辑缺陷**（`base_dir / run_id` 未做规范化与越界校验；`delete_run` 直接 rmtree 未校验归属） |
| **修复建议** | `get_run_dir`/`delete_run` 入口统一做 run_id 白名单校验（如 `^[A-Za-z0-9._-]+$` 且不含 `..`／不为绝对路径），或 `Path(...).resolve()` 后断言 `is_relative_to(base_dir)`；`delete_run` 复用同一校验。（修复需用户授权，本轮**仅登记不修**） |
| **测试结论** | 存储层**不满足上线标准**（多用户/公网部署下可越界读写与删除）。测试已固化判据：校验补齐后 3 条用例应转绿 |

> **修复回执（R2）**：S-01 落地后，`backend/tests/agents/real_core` + `eval` → **24 passed / 0 failed**，
> 上述 3 条用例全部转绿；`backend/tests` 既有测试 13 passed（回归无破坏）。D-01 状态 = **已修复并验证**。
