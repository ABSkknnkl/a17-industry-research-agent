## 1. D-03 · comps 矩阵覆盖面漂移（一票否决项 C1）

### 1.1 根因（E · 业务逻辑）

`agents_core/data-analysis/data_interpreter/engine.py::build_peer_comps_matrix` 原实现：

```python
# Strictly take company-level records from companies and financials domains
# Exclude macro, industry (index aggregates), reports, news ...
comp_records = list(dataset.companies) + list(dataset.financials)
for r in getattr(dataset, "industry_chain", []):
    ...
```

注释假设「`industry` 域 = 指数/板块聚合」，故整体排除。**但黄金样本的事实相反**：20 家对标公司（万向钱潮、铂力特、中鼎股份…）的逐公司估值行（`最新a股流通市值`、`最新市盈率ttm`、`最新市净率`）全部落在 `industry` 域，每行带真实 `entity_name`/`entity_code`。

证据（`dataset.json`）：

| 域 |  distinct 实体 | 含市值/PE 行 |
|---|---|---|
| `companies` | 23（多为 `entity_identity` 占位） | 仅 2 家有 `market_cap` |
| `financials` | 3（中电港/博通集成/中新赛克） | 有营收/利润明细 |
| **`industry`** | **20（全部真实公司）** | **20 家均有 `最新a股流通市值` 等** |

排除 `industry` 后，收编条件 `if any(x is not None for x in (market_cap, revenue, net_profit, pe))` 只命中 3 家 → `comps.entries=3` → CR3=CR5=100.0，与基准 37.602 / 55.5614 相对误差 100%。

> 台账 D-03 原归因为「`companies` 域键匹配零命中」，**实测修正**：键匹配本身有效（`最新a股流通市值` 含子串 `a股流通市值`，`get_val` 可命中），真正根因是 **`industry` 域被整体排除**。

### 1.2 修复

`engine.py`：

1. 新增模块级聚合实体护栏（与 `extract_industry_chain` 共用单一事实源，消除重复常量）：
   `NON_COMPANY_ENTITY_NAMES` / `NON_COMPANY_ENTITY_PATTERNS` / `_is_aggregate_entity()`。
2. `build_peer_comps_matrix` 纳入 `industry` 域中**实体为具体公司**的行，跳过板块/指数聚合：

```python
for r in getattr(dataset, "industry", []):
    ent = _entity(r)
    if ent and not _is_aggregate_entity(ent):
        comp_records.append(r)
```

聚合过滤为**双层**：实体级（`_is_aggregate_entity`）+ 指标级（既有 `AGGREGATE_METRIC_TOKENS` 与 `get_val(exclude_keys=...)`），并保留市值合理区间护栏（`0 < market_cap ≤ 50000` 亿）。

### 1.3 验证（确定性重算，零 LLM）

```
entries = 23
CR3 = 37.602   CR5 = 55.5614      # 与 eval/cases/baselines.json 基准逐位吻合
```

`backend/tests/l1/test_c1_formula_baselines.py`：`comps_coverage` / `cr3` / `cr5` 三条由 **fail → pass**。

## 2. D-08 · 图表数值装配（一票否决项 G4）

台账记录「三重错」：①图上值 ≠ A2 计算值；②缺失填 0；③期间错位。逐层定位与修复如下。

### 2.1 子缺陷 ① 数值不一致 —— A2 侧根因：同指标多期「后写覆盖」

`build_peer_comps_matrix` 收集指标时：

```python
item["metrics"][m_key] = (val, r.unit, r.record_id)   # 后写覆盖：最后一条胜出
```

`financials` 域按**报告期降序**（2025→2021）落盘，故最后写入的是**最旧期**。`compute_financial_ratios` 直接复用 comps 条目 → A2 报告的「当前」比率实为 2021 年值。

证据（中电港 `gross_margin` 按期）：

| 期间 | 值 | 谁在用 |
|---|---|---|
| 2025-12-31 | 3.2406 | 图表（最新期，**正确**） |
| 2021-12-31 | 3.5273 | 修复前 A2 `financial_ratios`（最旧期，**错误**） |

**修复**：改为**最新期优先**，无报告期的记录不得覆盖有报告期的记录：

```python
r_period = _period(r)
prev_period = item["periods"].get(m_key)
if (m_key not in item["metrics"]
        or (r_period is not None and (prev_period is None or r_period >= prev_period))):
    item["metrics"][m_key] = (val, r.unit, r.record_id)
    item["periods"][m_key] = r_period
```

修复后 A2（中电港，最新披露期 2025-12-31）：`gross=3.24 / net=43.37 / roe=5.35`，与图表口径一致。

### 2.2 子缺陷 ① 数值不一致 —— 图表侧根因：取数走独立证据选取（台账修复建议①）

即便 A2 修正，图表候选仍可能为某实体选到**非最新期**证据（实测：CHART-05 中电港 ROE 选到 2024=4.61；chart[0] 中新赛克 毛利率选到 2024=74.93），与 A2 最新期值偏离。

台账修复建议①明确要求：**「图表数值必须取自 A2 的 `financial_ratios`（同一字段），不得走二次推断」**。

**修复**：`agents_core/chart-generator/chart_generator/data_formulation.py` 新增 `_try_formulate_ratio_comparison`，在 `formulate()` 中作为 **3.0 步**优先于通用路径：当「单一 A2 财务比率指标（毛利率/净利率/ROE/资产负债率）跨实体对比」时，图上值直接取自 `report.financial_ratios[实体][字段]`，点级证据对齐到各实体在 `evidence_index` 中该指标的**最新期**记录。

严格护栏（任一不满足即 `return None` 回退既有路径，保证零回归）：

- 目标图为对比/柱状类（`bar`/`horizontal_bar`/`comparison_bar`/`diverging_bar`/`None`），**不**劫持 pie/scatter/line/radar/combo；
- `by_metric` 恰含一个指标且可映射到 `financial_ratios` 字段；
- `report.financial_ratios` 非空（合成/无比对报告直接跳过 → 既有 63 条图表算法测试零受影响）；
- ≥2 个实体，且其中 ≥2 个在 `financial_ratios` 中有该比率值；
- A2 无该实体比率值时**不画该实体**（禁止用原始记录二次推断冒充 A2 值）。

**验证**（以修复后引擎重算的 `financial_ratios` 注入报告，确定性跑 `DataFormulator.formulate`）：

| 图 | 修复前（冻结产物） | 修复后（重算） | A2 `financial_ratios` |
|---|---|---|---|
| chart[0] 毛利率 | 中电港 3.24 / 博通集成 28.64 / 中新赛克 74.93（2024，错位） | **3.24 / 28.64 / 71.18**，全部 2025-12-31 | 3.24 / 28.64 / 71.18 ✓ |
| CHART-05 ROE | 中电港 4.61（2024）/ 中新赛克 7.07 | **5.35 / 4.09** | 5.35 / 4.09 ✓ |

→ **G4「图表数值 == A2 计算值」按构造成立**，且全实体对齐到同一最新披露期。

### 2.3 子缺陷 ② 缺失填 0 —— 现状已修复（核实）

当前 `_formulate_time_series` 对缺失期 `vals.append(None)`（非 0.0），`_compile_bar` 原样透传 `None`，`NormalizedDataTable.series_data` 契约注明「缺失值为 None，严禁填 0.0」。冻结产物中的 `[0.0, 3.24]` 系 **2026-09-23 旧代码**所出（`data_formulation.py` mtime 09-24、`agent.py` 09-25，均晚于产物）。本轮核实生产代码已无 0 填充。

### 2.4 子缺陷 ③ 期间错位 —— 时序误判

`formulate()` 原时序门：

```python
if len(unique_periods) >= 2 and len(dated_records) >= 2:
    return _formulate_time_series(...)
```

只要记录集**跨实体**出现 ≥2 个不同报告期即判为时序——即便每个实体只有单点。chart[0]（中电港@2025 / 博通集成@2025 / 中新赛克@2024）因此被画上混期时间轴。

**修复**：要求**同一序列**具备 ≥2 期才走时序，否则落入实体截面（含共同期对齐）：

```python
periods_by_series = defaultdict(set)
for r in dated_records:
    periods_by_series[r.entity or canonical_metric_label(r.metric)].add(r.period)
max_periods_per_series = max((len(p) for p in periods_by_series.values()), default=0)
if len(unique_periods) >= 2 and len(dated_records) >= 2 and max_periods_per_series >= 2:
    return _formulate_time_series(...)
```

**验证**：chart[0] 证据集 → `AxisType.ENTITY_COMPARISON`（原 `TIME_SERIES`），不再混期。

### 2.5 关联缺陷 D-09（点级证据恒空）

当前 `_formulate_time_series` / `_formulate_entity_cross_section` / 新增 `_try_formulate_ratio_comparison` 均回填 `point_evidence_ids`（与 `series_data` 下标对齐，缺失点填 `""`）。冻结产物 6/6 图 `point_evidence_ids=[]` 系旧代码所出；生产路径已具备该能力。

### 2.6 连带修复 · 气泡图 SVG 渲染崩溃（既有潜伏 bug，被 D-08 修复暴露）

D-08 的比率对比分支改变了全链路管线的图表选型，使一张 **bubble（气泡图）** 进入 SVG 渲染路径，触发 `render.py` 一处**既有潜伏崩溃**：

- `compiler._compile_scatter` 产出的散点 `value = [x, y, company_name]`，第三元素是**字符串**（公司名），并非数值尺寸；
- `render.py` 散点/气泡的 **dict 分支** `sz = _num(raw_val[2])` 对字符串返回 `None`，且该分支 append 时**漏了** `or 8.0` 兜底（list 分支 714/720 行均有）；
- 气泡图渲染 `r = min(14.0, max(6.0, sz * 0.8))` → `None * 0.8` → `TypeError`，整张 SVG 渲染中断。

**修复**（`render.py` 散点 dict 分支）：尺寸取不到数值时回退默认 8.0，与 list 分支一致：

```python
sz = (_num(raw_val[2]) if len(raw_val) >= 3 else None) or 8.0
...
pts.append((name, xv, yv, sz or 8.0))
```

**验证**：`backend/tests/test_full_chain_integration.py::test_full_chain_contract_alignment_and_execution` 由 **fail（TypeError）→ pass**（1 passed，5m22s，跑完整五智能体管线 + 全图渲染）；`agents_core/chart-generator` 43 passed / 1 skipped（含渲染用例，零回归）。

> 该 bug 与 D-08 无因果关系，属既有潜伏缺陷；因 P0 修复改变选型而暴露，故一并修复以免交付链路在全量测试下崩溃。

## 3. C1 一票否决基准对账（经用户裁决 · 方案 A）

D-08 ① 修复后，A2 `financial_ratios` 由最旧期改为最新披露期，而 `eval/cases/baselines.json` 的 3 条比率基准（`gross_margin`/`net_margin`/`dupont_roe`）是从**修复前冻结产物**回填的最旧期值（3.53 / 87.72 / 14.85），导致 C1 比率组变红。

**用户裁决（2026-09-26）：方案 A —— 更新基准为修正值，不改动冻结产物。**

| 基准组 | 旧 expected（最旧期 2021） | 新 expected（最新期 2025） | 来源 |
|---|---|---|---|
| `gross_margin` | 3.53 | **3.24** | 修复后引擎在**同一** `dataset.json` 上确定性重算 |
| `net_margin` | 87.72 | **43.37** | 同上 |
| `dupont_roe` | 14.85 | **5.35** | 同上 |

- **非编数**：新值 = `DeterministicAnalysisEngine.compute_financial_ratios` 在黄金 `dataset.json` 上的确定性输出（无 LLM/无外呼），每条 `source.supersedes` 留痕旧值与原因，`_backfill.rebackfill_2026-09-26` 记录触发器/方法/未改动组。
- **冻结产物未改动**：`interpretation_report.json` 仍为修复前产物；其 `financial_ratios` 与新基准的差异属「产物早于修复」，需后续重跑全链路重新冻结快照后消除（报告 §9.3 既定恢复条件）。
- **遗留数据口径异常**：中电港 `net_margin=43.37%` 仍显著高于同期 `gross_margin=3.24%`（净利率＞毛利率，违反常识），属 **D-02（P3）** 数据口径问题，**非本次 P0 范围**，已在基准 `supersedes.reason` 中标注、单独跟踪。

C1 结果：`test_c1_formula_baselines.py` → **9 passed / 2 skipped**（比率组 + comps + CR3/CR5 全绿；2 skip = 同比组量纲待接入，合法跳过带理由）。
