### 1.2 改法（三处，最小侵入）

**改点 A · `_result()` 兜底（L719 附近，唯一出口）**

```python
# ── 新增：空数据集硬风控（P0-1）────────────────────────────
# 目的：无论上游走到哪条分支，只要最终记录数为 0，一律降级为 blocked，
#      并在 errors 里留下可被前端消费的原因（避免"假绿灯"流入下游）。
_SEVEN_DOMAINS = ("industry", "companies", "financials", "macro",
                  "industry_chain", "reports", "news")

def _total_records(dataset: Any) -> int:
    """统计七个数据域的记录总数（空数据集风控用）。"""
    return sum(len(getattr(dataset, name, []) or []) for name in _SEVEN_DOMAINS)
```

然后在 `_result()` 中（`dataset = self.fusion.fuse(...)` 之后、`return ResearchRunResult(...)` 之前）插入：

```python
        total = _total_records(dataset)
        if total == 0 and status in ("completed", "partial"):
            # 关键：空数据不得标记为成功。stop_reason 用独立枚举，便于监控统计。
            status = "blocked"
            stop_reason = "empty_dataset"
            errors = list(errors) + [
                RunError(
                    stage="data_fetch",
                    message=(
                        "全部数据域为空（检索未命中任何记录）：禁止下游生成量化结论；"
                        "请检查 query 构造或改用备用检索词后重试。"
                    ),
                    retryable=True,
                )
            ]
```

**改点 B/C · 两处 `coverage_complete` 判定（L180、L312）**

在设定 `"coverage_complete"` 之前加前置守卫：

```python
            # 记录数为 0 时不允许判为"覆盖完成"
            if _total_records(dataset) == 0:
                status, stop_reason = "blocked", "empty_dataset"
                break          # L180 处用 break；L312 处（循环外）直接赋值即可
```

## 2. 【P0-2】query 模板编译（自然语言 → 关键词串）

### 2.1 根因回顾（代码级）

`PLANNER_SYSTEM_PROMPT`（`agent.py` **L56–L83**）明确要求 LLM **把字段名/指标清单/时间跨度/排序写进 `query`**：

| 提示词行 | 原文（节选） | 导致的坏结构 |
|---|---|---|
| L68 | `expected_fields 必须包含："证券代码"、"证券简称"…` | 字段名当检索词 |
| L77 | `query 必须包含多年度连续时序（如"2021年至2025年"）` | 年份夹在中间 |
| L78 | `财务查询必须完整覆盖…营业收入、归母净利润…研发费用` | 一条塞 9 个指标 |
| L64 | `query 必须显式包含按总市值从大到小排序…取前 20~30 家` | 40 字长串 |

### 2.2 改法：**prompt 松绑 + 代码编译**（两步走，互不依赖）

**步骤 1 · 提示词松绑（改 `PLANNER_SYSTEM_PROMPT`）**

把上述 4 条的"**query 必须包含…**"统一改写为"**写入结构化字段**"：

```text
【query 与字段的职责边界（务必遵守）】
1. query 只写检索用的「实体 + 主题词 + 指标词 + 年份」，词间用空格分隔，词数 ≤ 7（中文约 ≤40 字符）；
2. 禁止把返回字段名写进 query（"证券代码/证券简称/总市值/营业收入/所属行业/所属概念"等），
   它们只能写入 expected_fields；
3. 禁止把说明性文字写进 query（"重点关注/用于评估/旨在/包括…等/时间范围/研究报告"等）；
4. 单条 query 的指标词不超过 3 个；超出的指标请拆成多条任务（或写入 expected_fields）；
5. 年份放 query 末尾或省略，不得夹在实体与指标之间；
6. 多年度时序请写入 arguments.time_range（如 "2021-2025"），不要塞进 query；
7. 排序与条数请写入 arguments.sort_by / arguments.limit，不要塞进 query。
```

**步骤 2 · 代码编译层（新增 `_compile_query()`，在 `_validate_tasks` 内调用）**

> **为什么要有编译层**：prompt 只能"劝"，编译层能"保证"。即使模型偶发跑偏，也被规范化后再发出。

**插入位置**：`_validate_tasks` 的 `elif not str(task.arguments.get("query", "")).strip():` 判定**之后**（约 **L462**），
在 `signature = self._task_signature(task)` 计算**之前**（保证去重基于编译后的 query）。

```python
# ── 模块级常量（放在 INTENT_SYSTEM_PROMPT 附近）────────────────────
_FIELD_NAME_NOISE: tuple[str, ...] = (
    "证券代码", "证券简称", "股票代码", "总市值", "流通市值", "营业收入", "归母净利润",
    "销售毛利率", "销售净利率", "ROE", "资产负债率", "经营活动产生的现金流量净额",
    "研发费用", "所属行业", "所属概念", "基本信息", "主营业务构成", "分行业", "分产品",
)
_DESC_NOISE: tuple[str, ...] = (
    "重点关注", "用于评估", "旨在", "有助于", "判断", "分析", "梳理", "测算", "评估",
    "时间范围", "研究报告", "研究提纲", "包括", "等，", "等。", "最新动态", "近一年资讯",
)
_PUNCT_RE = re.compile(r"[，。、；：,.;:！？!?（）()《》\[\]【】\"'“”‘’]")
_YEAR_RE = re.compile(r"^20\d{2}(年)?$")


def _compile_query(raw: str, *, max_tokens: int = 8) -> str:
    """把「需求描述式」query 编译为「检索关键词串」（P0-2）。

    规则：去标点 → 去返回字段名 → 去说明性文字 → 去重 → 年份移末尾 → 截断主体词数。
    设计原则：编译只做「减法 + 重排」，不发明新词，保证与原始意图一致、可审计。

    Args:
        raw: LLM 产出的原始 query。
        max_tokens: 主体部分保留的最大词数（默认 8）。

    Returns:
        编译后的关键词串；若编译后为空则原样返回 ``raw``（交由 P0-3 打分拒绝）。
    """
    text = _PUNCT_RE.sub(" ", str(raw or ""))
    for noise in _FIELD_NAME_NOISE + _DESC_NOISE:
        text = text.replace(noise, " ")
    tokens = [t for t in re.split(r"\s+", text) if len(t) >= 2]
    seen: set[str] = set()
    uniq = [t for t in tokens if not (t in seen or seen.add(t))]      # 去重且保序
    years = [t for t in uniq if _YEAR_RE.match(t)]
    body = [t for t in uniq if t not in years][:max_tokens]
    compiled = " ".join(body + years).strip()
    return compiled or str(raw or "")
```

**在 `_validate_tasks` 内调用（新增一个分支，位置在空 query 判定之后）**：

```python
            elif True:                                    # 占位：统一在此处规范化
                task = task.model_copy(
                    update={"arguments": {**task.arguments,
                                          "query": _compile_query(str(task.arguments.get("query", "")))}}
                )
                reason = None                             # 编译不算拒绝，继续走后续校验
```

> **实现提示**：更干净的做法是把编译放在循环体最前面（`signature` 计算之前），
> 用 `task = _compiled(task)` 统一改写，后续所有 `query` 读取点自动受益。

### 3.1 为什么要修正判据（**关键**）

原方案（外部建议）的伪代码有 **2 处会在中文上失效/误杀**：

| 原判据 | 问题 | 修正 |
|---|---|---|
| `len(q.split()) > 25` | **中文无空格分词** → 整句只算 1 个 token → **永不触发** | 改用**字符长度** + **标点计数** |
| `"等" in q → 扣 35` | **误杀正当词**（`等静压`、`等高线`） | 改用**精确模式** `包括.{0,20}等[，。]` / `等[，。]` |

### 3.2 实现（新增 `_score_query()`）

```python
_METRIC_TOKENS: tuple[str, ...] = (
    "营收", "收入", "净利润", "毛利", "净利", "ROE", "ROA", "资产负债率", "现金流",
    "市盈率", "PE", "PB", "市值", "增速", "产量", "产能", "销量", "库存", "价格",
)


def _score_query(q: str) -> tuple[int, list[str]]:
    """给 query 打质量分（0–100），返回 (分数, 扣分原因列表)（P0-3）。

    设计要点（针对中文）：
    - 长度用**字符数**而非 ``split()``（中文无空格分词，split 恒为 1）；
    - "等"用**精确模式**匹配（避免误杀"等静压"等正当词）。

    Args:
        q: 待评分的 query（建议先过 P0-2 编译）。

    Returns:
        (score, reasons)。score < 阈值（建议 75）应拒绝或重写。
    """
    score, reasons = 100, []
    if len(q) > 40:
        score -= 30; reasons.append("过长(>40字)")
    if _PUNCT_RE.search(q):
        score -= 25; reasons.append("含标点")
    if any(f in q for f in _FIELD_NAME_NOISE):
        score -= 40; reasons.append("含返回字段名")
    if re.search(r"重点关注|用于评估|旨在|有助于|研究提纲", q):
        score -= 35; reasons.append("含说明性文字")
    if re.search(r"包括.{0,20}等[，。]?|等[，。]", q):
        score -= 20; reasons.append("含举例式罗列")
    metrics = [t for t in _METRIC_TOKENS if t in q]
    if len(metrics) > 3:
        score -= 30; reasons.append(f"指标过多({len(metrics)}): {'/'.join(metrics[:5])}")
    if not re.search(r"[\u4e00-\u9fa5A-Za-z0-9]{2,}", q):
        score -= 30; reasons.append("无实体")
    return max(score, 0), reasons
```

            if _score < 75:

> **⚠️ 验收口径修正（2026-09-28 实测发现）**：
> **原定"≤20 字"不适用于中文关键词串** —— 中文按**字符数**计，一个 4–6 词的关键词串（含空格与年份）
> **天然就是 25–35 字符**。实测中 `碧水源 300070 SZ 近5年 2021-2025`（27 字）、
> `海水淡化行业 2025年吨水成本 技术路线 政策补贴 行业空间`（32 字）**都是健康 query**，若卡 20 字会被误判为不合格。
>
> **修正后的验收判据（4 条，全部为"必要条件"）**：
>
> | # | 判据 | 说明 |
> |---|---|---|
> | 1 | **不含标点** | `_PUNCT_RE` 无命中 |
> | 2 | **不含返回字段名** | 不命中 `_FIELD_NAME_NOISE` |
> | 3 | **不含说明性文字** | 不命中 `_DESC_NOISE` 与 `等X` 通用模式 |
> | 4 | **长度 ≤ 40 字符**（或词数 ≤ 7） | **取代原"≤20 字"** |
>
> **按修正口径复测调优后的结果**：
>
> | 指标 | 结果 |
> |---|---|
> | 坏样本达标（4 条判据全过） | **9/10** |
> | 唯一超标样本 | #8 `再生水行业2025年利用率投资需求行业规模及增速 近5年行业产值污水处理及再生水利用行业`（44 字）<br>**根因：行业名重复**（"再生水行业…行业规模……行业"）→ 需补一条**子串去重**规则（保留首次出现的词，移除其后作为子串重复的词） |
> | 正样本误伤 | **0/6**（含 `特种石墨 等静压 供需` → `特种石墨 供需`，"等静压"被"等X"规则误删 ⚠️ **见下**） |
>
> **⚠️ 新增待修项**：`等[一-龥]{0,4}` 通用清理**会吃掉"等静压"中的"等静压"**（把整词删掉）。
> **改法**：把通用清理限定为「**等 + 1–4 字 + 词边界且该词不在白名单**」，
> 或**先做词表白名单保护**（`等静压`/`等高线`/`等温` 等术语先保护再清理）。

> **结论**：**方案骨架已验证可用**（6/10 直接达标、0 误杀），剩余 4 项属**词表与语义转移的工程细化**，
> 不影响方案成立性；**建议实施时按上表 4 条同步完成**，并把本节实测表作为**单元测试夹具**。

## 5. 实施顺序与风险

| 序 | 动作 | 依赖 | 风险 | 回滚 |
|---|---|---|---|---|
| **1** | **P0-1** 空数据 → blocked + 告知 | 无 | 低：仅状态与上报；**可能让原本"通过"的用例变成 `blocked`**（这是**预期行为**，需同步更新测试期望） | 反向删除守卫即可 |
| **2** | **P0-2** prompt 松绑 + query 编译 | 无 | 中：编译可能**过度删词**（如把正当指标删掉）→ **必须跑 §4.1 正样本回归** | 编译函数可开关（加 `args.compile_query: bool = True`） |
| ~~3~~ | ~~P0-3 打分过滤器~~ **（不做）** | — | — | — |

**注意的副作用**：
- P0-1 生效后，**批② 的 71 条空数据用例状态将从 `approved` 变为 `blocked`** → 相关的既有测试期望需要同步调整
  （这属于**修正期望**而非放水：旧期望判的是"跑完了没有"，新期望判的是"数据够不够"）。
- P0-2 编译后，**`_task_signature`（去重）会基于编译后的 query** → 可能使原本"看起来不同"的两条任务**被判重复**并合并

## 6. 明确**不做**的事（附理由）

| 不做 | 理由 |
|---|---|
| **SFT / DPO 偏好微调** | ① 项目**无训练基础设施**（0 权重、0 处 peft/trl）；② 收益可被 **P0-2 代码编译**替代（代码约束更确定、可审计）；③ 样本**不成对**（843/0 是同一主题的 1 正 1 反，DPO 需要同 prompt 的 chosen/rejected 对）；④ 赛题为 **SkillHub 应用集成**，不要求模型训练 |
| **推理时"自检一步"（LLM 自评 + 重写）** | 与 **P0-3 打分过滤器**功能重复，且**多一次 LLM 调用**（成本↑、时延↑）；若 P0-2 已落地，模型本就不该生成坏 query |
| 下调 `analysis_depth` / 限制图表数"提速" | 影响报告质量与评选公平性（见执行手册 §8.4） |

## 7. 一句话原则（写进 code review checklist）

> **A1 的职责是"想清楚要找什么"，不是"把需求说明塞进检索词"。**
> **只有「实体 / 主题 / 指标 / 年份」能进 query；其余都是元信息，必须进任务配置。**
> **取不到时必须显式失败 —— 系统宁可"承认没拿到"，也不许"编出一份报告"。**
