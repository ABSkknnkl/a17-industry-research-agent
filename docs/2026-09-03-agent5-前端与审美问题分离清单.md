## 1. 前端问题（要动前端代码）

### FE-1【P0】用户没有"选产物/选风格"的入口 —— 你的"三种里选一种或全要"需求

后端已支持 4 个选项字段，但**前端零入口**（全仓 grep `output_formats`/`visual_style`/`visual_density`/`report_depth` 在 `frontend/src` 零命中）：

| 后端字段 | 取值 | 语义（9-02 改后） |
|---|---|---|
| `output_formats` | html / pdf 交付格式，可多选 | 缺省 → `["html","pdf"]`；**markdown 恒渲染**，不在此列（是预览源） |
| `visual_style` | auto / data_manual / analysis_note / deep_research | 主题风格 |
| `visual_density` | compact / balanced / detailed | 信息密度 |
| `report_depth` | brief / standard / deep | 内容深度 |

- 现状证据：`frontend/src/components/ReviewActions.vue:194 submitRevise()` 只构造 `data_fetch`/`data_interpret` 的 `edited_data`；`:296-297` report_fusion 阶段只有一个"发布模式"入口和 `:391` 提交按钮，**没有任何格式/风格控件** → 每次 revise 都走默认（HTML+PDF + auto）。
- 要做的 UI（建议放在 report_fusion 发布区，或单独"生成设置"抽屉）：
  1. **产物交付格式**：`html`/`pdf` 两个 checkbox（缺省全选）；旁注"Markdown 预览始终提供"。
  2. **风格**：4 选 1 单选（带 1-2 字描述：数据手册/分析笔记/深度研究）。
  3. **密度**：3 选 1（紧凑/均衡/详细）。
  4. **深度**：3 选 1（简报/标准/深度）。
- 后端改动为零（字段已支持、缺省语义已定）。**前端改完要覆盖的回归**：`formats` 现在只报交付格式，全失败时回退报实际落盘格式——下载区 UI 不要信 `formats` 字段，要以**实际落盘 artifacts 的 kind** 为准渲染按钮（见 FE-7）。

### FE-2【P0 拍板后执行】浏览器预览的渲染源：markdown 还是 HTML？

- 现状证据：`frontend/src/components/ReportReader.vue:3` `import { marked } from 'marked'`，`:28` `marked.parse(..., {gfm:true})`，`:135` `v-html="html"`，`:9/38` 只接收 `markdownArtifact` —— **浏览器看到的样式与 PDF 完全两套，前端改 CSS 动不了 PDF 一个像素**。
- 选项：
  - **A. 保持读 markdown（后端方案 A 已按此落地）**：预览永不断，前端只需把 `md-content` 的皮肤做精致。PDF 视觉归模板管，两套视觉仍是分叉——通过"两边共用一份 design token"（Q3）拉齐，做不到像素级一致。
  - **B. 浏览器改读 HTML 产物**：一套 HTML+CSS 两处呈现（浏览器 + PDF 同模板），视觉天然一致。代价：①`v-html` 渲染的是后端 Jinja 产物，需先过 **DOMPurify**（S-1 后端不修，前端必须自己堵）；②报告预览要能拿到 `report_html` artifact（现在 ReportReader 只接 markdownArtifact）；③md 仍要保留作降级/分享文本。
- 我的建议：**首版走 A（零风险、md 恒在），把 B 列为 v2**；但 Q3（单一事实源）无论 A/B 都要先定，否则前端做了皮肤、PDF 模板又改一遍，两边漂移。

### FE-3【P1】换格式 = 重跑 fusion = 新 revision，旧分享链接失效

- 后端语义：revise 必产生新 revision，产物 uri 变化 → 用户之前分享/下载的链接失效。
- 前端两条路（要产品拍板）：
  - 轻量：发布区展示"当前 revision 产物列表 + 复制链接"入口，提示"修改会生成新版本，旧链接仍指向旧版本"（需后端保留历史 artifact 的查询）。
  - 完整：等后端加 `POST /runs/{id}/export`（`report_view.json` 已落盘，重导出零成本）→ 前端在报告页放"导出 PDF / 导出 HTML"按钮，导出不改 revision、链接稳定。

### FE-4【P2 可选】浏览器端交互增强（只对"浏览器阅读体验"有效）

| 项 | 来源 | 说明 |
|---|---|---|
| 目录吸顶 + 当前章节高亮 | 视觉方案 Q15 | 仅长报告有价值；PDF 无此概念 |
| 来源引用悬浮详情 | Q16 | 现在是 `〔来源1〕` 静态文本；悬浮=两套呈现（PDF 静态），可接受的话要做 |
| 图表点击放大/lightbox | Q17 | 收益低，建议缓 |

### FE-5【P2 可选】深色模式（Q11）

- PDF 只能浅色；浏览器可做深色。做了要维护第二套 token。**建议首版不做**，除非产品有"夜间阅读"诉求。

### FE-6【P2】视觉回归基建（Q18）

- 若 FE-2 走 B（浏览器读 HTML）：前端可加截图基线 + 像素 diff（阈值建议 0.5%）；若走 A：视觉回归只能挂 PDF 侧（后端 nightly），前端不用建。
- 决策点：**回归挂在 nightly 还是 PR**。PDF 渲染慢 + 字体版本噪声大，建议 nightly，不挂 PR。

### FE-7【P1】产物展示细节（跟新语义走）

- 报告页 artifact 区：现在以 kinds 渲染 md/html/pdf 下载按钮即可，但要补：
  - 标签对齐新语义：md 标"预览/文本"，html/pdf 标"交付格式"；
  - 后端 pdf-only 全失败回退时，`formats` 报的是"实际落盘格式"——下载按钮**以 artifacts kinds 渲染**，别读 `formats`；
  - `markdownArtifact` 为空时的降级 UI 已有（`:121` el-empty），确认 html 产物缺失时也有对应空态。

## 2. 审美问题（纯视觉/设计）

> 共性问题：项目里**已经有一份做完的好设计**（`docs/agent5-layout-generation-spec.html`：12+ design token、封面斜切渐变、`.stat-grid`/`.matrix`/`.token` 组件），但从没进过报告模板。审美主线 = 移植它，而不是重新设计。

### V-1【P0 主线】spec.html 视觉语言移植进 `report.html.j2`

- 资产清单：`--brand:#0b4fa3` 等 12+ token；封面"品牌色顶边 10px + 145deg 斜切渐变"；44/19/13px 标题-导语-辅文字阶；`--shadow:0 12px 36px rgba(31,57,91,.10)`。
- 移植 = 最快变好看路径。做的时候**只改模板 CSS/结构**，不动 `ReportViewModel` 契约、不动渲染函数签名。

### V-2【P1】三套 VisualStyle 完整主题包（视觉方案 §5.1）

| 风格 | 语气 | 建议主色 | 字体 | 版心 |
|---|---|---|---|---|
| data_manual 数据手册 | 冷峻、数值优先 | `#17365d` 深蓝 | 无衬线 + 等宽数字 | 1120px，密度高 |
| analysis_note 分析笔记 | 平衡、亲和 | `#0b4fa3` 品牌蓝 | 无衬线 | 1040px |
| deep_research 深度研究 | 沉稳、论证感 | `#7c2d12` 赭石 | 衬线（Songti/Noto Serif CJK） | 920px，行距大 |

- 现有 `visual-*` 骨架在模板里，但只是"版心/padding"差异（B-4 刚修了 print 覆盖），**不是主题**。要做成一套变量完整的三套皮肤。

### V-3【P1】9 个组件（做精比做多重要，视觉方案 §5.3）

1. 封面：顶边 + 斜切渐变 + 标题 + headline + 5 格元信息（B-6 已把 5 格网格修对，样式仍待做）
2. 目录：两列 + 点线引导 + 页码（页码依赖路线决策，见 V-7）
3. **KPI 卡片组（收益最高）**：章节开头 3-4 个关键数字卡（32px 等宽数字 + 标签 + 同比涨跌）——研报"专业感"最便宜的来源
4. 结论块：左侧色条 + 置信度徽章 + 来源 chips + 不确定性说明
5. 正文段落：首段结论句加粗、段距 10px、首行不缩进（中文研报惯例）
6. 图表框：屏幕阴影 / 打印细边框 + 图表编号 + 来源脚注 + 分析目的
7. 数据表：斑马纹、数字列右对齐 `tabular-nums`、表头重复、单位行
8. 风险/不确定性框：浅黄底 + 图标 + 圆角
9. 来源索引表：**7 列改 5 列**（合并"获取方式/层级"），超长文本 `overflow-wrap:anywhere`

### V-5【P2】双媒介规则（屏幕 vs A4，视觉方案 §5.2）

### V-8【P2】极端/脏数据的"体面降级"（Q20 + degraded-dirty 夹具）
