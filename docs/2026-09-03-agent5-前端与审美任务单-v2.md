## 0. 大白话版：我们要干啥（先看这段，够用了）

**报告现在啥样？** 内容是对的、字是齐的，但长得像 2010 年的网页——没页码、封面素、长表格被拦腰切断、图表配色死板。**能用，但不好意思发给客户。**

**这轮要它变成啥样？** 像券商研报：封面有气质、目录能点、每页有页码、章节清爽、关键数字做成"卡片"一眼看到、图表和正文是一套颜色。不求花哨，求**专业感**。

**活怎么分？**
- 后端那摊**已经干完**（把内容修"对"：不丢图、目录能点、水印不乱飘、导出不卡死）。你不用碰。
- 你要干的：让报告**好看**。具体两块：① 浏览器里看的报告；② 导出的 PDF。⚠️ 注意：**这俩现在是两套代码**——浏览器读的是 markdown（自己渲染样式），PDF 走的是后端另一套模板。想让它们长得一样，得先回答一个选择题（Q2，见 §6）。

**测试咋办？放心，不连累你、也不用等别人。**
- Agent5 渲染报告是个**"纯函数"**：喂进去一份 JSON，吐出来一份 HTML/PDF，**不碰数据库、不调大模型、不联网**。
- 所以测试**只测 Agent5**：前面 Agent1~4 根本不跑，数据**全用假的**（我们按"前 4 个智能体全对"来捏造：光伏、白酒、半导体各一份正常报告 + 一份故意刁难人的极端数据 + 一份脏数据），直接喂给渲染，看 PDF 好不好看、分页崩没崩、表格被切没切。
- 效果：**你改样式不用跑整条流水线**，本地一条命令出 PDF，改完存"基线截图"，以后每次改样式都自动对比一遍，防止把好看的改回丑的。详见 §4。

**一个要一起想的大问题：要不要接个大模型专门写 HTML、让报告更好看？**
想法很诱人（"AI 帮我排版"），但我们强烈建议：**别让它写整份 HTML**。它看不见分页（不知道这张图会被切成两半）、每次生成都不一样（没法复现同一份报告）、还可能写出带漏洞的代码、出了问题你还得写一套检查器——那工作量约等于自己写模板。**它适合干的是"出主意"**：给配色（新能源青绿、金融深蓝、消费暖橙）、给排版方案（这节用卡片还是表格）、给图表颜色。主意它出、代码模板写，又好看又稳。详见 §5。

**最后：你只需要拍板几个小选择题**（每个都给了建议答案，§6）：要不要页码（建议要，用 Paged.js）、浏览器读 markdown 还是 HTML（首版建议维持 markdown）、正文两端对齐还是左对齐（建议左对齐）……拿不准就先用建议值，跑起来再调。

## 2. 前端要干的活（动前端代码）

### FE-1【最优先】给用户"选产物/选风格"的入口（产品要的"三种里选一种或全要"）

后端已支持 4 个选项字段，但**前端页面一个入口都没有**（在 `frontend/src` 搜这四个字段，零命中）：

| 字段 | 取值 | 现在的语义（9-02 改后） |
|---|---|---|
| `output_formats` | html / pdf，可多选 | 不选 = HTML+PDF；**markdown 永远生成**，不算交付格式（是预览用） |
| `visual_style` | auto / data_manual / analysis_note / deep_research | 报告风格 |
| `visual_density` | compact / balanced / detailed | 信息密度 |
| `report_depth` | brief / standard / deep | 内容深度（简报/标准/深度） |

- 证据：`frontend/src/components/ReviewActions.vue:194 submitRevise()` 只给前两个阶段传编辑数据，`:296-297`"发布模式"区只有个按钮，`:391` 提交——**没有任何格式/风格控件**，所以现在每次都是默认 HTML+PDF、auto 风格。
- 要做：在发布区加一组控件即可——交付格式两个勾选框（缺省全勾，旁注"Markdown 预览始终有"）、风格 4 选 1、密度 3 选 1、深度 3 选 1。**后端零改动。**
- 回归提醒：提交字段后 `formats` 现在只代表"交付格式"，全部导出失败时会回退成"实际落盘格式"——**下载按钮请按实际落盘的产物来渲染，别信 `formats` 字段**（见 FE-7）。

### FE-2【先拍板再动】浏览器预览到底渲染 markdown 还是 HTML？（Q2）

- 证据：`frontend/src/components/ReportReader.vue:3` 用 `marked`，`:28` `marked.parse(...)`，`:135` `v-html`，`:9/38` 只接收 `markdownArtifact`。→ **你在前端 CSS 里改的样式，PDF 一个像素都不会变**，因为 PDF 走的是后端模板。
- 两条路：
  - **A. 维持读 markdown**（后端方案 A 已按这个落地）：预览永不坏；你把 markdown 皮肤做精致即可。代价：和 PDF 始终是两套视觉，只能靠"两边共用一套设计变量"（Q3）拉近，做不到一模一样。
  - **B. 浏览器改读 HTML 产物**：浏览器和 PDF 用同一份 HTML+CSS，视觉天然一致。代价：① `v-html` 渲染后端 HTML 前必须过一遍消毒（DOMPurify）——后端那道安全加固明确不做了，这活落你头上；② 预览要能拿到 html 产物（现在只接了 markdownArtifact）；③ markdown 仍要留作降级/分享。
- 建议：**首版走 A（零风险），B 放 v2**。但 Q3（样式放哪一份文件里管）不管 A/B 都得先定，否则你做完皮肤、PDF 模板又改一遍，两边越漂越远。

### FE-3【P1】换格式 = 重新生成 = 新版本，旧分享链接会失效

- 现在用户改一次报告就产生新 revision，产物下载地址变，之前分享的链接打不开。两条路（问产品）：
  - 轻量：报告页展示"当前版本产物 + 复制链接"，并提示"修改会产生新版本，旧链接仍指向旧版本"。
  - 完整：后端加个"按需导出"接口（`report_view.json` 已落盘，随时能重出 PDF）→ 报告页放"导出 PDF / 导出 HTML"按钮，导出不产生新版本、链接稳定。

## 3. 审美/视觉要干的活（纯设计）

> 先说省力诀窍：**好看的设计已经有人做完了**——`docs/agent5-layout-generation-spec.html`（下称 spec.html）里有整套配色变量、封面斜切渐变、数字卡片、规整表格样式。你要做的**主要是把它搬进报告模板**，不是从零设计。

### V-1【最优先】把 spec.html 的视觉语言搬进报告模板
- 搬什么：12+ 个设计变量（主色 `--brand:#0b4fa3` 等）、封面"顶部一条品牌色 + 斜切渐变"、字号阶梯（大标题 44 / 导语 19 / 正文 13）、卡片阴影。

### V-2【P1】做三套完整皮肤（对应三种风格）

| 风格 | 气质 | 主色建议 | 字体 | 版心 |
|---|---|---|---|---|
| data_manual 数据手册 | 冷、数字说话 | `#17365d` 深蓝 | 无衬线 + 等宽数字 | 宽、密度高 |

### V-3【P1】九个组件（宁精勿多）
1. 封面：品牌色顶边 + 渐变 + 标题 + 一句话导语 + 5 格信息

3. **关键数字卡片组（最划算）**：章节开头放 3-4 张数字卡（大数字 + 说明 + 涨跌色），研报"专业感"最便宜的来源
4. 结论块：左边一条色带 + 置信度小徽章 + 来源小标签 + 不确定性说明
5. 正文：每段开头结论句加粗、段落间距 10px、段首不缩进（中文研报习惯）
6. 图表框：屏幕下有阴影、打印时细边框，带"图 X-Y"编号 + 来源脚注 + 一句"这张图想说明啥"
7. 数据表：隔行变色、数字列右对齐、表头每页重复、带单位行
8. 风险/不确定性提示框：浅黄底 + 圆角
9. 来源索引表：**7 列改成 5 列**（合并两列），超长文字自动换行

## 4. 测试怎么做：只测 Agent5，假数据随便捏（新增建议 ①）

### 4.1 为什么能只测 Agent5、甚至不用真数据
- Agent5 的渲染函数 `render_html(报告JSON) -> HTML` 是**纯函数**：输入一个 JSON、输出 HTML，**不碰数据库、不调大模型、不联网**；PDF 只是把 HTML 交给无头浏览器。
- 前 4 个智能体干的所有活，最终都汇成这一个"报告 JSON"（`ReportViewModel`）。所以**只要捏造这个 JSON，就等价于"前 4 个智能体全对"**——它们的正确性不在这次测试范围内，你要验证的只有一件事：**这份报告渲染出来好不好看、分页崩不崩**。
- 反过来也成立：如果假数据下版式都崩，真数据只会更崩（真实数据更脏、更缺字段），所以这套测试的可信度不输端到端测试。

### 4.2 捏 5 份假数据（夹具），覆盖各种情况

| 夹具 | 内容是啥 | 测什么 |
|---|---|---|
| 光伏（golden） | 正常行业报告：7 章、8 张图、60 条来源 | 主视觉基线（好看的标准答案） |
| 白酒（golden） | 短报告：7 章、5 张图、简报深度 | 短报告/少图时别空荡荡 |
| 半导体（golden） | 复杂图表全上：雷达图/热力图/箱线图 12 张 | 复杂图表不破版 |
| 极端刁钻（stress） | 60 字超长标题、一章塞 21 节、30 图、200 来源、超宽表、超长数字串 | **版式抗揍测试**（生产真会遇到） |
| 脏数据（degraded） | 空来源、0 图表、草稿水印、超短段落、一堆质量告警 | 降级场景不能崩 |

> ⚠️ 别只测好看的数据——那会做出生产上崩掉的版式。**脏数据那份必须做。**

### 4.3 怎么捏 + 怎么跑
```
捏造：拿 ReportViewModel 结构定义 + 一个最小示例 → 交给大模型生成整份 JSON
      → 程序严格校验（章节数、图表编号、来源引用对得上，过不了就重新生成）
      → 人扫一眼业务是否自洽（数值不打架、结论有出处）→ 冻结进 git，以后只增不改

跑：render_fixture.py <夹具.json>
      → 渲染出 report.html / report.pdf
      → 无头浏览器逐页截图 page-01.png ... page-NN.png
      → 放到 artifacts/visual/<夹具名>/ 下
```
- 你**本地一条命令就能看 PDF 效果**，不用起后端、不用等流水线。
- **基线**：第一版人工确认"好看"后，把截图存为基线；以后每次改样式重跑，逐页和基线比像素（差异面积 ≤0.5% 算过）。像素对比只告诉你"变了"，不告诉你"变好变坏"——**每次改动仍要人眼过一遍整份 PDF**。
- CI：建议挂 **nightly**，不挂 PR（慢 + 字体版本易出噪声）。

`backend/tests/reporting/` 目前只有 `test_svg.py`，HTML/PDF 渲染**零测试、零夹具**——这套是新建，不是补。后端侧 9-02 已就位了渲染器改造，夹具与脚本是接下来的共建项（后端出脚本，你出视觉判断）。

## 5. 要不要外接一个大模型、专门写 HTML？（新增建议 ②，给前端的话）

### 结论先放这
**别让它写整份 HTML。** 可以让它"出主意"（配色/排版方案/图表颜色），代码仍由你写进模板。

### 为什么"AI 写整份 HTML"是坑（大白话五条）
1. **它看不见分页（最致命）**。它不知道这段文字会落第几页、这张图会不会被切一半——分页是排版引擎"算"出来的，不是"写"出来的。它写得再漂亮，PDF 照样断得难看。
2. **同一份报告会变样**。AI 每次生成都不完全一样 → 同一天导出的两份 PDF 长得不同，报告没法当正式交付物追溯（系统里每个产物都记 sha256，样式改动不能破坏它）。
3. **安全门被拆了**。现在报告正文一律当"不可信内容"转义后才进 HTML；让 AI 直接写 HTML 等于把这道保险交给掷骰子——它可能写出 `<script>` 之类的东西。
4. **你还是要写一套检查器**。AI 写完你还得验：标签闭没闭合、有没有外链、有没有脚本、字段丢没丢、分页崩没崩——这套检查的复杂度 ≈ 你自己写模板。
5. **以后改样式更麻烦**。改个配色，现在改一行 CSS；AI 方案要改提示词 + 重跑 + 重新验，还可能有回归。

### 那 AI 该待在哪儿（四选，可多选）

| 位置 | AI 干啥 | 产出 | 风险 | 值不值 |
|---|---|---|---|---|
| **① 配色生成器（强烈推荐）** | 按行业/风格给配色 | 一个几十项的 JSON | 极低（程序白名单校验数值范围） | 每份报告有"行业气质"：新能源青绿、金融深蓝、消费暖橙 |
| **② 排版方案（推荐）** | 读章节内容，决定"这节放卡片/表格/图半宽" | 结构化方案（章节→组件+尺寸） | 低（枚举校验，非法值自动回退默认） | 真正的"AI 排版"，且可控可回归 |
| **③ 图表配色参数（可选）** | 给图表要主色/网格密度 | 参数对象 | 低 | 图表跟报告主色自动协调 |
| **④ AI 写一段主题 CSS（实验）** | 直接生成主题样式 | CSS 文本 | **中：必须过沙箱** | 自由度最高但要写校验器 |

- **如果你/团队就是想试④**，沙箱检查清单（全过才放行）：只允许 CSS 变量 + 白名单选择器，禁止 `@import`、`url()`、`position:fixed`；体积 ≤8KB；真渲染一次抓 console 报错；正文对比度 ≥4.5:1；**任何一条不过 → 静默退回默认皮肤，别报错给用户**。
- 想让 AI 给"美观度打分"？可以当**粗筛**用（先让机器过 20 份夹具，人只看可疑的几份），**不能当发布闸门**——AI 审美不稳定，同一份 PDF 两次打分能差 1 分。

### 落到行动
如果你想试"AI 排版"，从 **①配色生成器** 开始（风险最低、效果最直观）。方案/契约由你、产品和后端一起定，渲染仍走确定性模板。
