产业链图算法溯源

它是为了解决什么问题被造出来的 · 依据 2026-10-16 ~ 11-12 的 20 余份项目文档与当前代码 · 2026-11-20

一句话答案：这不是一个"画图算法"，是一个分工算法。
它要解决的核心问题是：大模型没法可靠地"决定产业链长什么样"——它会漏掉没有上市公司的必需环节、把品类词当公司名、把上游厂塞进品牌位、把同行当客户、同一家公司写两种名字、一次只处理前几项。
所以算法把职责反过来分：结构、口径、上限、修复规则、缺失怎么显示，全部由代码定死；模型只负责往固定格子里填内容，而且填的每个企业名都必须能在检索片段里找到出处。

一、你当初要解决的是什么问题

不是"图画得不好看"，是三类事实性错误。按严重程度排：

错误类型具体表现（都是真实运行踩出来的）为什么致命
结构错白酒、创新药、物流全被套成"零部件 → 整机制造"的硬件四段式。白酒的「陈酿 / 勾调 / 制曲」系统性消失，因为这三个环节没有独立上市公司。图从第一眼就错。专业观众看到"白酒有整机制造"就知道没入门。
归属错风电品牌卡里出现东方电缆、中天科技（都是海缆厂）；机器人「关节模组与结构件」能力卡里填的是兆威机电、鼎智科技（零部件商）；低空经济「科研与教育」客户格填的是乐聚、智元、银河通用（全是同行整机厂）。上下游边界混乱，等于把供应链关系讲反了。
表达错「白酒」被当成一家公司写进品牌卡；「运维服务」「备件供应」这类品类词进了企业位；同一家公司「贵州茅台」和「贵州茅台酒股份有限公司」各占一格；11 个节点描述写着占位语「证据未覆盖」，其中 3 个明明有企业。数据没对齐，一页图就能看出是机器拼的。
关键判断：这些不是"模型幻觉"。10-17 的排查结论是——A2 拓扑其实写对了，是 A3 的修复规则把它改坏的（白名单自证循环、企业数主导核心判定、问财召回的是概念股）。所以问题不在"模型乱编"，在"规则没把边界划清"。

三、关键实验：为什么"换个更强的模型"不是解药

你当时问过一个很关键的问题："参考豆包，只联网 + 模型本身就能得到正确答案，为什么我的项目会错？"

于是做了 7 组消融实验，同一个模型、同一套模板，每次只改一个变量。以白酒为例，看上游能分出几大类、陈酿和勾调能不能保住：

组模型给素材放开常识上游大类陈酿勾调
E1flash不给—4✓✗
E2flash给只用素材2✗✗
E3flash给放开3✗✓
E4flash给放开 + 思考4✗✓
E5pro给只用素材1✗✓
E7pro不给—3✗✗

三条结论，直接决定了算法长什么样：

  1. 给素材反而更差（4 类 → 2 类）。「陈酿」一给素材就没了。
  2. 换更强的模型更差（pro 只分出 1 类，flash 还有 2 类）。因为 pro 更"服从"只用素材的指令，更不敢补产业必备环节。
  3. 没有一组是 4/4。放开常识能找回勾调，开思考能找回酒曲，但凑不齐。
机制：检索素材只覆盖"有上市公司的部分"。陈酿、勾调、自研算法这些环节没有独立上市公司 → 搜不到 → 被模型挤掉。
宇树的"自研算法" = 白酒的"陈酿"。 这是同一个结构性缺陷，不是模型不够强。

所以算法从"让模型想清楚"改成"先把格子画好，再让模型填"。

四、算法的设计原理：一次职责反转

三条原则含义落在哪里
结构给死有哪些环节、分几段、谁是核心，由代码常量决定，不由模型决定六类结构骨架 + 固定槽位表
内容放开每个槽位里填谁，必须来自检索证据；环节名可来自模板，企业名必须来自片段联网取证 + 抽取规则
缺失显式没证据就空着，让渲染层说"暂无"，绝不用常识或问财凑数据层不写占位语；空位不画企业行

为了防复发，又加了三道闸：

闸门拦住什么
骨架槽位表结构漂移、维度混杂、必备环节丢失
兜底硬闸通用画像的硬件描述外溢到非制造行业（白酒出现"电气设计"）
内外一致性绊线内置兜底副本与外部画像数据漂移（靠它在 5 分钟内发现过一次误删）

五、算法的五层结构（大白话）

① 结构骨架（定"分几段、有哪些格子"） 六类：离散制造 / 消费 / 流程 / 医药 / 数字 / 服务 ↓ ② 行业画像（定"这个行业的常识"） 25 份画像：龙头名单、认证机构、能力卡词表、上下游清单、禁用词 ↓ ③ 联网取证（定"每个格子填谁"） 按段发 8 条检索 → 片段按槽位归类 → 整组替换，不是只补空 ↓ ④ 校验与修复（定"什么算错"） 结构校验 → 一组硬规则 → 确定性修复，每条留痕 ↓ ⑤ 版式渲染 + 体检（定"怎么画"） 三列目录式 → 卡片零连线 → 2 根列间箭头 → 图上不许有数字

5.1 第一层：六类结构骨架

不是所有行业都长成"零部件 → 整机"。代码里写死六类：离散制造、消费、流程、医药、数字、服务。每类有自己的列头文案和固定槽位（14–16 个格子），模型只能填、不能增删改。

为什么必须写死：白酒的"陈酿/勾调/制曲"、宇树的"自研算法"这类环节，没有独立上市公司，靠检索永远搜不出来。如果等模型自己发现，它一定漏。

5.2 第二层：行业画像

25 份画像 JSON，每份给这个行业四样东西：龙头名单、认证/监管机构、中游能力卡词表、上中下游的专属清单。再加一份"禁用词"，防止把别的行业的东西搬过来。

为什么需要：光有骨架只知道"有 5 个上游格子"，不知道"这个行业的上游具体是什么"。肖像是把行业常识从模型脑子里搬到可审计的文件里。

5.3 第三层：联网取证

清空所有非核心企业（上一站顺手写的企业名不可靠）→ 按上游/中游/下游/配套四段各发 2 条检索，共 8 条 → 片段按 16 个格子归类 → 某格搜到了就整组替换，不是"只补空的"。

为什么整组替换：如果新旧混着放，一次错误召回会永久留在图里。整组替换保证每一格的企业名单来自同一次、同一批证据。

5.4 第四层：一组硬规则 + 确定性修复

这是最像"算法"的一层，也是你最容易看不懂的地方。它是一条固定顺序的修复流水线，每一步只干一件事，改完留痕：

顺序规则解决什么
0.1b上游厂商不是客户下游"场景"格填的是采购方，不能填同行整机厂
0.1c企业名不得与同节点的品类词重复「运维服务」「备件供应」进了企业位
0.1d描述不得是占位语「证据未覆盖」写进数据层
0.15泛词环节名具体化「其他」「相关环节」这类空壳名
0.2非产业链环节剔除股权投资、参股属股东关系，不是产业链环节
0.25知识底座归属裁决（四态）只有明确判"不匹配"才改名删名；"查不到"只留痕不删人
0.4企业跨节点唯一化同一家公司只能出现一次（当时的设计）
0.45品牌卡上游角色归位品牌卡里混进上游零部件商
0.5核心节点归属归一多个核心节点 / 核心节点挂错段
0.56品牌卡先角色剪枝、后截断先按 2–8 家截断会把真龙头截掉
3配套类节点迁到配套带售后/回收/软件被放进下游销售区
6.5企业名不在白名单 → 摘除编造企业（真实运行踩坑后补）
7瓶颈标记合规化瓶颈只能标上游，全图 1–3 个
注意一个口径漂移：代码注释写"8 条硬规则"，但正文编号实际到 11 条（前 8 条是原版，9/10/11 是后来补的瓶颈、连线方向、监管职能）。答辩时建议说"一组硬规则"，别说死"8 条"，否则被逐条对会尴尬。

5.5 第五层：三列目录式渲染

这一层是纯几何，跟金融无关，但决定了图的观感：

决策定稿依据
图种分层目录图（容器 + 卡片网格），不是工艺流程图上游零部件并行供给，没有先后关系
列数与连线三列；卡片之间零连线，只有 2 根列间粗箭头多对多网状关系画不出来，只留价值方向
整机位置并入中游列顶部大卡（占列高 58%）拆成独立一列会暗示不存在的代工分工
网格规则≤3 张卡用 1 列，≥4 张用 2 列避免 2×2 右下空一格
画布1600×900（16:9）研报插图常用比例

5.6 出图前体检

图上不许出现任何裸数字（份额/产能/营收/价格/型号）；每个环节名和企业名必须逐字出现在图里（防止被裁）；连线样式必须符合语义。体检不通过就降级，不出图。

六、每一个设计，对应一个真实事故

当年踩的坑现在由哪条机制挡住
模型不会补"产业必备但无上市公司载体"的环节六类骨架 → 固定槽位表，模型只能填不能增删
分类维度会被素材分布主导（素材里包材文章多，上游 6 格全被原料包装占满）骨架优先、素材只填内容；按段发检索，不是"先搜一批再归类"
把品类词/主题词当企业名（"白酒"成了一家公司）企业名 ∩ 品类词 → 删；等于主题词 → 删
同一实体多种写法各占一格短名 + 法定后缀判定 + 显式别名表，绝不模糊改写
提示词写"不得增删"，模型照样自创环节槽位表 + 显式例外（只有"工序①②③"允许按行业改名）
一次给 16 个环节，只返回前 5 个分批抽取（8 个一批），检索片段按批切
占位语写进数据层提示词点名禁止 + 确定性清洗 + 缺失由渲染层表达
品牌卡为凑数抓上游厂数量由真实整机厂决定（2–8 家），不足就少排，不得补空
中游能力卡填外部供应商删除兜底名单；能力卡不放任何外部主体
下游场景填同行整机厂场景节点出现"机器人/无人机/机械臂"结尾的公司 → 整批清空
骨架写完了没接进生产契约测试断言"A2 和 A3 的骨架同源"
验证走了旁路（脚本自己拼图，不经过 A2）验收必须走生产入口；脚本改名"黄金样本生成器"

七、这套算法的边界（10-30 你自己的批判）

这一节很重要——它说明这套算法不是万能解，答辩时主动说反而加分。原文的判断是：

  1. 它仍然是"先定槽位、再让模型给名单、最后用规则修名单"。没有在数据模型里把每一个"企业属于某环节 / 企业供应某客户"的判断绑定到独立证据。
  2. 画像同时承担了"事实"和"结构"两个职责。缺画像时，两种能力同时下降。
  3. 知识图谱的两张关系表不可靠（行业上下游表、产品-产品表），没能充当工业底座；实施退化成"知识库校验 + 模型命名"。
  4. 一家公司只许出现一次——但真实世界一家公司可以同时做品牌、代工、零部件。展示去重不能删掉真实的多重参与关系。
  5. A2 为填空会从企业最多的阶段搬企业——这是为了版面完整而做的推断，不是事实归属。
  6. 三列和四段只是一种视图，不是产业唯一正确的形态。产业也可能是网络、平台生态、服务履约链。

所以 10-30 提出了一套"证据图谱 + 动态行业本体"的新架构：每条关系都是独立断言（A 供 CPU / CPU 用于笔记本 / A 供货给 B 是三条不同关系），带时间、范围、证据引用，事实状态分 candidate / supported / contradicted / unresolved / expired。但这份文档明确写着"只写方案，没有修改应用源码"——它没有实施。

九、你该怎么讲（三句话 + 四个追问）

9.1 三句话版本

第一句（问题）："我们最早让大模型自己决定产业链分几段、每段放哪些企业，结果发现它有三个系统性缺陷：没有上市公司的必需环节会漏掉、品类词会被当成公司、上游厂会被塞进品牌位。"

第二句（解法）："所以我把职责反过来了——结构、口径、上限、修复规则全部由代码定死，模型只往固定格子里填内容，而且每个企业名都必须在检索片段里有出处。"

第三句（边界）："这套做法能保证结构和归属不出系统性错误，但它不能证明'这个行业只有这些环节'。所以我们保留了缺口标记和人工审核门，不宣称全自动正确。"

9.2 四个最可能被追问的问题

追问回答要点
这张图是 AI 生成的吗？分两层：结构和版式是代码定的，不是 AI 想的；每个格子里填哪几家企业来自检索证据，并且要过白名单和硬规则。AI 负责"填内容"，不负责"设计结构"。
为什么不用知识图谱直接生成？试过。项目审计发现现成的行业上下游关系表、产品关系表不可靠，撑不起全行业底座，最后退化成"知识库校验 + 模型命名"。知识图谱不是正确性的裁判。
换个大模型是不是就好了？做过 7 组消融实验：给素材反而更差，换更强的模型更差（上游从 2 类掉到 1 类），没有一组能全对。原因是"素材只覆盖有上市公司的部分"，这是结构性问题，不是模型能力问题。
这套算法的局限是什么？三条：画像是人工资产，新行业要先建画像；企业归属目前绑在节点上，没有做到"每条供货关系一条独立证据"；一家公司只出现一次是展示去重，不等于真实世界里只参与一个环节。

10.1 三份容易被误读的文档，先打个标记

① “10-30 重构方案”不是现状——它自己写明"没有实施应用代码修改"。别在汇报里把它当成已实现的能力。
② “8 条硬规则”是旧口径——代码正文编号已到 11 条，答辩说"一组硬规则"更稳。
③ “6 张图 / 15 张图 / 14 就绪”是三套不同语境——模板门禁要 15 张、某次放行产物 6 张、PPT 统计 14 就绪。讲产业链图时不要顺带把图数说错。

十一、补问："证据图谱 + 动态行业本体"为什么没有落地

先纠正一个说法：它不是"没实现"。
2026-10-31 的提交 d63c799 已经建了共享包 chain-research（模型 / 存储 / 取证适配 / 研究服务 / 视图编译），8e5068d 把骨架、画像、检索、诊断接进生产。适配层在 A1 / A2 / A3 都有 v2 分支，设 CHAIN_ENGINE=evidence_v2 就能走。
包自述原话："当前为可运行的生产切片，不代表 T9 或未知行业认证完成。"

所以准确的表述是四句话：管道实现了，验收没完成，默认没切换，A17 这张图没有用它。原因分四层，从表到里：

11.1 第一层：目标是主动降级的，不是没做完

10-30 同一天出了两份文档，一份是"证据图谱 + 动态本体"的完整架构，另一份是《比赛版最终修改方案》。后者第一句就写清楚了：

"目标：优先交付重点行业结构完整、企业归属合理、可解释、适合比赛展示的产业链图。允许补专属行业画像，不再以任意陌生行业自动百分之百正确作为本轮完成条件。"

也就是说：v2 的核心卖点是"没见过的行业也能冷启动生成"，而比赛只需要一两个重点行业。为一个比赛用不上的能力，去重做半条链路，投入产出不成立。这是主动取舍，不是能力不足。

11.2 第二层：自动启用要求"已审画像"，而现有两份都是草稿

创建任务时的路由逻辑是这样的：如果用户没指定引擎、但明确要产业链图，系统会尝试"优先 v2"。触发条件是——研究策略是 explore，或者匹配到的行业画像状态是 reviewed（已审）。否则就退回旧路径，并在备注里写"缺少已审画像且未启用开放研究，产业链仅按环节分类呈现"。

而新版画像目录里只有两份：笔记本、白酒，都是 draft（草稿）。包自述："结构与产品映射已整理，但没有声称经过原始资料或人工审定。"

所以不是代码不跑，是没有"已审画像"给它跑。画像从草稿变成已审，需要逐条回到原始资料核对、再过人工审阅——这是人的工作量，不是写代码能解决的。

11.3 第三层：A17 这张图是"模板运行"，代码里显式排除了 v2

你答辩用的新能源汽车报告走的是五问模板：15 张指定图、固定挂在指定小节、每张图有固定契约。判定条件是"出题模式 = apply 且命中模板"，此时 v2 分支被明确关掉（_chain_v2 = 引擎是 evidence_v2 且 不是模板运行）。

原因是两套东西的产物契约不同：

v2 证据图谱A17 模板
输出通用产业链视图（结构可发现、可 partial）15 张固定图 + 固定小节位置
结构来源资料发现 + 已验画像人工审定的产业事实底座
质量状态candidate / supported / contradicted / unresolved / expired固定契约逐点核验，缺一张即阻断
适合场景陌生行业探索、研究型输出比赛演示、可复现交付

答辩要的是"同一份报告、每次都一样、每张图都能点开证据"。模板 + 审定底座能保证；v2 的输出是概率性的、允许 partial 的，不适合当演示底稿。

11.4 第四层：没有金标准，就不能宣布"完成"

v2 的验收要求比旧路径严得多：每条"企业参与某环节"要是独立断言、能回到原文、标出适用范围和时间；还要拿 20 个没见过的行业做留出测试，冻结评分分母，同时报自动通过率。文档自己承认："未验证建议门槛可达。"

而旧路径的验收是"八行业 + 人工审定 + 逐卡审阅"，标准低得多、可交付。在没有金标准的情况下，v2 只能标 partial —— 一个只能标 partial 的引擎，不能用来替代答辩现场的正式图。

11.5 如果被问"为什么不做完"，可以这样答

问法回答
这套新架构为什么没上线？上线了，是可运行的 v2 通道，用开关选择。没做的是三件事：把画像从草稿审成正式、建立跨行业金标准验收、以及适配五问模板的固定图契约。
是不是做不出来？不是。管道和契约层已经跑通，卡点在"人的审阅"和"验收标准"，不在代码。要真正替代旧路径，需要逐行业审画像、逐条核原文，这是工作量问题。
那现在这版是不是妥协？是明确的取舍：比赛阶段优先"稳定、可复现、可解释"，而不是"任意行业全自动"。我在文档里写清楚了边界，没有把 partial 说成 verified。
一句话总结：v2 是"能力上限更高、但验收成本也更高"的方案；A17 是"能力范围更窄、但每次都能稳定交付"的方案。10-30 选择了后者，因为比赛要的是后者。不是没做，是没把它当成这场的交付物。

附：一句话浓缩

这个算法的本质，是把"模型该决定什么"和"代码该决定什么"划清楚。
结构、口径、契约、兜底、缺失表达全部交给代码；模型只负责往固定槽位里填内容，且填的每个企业名都必须能在检索片段里找到出处。
当年所有事故，最后都归到同一句话——以为模型会自觉，于是没写约束。
