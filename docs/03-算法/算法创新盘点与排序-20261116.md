## 1. 判定口径

### 1.1 四级（沿用你的定义，不重复）

理论首创（论文里提出新算法）→ 组合创新（已有方法组合成新机制解决新问题）→ 应用创新（方法已有但用在没人这么用的场景）→ 已有（教科书级）。

### 1.2 我加了 5 个排序维度

单靠"创新等级"排不出高下，因为组合创新也有强弱。加 5 个可打分维度：

| 维度 | 问什么 |
|---|---|
| **D1 后果严重性** | 做错了会怎样？是"不好看"还是"数据错了还看不出来" |
| **D2 反常识度** | 是否与主流做法相反，且能解释主流为什么错 |
| **D3 可形式化度** | 能不能写成定义 / 引理 / 性质（论文有没有骨架） |
| **D4 代码完成度** | 是否真落地、有测试、有评测证据（不是 PPT 上的构想） |
| **D5 讲清成本** | 一句话能不能让评委听懂（答辩窗口只有 90 秒） |

五星制。总分 = D1+D2+D3+D4+D5（各 1 分，共 5）。

### 2.1 CLA — 断言类型学分治 + 幂等裁剪算子 ★★★★★

**代码坐标**：`agents_core/financial_semantics.py:936 quantity_issues`、`:664 _claim_clauses`、`:649 retain_supported_claims`；消费方 `report_fusion/agent.py:54 _audit_numeric_components`

**做了什么**（这是全项目最硬的一块，你原来的描述只覆盖了其中 1/6）：

代码先把段落切成子句（`_CLAUSE_BOUNDARY` 支持中英文标点、并规避小数点误切），然后**给每个子句判定断言类型**，再给不同类型配**完全不同的验证语义**：

| 断言类型 | 判定触发 | 验证语义 | 不可验证时 |
|---|---|---|---|
| 数值断言 | `QUANTITY_RE` 命中 | 公式族反算（yoy / cagr / share / level / change），`|computed − claim| ≤ ε` | ⊥ 拦截 |
| 方向断言 | 出现"增长/下降/持续…"且无量化 | 必须找到**同实体 + 同指标族 + 同口径 + 可比期**的真实序列，首末差方向一致 | ⊥ 拦截 |
| 因果断言 | `_CAUSAL`（导致/带动/表明/意味着…） | 只认两种出口：①原文直引（`clause_text in value`）②显式标注为假设（`_UNCERTAIN_CAUSE`） | ⊥ 拦截 |
| 排名/无界断言 | `unbounded_rank`（行业第一/最高/最优…） | 必须有**有界基期**（样本内可比），无基期不许说"第一" | ⊥ 拦截 |
| 预测断言 | forecast（"将持续/势必"） | 不许用历史观测冒充预测依据 | ⊥ 拦截 |
| 情景断言 | `_ASSUMPTION_INPUT` + `_SCENARIO_OUTPUT` | **输入假设只在自身子句内有效**，不得给别的子句当证据（`unsupported_sensitivity_output`） | ⊥ 拦截 |

**修复不是重写，是保序删除**：`retain_supported_claims` 逐子句判定，留下**独立成立**的子句（连标点一起留），丢掉不成立的；然后 `_audit_numeric_components` 再做一次整体复验，只有整体也成立才保留，否则清空。表格单元格降级为"待核验"，metric card 直接摘除，全套处置写进 `content_audit` 留痕（原句 + 处置 + 证据 ID）。

**已有部分**：claim verification（FEVER / TabFact）、句级过滤、正则归一化——都是成熟方向。

**你们新增**：
1. **验证语义按断言类型分治**，而不是"一个阈值套所有句子"。这是最关键的一步：数值可反算（可判定），方向只能靠序列（不可反算），因果只能靠原文（不可计算），情景必须限作用域。**这套不对称是智力内容**，不是调参。
2. **因果断言的双出口设计**：要么原文直引，要么显式标注假设。中间态（模型觉得"应该有关系"）一律不许过。
3. **假设作用域隔离**：假设输入不得跨子句外借（防"敏感性分析"变成"伪造预测"的通用漏洞）。
4. **算子的三条性质**（可证明、可测）：
   - 幂等：`T(T(x)) = T(x)`
   - 单调：`T(x) ⊑ x`（只减不增，不新增任何未支持内容）
   - 闭包：`T(x)` 要么整体受支持，要么为空——保证输出可被下游门禁直接消费

**一句话口径**：
> 别人做事实核验是"让模型判一句话对不对"；我们做的是**先给断言定类型，再给每类配一种证据标准**——数值能反算、方向只能靠序列、因果只能靠原文、情景不许外借。裁完还保证幂等。

**论文面**：★★★★★。有定义（断言类型学）、有算子（T）、有性质（幂等/单调/闭包）、有全链路落地、还有现成评测台（见第 4 节）。

### 2.2 SBB — 同跨度证据绑定（span-bound binding） ★★★★

**代码坐标**：`agents_core/chain-research/chain_research/service.py`（引文锚定抽取 + verify）、`membership.py:21 decide_memberships`、`identity.py:5 normalize_identities`

**做了什么**：
1. **引文跨度是唯一事实载体**：抽出来的每条断言，`quote` 必须是原文的**逐字子串**（`doc['text'].find(quote)`），定位记为 `chars:pos:pos+len`。找不到就整条丢弃，不进候选。
2. **同跨度限定语绑定**：企业要作为"代表企业"进某个环节，除了要有 `OFFERS` 断言，`application_terms`（应用场景词）还必须出现在**同一条 quote 里**。代码注释写得很直白："Same source span must support application; unrelated quotes cannot supply it."
3. **类型谓词准入**：`claim.endpoint_ok(subject_type, object_type)` 做 domain/range 检查，防止"公司 → 公司"这种非法边；`IS_A` / `PART_OF` 永远不接受模型提出的分类（"Model-proposed taxonomy never becomes an accepted policy mapping"）。
4. **并查集实体归并，但只在证据内归并**：跨语言别名（中文名 vs 英文名）只有出现在**某条受支持断言的引文里、且是显式括号形式**（`中文（English）`）才允许合并。父子关系、品牌 vs 工商名一律不猜。

**已有部分**：引用式生成（attributed generation）、quote-grounded extraction、union-find。

**你们新增**：**"同跨度"约束**。这是真正值钱的一点——它把"证据拼贴"这个最难防的漏洞堵死了。LLM 很容易把 A 段的"公司"和 B 段的"场景"拼成一条看似成立的断言；要求两者必须落在同一段引文，等于把"证据可组合性"限制到最小。

**等级**：组合创新 ★★★★。
**论文面**：★★★★。适合知识图谱 / 信息抽取方向，比 CLA 更容易做出"精度-召回"曲线。
**风险**：这条**必须**讲成"跨度约束"，不能讲成"我们做了实体对齐"（实体对齐是 1970 年代的东西）。

### 2.3 RPD — 裁判-修复对偶完备性 ★★★★

**代码坐标**：`chart_generator/chain_topology.py:1206 validate_topology`（裁判）、`:1499 repair_topology`（修复）、`:359 degree_limit` / `:382 core_misplacement`（两边**共用同一批判据函数**）

**做了什么**：代码里有一条被反复守住的隐式定理：

> **校验器能报的错，修复器必须能修。否则整张拓扑会被整体丢弃 → 退化成三节点空壳图。**

所以 `degree_limit()`（16/12/8）同时被校验器（`:1438`）和修复器（`:1989`）调用；`core_misplacement()` 同理。注释里明确写了："保证「validate 报错」与「repair 能修」严格等价——否则会出现『报错却修不好 → 整图退化』"，并且"这里**不判**混入竞品：竞品清理由 repair 侧做，若在此判错则 repair 必须能修"。

**已有部分**：generate-verify-repair 循环（Self-Refine / Reflexion）、AST 程序修复、约束解码。

**你们新增**：
1. 把"**报错集 ⊆ 可修集**"当成**设计不变量**来守，而不是当成巧合。判据函数同源是实现手段，可测指标是"报错中可修比例 = 100%"。
2. **修复的最小损伤原则**：删边按 `recycle(0) < service(1) < technical(2) < material(3)` 优先级从低到高删，保护主链（实物流）不被砍。这是一个"度数约束下的保主链删边"——目标函数是 `min Σ w(flow)`，`w` 是类别权重。诚实说：**这是加权贪心，不是最优解**（精确问题是 b-matching），但它的价值在于"可解释 + 保主链"。
3. **修复不改名**：注释里明确"只补描述、绝不改名"，因为改名会触发 `assert_graph_fidelity` 逐字核对失败。这条约束很硬：修复必须在**语义不变形**的前提下进行。

**等级**：组合创新 ★★★★（前提是你把它形式化）。**不形式化的话只是 ★★★**。
**论文面**：★★★☆。更像 system paper / demo paper，不适合当主论文。

### 2.4 TTL — 分级信任 + 规则强度随层级放松 ★★★★

**代码坐标**：`chain_topology.py:485 classify_company_traceability`、`chain_graph.py` 的 `source_tier` 字段、`chain_render.py` 的角标渲染

**做了什么**：企业来源分四层：`evidence`（有问财结构化证据）/ `industry_common`（行业公认，问财只覆盖 A 股所以取不到）/ `web_unverified`（联网未复核）/ `inferred`（三项全空）。

关键不是分层，而是**规则强度跟着层级变**：

- `evidence` 层：白名单强校验（企业名必须在证据里，否则判"编造"并摘除）
- `industry_common` 层：**关掉白名单强校验**，企业保留，只降 tier，渲染不画红标
- `inferred` 层：虚线 + "推断"角标

代码里给了为什么必须这么做的实测证据：低空经济那一轮，8 家整机厂全对（亿航/小鹏汇天/峰飞/沃飞/大疆/纵横/极飞/中航成飞），但问财只覆盖 A 股，前 6 家境外或未上市 → 旧逻辑当"编造"摘掉 → **只剩 2 家，行业代表性归零**。

**已有部分**：provenance / 置信度分级。
**你们新增**：**非均匀验证策略**。同一个产物里，不同证据层用不同严格度的规则——这是把 precision/recall 权衡**显式化**，而不是全局调一个阈值。这个思路在"高召回场景"里很实用（宁可标注，不要误删）。

**等级**：应用创新 ★★★★。
**答辩价值**：高。因为它是"我们踩过坑并给出了机制"的典型叙事。

### 2.5 ODD — 数量级漂移检测（scale-hypothesis test） ★★★

**代码坐标**：`report_fusion/agent.py:1413 _audit_cross_chapter_consistency`、`:1462 _reconcile_market_cap_consistency`

**做了什么**：终稿阶段扫全文的"X 万亿 / X 亿"，对每个数值做**量级假设检验**：如果它等于 `canonical × 10` 或 `canonical ÷ 10` 的 20% 邻域内，就判为"亿/万亿错位"，然后**只在归属明确的子句里**改写（必须出现"总市值"锚点；metric card 走另一套锚点规则）。

**已有部分**：单位检查、一致性检查。
**你们新增**：把"单位错了"变成"**量级假设检验**"（H0: 单位 u₁ vs H1: u₂·10），并且订正受**归属约束**（没有"总市值"锚点的子句不动）。这防的是最危险的一类金融错误：数字全对、量级错 10 倍，人眼看不出来。

**等级**：应用创新 ★★★。
**注意**：这条别写成"我们做了单位换算"，会被打。要写成"量级漂移的检测与受限订正"。

### 2.6 TCR — 四态方向一致率（concordance ratio） ★★★

**代码坐标**：`data_interpreter/engine.py:502 _trends`

**做了什么**：
```
monotonicity = max(#上升, #下降) / #非零变化        # 相邻期方向一致率
direction ∈ {up, down, flat, volatile}
strength ∈ {strong: mono≥0.8 且 |Δ|≥0.2, moderate: mono≥0.67 且 |Δ|≥0.05, weak}
```
同时声明了 `total_change_basis`：首期为负时，变化率的分母取 **|首期|**，并在字段里显式标注 `absolute_base`。还单独处理了"指标本身就是同比/环比"的情形（不重复造趋势）。

**已有部分**：Kendall τ、单调性检验。
**你们新增**：`max(pos,neg)/nonzero` 其实就是 `(τ+1)/2` 的相邻对版本，但**加了第四态 `volatile`** 和**负基数口径声明**。这两个东西解决的是"看起来在涨其实是锯齿"和"基期为负导致增长率符号失真"——都是研报里真实会错的点。

**等级**：应用创新 ★★★。
**用法**：**不要单列一页**，作为 DPE 页的"趋势侧"补充即可。

## 3.1 重要建议：CMA 不要单独讲了

现在你有 **DPE（精度裁定）** 和 **CMA（断言反算）** 两个四星点。拆开讲会有两个问题：

1. **评委问"这两个有什么区别"** ——你答"一个判精度一个判数值"，听起来像是同一个东西拆成两半。
2. **CMA 的"末位半个单位"其实是 DPE 的结论**，你把它当 CMA 的创新点，会被追问"那你的 DPE 是什么"。

**正确结构**：把它们合成一个三层结构，讲成**一件事的三层**：

```
CLA（断言类型学分治）           ← 第一层：哪些断言要判、怎么修
 ├─ 数值断言 → CMA 的反算子      ← 第二层：怎么判数值（公式族反算）
 │              └─ 依赖 DPE      ← 第三层：判等时用什么容差（精度裁定）
 ├─ 方向断言 → 同口径序列
 ├─ 因果断言 → 原文直引 / 标假设
 └─ 情景断言 → 作用域隔离
```

这样讲，CLA 是"总纲"，CMA 是"数值分支的算法"，DPE 是"判等算子"。三个点变成一个体系，评委会觉得你想清楚了；拆开讲反而像凑数。

### Paper A（首选）：Typed-Claim Verification with Idempotent Repair for Grounded Financial Report Generation

**问题**：LLM 写研报的主要失败模式不是"句子不通"，而是**数字看起来对、其实不可核验**；现有做法是让另一个模型审，代价是判据不可辩驳。

**贡献点**：
1. 断言类型学（6 类）与**验证语义不对称原则**：可反算的才反算，不能反算的降级为"序列一致 / 原文直引 / 有界基期 / 作用域隔离"。
2. 精度感知判等（半末位容差 + 披露步长反推 + 跨单位步长同步 + 三态）。
3. 保序幂等修复算子 T，证明三条性质：幂等、单调、闭包；并给出表格降级（→"待核验"）与卡片摘除的分级策略。
4. 评测：变异注入 + pass@k + 检出率/误杀率/幂等性。

**可证明的性质**（这些是论文的骨架，不是修辞）：
- **引理 1（幂等）**：`T(T(x)) = T(x)`。因为 T 的输出每个子句都满足 `is_supported`，而 `is_supported` 对同一子句是确定的。
- **引理 2（单调）**：`T(x)` 的每个子句都来自 x，无新增内容。
- **定理 1（闭包）**：`T(x)` 要么整体受支持，要么为空——所以 T 的输出可直接被发布门禁消费，不需要二次人工。
- **命题 1（fail-closed）**：精度不可确认 ⇒ 判 ⊥ 而非"通过"，因此漏判率上界为 0（代价是误杀）。

**实验设计（用你现成的 eval 台，加 4 个 mutator 就够）**：

| 变异 | 注入什么 | 期望 |
|---|---|---|
| M1 末位扰动 | 16.17 → 16.2 | 判为**等价**（不能误杀） |
| M2 量级漂移 | 亿元 → 万亿 | 判为**冲突** |
| M3 类型伪造 | "营收 100 亿" → "营收增长带动利润提升" | 因果断言 ⊥ |
| M4 口径越界 | 分部数据写进合并结论 | 值对但口径错 → ⊥ |

指标：`detection_rate`（M2–M4 应拦）、`false_reject_rate`（M1 不应拦）、`idempotence_violation = 0`、`repair_completeness`（每次拦截后能否被裁剪修好）。

### 5.2 精度裁定与三态裁决 / PRECISION ADJUDICATION

**输入层**：原始披露字符串 ｜ 数值 ｜ 单位 ｜ 币种 ｜ 口径

```
s = 10^(−decimals(披露串))
round_s(v) = (v / s).quantize(1, HALF_UP) × s

```

> 精度不是阈值参数，是数据的属性——所以我们从披露字符串里把它读出来。

### 9.2 结论有三种，不是两种

**符号写法**

```

```

**读法**：一个判断只有三种结局——成立、冲突、判不了。

**为什么不能只要两种**：如果把「判不了」硬塞进「冲突」，系统会为了少误杀而不断放宽判据，最后什么都判不了；塞进「成立」，假的就放行了。**「不知道」必须能单独存在**，这是整套方法的地基。

### 9.3 精度裁定（DPE）

#### 第一步：精度从数据里读出来，不是拍参数

**符号写法**

```
s = 10^(−d)
```

**读法**：一个数显示到小数点后两位，就认为它的精度是 0.01。

**为什么**：行业常规是把容差设成一个百分比（比如 ±0.5%）。但源数据若是 1 位小数、你重算的是 2 位小数，固定百分比要么漏判（真冲突放过），要么误判（16.17 与 16.2 判成冲突，记录被踢、要重采）。

#### 第二步：把数搬到刻度上

**符号写法**

```
round_s(v) = s × 四舍五入(v / s)
```

**读法**：先除以步长、取整、再乘回来——就是把数挪到最近的刻度上。16.17 在 0.1 的刻度上挪到 16.2。

#### 第三步：判等（核心只有一句）

**符号写法**

```
round_{s_粗}(v_细) = v_粗
```

**读法**：把精细的那个数，舍到粗的那把尺子上，看是否刚好等于粗的那个数。

**例子**：16.17（2 位）与 16.2（1 位）→ 16.17 舍到 0.1 → 16.2 → 相等 → **不是冲突**。

**方向不能反**：反过来（把粗的舍到细的格上）几乎永远不等，会把所有正常数据判成冲突。代码里两个分支（谁粗谁细）做的都是同一件事——**细的向粗的对齐**。

#### 第四步：整组怎么裁决

| 情形 | 结论 | 人话 |
|---|---|---|
| 所有值一模一样 | ⊤ | 不用比，本来就是同一个数 |
| 有任何一条的精度查不到 | ⊥_U | 不知道精度就不下结论，先拦 |
| 基准（最精细）舍到某条粗格上对不上 | ⊥_C | 真冲突 |
| 其余 | ⊤ | 只是显示位数不同，实质一致 |

同一件事的符号写法：

```
V(G) = ⊤     若 |{v_i}| ≤ 1
     = ⊥_U   若存在 s_i 缺失
     = ⊥_C   若存在 i ≠ 0 使 round_{s_i}(v₀) ≠ v_i
     = ⊤     其余
```

其中 `v₀` 是精度最高（步长最小）的那条的值，作为基准。

#### 第五步：跨单位时，步长要跟着放大

**符号写法**

```
s^元 = s × 倍率         v^元 = v × 倍率
```

**读法**：0.01 亿元 是 100 万元，不是一分钱。所以换单位时，数值和步长必须一起换。

这是和「固定百分比容差」的第二个实质差别：只换数值不换步长，精度会被系统性放宽一亿倍。

#### 这条链为什么站得住

**可靠性**：判「等价」时，一定存在一个数，同时落在组内所有披露格子里。

> 一句话证明：拿最精细那条的值当这个数——它在自己格里；判等价意味着它也在每个粗格里。所以不会把两个真值不同的数说成同一个。

**误杀的代价**：判「冲突」时两格仍可能擦边，但只可能发生在粗格边界、半个细步长的薄层内。精度越高，误杀越少。

> 这句话的用处：别人说「半末位容差是常识」，你可以答——常识没有可靠性证明，也没有误杀上界。

### 9.4 断言核验（CLA）

#### 先分型，再判

**符号写法**

```
τ(c) ∈ { 数值, 方向, 因果, 排名, 预测, 情景 }
```

**读法**：每句话先归到六类里的一类，不同类用完全不同的证据标准。

| 类型 | 怎么判 | 人话 |
|---|---|---|
| 数值 | 用公式反算，差 ≤ ε | 能算就一定能判 |
| 方向 | 找同口径的真实序列，看首末方向 | 不能算，只能「对着看」 |
| 因果 | 要么原文逐字有这句，要么明说是假设 | 不能算，只能「引用或降级」 |
| 排名 | 必须有明确的比较范围（样本内） | 「行业第一」没有基期就是废话 |
| 预测 | 没有核验过的预测通道就不许说 | 不许拿历史当预测 |
| 情景 | 假设只能在本句内生效 | 假设不许跨句外借 |

关键不是「分类」，是**六类的判据不对称**：能反算的才反算，不能反算的一律降级到引用、序列或作用域约束。

#### 容差

**符号写法**

```
ε(d) = ½ × 10^(−d)
```

**读法**：容差取「显示末位半个单位」。显示到 0.01，就允许差 0.005。

#### 修复算子

**符号写法**

```
T(x) = 只保留 π(c) = ⊤ 的子句；若整体复验不过，整段清空
```

**读法**：站得住的句子留下，站不住的删掉；删完再整体过一遍，过不了就整段不要。

三条性质（这是它能被门禁直接消费的原因）：

| 性质 | 符号 | 人话 |
|---|---|---|
| 幂等 | T(T(x)) = T(x) | 再裁一遍，结果不变 |
| 单调 | T(x) ⊆ x | 只删不增，不会自己编内容 |
| 闭包 | T(x) ≠ 空 ⟹ 整体过检 | 要么整段干净，要么这段不要 |

**没有「半干净」的中间态**——所以下游门禁不用二次判断。

**一句诚实的边界**：因果断言在代码里用「前 35 个字符」判断归属，所以「每句独立可判」不是严格成立；实现靠「整体复验」这一层把闭包补回来。要在论文里主张严格幂等，得把归属前缀固定进子句（改一行）。

### 9.5 裁判–修复（RPD）

**度数上限**

| 节点 | 上限 |
|---|---|
| 核心整机 / 本体 | 16 |
| 中游 | 12 |
| 其余 | 8 |

**删边规则**

```
谁超限，就从它身上删掉权重最小的那条边；
删一条、重算一次度数，直到所有节点都不超限。
```

**权重顺序**

```
循环 < 服务 < 技术 < 实体物流
```

**读法**：先删「回收」这种弱关系，最后才动「实物流」这条主链。

**完备性**

```
对每个报出来的错 e，都存在一个修复动作 ρ，执行后 e 不再成立。
```

**读法**：能报出来的错，一定有办法修掉。

**为什么重要**：校验器能报的错，修复器必须能修；否则整张图会被整体丢弃、退化成三节点空壳图。实现手段是两边共用同一批判据函数（度数上限、核心归属判定）。可测指标：可修率 = 1。

**诚实边界**：一个节点溢出时贪心最优；全局等价于「带度数上限的最大权子图」，贪心没有近似比保证——不要声称最优。

### 9.6 覆盖契约（QCC）

**符号写法**

```
在总数 ≤ N 的条件下：
先最大化「有图的题数」，再最大化「被覆盖的指标数」。
```

**读法**：先保证每道题至少有一张图，剩下的名额再按覆盖贡献分。

**注意**：这不是标准集合覆盖，是「主图优先 + 逐层分配」。所以经典 `ln n` 近似比**不适用**，别引用。

### 9.7 量级漂移（ODD）

**先统一单位**：样本总市值的原始单位是**亿元**，基准 `b` 换算成**万亿元**：

```
b = 总市值(亿元) / 10⁴
```

**判据（两侧各测一次）**

| 文本里的数 | 与基准的关系 | 判定 |
|---|---|---|
| ≈ 10b | 大了十倍 | 漂移 |
| ≈ b/10 | 小了十倍 | 漂移 |
| ≈ b | 正常 | 放行 |

同一件事的符号写法：

```
|X − 10b| / (10b) < 0.2   或   |X − b/10| / (b/10) < 0.2
```

**读法**：把数拿去和「基准的十倍」「基准的十分之一」各比一次，落在 20% 以内就算小数点错了一位。

**单位更正（这条重要）**：10 倍上下 = **小数点错一位**，不是「亿↔万亿」——亿到万亿是 10⁴ 倍，那是单位归一化那一层的活。别在文档里写成「亿/万亿两种方向」，会被懂行的人当场纠正。

显式换算式（如果要写进论文）：

```
10b  = 总市值(亿元) / 10³
b/10 = 总市值(亿元) / 10⁵
```

**订正受归属约束**：只有子句里明确出现「总市值 / 合计市值」这类锚点时才改写；公司市值不许被改成样本总额。

一句话：**漏改可以审计，错改不可审计。**

---

### 9.8 方向一致率（TCR）

**符号写法**

```
mono = max(上涨期数, 下跌期数) / (上涨期数 + 下跌期数)
```

**读法**：相邻两期比，涨了几次、跌了几次，取多的那一侧占比。

**命题**

```
mono = (1 + |τ|) / 2
```

其中 `τ` 是相邻期上的 Kendall 秩相关。

**读法**：这个比值不是新指标，它就是秩相关的仿射变换。

**推论（这条最能加分）**

| 阈值 | 等价于 |
|---|---|
| mono ≥ 2/3 | \|τ\| ≥ 0.34 |
| mono ≥ 0.8 | \|τ\| ≥ 0.6 |

所以 0.67 和 0.8 不是拍脑袋，是秩相关的两个标准档位。

**四态**：`mono < 2/3` 判「震荡」；`|总变化| < 2%` 判「走平」；否则按总变化符号判涨 / 跌。
**负基数**：首期为负时，变化率的分母取绝对值，并显式标注。
