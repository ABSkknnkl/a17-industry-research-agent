## 0. 先摆：本方（用户）反驳 codex/上一版评估的 2 个点

- 修正：**只要保留现有"阶段级"审核前端（`ReviewView` 三栏、按 stage 提交反馈），并行就只是后端执行细节，审核语义不动、前端不动**。赛题要求的"每阶段可审核"这条红线**不被段内并行触碰**。

**反驳 2 —— "约等于推倒重做整个 workflow 层"高估：就是"后端并行"，不是重做编排。**
- 修正：若并行限定为**段内**（Agent4 的 7 章在内部并发、Agent2 的两段并发），改动落在 **Agent 内部子图 + 持久层写并发处理**，`graph.py` 的 `STAGE_ORDER` 线性状态机、`runner.py` 的同步执行、五阶段图骨架**都不动**。这不是"推倒重做 workflow 层"。我上一版把 codex 跨阶段 DAG 的量级错安到了段内并行头上。

## 1. 但必须诚实标出的一条边界（否则就是附和）

**"保住阶段级审核" 与 "codex 那张跨阶段性能表" 互斥。**

- codex §3.1 的 **总时长快 55–75%、首条可用内容 20–45s** 主要来自 **Phase 3 跨阶段 artifact DAG**——即"Agent2 还没过审，Agent4 就消费其 provisional 产物提前写章"。
- 而 Agent4 依赖 Agent3 的真实图表、Agent3 又依赖**已过审**的 Agent2（v3.1 已证 `1→2(审)→3→4` 串行锁死）。**一旦坚持"阶段级整体过审才放行下游"，就拿不到跨阶段重叠**，首条内容时间被 `T1+T2` 的下限锁死，压不到 20–45s。
- 所以本方框架的正确读法是：**采纳"段内并行 + 前端阶段审核不变"，不采纳"跨阶段 DAG + artifact 级审核"**。这与 v3.1 结论完全一致；不是新增分歧。
- 净结论：反驳 1、2 成立 ⇒ 我们要做的**就是段内并行**（小改动、不碰审核），而 codex 方案里"全异步跨阶段 DAG / 审核对象改 artifact / 首条 20–45s"那一大块**不在采纳范围**，也**不该用它的工作量与风险来吓自己**。

## 2. 两套"并行"分开算账（关键：别把二者混成一个数）

| 维度 | 段内并行（**采纳**） | 全异步跨阶段 DAG（codex 全案，**不采纳/后置**） |
|---|---|---|
| 审核模型 | **前端阶段级不变**（反驳 1） | 需改成 artifact 级（§6），触碰审核语义 |
| 改动落点 | Agent 内部子图 + 持久层写并发 | `graph.py`/`state.py` 状态机、scheduler、events、幂等/失效、DB 迁 PG |
| 真实工作量 | **中等、可控**（详见 §4 口径①） | **≈ 编排+持久+API+前端四层再架构**（8+ 新模块，§4 口径②） |
| 可达收益 | A1→A4 总时长 **约降 35–50%**（codex §3.1 的 P0 行） | 声称 55–75% + 首条 20–45s，但**与阶段级审核互斥** |
| 风险 | 低—中：不碰审核、不碰跨阶段契约 | 高：结果不确定序、投机返工、审核语义重定义、回归面大 |
| 与 v3.1 关系 | 就是 v3.1 的 P0/P1 | 被 v3.1 判为"当前不成立" |

## 3. 保留一条对 codex 的技术质疑（与本方 2 点反驳无关，独立成立）

即便只看"段内并行里，Agent2 能不能按证据域分片"这一点，codex 方案 §5.3 的"**按 finance/growth/competition/policy/risk 分 shard + 确定性 reducer 合并**"仍会让**研报深度倒退**——这正是用户此前质疑的"单维度分析太浅"，用测试语句坐实：

**（1）复合意图测试语句里，跨维是因果耦合，不是并列**（`eval/cases/intent_golden.json`，15 条中 4 条 ≥2 维）：

| 用例 | 输入 | 跨维 | 耦合 |
|---|---|---|---|
| I-C01 / I-C15 | 光伏逆变器国内外厂商市占率**及海外政策影响** | 竞争 + 政策 | 政策是市占率的**因** |
| I-C02 | 宁德时代近四年营收/毛利率/费用率**并梳理主营业务结构** | 财务 + 业务 | 业务结构**解释**毛利率 |
| I-C12 | 宁德时代**增发方案**和最新**财务情况** | 事件 + 财务 | 增发**摊薄**财务指标 |

分片后：竞争 shard 只给"市占率 X%→Y%"，政策 shard 只给"存在 IRA 政策"；**因果 claim 合不出来**——因为每个 shard 只吃自己那份证据（§5.3），而 reducer 是确定性的（"不依赖 LLM 决定合并顺序"）。

**（2）极端：5 维强相关是系统的固有产物，不是偶发输入**。61 条路由金标准**每条都强制带 `industry_topic`**（查询从不维度孤立）；更硬的证据是最终产物 `AnalysisCoreDraft` 的硬 schema（`openai_compatible.py:98,103-116`）：`dimensions` **恰好 5 个**（各一次）、`validation_cards` **恰好 3 张跨维校验卡**（口径可比性/财务质量/估值预期）。这 5 维 + 3 卡本质是**跨维联合判断**，单维 shard 产不出校验卡、确定性 reducer 也合不出 5 维自洽的一份草稿。**⇒ 若采纳 Agent2 按域分片，必须保留一个"看全维证据的跨维 synthesis/校验卡生成"步骤**（可以是最后一个 LLM reduce 调用），否则 compound 用例深度明显倒退。codex §5.5 的"全局结论摘要只读快照"是**一致性补丁、不是深度补丁**，且这份摘要由谁产，方案里没人产——是个循环缺口。

## 4. 工作量：两个口径，别混

**口径①（采纳的段内并行）**——真实增量：
- Agent4：`chapter_writer/graph.py:289-314` 的 `current_index` 串行循环 → 改为**受限并发 Map（默认 3–4 章）** + 一个**跨章一致性 Reduce**；`prompt_adapter.py` 加"全局术语/口径只读快照"。
- Agent2：`openai_compatible.py:852-871` 两段 `for` → `gather`（≤2），并**先列字段依赖矩阵**（supplement 的风险/情景/图表候选可能依赖 core claims，不独立就不并发，§4.3）。
- 持久层：`chapter_repository.py` 并发写前上**单写者队列或 WAL+busy_timeout**（防 `database is locked`）。
- 体感层（与并行无关，建议照做）：`POST /runs` → **202+run_id 异步**、SSE 替代 3 秒轮询、去掉 300s 长超时。**注意：这一步只改"等不等得到"，不改总计算时长**。
- 量级：**Agent 内部子图 + 持久写并发 + API 异步化**，不动五阶段编排、不动审核语义。**约数周级、可分步灰度、每步可回滚**。

**口径②（不采纳的跨阶段 DAG）**——codex 全案，仅作对照：
- 新增 ≈8 模块（`workflow_v2/{dependency_graph,scheduler,events}`、两个 `reducer`、`artifact_repository`、SSE `run_events`、前端 `useRunEvents`+`PipelineOverlay` 重写）；重写 `graph/state/runner/routes` + Agent2/3/4/5 触发契约 + SQLite→PG + run 级原子预算 + 全量可观测性。
- 量级：**月级、触碰审核语义、回归面覆盖赛题核心**。→ **不采纳，除非将来赛题允许 artifact 级审核且愿意承担深度/审核风险**。

## 5. 前置阻断（最高优先级，无论并行与否都要先做）

codex §2.5：2026-09-09 真实浏览器测试中 Agent1 **返回 0 条来源**（`core_data_group_unavailable`），且 `AGENT1_SEMANTIC_ROUTER_ENABLED=False`、`INTENT_DECOMPOSER=False`、`FALLBACK_CHAIN=False`、`WEB_FALLBACK=False`。
**在"当前取不到数"的链路上做并行 = 更快地失败。** 并行收益评估的前提是 Phase 0（恢复非零、可追溯证据）先完成——这条 codex 排对了，照收。

## 6. 结论与建议顺序

1. **接受本方 2 点反驳**：段内并行**不碰阶段级审核、不是重做 workflow 层**；我上一版"触碰审核语义/推倒重做"的说法**收回**，那是把 codex 跨阶段 DAG 的账错记到段内并行上。
2. **但因此锁定范围**：保阶段审核 ⇒ 只做**段内并行**；codex 的跨阶段 DAG、artifact 级审核、首条 20–45s 表 **不采纳**（与阶段审核互斥，非成本问题）。
3. **执行顺序**：Phase 0 修取数 → Agent4 章节受控并发（带只读 ReportPlan + 跨章 Reduce）→ Agent2 两段并发（先切上下文、先出依赖矩阵、保留跨维 synthesis）→ 异步 202 + SSE（体感）。
4. **红线不变**（v3.1）：每阶段人工审核、证据单写者、层级锁死、并发上限可配、生成层不追求文案哈希等价、**不为通用化牺牲赛题看重的数据质量/图表关联/审核/报告深度**。

> 一句话：你说得对——段内并行是"后端并行而已、前端照旧阶段审核"，我上一版高估了它的审核风险和改动量级；代价是也因此拿不到跨阶段那张激进的性能表，而那本来就该放弃。真正独立成立的技术警示是：**Agent2 若按证据域分片，必须补一个跨维 synthesis 步骤**，否则 I-C01/C02/C12 这类 compound 用例的分析深度会倒退。
