### 2.2 为什么这样放（对照参考图做的取舍）

| 参考图 | 本方案 | 理由 |
|---|---|---|
| 顶部「报告融合助手 + 时间 + 等待审核」 | 复用 ReviewView 现有卡片头（阶段名 + 状态 tag + 版本） | 项目已统一用这个头部语言，不另起一套 |
| 4 张彩色圆角指标卡（蓝/绿/紫/橙图标） | 复用 `MetricCards`（左侧 2px 色条 + 藏青数字） | 项目指标卡已成型，**不引入参考图的彩色图标体系**（与研报风冲突） |
| 融合检查 4 个卡片（带绿勾 + 百分比） | 复用 `QualityPanel` 的检查项列表 | 已有实现，且它诚实区分"通过/告警/阻断"三态 |
| 最终报告预览（左封面 + 右目录） | 直接挂 `ReportPreview` | 组件已按项目风格做好 |
| 交付质量 3 条进度条 | 复用 `QualityPanel` 子评分条 | 已有，且标注了"前端聚合口径" |
| 底部「通过并完成研究 / 修改融合内容 / 重新融合」 | 调整 `ReviewActions` 文案与顺序 | 现有按钮语义已覆盖，改文案即可 |

**风格适配说明**：参考图是"彩色图标 + 渐变大按钮"的 SaaS 风格；项目是「藏青主色 + 金铜点缀 + 米白纸面 + 衬线标题」的研报风（`style.css:1-45`）。
本方案**全部沿用项目令牌**，不引入参考图的彩色/渐变，只在**信息层级和分组**上参考它。

## 三、报告融合与预览的交互流程

```
用户进入阶段五（waiting_review）
        │
        ├─① 一屏看懂融合结果
        │    指标卡（章节/图表/证据/产物）
        │    → 融合检查项（通过 / 告警 / 阻断）
        │    → 交付状态标签（可正式交付 / 附限制 / 受阻）
        │
        ├─② 看报告长什么样
        │    封面 + 目录摘要（ReportPreview）
        │    → 点「预览完整报告」
        │       └─ 抽屉/弹窗内 iframe 加载 HTML 产物（不离开当前页）
        │
        ├─③ 下载交付物
        │    ArtifactList：Markdown / HTML / PDF / 清单
        │    每项显示 版本 · 时间 · 大小，点击下载（按钮进 loading，防重复点击）
        │
        └─④ 决策（三选一）
             ├─ 通过 → 《通过并完成研究》→ 走完流程
             ├─ 修改 → 《修改融合内容》→ 弹出反馈输入（带"修改目标"回显）
             │         → 填写诉求 → 提交修改 → 阶段重跑 → 回到 ①
             └─ 重做 → 《重新融合》→ 确认后原条件重跑
```

### 关键交互细节

**「修改融合内容」的反馈输入**（参考图底部那块）

- 弹窗内固定回显**修改目标**：`报告融合 / 最终报告 v3`，用户知道改的是哪一版
- 输入框 placeholder 给**具体示例**（沿用项目已有风格，如章节重生成弹窗的做法）：
  「请统一各章节结论表述，并在摘要中突出海外市场增长机会」
- **提交前校验非空**：空内容提交要内联提示，且**不清空已输入内容**（项目红线）
- 提交中按钮 loading，不允许重复提交
- 提交成功 → 关闭弹窗 + 刷新工作流（现有 `refreshAll()`）

**「预览完整报告」**

- 产物 HTML 是完整文档（自带 `<style>`），**必须用 iframe 隔离**，不能直接插进 Vue 模板（样式会污染全局）
- 取数走已有 `downloadArtifact` → `URL.createObjectURL(blob)` → iframe src
- **用完必须 `URL.revokeObjectURL`**（否则内存泄漏），关闭时同时清空 iframe src
- 加载期间要有骨架/loading，不能白屏
- PDF 产物：不内联，走下载（PDF 内联预览体验差且体积大）

**「重新融合」**

- 破坏性动作（会覆盖当前版本），需二次确认（沿用 `ElMessageBox.confirm` 模式）
- 已有 `recoveryBlocked`（运行时预算耗尽）时按钮要禁用，现有逻辑已覆盖

## 五、数据缺口的处理原则（重要）

参考图有 7 个数字后端没有：**报告页数、4 个融合检查百分比、内容完整度、阅读体验**。

**推荐做法：不显示，而不是编。**

| 缺口 | 处理 | 理由 |
|---|---|---|
| 报告页数 | **不显示这张卡**，改为「引用证据 28」（有真实来源） | 页数只能由 PDF 渲染后统计，前端估不准 |
| 融合检查 4 项百分比 | **Phase 1 不显示百分比**；用 `QualityPanel` 现有的三态检查项（✅通过 / ⚠️告警 / ❌阻断）替代 | 「96% 图表一致性」这种数字若无后端口径支撑，就是**假精确**——比没有更糟 |
| 内容完整度 / 阅读体验 | 保留 `QualityPanel` 现有 3 条（章节完整度 / 结构完整度 / 证据覆盖率），**已标注"前端聚合口径"** | 口径透明，用户知道数字怎么来的 |

若产品坚持要这 4 个百分比 → 走 Phase 3，由后端定口径。

> ⚠️ 这一条我建议坚持：参考图里「图表一致性 96%」这种数字，如果前端自己按 `charts.length / 期望值` 凑，
> 用户会**当真**，而它没有任何后端依据。项目里 `QualityPanel` 对"前端聚合口径"做了显式标注，是好做法，应延续。

## 六、需要注意的细节（自查清单）

### 数据与口径
- [ ] 所有百分比/评分**必须能追溯到后端原始字段**；前端聚合的要在 UI 上标注口径（沿用 `QualityPanel` 的做法）
- [ ] `quality` 可能整体缺失 → 所有卡片都要能优雅降级（现有 `QualityPanel` 已做 `?? {}`）
- [ ] 阶段数据是**宽松类型**（`Record<string, unknown>`），取值一律做类型守卫，不假设字段存在

### 交互与状态
- [ ] 下载/预览/提交**全部要有 loading 态**（超过 1 秒的操作不给反馈 = 用户重复点击）
- [ ] 失败时**保留用户输入**，只高亮错误 —— 项目红线，反馈输入框尤其重要
- [ ] 「重新融合」是覆盖性动作，必须二次确认
- [ ] 关闭预览抽屉时 `URL.revokeObjectURL` + 清空 iframe src，防内存泄漏

### 性能
- [ ] 报告 HTML 可能数 MB → **iframe 懒加载**（抽屉打开时才取 blob），不要进页面就下载
- [ ] `charts[].svg` 是内联 SVG，列表里只渲染**前 3 张缩略图**，避免大 DOM
- [ ] 抽屉/弹窗用 `v-if` 而非 `v-show`（避免离屏渲染）

### 无障碍
- [ ] 融合检查项**不能只靠颜色区分**（现有实现是图标 + 文字，✅）
- [ ] 进度条要有可读文本（现有实现右侧有百分比数字，✅）
- [ ] 预览抽屉打开后**焦点要移入**，ESC 可关闭（`el-drawer` 原生支持，确认未被覆盖）

### 响应式
- [ ] `QualityPanel` 已有 1100px 单列断点（✅）
- [ ] `ReportPreview` 封面 + 目录在窄屏必须**塌缩为单列**（当前是 `flex-direction: column`，天然满足，但要验证窄屏下封面比例）
- [ ] `ArtifactList` 在移动端表格要转卡片视图（当前未知，需检查）

### 风格一致性
- [ ] 全部使用 `--rp-*` 令牌，**不写死颜色**
- [ ] 标题用 `var(--rp-serif)`，正文用项目默认无衬线
- [ ] 不引入参考图的彩色图标/渐变按钮
