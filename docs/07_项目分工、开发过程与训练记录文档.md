## 三、问财技能编排与 Prompt 调优/训练记录

### 1. 问财 SkillHub 技能编排策略演化
在项目初期，直接将用户输入作为单句查询传入问财，经常导致词槽解析冲突或跨界污染（如查“商业航天”混入大量低空经济或汽车巨头）。为此，团队进行了三轮编排策略演进：

```
[初版：直接查询]  "商业航天 A股 市盈率 营收 净利润" 
               --> 痛点：词槽冲突，问财返回 0 结果，或因泛查导致召回无关跨界标的
                      ▼
[二版：固定模板]  硬编码固定查询语句 
               --> 痛点：缺乏对新兴概念细分赛道（如相控阵芯片、可回收火箭）的穿透力
                      ▼
[最终方案：三层递进分层查询算法]
  - Layer 1 (定界)：宽基选股 + 细分赛道选股 + 宏观指标 + 权威研报并发抓取；
  - Layer 2 (锚定)：提取确权龙头公司名称作为主语，发起点对点财务与行情穿透；
  - Layer 3 (补齐)：根据缺口自动触发动态查询松弛（Query Relaxation）定向补齐。
```

### 2. 金融长文本写作 Prompt 调优与反幻觉消融实验
为了解决大模型生成研报时的“假大空套话”与“虚构财务数字”问题，团队对 Agent 4（`chapter-writer`）进行了多轮系统化 Prompt 调优与消融实验：

| 实验轮次 | Prompt 策略调整 | 引入的核心约束 / Few-Shot | 事实准确率 | 幻觉率 | 结构完整度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Baseline (原版)** | 简单提示“请撰写一段关于行业财务质量的分析” | 仅提供行业名称与少量原始表格 | 71.4% | 28.6% | 62.0% |
| **Iter 1 (范式规范)** | 强制要求输出“本节要点”、“论述”、“对比表”与“待验证事项” | 规范段落结构，限制金融投研术语体系 | 84.2% | 15.8% | 95.2% |
| **Iter 2 (强引用约束)** | **每句数值强制附加来源角标**（如 `[来源xx]` 或 `[R-xxxx]`） | 声明“所有数值必须完全出自提供的数据包，无来源视为严重违规” | 96.5% | 3.5% | 100% |
| **Iter 3 (反幻觉安全网)** | **未查证数据主动披露机制** | 强制要求：“若数据源中未包含某项指标，严禁推测，必须在待验证事项中主动披露‘数据待披露’” | **100% (全溯源)** | **0.0%** | **100%** |

### 3. 可视化图表生成 Prompt 演化：从长 JSON 到轻量 Spec
早期让大模型直接输出完整 ECharts Option，存在显著缺陷：
1. **生成耗时过长**：大模型输出 300 行 JSON 耗时高达 20~30 秒，极易偶发格式括号不匹配；
2. **零轴截断等金融违规无法控制**：LLM 常常为了图表美观设置 `min: "dataMin"`，导致柱状图截断。  
**优化方案**：重新设计了 `ChartSpec` 协议，大模型仅负责语义决策（指定图表类型、X/Y 轴对应指标、主标题与解读重点），本地编写确定性 Python 编译器（`compiler.py`）将 Spec 转化为符合金融合规的严谨 ECharts Option，**生成耗时从 25 秒降至 0.2 秒，格式错误率彻底归零**。

## 四、核心工程难题与技术攻关台账（D-01 至 D-15）

在项目全链路集成与实测过程中，团队建立了严格的缺陷攻关机制，累计攻克了 15 项关键工程与算法缺陷，全部沉淀为自动化测试回归断言：

| 编号 | 攻关难题与缺陷现象 | 根因分析 | 解决方案与最终效果 | 对应验证用例 |
| :--- | :--- | :--- | :--- | :--- |
| **D-01** | 事件驱动流通信卡死 | 适配器层事件队列满时引发死锁阻塞主线程 | 重构为非阻塞异步事件管道，增加队列容量与丢弃策略 | `test_def_01_adapters_events_protection` |
| **D-02** | 环形图空数据降级混乱 | 当分类占比数据为负或全空时直接抛出异常 | 引入轻量级 Lint 拦截，自动安全降级为条形图或隐藏 | `test_def_02_donut_downgrade_and_linting` |
| **D-03** | 跨章节图表编号跳变与重复 | 并发撰写时各小节独立编号（出现多个图 1） | 建立全局图表元数据中心，报告融合阶段统一重编索引（Figure 1~N） | `test_def_03_figure_number_reindexing` |
| **D-04** | 交付状态被硬编码覆盖 | 合并代码时将交付状态无条件写死为 `ready`，掩盖了带保留交付 | 从 `report_view.json` 解析真实状态，审计未过时设为 `ready_with_limits` | `test_d04_delivery_status_must_not_be_hardcoded` |
| **D-05** | PDF 导出的目录页码错位 | 单遍渲染时由于内容流排版未定，无法获取准确页码 | 研发 Playwright 两遍排版算法（首遍测算精确分页，次遍注入真实页码） | `test_def_05_pdf_two_pass_toc_implementation` |
| **D-06** | 双折线图末端标签重叠碰撞 | 数据量相近时两条折线的末端文字相互遮挡 | 引入碰撞检测算法，动态计算并偏移末端标签 Y 坐标 | `test_def_06_line_chart_endpoint_anticollision` |
| **D-07** | 数据获取阶段的非确定性偏采 | 意图识别 LLM 在温度较高时随意发散实体 | 增加确定性行业白名单与硬性互斥过滤规则（排除无关行业） | `test_def_07_data_fetcher_deterministic_guard` |
| **D-08** | 英文金融字段未本地化 | 原始接口的 `total_revenue`、`net_profit` 直接暴露在正文中 | 建立金融术语字典映射层，强制翻译为标准中文字段 | `test_def_08_metric_translation` |
| **D-09** | 金额量纲单位错乱（万与亿混淆） | 问财部分接口返回万元，部分返回亿元 | 统一量纲归一化算子，强制标定并在图表标题注明单位 | `test_def_09_formatting_and_units` |
| **D-10** | 双轴图右轴百分比单位污染 | 双轴图中右轴为金额时，误带上了 `%` 符号 | 区分 `metric_type`，数值轴与比率轴严格隔离量纲格式化器 | `test_new_01_combo_chart_no_percent` |
| **D-11** | 产业链拓扑图残存半截描述文本 | 文本截断导致拓扑节点出现无意义的碎词碎片 | 正则提取完整业务术语，过滤无效标点与碎片短语 | `test_new_05_industry_chain_no_prose_fragments` |
| **D-12** | 极端离群值扭曲估值中位数 | 早期亏损概念股 PE 高达数千倍，拉高全行业均值 | 采用中位数与 MAD 稳健估值算法，实施分层估值与风险警示 | `test_new_06_heatmap_percentile_ranking` |
| **D-13** | 跨章节事实自相矛盾 | 前文写某企业毛利 30%，后文误引用为 40% | 融合智能体引入全局事实缓存池，强制校验跨章节引用一致性 | `test_dynamic_cross_chapter_consistency` |

## 五、研发经验总结与未来反思

### 1. 核心经验沉淀
1. **Multi-Agent 必须坚持“确定性计算”与“LLM 语义推理”边界清晰**：
   加减乘除、CAGR、离群值侦测、ECharts 语法编译等务必交给确定性 Python 代码；LLM 专注于意图拆解、定性逻辑归纳与专业行文创作，二者各司其职方能实现零幻觉与高时效。
2. **“三层递进”是垂直领域数据抓取的最优范式**：
   面对问财 SkillHub 海量技能库，先定界、再锚定实体、后定向补齐的策略，彻底解决了“泛查噪声大”与“单句过长词槽冲突”的矛盾。
3. **人机协同（HITL）是严肃金融场景落地的前提**：
   在证券投资这一对准确率要求极高的场景中，完全脱离人类判断的“纯自动”往往带来合规风险；提供透明的断点、可解释的证据链和极简的干预手段，才是真正提升分析师生产力的关键。

### 2. 团队反思与后续工作
- **跨期预测模型深化**：未来可接入基于时序的深度学习预测算法，为第 7 章的情景测算提供更丰富的敏感性曲线；
- **协同研报评论流**：下一步计划支持多名分析师在 Web 工作台同时在线协同批注与讨论，进一步拓展系统在大型券商研究所的团队协作能力。
