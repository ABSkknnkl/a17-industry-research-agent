# Agent 3 图表能力同步设计规格

## 1. 背景与目标

本次改动面向行业研究流水线第三阶段 `chart_generate`（Agent 3）。目标是在最新 `main` 基线上，严格落实《图表改动.md》列出的 16 项图表能力，并保证同一份图表契约在前端 ECharts、报告 HTML、后端 SVG/PDF 三条交付路径中保持一致。

问财“智能图说”仅作为交互与展示行为参考。公开页面实测表明，其“业务图表”是由基础图形、数据口径、图例、时间选择和结论摘要组合而成，并非每个入口对应一种新的底层图表类型。因此本项目继续保留现有 12 种基础图表类型，通过路由、主题、注释和布局组合扩展表达能力，不复制或提交第三方压缩源码。

## 2. 范围

### 2.1 本期范围

1. 过滤 `未提供`、`文本`、`不适用` 和空字符串等单位占位词；占位词不进入坐标轴，而是归一为 `[需核实:货币单位]` 图注，并在上游数据融合处减少占位词产生。
2. 基于证据、语义和图表意图进行去重，并记录被抑制图表及原因。
3. 组合图按单位自动路由：同单位单轴、不同单位双轴、全空数据拒绝生成。
4. 单序列或可判定标签总数不超过 12 时展示数据标签，超过阈值自动关闭。
5. 纵轴非零起点或截断时显示明确脚注。
6. 支持 `reference_line`、`shaded_region`、`callout` 三类注释。
7. 涨跌语义采用 A 股惯例：上涨红色、下跌绿色；非涨跌序列仍使用主题调色板。
8. 增加 `broker_thin` 券商研报主题。
9. 增加 `dual_panel` 左右双图布局：左侧承载绝对量，右侧承载相对率或价格指数；共享时间轴且序列互不交叉。
10. 将点数、标签、缺失率等阈值集中到 `constants.py`。
11. 报告增加图表目录，并在整份报告内连续编号。
12. 图表来源使用具名来源，禁止只输出模糊的“公开资料”等描述。
13. ECharts option 与 SVG/PDF 渲染在标题、系列、轴、单位、注释、颜色和脚注上保持语义一致。
14. 校验标题是否包含可由数据支持的结论性表达；不满足时进入质量问题，而不是伪造结论。
15. 写入 JSONL 审计记录，覆盖规划、路由、抑制、降级、失败和最终交付结果。
16. 增加数据健康检查：有效行少于 5、字段少于 2、缺失率超过 20% 或列内类型不一致时阻止对应图表就绪，并返回结构化问题。

### 2.2 明确不做

- 不新增 3D 图、地图或平滑曲线。
- 不修改 Agent 2 的标题提示词。
- 不改造工作流断点续跑编排。
- 不更换 ECharts 或 SVG 渲染技术栈。
- 不将问财的 K 线、分时行情、交易盘口和动态播放控件引入静态行业报告。
- 不复制、反编译或提交问财的专有前端代码。

## 3. 总体方案

### 3.1 数据流

```text
Agent 2 图表候选 + DataFetcher 数据集
                  │
                  ▼
        数据健康与字段校验
                  │
                  ▼
       语义去重与数据集匹配
                  │
                  ▼
     图表路由 / 轴策略 / 面板策略
                  │
                  ▼
       ECharts option + 审计事件
                  │
          ┌───────┴────────┐
          ▼                ▼
     前端交互渲染      SVG/HTML/PDF 渲染
          └───────┬────────┘
                  ▼
       Agent 4/5 报告编排与交付
```

Agent 3 仍是唯一的图表决策入口。渲染器消费其确定性结果，不自行推断新的轴、单位、颜色或注释。

### 3.2 基础图表与问财行为映射

| 问财展示行为 | Agent 3 表达方式 |
| --- | --- |
| 柱状图、折线图、饼图、散点图 | 现有 `bar`、`line`、`pie`、`scatter` |
| 分组/堆叠柱线图 | 现有图表类型 + series 配置 |
| 柱折图、双柱图 | `combo` + 单轴/双轴路由 |
| 收支构成、资产负债结构 | `bar`/`pie`/`treemap` 数据配方 |
| 目标价、承压位等阈值表达 | `reference_line` 或 `shaded_region` |
| 多指标上下分区 | `dual_panel` |
| 动态图表 | Web 可交互展示；PDF 固化为最新静态快照 |
| K 线、分时、盘口类入口 | 本期排除，避免扩大行业报告范围 |

## 4. 契约设计

### 4.1 后端运行时模型

`backend/app/schemas/chart.py` 增加或完善：

- `ChartPanel`：面板标识、标题、序列归属、轴索引及宽度权重。
- `ChartAnnotation`：统一表示三种注释，按类型约束必填字段。
- `ChartVariant.dual_panel`：作为布局变体，不新增底层图表类型。
- 图表结果中的 `panels`、`annotations`、脚注、具名来源和质量检查结果。
- 将普通图表允许的序列数量从 2 扩展到 4，以承载本期组合表达。

所有字段继续使用 snake_case。未知字段按项目现有模型策略处理，不在渲染端静默发明默认语义。

### 4.2 JSON Schema 与前端类型

同一提交同步更新：

- `contracts/schemas/chart-generation-result.schema.json`
- `frontend/src/api/types.ts`
- 相关 schema/契约测试与前端消费逻辑

`dual_panel`、`panels`、`annotations`、质量检查结果必须在运行时模型、JSON Schema、TypeScript 类型三处同名同义。契约测试要从真实模型输出验证 JSON Schema，并覆盖前端所依赖的字段。

### 4.3 兼容性

新增字段使用兼容默认值。现有只包含 `option` 的图表仍可被前端和报告渲染器消费；没有面板或注释时不得改变旧图表输出。既有 12 种 `chart_type` 枚举保持不变。

## 5. 核心规则

### 5.1 数据健康

处理顺序为：字段存在性 → 类型兼容性 → 空值统计 → 图表专属约束。

- 必需字段缺失：阻止当前图表，记录字段名。
- 普通点数据有效行少于 5 或 `label + value` 两个最低字段不成立：阻止当前图表。
- 数值字段混入不可转换类型：阻止当前图表，记录样本位置。
- 参与绘图的数据缺失率 `> 20%`：阻止当前图表。
- 缺失率等于 20%：允许继续，但保留健康摘要。
- 组合图所有系列均为空：拒绝生成，不输出空坐标系。

失败只影响对应图表，除非现有质量门规则认定整批结果不可交付。

### 5.2 去重与抑制

去重键分三层：

1. 完全重复：相同证据集合、指标、维度和图表意图。
2. 语义重复：标题归一化后表达相同结论，且使用高度重叠的数据。
3. 展示冲突：同一证据被多个候选重复消费，按现有优先级保留信息密度更高者。

抑制结果必须包含稳定 reason code、被保留图表 ID 和人类可读说明；不得静默删除。

### 5.3 组合图轴策略

- 所有非空系列单位相同：单轴。
- 存在两个不同单位：双轴，并确保每个系列明确绑定轴索引。
- 超过两个不兼容单位：优先转为 `dual_panel`；仍无法清晰表达时抑制并记录原因。
- 单位缺失不靠筛选器占位文案补齐；使用已有数据口径或标记质量问题。

### 5.4 标签与截断轴

- 数据标签阈值统一为 12，配置来自 `constants.py`。
- 统计真实可见标签数，不以原始数组长度替代。
- 纵轴最小值不为零且可能放大变化时，必须生成截断轴脚注。
- 前端、SVG 与 PDF 使用同一判定结果，不分别计算。

### 5.5 颜色与主题

`broker_thin` 关闭网格线，使用 1.5px 细线、无数据点圆圈和深海军蓝主色。只有名称含“涨跌、同比、增速”等明确涨跌语义的指标使用红涨绿跌：正值红色、负值绿色；普通比较图不将红绿强行解释为方向。

### 5.6 注释

- `reference_line`：目标值、均值、政策阈值等单值参考线。
- `shaded_region`：预测区间、政策窗口或风险区间。
- `callout`：绑定到一个数据点或坐标位置的简短结论。

注释只能引用输入数据或已存在的分析结论，不得自行生成新事实。ECharts 使用原生标记能力，SVG 使用等价图元与文本实现。

### 5.7 双面板

`dual_panel` 是单个图表对象中的两个左右并排面板，适合把绝对量放在左侧、相对率或价格指数放在右侧。两面板共享时间轴口径和总标题，各自拥有纵轴、单位和互不交叉的系列集合。若时间维度不一致，则不得为了双面板强行对齐或填造数据。

## 6. 报告交付

### 6.1 编号与目录

图表编号由报告层按最终出现顺序统一生成，跨章节连续，不复用 Agent 3 的内部排序号。图表目录读取同一份最终编号与标题映射，避免目录和正文二次计算产生漂移。

### 6.2 来源

每张图展示可识别的机构、数据库、公告或文件名称。多个来源去重后按稳定顺序连接。只有 URL 而没有名称时允许使用主机名作为降级名称；无来源名称进入质量问题。

### 6.3 渲染一致性

一致性按语义字段断言，不要求像素完全一致：

- 标题、编号、系列名称与数量一致。
- 轴数量、轴单位和系列轴绑定一致。
- 注释类型、值/区间和文本一致。
- 红涨绿跌与主题系列色含义一致。
- 数据标签开启条件和截断轴脚注一致。
- 空数据与质量失败在所有交付路径均不伪装为成功图表。

## 7. 审计与失败处理

JSONL 审计采用追加写入，每行一个结构化事件。核心业务字段固定为 7 个：`chart_id`、`stage`、`decision`、`evidence_ids`、`quality_issues`、`degradation`、`retry_of`；另带 `ts`、`run_id`、`revision` 运行信封，标题只保存短哈希。禁止记录访问令牌、完整提示词或不必要的原始敏感数据。

核心事件包括：

- `data_health_checked`
- `candidate_suppressed`
- `route_selected`
- `chart_degraded`
- `render_succeeded`
- `render_failed`

审计层为 best-effort 旁路，I/O 或序列化失败不得中断图表生成主链路。图表自身的生成失败则单独落盘，并在质量结果中保持失败状态。

## 9. 测试策略

实现采用测试驱动顺序：先提交失败测试，再补生产实现。

### 9.1 单元与属性测试

- 16 项需求分别至少有一个正向和一个关键边界用例。
- 组合图覆盖同单位、异单位、全空、三个单位。
- 标签覆盖 12、13 个可见点。
- 缺失率覆盖 20% 与大于 20%。
- 普通点数据覆盖 4/5 行和 1/2 字段边界。
- 注释覆盖三种类型和非法字段组合。
- 去重覆盖完全重复、语义重复与不应误删的相近候选。

### 9.2 契约与渲染测试

- Pydantic 输出通过仓库 JSON Schema。
- TypeScript 类型与 API fixture 同步。
- 同一 fixture 的 ECharts option 与 SVG 语义快照一致。
- `dual_panel` 在 Web 与 SVG/PDF 中都包含两面板及正确轴绑定。
- 图表目录编号、正文编号和标题一致。

### 9.3 回归验证

- Agent 3 与 report fusion 定向测试全部通过。
- 后端全量测试必须保持最新 `main` 的绿色基线。
- 前端 lint 与 production build 通过。
- 禁止路径与意外大文件检查通过。
