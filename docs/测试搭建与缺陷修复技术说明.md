### 1.5 编写思路（两条关键方法论）

**思路一：判据层测试 ≠ 用例层执行**

任务书里的用例是「用户语句 → 预期结果」形式，执行它们**必须真实模型**（不在本轮范围）。
因此本轮把判据**下沉到"产物层"**：直接对**历史 run 的产物**做断言。好处：
- 零外呼、确定性、可重复；
- 失败可精确定位到产物字段（附 JSON 指针）；
- 与"用例层执行"互补：产物层判据先立起基线，真实模型轮再补用例层。

**思路二：把"不可直接观测的判据"翻译成可判事实**

举三个例子（这三条后来都抓到了真缺陷）：

| 原始判据 | 翻译成的可判事实 |
|---|---|
| "无数据不绘图" | ① 每张已出图必须带非空 `evidence_ids`；② 被抑制的候选必须带 `reason_code`+证据；③ **以"缺连续时间点"为由抑制时序图时，数据里该实体的时间点必须确实稀疏**（这条证明了抑制是合理的，把矛头指向数据层） |
| "不伪造不补数" | 全部引用（章节/图表/结论）必须 ⊆ A1 证据池（顺带验证了 **A2 ⊆ A1、A3 ⊆ A1** 的单写者不变量） |
| "失败降级正确" | 中断样本的下游产物**必须不存在**（而不是"存在但为空"） |

**思路三：判据基准必须来自生产定义或真实产物，禁止自造**

- 章节数基准从 `DEFAULT_OUTLINE` **推导**（不写死 7/21）；
- 交叉验证 `status` 枚举**从 Pydantic 模型动态读取**（曾自造白名单导致误判，已修正）；
- 基准值从黄金样本**回填**（`eval/tools/backfill_baselines.py`），**禁止编数**。

## 二、问题排查

### 2.1 排查方法论（5 条，按实际使用频率排序）

| # | 原则 | 为什么 |
|---|---|---|
| 1 | **先建"前置断言"，再判因果** | 例如判 CR3/CR5 前先断言"重算条目数 == 产物条目数"。这条前置断言一失败，立刻定位到"收编覆盖面"而非"公式算错"，否则看到 100% vs 37.6% 极易误判为计算 bug |
| 2 | **差异方向先看**（谁多谁少、谁新谁旧） | `diff` 只报"不同"不报"方向"；用 `+N/-N` 与 mtime 区分"一方独有" vs "双方分叉"，避免覆盖掉对方的成果 |
| 3 | **矛盾必反查**（不轻信第一印象） | 例：`state.error` 为 None 不代表没问题，可能是样本本身没有错误结构；`unit` 全空要先确认是否藏在 `raw_fields` 里 |
| 4 | **失败先分类再动手** | 分四类：①评测器缺陷（我改）②用例预期偏差（我改）③确定性生产 bug（只登记/授权后修）④模型行为（本轮不涉及）。**不分类就改，等于掩盖问题** |
| 5 | **为了"全绿"改判据 = 红线** | 合法跳过必须写理由并计入 `skipped`；`blocked` 等同 `fail` |

### 2.2 排查工具

| 工具 | 用途 | 典型用法 |
|---|---|---|
| `pytest --collect-only -q` | 先保证**零收集错误** | 新测试落地第一步 |

#### D-01 · 存储层 run_id 路径穿越（阻断级）

**改动点**：`backend/app/core/storage.py`

```python
_RUN_ID_RE  = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$")   # 白名单
_FILE_NAME_RE = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$")

def _safe_run_dir(self, run_id: str) -> Path:
    """校验 run_id 并返回 base_dir 内的目标目录（未创建）。
    Raises: ValueError —— 非法字符 / `.` `..` / 解析后越出 base_dir
    """
    if not isinstance(run_id, str) or run_id in {".", ".."} or not self._RUN_ID_RE.match(run_id):
        raise ValueError(f"非法 run_id: {run_id!r}")
    base, target = self.base_dir.resolve(), (self.base_dir / run_id).resolve()
    if target == base or not target.is_relative_to(base):
        raise ValueError(f"run_id 越界: {run_id!r}")
    return target
```

**接线**：`get_run_dir` / `delete_run` / `save_artifact_file` 统一走校验入口。

**验证**：`test_adapter.py` 3 条失败用例全部转绿（24 passed）；既有后端测试 13 passed（无回归）。
**兼容性**：合法 run_id（`run-20260923094843-353`）行为不变；非法 run_id 由"静默逃逸"改为抛 `ValueError`。
