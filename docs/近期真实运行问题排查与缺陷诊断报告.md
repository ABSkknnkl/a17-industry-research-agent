### DEF-01: `events.jsonl` 被 Stage 5 覆写导致前序执行事件丢失

> **【真实性核验结论】：100% 证实真实存在**
> - **实证数据**：在 `run-20260927154455-936` 与 `run-20260927155854-457` 的产物 `events.jsonl` 中，全文件分别仅有 15 行与 16 行，全为 `fusion_started` 后的 Stage 5 局部事件，前序 Stage 1~4（数据采集、数据解读、图表生成、章节撰写）的 120+ 条全生命周期事件 100% 丢失。
> - **影响**：前端任务详情页刷新后，无法查看前 12 分钟的执行轨迹，可观测性严重受损。

* **现场现象**：
  在 `data/runs/run-20260927154455-936/artifacts/events.jsonl` 中，全文件仅包含 15 行事件，且**全部来自阶段 5 (`report_fusion`)**。数据采集、数据解读、图表生成、章节撰写这 4 个阶段耗时 12 分钟的全部数百条关键执行事件全部蒸发。任务完成后前端工作台刷新后，只能展示阶段 5 的事件。
* **代码溯源**：
  位于 [backend/app/agents/adapters.py#L1218-L1225](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/backend/app/agents/adapters.py#L1218-L1225)：
  ```python
  # 同步生成的文件至当前任务的 artifacts 目录
  if hasattr(result, "artifact_dir") and result.artifact_dir:
      src_dir = Path(result.artifact_dir)
      if src_dir.exists():
          for f in src_dir.iterdir():
              if f.is_file():
                  shutil.copy2(f, art_dir / f.name)
  ```
* **机理剖析**：
  `ReportFusionAgent` 在独立工作目录 `output/runs/report-...` 下生成了包含本阶段事件的临时 `events.jsonl`。当外层适配器使用 `shutil.copy2` 同步文件至任务根目录时，没有任何文件黑名单过滤，直接用阶段 5 单阶段的事件文件覆盖了全局事件流管理器累积的完整 `events.jsonl`。
* **整改方案**：
  修改文件同步逻辑，排除 `events.jsonl`，统一由全局 `event_hub` 全生命周期持久化：
  ```python
  for f in src_dir.iterdir():
      if f.is_file() and f.name != "events.jsonl":
          shutil.copy2(f, art_dir / f.name)
  ```

### DEF-02: 环形图错误装入同比增速（常识性金融统计违规）

> **【真实性核验结论】：100% 证实真实存在**
> - **实证数据**：在 Run 1（人工智能）的 `CHART-03-FF3BA474` 中，图表类型为 `donut`，中心文字为“结构分布 621.1”，寒武纪占比计算为 73.0% (453.2)。将 5 家公司的同比增速（%）求和为 621.1 并计算占比，完全违反金融常识。
> - **影响**：专业评审与读者极易识别此逻辑硬伤，直接削弱研报权威性。

* **现场现象**：
  在 Run 1（人工智能）的交付产物中，`CHART-03` 生成为环形图（Donut），题为《核心企业营业收入同比增长率集中度分布》。中心文字为 `结构分布 621.1`，各扇区为：
  - 寒武纪：`73.0% (453.2)`
  - 中际旭创：`9.7% (60.3)`
  - 工业富联：`7.8% (48.2)`
  - 浪潮信息：`7.0% (43.3)`
  - 科大讯飞：`2.6% (16.1)`
* **机理剖析**：
  环形图/饼图的数学与商业定义是**全集构成比（Parts of a Whole）**，扇区总和必须等于 100% 且具备明确整体物理含义（如总市值、全行业总营收）。各公司的营收同比增速（%）属于离散的比率指标，各家增速相加求和（$453.2 + 60.3 + 48.2 + 43.3 + 16.1 = 621.1$）毫无统计意义，以此换算出的“占比”（如寒武纪占73%）更是荒谬。
* **代码溯源**：
  `agents_core/chart-generator/chart_generator/compiler.py` 在根据语义洞察匹配 `donut` 类型时，仅判断了指标是否包含“集中度”关键词，未检查底层指标的量纲类型是否可求和（Additive vs. Intensive/Rate）。
* **整改方案**：
  在图表选型编译器中加入硬核类型拦截：
  ```python
  NON_ADDITIVE_METRIC_KEYWORDS = ["率", "比", "ratio", "margin", "growth", "roe", "roa", "pe", "pb"]
  if chart_type == "donut" and any(k in metric.lower() for k in NON_ADDITIVE_METRIC_KEYWORDS):
      # 强制降级为横向对比柱状图
      chart_type = "comparison_bar"
  ```

### DEF-04: 图表内外双重渲染标题与数据来源（双下巴现象）

> - **影响**：版面视觉冗余、排版不洁。

  - **底部**：SVG 画布底端绘制了卡片样式的 `核心结论` 与 `数据来源`；画布下方 HTML 的 `<figcaption>` 又渲染了 `研判焦点` 和 **`数据来源: 数据来源: 公司公告、同花顺 iFinD...`**（出现词缀重复）。
* **代码溯源**：

  统一图表视觉边界权责：
  - 方案 A（推荐）：SVG 纯粹作为“数据可视化图表区域”，移除 SVG 内部硬编码的大标题与底部数据来源条，统一由外层 HTML/PDF 容器的 `.figure-heading` 和 `<figcaption>` 统一排版管控。
  - 方案 B：若保留 SVG 内嵌标题，则在 HTML 模板中通过样式或条件控制隐藏外部重复的 `.figure-heading` 与 `<figcaption>`。

### DEF-05: PDF 目录页码列完全空白

> **【真实性核验结论】：100% 证实真实存在**
> - **实证数据**：使用 PyMuPDF 对 Run 1 和 Run 2 导出的 `report.pdf` 第 2 页进行文本与坐标提取：目录包含全部章节标题与点状虚线引导符（Leader），但右侧的“页码”列下方完全为空白（纯占位符 `<span class="pg"></span>`，无任何页码文本输出）。
> - **影响**：破坏专业出版规格，使纸质打印与目录检索功能失效。

* **现场现象**：
  在两份 33~35 页的正式 PDF 研报中，第 2 页为出版级排版的“目录”，包含章节名与点状引导线（Leader），右上角表头为“页码”，但**整列页码全部为空白**。
* **代码溯源**：
  - HTML 模板：`templates/auto/report.html#L746` 中写有 `<span class="leader"></span><span class="pg"></span>`；CSS 注释声明“页码由导出阶段二次渲染回填”。
  - PDF 渲染器：[agents_core/report-fusion/report_fusion/pdf.py](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/agents_core/report-fusion/report_fusion/pdf.py) 仅调用了单次 `page.pdf(format="A4")`，并未实现任何提取章节页码并回填 DOM 的两阶段逻辑。
* **整改方案**：
  在 `pdf.py` 中引入两阶段渲染机制：
  1. 第一次在无头浏览器中渲染页面，通过 JavaScript 查询每个 `<section class="chapter">` 与 `<h3>` 的垂直偏移高度，按页面高度（约 1122px）计算出对应所在的真实页码；
  2. 将计算得到的页码更新至 `.toc .pg` 节点；
  3. 执行 `page.pdf()` 导出带有精确页码的正式 PDF。

### DEF-06: 折线图末端数据标签堆叠遮挡

> **【真实性核验结论】：100% 证实真实存在**
> - **实证数据**：在 Run 1 `CHART-05`（毛利率）与图 8、图 15 的 SVG 产物中，密集区间（如 4%~7% 区间内工业富联、浪潮信息等）末端标签由于仅按数据点 Y 坐标绘制，发生重叠，字迹涂黑无法辨识。
> - **影响**：多标的对比折线图可读性下降。

* **现场现象**：
  在 Run 1 的 `图 8`（归母净利同比趋势）、`图 13`（毛利率趋势）、`图 15`（净利率趋势）以及 Run 2 中，折线图最右侧报告期（2025-12-31）处，当有多家企业数值密集（如 4%~7% 之间存在工业富联、浪潮信息等）时，公司简称与数值标签直接按原始坐标重合，字迹重叠涂黑，无法辨识。
* **代码溯源**：
  `agents_core/chart-generator/chart_generator/render.py` 中的 `_render_line_series` 直接根据数据点的 Y 坐标写入 SVG `<text>`，缺乏末端标签垂直防碰撞（Collision Avoidance）算法。
* **整改方案**：
  在 SVG 折线图末端标签渲染前，收集所有终点标签的 Y 轴像素位置；若相邻两个标签的距离小于 16px，采用向上下交错位移（Staggered Shift）算法，并引出微型连接线。

> - **实证数据**：在 `output/runs/charts-20260927164840-d972fef7/request.json` 中，`report.subject` 为“商业航天”，但实际绑定的图表证据实体全部为低空经济企业（万丰奥威、中信海直），导致图表脱节。
> - **影响**：离线单模块验证与回归测试时易产生失真结论。

* **机理剖析**：
  在测试脚本调用各独立智能体时，缺少“请求主题与传入数据集主题一致性”的前置断言校验，导致数据被误传时系统仍强行推进并生成荒谬产物。
* **整改方案**：
  在 `data_interpreter`、`chart_generator`、`chapter_writer` 的入口 `validate_request` 中，增加一致性校验：
  ```python
  if dataset.industry and request.subject and dataset.industry != request.subject:
      raise ValueError(f"输入数据集行业 ({dataset.industry}) 与请求分析主题 ({request.subject}) 不一致！")
  ```
