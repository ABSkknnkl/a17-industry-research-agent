尽管前期修复全部生效，但在真实全流程渲染与端到端审阅中，发现了 4 个此前未覆盖的深层逻辑与渲染缺陷，其中包括 **1 个 P0 级金融常识灾难** 和 **3 个 P1 级业务完整性与视觉缺陷**。

### 【NEW-01】P0 级：双轴组合图（Combo Chart）右轴强行硬编码百分号与数据量级失控（CHART-13）

#### 1. 现象与视觉证据
在 PDF 第 19 页、HTML 第 753 行的 `图 13: 万丰奥威毛利率与研发费用`（图表 ID: `CHART-13`）中：
- 左轴为毛利率（百分比，0% ~ 25%）。
- 右轴为研发费用（绝对金额）。
- **灾难性视觉渲染**：
  - 右侧 y 轴刻度标签显示为：`1.0亿%`、`2.0亿%`、`3.0亿%`、`4.0亿%`、`5.0亿%`！
  - 柱子顶端的数据标签显示为：`412853240.3%`、`467858426.2%`！
  - **把四亿多元的研发费用全部打上了百分号 `%`，右轴刻度变成了“几亿百分比”，属于严重的金融研报常识事故。**

#### 2. 代码根因定位
问题由两层错误叠加导致：
1. **渲染层强行写死百分号**：
   在 [`chart_generator/render.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/chart_generator/render.py#L558-L560) 的 `render_combo_chart` 函数中：
   ```python
   # L558: 右轴刻度标签硬编码加上了 %
   f'<text x="{r_x}" y="{y:.1f}" text-anchor="start" font-size="10" fill="#6B7280">{_format_num(r_ticks[i])}%</text>'
   
   # L638: 柱状图/折线图标签硬编码加上了 %
   f'<text x="{x:.1f}" y="{lbl_y:.1f}" text-anchor="middle" font-size="10" fill="#1E293B" font-weight="600">{val:.1f}%</text>'
   ```
   代码开发者默认假定“双轴组合图右轴必然是增长率百分比”，而未根据右轴实际指标的单位（元、亿元、人、万等）动态判断是否显示 `%`。
2. **数据成型层未对研发费用进行量级缩放**：
   在 [`chart_generator/data_formulation.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/chart_generator/data_formulation.py) 的 `_formulate_entity_combo` 中，对研发费用提取的是原始绝对数值（`467858426.2` 元），既没有除以 $10^8$ 换算为亿元，又直接送入了 `render_combo_chart`，导致产生四亿的数值被带上百分号。

#### 3. 修复方案
- 在 `render_combo_chart` 中增加 `right_unit` 参数，只有在右轴单位包含 `%` 或指标为比率/增速时才追加 `%`；若单位为 `亿元`、`万元` 或 `元`，右轴刻度与数值标签应根据单位格式化（如 `4.68亿` 或 `4.68`，顶部注明显著单位 `单位: 亿元`）。
- 在 `_formulate_entity_combo` 中增加数值量级自适应换算（若数值 $> 10^7$ 且单位为元，自动换算为亿元并规范标注单位）。

### 【NEW-02】P1 级：双轴组合图退化与单系列残缺（CHART-06 与 CHART-08）

#### 1. 现象与视觉证据
1. **CHART-06（PDF 第 7 页，图 2）**：
   - 标题为：`宗申动力营业收入与归母净利润同比增速双轴组合`。
   - 底部脚注说明写道：`注：柱状为营收增速，折线为净利增速`。
   - **实际渲染**：图表中**仅有一组柱状系列（宗申动力），完全没有右轴折线系列！** 所谓的“双轴组合”退化成了单一指标柱状图，脚注与图表内容严重脱节。
2. **CHART-08（PDF 第 8 页，图 4）**：
   - 标题为：`中信海直毛利率与净利率演进双轴`。
   - 图表类型被判定退化为 `line`（单轴折线），且图表内部只有一条线（中信海直），另一个指标（净利率）被完全丢弃。
   - 与此同时，`CHART-10` 又是 `中信海直毛利率与净利率演进`，形成了重复图表。

#### 2. 代码根因定位
在 [`chart_generator/agent.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/chart_generator/agent.py) 与 [`chart_generator/compiler.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/chart_generator/compiler.py) 中：
- 当规划器提议生成“营业收入增速与净利润增速双轴组合”或“毛利率与净利率演进双轴”时，规划期望将两个指标并列。
- 但在 `data_formulation.py` 的处理逻辑中，如果第二个指标的数据时间序列键与第一个指标不严格对齐，或者在多实体与多指标的交叉提取时，将第二个指标当作了实体维度或者直接丢弃，导致构建出的表格只有 `[时间, 指标1]` 一列数据。
- 编译器在发现只有一列数据时，没有降级图表标题和注释，也没有警报补救，依然保留了带有“双轴组合”、“柱状为...折线为...”的模板标题与脚注。

#### 3. 修复方案
- 强化 `_formulate_entity_combo` 的双指标提取对齐逻辑，确保左右轴两个指标完整提取。
- 编译器增加健康检查：如果渲染数据实际只有单一系列，严禁使用“双轴组合”标题和“柱状为...折线为...”的注释；若关键第二指标缺失，应触发兜底重提或平滑降级为标准单轴图。

### 【NEW-03】P1 级：产业链拓扑图与气泡图的单位/标签错乱与文字重叠（CHART-04 与 CHART-12）

#### 1. 现象与视觉证据
1. **CHART-04（PDF 第 12 页，图 6: 产业链价值传导拓扑）**：
   - 产业链环节的实体卡片上，毛利率的徽标显示为：
     - `万丰奥威 16.36元`
     - `中信海直 26.52元`
   - **把毛利率 16.36% 和 26.52% 的单位显示成了“元”！**
2. **CHART-12（PDF 第 18 页，图 11: 营业收入与归母净利润定位）**：
   - 图表右上角的单位标识赫然显示为：`单位：归母净利润`！
   - 将指标名称当作了计量单位。
3. **CHART-12 内部文字重叠**：
   - 气泡图第四象限左下角的公司标签 `莱斯信息` 与背景浅灰色象限水印文字 `【低归母净利润 · 低营业收入】` 产生了视觉重叠，字母与象限文字交错在一起。

#### 2. 代码根因定位
1. **拓扑图毛利率单位成“元”**：
   在 [`chart_generator/data_formulation.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/chart_generator/data_formulation.py#L777) 的 `_formulate_entity_cross_section` 中：
   ```python
   currency_unit = determine_series_currency_unit(records, metric_field)
   ```
   `determine_series_currency_unit` 的内部默认返回值在未匹配到万元/亿元时，硬编码回落为了 `"元"`，而未优先检测该指标字段名是否包含 `margin`, `rate`, `ratio`, `率`, `比` 等比例特征。导致毛利率这类百分比指标被赋予了单位 `"元"`。
2. **气泡图单位变成指标名**：
   在 [`chart_generator/render.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/chart_generator/render.py#L328) 中：
   ```python
   unit_str = f"单位: {unit}" if unit and len(unit) <= 6 else ""
   ```
   当上游传入 `unit = "归母净利润"`（长度为 5 $\le$ 6）时，代码误认为是一个简短的物理单位并渲染了出来。
3. **象限水印与散点碰撞**：
   象限背景标签固定渲染在各象限正中央或左下角，未与靠近原点的散点（如莱斯信息）做动态坐标偏移或避让。

#### 3. 修复方案
- 在 `determine_series_currency_unit` 与指标格式化函数中，建立强类型的指标单位推导规则：凡含 `率`、`比`、`margin`、`rate`、`ratio`、`pct` 的指标，单位强制锁定为 `%`，禁止 fallback 到 `"元"`。
- 在 `render.py` 中过滤非法单位词汇列表（如 `["归母净利润", "营业收入", "市值", "净利润"]` 等指标名称严禁出现在 `单位: ` 中）。
- 气泡图象限水印文字调整为低透明度（opacity 0.08）且位置置于角落，或为气泡公司标签添加白色轮廓阴影（`paint-order: stroke; stroke: white; stroke-width: 3px;`），消除交错干扰。

### 【NEW-04】P1 级：数据获取预算耗尽导致多项数据源空白与宏观查询语法失效

#### 1. 现象与日志证据
查阅 `run-20260927194909-370` 的 `events.jsonl`：
1. **技能调用预算耗尽**：
   在 `data_fetch` 阶段的第一轮迭代中，规划器分解了 16 个查询任务。但由于系统硬编码了 `max_skill_calls = 12`：
   - 任务 1~12 连续执行（宏观 1 + 行业 1 + 标的1/2/3/4各两项基本财务 + 标的1/2主营 = 12 次）。
   - **任务 13（宗申动力主营）、任务 14（莱斯信息主营）、任务 15（研报获取 reports）、任务 16（新闻获取 news）直接被拦截中止！**
   - 日志记录：`Task task13_business_001696 skipped: budget would be exceeded`。
2. **宏观查询语法失效**：
   - `task2_macro_gdp_industry` 执行问财查询：`低空经济 2022年到2024年GDP和工业增加值`，问财语法无法理解这种多实体复合句式，返回记录数为 0。
3. **结果影响**：
   最终数据集结构中：
   - `macro_economic = 0` 条
   - `news = 0` 条
   - `reports = 0` 条
   - **8 个规定数据板块中有 3 个完全为 0 条数据，有效覆盖率仅 62.5%**。后续宏观分析章节与政策章节完全失去了真实数据支撑，被迫依赖通用大模型幻觉兜底。

#### 2. 代码根因定位
1. **Adapter 预算硬编码过小**：
   在 [`backend/app/agents/adapters.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/backend/app/agents/adapters.py#L239) 中：
   ```python
   max_calls = 12  # 被硬编码为 12
   ```
   而在赛题性能要求中，单次研报生成允许调用工具 24 次。当分析 4 家核心标的时，仅基础财务与主营就需 12 次调用，根本无法顾及行业、宏观、新闻与研报。
2. **宏观查询句式未做拆解与规范化**：
   在 [`data_fetcher/agent.py`](file:///Users/panheng/Desktop/同花顺赛题/a17-industry-research-agent-agent-chart-mvp-sync/data_fetcher/agent.py) 中，宏观查询任务将 GDP 和工业增加值合并，且带上了行业前缀，超出了问财 macro 接口的自然语言解析能力。

#### 3. 修复方案
- 将 `adapters.py` 及全链路的 `max_skill_calls` 调优至 20~24 次，并在第一轮调度时对任务按优先级排序（行业/宏观/标的财务 > 新闻/研报 > 个股细分主营），防止长尾任务挤占全局关键数据。
- 规范宏观查询模版，拆分为问财标准关键词（如 `全国GDP`、`通用航空制造业增加值` 等独立查询）。
