## 四、逐条讲清「这是什么意思」

### 3.1.1 产业链全景图谱（S1 · 功能创新 · 必留）

- **一句话意思**：把研报里的产业链图，从「让模型画一张示意图」变成「按结构约束校验出来、且每个环节都挂得上证据的图」。
- **项目里对应什么**：报告第 4 图固定使用三列产业链全景 SVG；`chain_topology.py` 的 `validate_topology` / `repair_topology` / `design_topology`；七条结构约束（节点编号唯一、阶段枚举合法、唯一核心节点、企业单一归属、实物流方向合规、度数上限、证据编号真实）；低空经济 8 家整机厂场景用分层节点保留完整行业结构；图中保留五家公司年报证据关联。
- **别人怎么做 / 我们怎么做**：别人让模型直接画一张好看的图或贴网图；我们先定义合法拓扑的约束，校验与修复共用同一判据，调整后重新校验入稿。
- **核心亮点**：结构完整性与证据真实性可以同时满足；证据覆盖不同的节点分层表达，行业代表性不因样本收窄而塌缩。
- **写进哪一节 / 配图**：2.3.1 首段 + 3.3.4 算法；配三列全景 SVG（项目既定资产，**不得替换为简化示意图或自动重绘图**）+ 七约束示意图。
- **一句话话术**：「产业链图不是画出来的，是按约束校验出来的。」
- **别写错**：箭头表达的是价值方向，不是供货关系；不要写「错图不交付」「修不好回退」这类表述。

### 3.1.2 智能取数探针（S3 · 功能创新 · 必留）

- **一句话意思**：数据取不到时，不是让模型反复重试或自由改写查询，而是按数据点下单、按次计量、有预算有轨迹地把证据补上来。
- **项目里对应什么**：`PartialRefetchPanel.vue` 勾选数据点并显示「已选 N 点 · 最多 N×4 次改写 / 调用」与四步执行计划；静态侧四类 schema 解析（宏观 / 行式 / 宽表序列 / 分组年度）；规程化动态探索限定 5 类白名单技能、最多 4 次改写、JSON-only、重复查询去重、按实体／指标／期间／数值四要素校验命中；独立预算与 `probe_id` 留痕，不挤占主流程 24 次调用额度。
- **实测支撑**：静态 4/4 取得原始行、动态 3/4 命中；出口年度 0→5 个年度值、业务构成 0→3 个分产品、PB 宽表 0→60 个月末点；演示口径 373→375 条、五问覆盖 3/5→5/5。
- **核心亮点**：两条通道互补、按点下单、全过程可复算；是全套唯一有完整前后对比台账、唯一能现场点出覆盖度变化的一条。
- **写进哪一节 / 配图**：2.3.3 首段 + 3.6.1 实现；配补采面板截图与覆盖矩阵前后对比。
- **一句话话术**：「补采不是再来一次，是按点下单。」
- **别写错**：① 3/5→5/5 属**归档回放演示口径**，现场须如实标注，不写成实时大模型；② 不写「探针 4 次全失败」「失败也是产物」「零结果触发」；动态通道用「在未知宽表结构下触发」；③ 这条排在 S 级第 3，是因为赛题【问题说明】(2) 点名了查询优化与边界情况，容易被读成必答题——**文档里往「按点下单、独立预算、全轨迹可复算」上写，不要往「取数更准」上写**。

### 3.1.3 五阶段分级复核台（S4 · 功能创新）

- **一句话意思**：人机协同不是一个聊天框，而是五个阶段各有一张编辑台，用户在数据点、图表、段落、指标卡这些原对象上直接改。
- **项目里对应什么**：`ReviewView.vue` + `StageStepper.vue` + `StageInterventionModal.vue`（2912 行，五阶段干预合一）+ `ReviewActions.vue` + `PartialRefetchPanel.vue` + `RevisionDiffViewer.vue`（656 行）+ `StageDigest.vue`（902 行）+ `EvidenceDrawer.vue`（477 行）+ `QualityPanel.vue` + `MetricCards.vue` + `ChartGallery.vue` + `AgentLiveTrace.vue`，共 16 个真实组件。五阶段编辑台内容：A1 检索范围与关键词／局部重采，A2 背景知识与判断修正／可比公司标的池，A3 图表样式与强调重点／定向图表诉求，A4 修改意见／段落就地精修／风格引导，A5 整体终审／8 张指标卡。
- **别人怎么做 / 我们怎么做**：别人是聊天框，用户说「这里改一下」，模型猜；我们是五张编辑台，用户直接在原对象上改，系统据此判定影响范围并生成执行计划。
- **核心亮点**：赛题 §5（7）每阶段审核与反馈正面命中；组件全部已实现，可边讲边点、点完即见变化。
- **写进哪一节 / 配图**：2.3.4 首段 + 2.2.2—2.2.6 界面章节各补一句；配五阶段编辑台拼图（每阶段一张）+ 修订对比 + 证据穿透抽屉，直接用现有界面截图。
- **一句话话术**：「补得齐、改得动、核得回。」
- **别写错**：A1「脏数据清洗」按钮、A2「核心研判论点精修」「异常指标与风险裁决」两个 tab 已删除，**不要写进去**；`ReviewActions.vue` 真实 UI 里有大量「风险确认 / 硬阻塞 / 不可恢复」提示文案，一律翻成「审核事项分级签认」「关键事项由研究人员确认后进入下一阶段」。

### 3.2.1 数值勾稽与精度裁定（S2 · 技术创新）

- **一句话意思**：研报里的数字由确定性算子算出来，模型只负责解释；两个数看起来不一样时，按原始披露的小数位数判断它们是不是同一个数。
- **项目里对应什么**：`financial_semantics.py`（1416 行）的 `decimal_step_from_text` / `matches_disclosed` / `rounding_verdict` / `measurement_conflict_verdict` / `quantity_issues`；`engine.py` 的净现比、研发费用率、PE 溢价、CAGR、结构占比等口径；稳健 Z 异常判定与趋势强度判定；事实视图只读。
- **最有说服力的一个数**：16.17 与 16.2 判为等价（按 0.1 的步长舍入），1.2 亿元与 12000 万元同步步长后一致；避免固定百分比容差随分母漂移造成的误判。
- **为什么排第 2**：赛题 (3)(5)(6) 提了异常值、幻觉、口径一致，**完全没提披露精度步长与四舍五入判等**——这是团队自己发现的纯增量，一个数讲清机制，「勾稽」又是投研本行术语，最容易被认定为创新。
- **写进哪一节 / 配图**：2.3.2 首段 + 3.3.1 / 3.3.3 公式（式 3-1、式 3-4）；配双核量化推演流程图与金融计算口径表 3.3。
- **别写错**：不说「防止模型编数字」，说「能算的结论全部由确定性算子生成，模型只在算好的结果上做解释，每个关键数字都能回到一条具体记录」。

### 3.2.2 证据穿透与底稿溯源（A5 · 技术创新）

- **一句话意思**：每个数字、每句结论都有一个能沿编号追回原始记录的坐标，形成可复核的研究底稿。
- **项目里对应什么**：R- 前缀 + 内容哈希的唯一编号，携带来源、期间、单位、口径与取数时点；段落切分子句后按数值、方向、因果、排名、预测、情景六类配置证据标准；同实体同指标同期间下独立来源不少于 2 才做交叉验证；多来源候选全部保留并交人工仲裁；公告证据按 URL / 日期 / 页码 / 摘录 / 主题五要素关联原文；`EvidenceDrawer.vue` 直达原始记录。
- **写进哪一节 / 配图**：3.3.2 断言分型核验；配六类断言证据标准表 3.4 + 证据穿透界面图 2.7。
- **别写错**：不写「判不了就拦 / fail-closed」，写「按断言类型配置差异化证据标准，判定依据与结论一同留档，复核者可沿同一路径重走一遍」。

## 四之三、金融专属度（决定每条怎么写才有投研味）

### 1. 分级判断

| 序 | 创新点 | 金融专属度 | 专属在哪 | 换行业还成立吗 |
|---|---|---|---|---|
| 1 | 数值勾稽与精度裁定 | ★★★ | 披露精度判等、财务口径族、期间与单位溯源 | **基本不成立**，唯一一条赛题未要求、团队从金融数据里自己发现的问题 |
| 2 | 产业链全景图谱 | ★★☆ | 上下游环节、企业单一归属、实物流方向、代表企业证据 | 内容专属，**校验机制通用** |
| 3 | 证据穿透与底稿溯源 | ★★☆ | 公告五要素翻页、研究底稿、署名负责、投研合规 | 合规语境专属，**编号与核验框架通用** |
| 4 | 智能取数探针 | ★☆ | 指标名错配、宽表期间列、累计／年度口径、分产品与月度渗透率 | 数据形态专属，**探针机制通用** |
| 5 | 五阶段分级复核台 | ★ | 8 张指标卡、可比公司标的池、研报三审语境 | **几乎通用**，与 A08 优先级配置、A21 工作流编排形态相似 |

**一个结构上的巧合并非硬凑**：按 A08 规格归到 3.2 技术创新的两条（数值勾稽 ★★★、证据穿透 ★★☆），恰好是金融专属度最高的两条。因此 3.2 应写成「金融场景专有的判定机制」，3.1 写成「面向研报生产的功能形态」。

### 2. 最硬的三组金融证据（可直接引）

- **披露精度判等**：只在有法定披露文本的金融场景才存在「年报披露 16.2%、数据库算出 16.17%」这个矛盾，按原始披露串反推小数步长才能判等价；配套元／万元／亿元倍率同步步长，1.2 亿元与 12000 万元判一致。建筑能耗 COP、新闻可信度评分都没有「披露口径 vs 计算口径」这回事。
- **财务口径族与期间口径**：净现比、研发费用率、PE 溢价、CAGR、结构占比、稳健 Z 同业横截面；累计 vs 年度、报告期 vs 披露期、月度 vs 年度渗透率。赛题正文一个字都没提这些计算对象。
- **合规语境**：公告证据按 URL／日期／页码／摘录／主题五要素直达年报原文；六类断言里「预测不得用历史观测冒充依据」「排名须有界基期」；研究底稿与分析师署名负责，对应项目已核查的中证协 2025 首次提出 AI 投研内控与全流程留痕要求。

### 3. 反直觉点：名字金融 ≠ 机制金融

**名字最金融的两条，机制反而最通用**：「复核台」听着像研报三审，底层是通用人机协同工作台；「智能取数探针」名字不金融，但指标名被解析成 GDP 同比、宽表 `市净率[YYYYMMDD]`、累计与年度混用这些坑，全是金融数据才有的。

**因此文档里要强调：专属的是约束内容与数据口径，不是校验／取数这套工程。** 撰稿时把下面每条的限定语放在首段第二句，用事实把金融味写出来，不要写「金融专属」「行业首创」这类自评词。

### 4. 每条一句「金融场景限定语」（可直接粘贴）
