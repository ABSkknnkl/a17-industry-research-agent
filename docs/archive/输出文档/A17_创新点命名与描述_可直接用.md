## 一、对标文档的写法规律（决定本次怎么措辞）

| 维度 | A08 做法 | A21 做法 | 本次沿用 |
|---|---|---|---|
| 命名 | 自造专名：AgenticRAG、Bems-Agent、片区能源异常优先级报警机制 | 能力名 + 场景：智能体工作流与 API 创建、浏览器插件随时分析、区块链存证 | 自造专名 + 能力对象，不用机制/状态词 |

### 创新点 1 · 双核量化确定性研报引擎

| 命名备选 | 侧重点 |
|---|---|
| **双核量化确定性研报引擎**（推荐） | 强调"计算 + 解释"两套引擎，工程感强 |
| 事实—表述分离计算架构 | 强调架构分层，适合详细方案 3.3.1 |
| 代码定数·模型释义协同机制 | 强调职责边界，适合答辩口头解释 |
| 确定性数值主干 | 强调数值可信这一结果，适合 PPT 标题 |

- **项目体现（真实存在）**：A2 确定性分析引擎完成财务指标、勾稽、可比性与异常识别；净现比、研发费用率、PE 溢价、CAGR、结构占比等口径固化为算子；稳健 Z 异常判定与趋势强度判定不引入模型判断；事实视图只读，数字由代码生成，模型只做解释。
- **核心亮点**：数值的产生方式可复算、可审计；精度裁定按原始披露串反推步长，16.17 与 16.2 判为等价，不误杀四舍五入的正确数。
- **更有说服力的表述**：不说"防止模型编数字"，说**「能算的结论全部由确定性算子生成，模型只在算好的结果上做解释；每个关键数字都能回到一条具体记录，而不是回到模型的记忆」**。
- **建议配图**：双核量化推演流程图（现有 3.3.1 表 3.3 可直接引用）。

### 创新点 3 · 事务化多智能体协同与审核动作执行体系

| 命名备选 | 侧重点 |
|---|---|
| **事务化五阶段协同引擎**（推荐） | 强调状态机与事务，技术含量最高 |
| 审核动作即执行计划 | 强调八种动作各自决定重跑范围，机制感强 |

| 可局部返工的研报生产线 | 强调效率收益，适合价值章节 |

- **项目体现（真实存在）**：八种阶段状态与八种审核动作（通过、采纳建议、修改后重跑、带参重跑、重新生成、就地编辑、带确认项继续、取消）构成完整迁移表；提交携带读取时修订号进行并发版本控制，服务端按版本号校验保证并发修改互不覆盖；每次审核生成不可变决策包，记录 run_id / stage / revision / action / actor / decision_id / 快照摘要 / 已确认事项编码；动作粒度按阶段划分，数据阶段最小到一次补采、图表阶段最小到单张图、章节阶段最小到一个段落。
- **核心亮点**：审核不是一次态度表态，而是一份可执行计划；改一个段落只更新该段及其引用关系，不重跑整章；谁在哪个版本做了什么动作，均可回溯。
- **更有说服力的表述**：不说"失败回滚"，说**「审核以事务执行：先冻结输入版本，再按动作类型决定重跑范围，完成后写入新版本与决策包。用户看到的是改一段只动一段，退回一次只影响相关下游」**。
- **建议配图**：状态机迁移图 + 八种审核动作与重跑范围对照表。

- **上台优先级**：**P0，建议列为 3—4 个 headline 之首**。理由：赛题 §5（7）明文要求「每个阶段设置人类审核与反馈节点」，这一条正面命中；且组件全部已实现、可现场点开，是全套创新点里唯一能「边讲边点、点完即见变化」的一条。

## 五、可直接使用的成稿（按 A21 的 2.3 格式）

### 2.3.1 双核量化确定性研报引擎

本模块将行业研究中的数值计算与文字表述分离，把财务指标、勾稽关系、可比性分析与异常识别交由确定性算子完成，由模型在已算好的结果上生成解释与论述，实现数值可复算、口径可核对、结论可追溯的一体化研报生成能力。

1．**确定性计算内核**：净现比、研发费用率、PE 溢价、CAGR、结构占比等口径固化为可复用算子，横截面与时序异常采用稳健 Z 与趋势强度判定，全部由代码执行，不引入模型的主观判断。
2．**披露精度自适应裁定**：按原始披露串反推小数步长，在更精细侧向粗侧舍入后判等，16.17 与 16.2 判为等价，1.2 亿元与 12000 万元同步步长后一致，避免固定百分比容差随分母漂移造成的误判。
3．**事实视图只读**：关键数值一经生成即冻结，模型输出与正文共用同一份事实视图，读者看到的每个关键数字都能回到一条具体记录。

### 2.3.2 全链路证据编号与断言分型核验体系

本模块为每条关键记录生成带内容哈希的唯一编号，并在段落、图表与结论之间建立贯通的引用关系，配合按断言类型分级的核验规则，实现从披露原文到成稿结论的全链路可信核验。

1．**证据编号贯通**：编号携带来源、期间、单位、口径与取数时点，下游结论、图表、段落与摘要均引用同一编号，任意结论可沿编号反查至原始取数记录。
2．**六类断言分级核验**：数值、方向、因果、排名、预测、情景六类断言各配置独立证据标准，数值可反算、方向看同口径序列、因果看原文直引、排名须有界基期，判定过程可复现。
3．**多来源交叉验证与仲裁**：同实体、同指标、同可比期间下独立来源不少于 2 才做交叉验证，全部候选值连同期间、口径与成因完整保留，由研究人员完成仲裁。
4．**公告证据直达原文**：按 URL、日期、页码、摘录、主题五要素关联公告原文，证据不是一条链接，而是可翻到具体页的坐标。

### 2.3.3 事务化多智能体协同与对象级审核工作台

本模块把五个生成阶段组织为可暂停、可恢复、可局部返工的事务化流程，并在每个阶段提供面向原对象的审核工作台，使用户能够在数据点、图表、段落与指标卡上直接完成确认与精修，实现审核动作与执行计划的一体化。

1．**状态机与动作契约**：八种阶段状态、八种审核动作构成完整迁移表，动作决定重跑范围、是否调用模型与是否携带确认编码；等待审核是显式的可介入节点，人工动作决定推进方式与执行范围。
2．**并发版本控制与决策包**：提交修改携带读取时修订号，服务端按版本号校验并保证并发修改互不覆盖；每次审核生成不可变决策包，记录版本、动作、执行人、已逐项签认的审核事项与决策快照摘要，责任边界可回溯。
3．**五张编辑台就地精修**：A1 至 A5 分别提供检索范围确认、背景知识补充、图表样式选择、段落就地编辑与整体终审，用户在原对象上修改，系统据此判定影响范围，改一段只更新该段及其引用关系。
4．**修订对比与覆盖矩阵**：改前改后逐项对照，五问证据覆盖、图表覆盖状态与证据引用条数同步刷新，审核后不仅得到新版本，也清楚知道变了什么、覆盖到了哪一步。

### 2.3.4 静态优先·动态受限双通道探针

本模块面向研究过程中的证据扩充需求，构建静态精确查询与受限动态探索互补的双通道补采机制，支持按数据点下单、按次计量、按轨迹审计，实现证据覆盖度的自适应增强。

1．**静态确定性通道**：固定查询配合宏观、行式、宽表序列、分组年度四类 schema 解析，负责已知口径下的确定性取数，实测四类待补数据点上 4/4 取得原始行。
2．**受限动态探索通道**：在未知宽表结构下触发，限定 5 类白名单技能、最多 4 次改写、JSON-only 输出、重复查询自动去重，并按实体、指标、期间、数值四要素校验命中；实测出口年度由 0 补齐 5 个年度值、业务构成由 0 补齐 3 个分产品、PB 宽表由 0 补齐 60 个月末点。
3．**独立预算与全轨迹审计**：探针使用独立预算与 probe_id，不挤占主流程调用额度；每次尝试记录技能、查询、原始行数与命中情况，补采路径可复算、可复盘。
4．**覆盖度闭环提升**：演示口径下首轮 373 条记录、五问覆盖 3/5，按点补采后达到 375 条、覆盖 5/5，补采动作与覆盖度变化一一对应。

### 2.3.5 约束驱动的产业链拓扑生成与自愈

本模块把行业研究中的产业链结构表达转化为可校验、可修复的形式化构建过程，通过七条结构约束与同源修复算子，实现产业全景图在结构完整性与证据真实性上的统一。

1．**七条结构约束**：节点编号唯一、阶段枚举合法、唯一核心节点、企业单一归属、实物流方向合规、节点度数上限、证据编号真实，共同定义一张可入稿的产业全景图。
2．**裁判—修复同源**：校验与修复共用同一套判据，按边权重由低到高做确定性调整，调整后再次校验，形成「生成—校验—修复—复核」的闭环，避免报错与修复能力脱节。
3．**分层保真表达**：证据覆盖不同的节点以分层方式呈现，低空经济 8 家整机厂场景中 A 股标的以实心节点标识、其余以行业共性节点保留，行业代表性不因样本范围收窄而塌缩。
4．**固定全景资产**：报告第 4 图采用三列产业链全景 SVG，箭头表达价值方向，并保留五家公司的年报证据关联，全链路沿用同一图稿。

### 2.3.6 契约化提示词工程与三格式同源签发

本模块把提示词设计为智能体之间的可校验接口，并以统一事实视图驱动多格式交付，配合发布前的四类硬条件校验，实现从受控生成到可信签发的完整闭环。

1．**五层提示词契约**：角色边界、事实证据、任务方法、输出契约、自检修复五层结构，17 条主提示词、4 条产业链前置提示词与 66 份技能说明按五个智能体分域，五个任务对应五套契约，而非同一模板换词。
2．**受控输出与预算装配**：输出为带字段契约的 JSON，段落类型、图表类型与置信度均为受控枚举，证据编号逐字取自证据索引，图表引用须使用完整占位符；固定基座、条件片段、技能文本与上下文预算四步装配，超限时按既定顺序裁可选段，必答证据不动。
3．**跨章一致与发布校验**：全局数值锚点统一全文口径，跨章引用逐项对齐；发布前按核心结论证据、引用落地、冲突消解、交付齐全四类硬条件校验，通过后签发。
4．**三格式同源交付**：Markdown、HTML、PDF 由同一事实视图渲染，导出附生成时间、版本号与校验摘要；三层测试体系以 395 条代码级回归、8 组 60 条判据、512 条结构化用例与 168 次真实运行分层守护，回归防改坏、判据防放松、批跑防跑偏。

### 2.3.7 五阶段对象级人机协同审核工作台

本模块为五个生成阶段各配置面向原对象的编辑台，把检索范围、背景知识、图表样式、正文段落与核心指标卡作为可直接操作的对象，配合按点补采、修订对比、证据穿透与覆盖度总览，实现「AI 分步打磨、人工逐项把关、反馈即执行」的人机协同闭环。

1．**五阶段五张编辑台**：数据获取阶段支持审核确认检索范围与关键词、局部子域重采与归档回放补采；数据解读阶段支持补充专家背景知识、修正核心研判判断与调整可比公司标的池；图表阶段支持选择呈现样式、指定重点标的高亮与基准线、新增定向图表诉求；章节阶段支持按范围与目标章节提出修改意见、正文段落就地精修与行文风格引导；融合阶段支持整体终审与 8 张核心指标卡定制。用户在原对象上修改，系统据此判定影响范围并生成执行计划，无需模型猜测意图。
2．**按点下单的补采面板**：以勾选方式选定待补数据点，实时呈现「已选 N 点 · 最多 N×4 次改写 / 调用」的预算与四步执行计划，支持静态精确查询与受限动态探索两种取数方式，补采动作与覆盖度变化一一对应，演示口径下五问证据覆盖由 3/5 提升至 5/5。
3．**审核事项分级签认与动作联动**：审核事项按主题聚合、按级别分级，以「N 类 / M 处」集中呈现，研究人员逐项确认后提交；八种审核动作分别决定重跑范围、是否调用模型与是否携带确认编码，界面操作直接生成结构化决策包，全过程留痕可回溯。
4．**修订对比、证据穿透与覆盖总览**：改前改后逐项对照并支持历史版本恢复；由证据编号直达原始记录，展示指标、取数技能、所属领域与数值；阶段摘要一屏呈现五问证据覆盖、逐问状态、图表覆盖与引用条数；配合阶段进度条、执行动线与交付质量明细，使进度、产物、动作与修订在同一工作台内可见可核。

## 七、包装边界（拿去用之前请守住）

**可以适度拔高**：命名自造专名、把分散机制归纳成体系、用「自主实现 / 一体化 / 全链路 / 精细化 / 显著」等正向效果词、把实测口径写成体系能力、把已有公式与约束条数作为技术含量呈现。

**不要写进文档**：
1. 没有实测台账的效果数字（如具体耗时、批跑条数以外的推算值）；
2. 「跨行业自动迁移 / 自动学习口径词典」——与五个行业的选图规则仍为人工配置的事实不符；
3. 「100% 自动补全」「实时大模型」——演示涉及归档回放，现场须如实标注；
4. 任何失败、缺陷、抑制、拦截、受限、未通过的表述，以及把某次运行的质量状态写成创新点；
5. 「首创」「行业唯一」等无法举证的绝对化用语。

**口径提示**：文中 4/4、3/4、373→375、3/5→5/5、395 条、60 条判据、512 条用例、168 次运行均来自项目现有记录与文档，可直接使用；若赛前复核发现台账与文档不一致，以台账为准，不要在答辩现场给出评委无法核实的数字。
