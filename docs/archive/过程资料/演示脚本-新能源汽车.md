# 局部子域重采 + 大模型探针 · 新能源汽车演示脚本

> 一句话定位：**清单负责「点谁」，探针负责「怎么捞回来」。**
> 预览地址：http://localhost:5173/scope-refetch-preview.html?rec=1

---

## 一、为什么要把两者合并

- 主链路 `fetch_supplemental` 拿到 query_hint 只发**一次**查询，不会改写、不会重试。问财对着一长串「点名清单」基本给不出东西。
- 大模型探针有 **最多 4 轮自纠错**：自己选 skill、改写 query、看返回结果再调整。冷门指标只有它能捞回来。
- 所以：**点级重采 = 探针的清单入口**。不是两个功能，是一个功能的两半。

---

## 二、现场怎么点（约 30 秒）

### 第 1 步：清空默认

点顶部 **「清空」**。默认预选了 8 个缺口项，清空后画面才有说服力。

### 第 2 步：勾 2 个点（都在「重点公司财务与盈利指标」这一组）

| 勾 | 数据点 | 状态 | 演示话术 |
|---|---|---|---|
| ☑ | 营业收入 · 比亚迪 FY2025Q3 | 已齐 96% | 「已经有的也能按新口径重抓」 |
| ☑ | 归母净利润 · 比亚迪 FY2025Q3 | 缺失 | 「缺的这个补回来」 |

> 只勾同一组的原因：后端按 `domains[0]` 定位子域，跨组勾选只认第一组。演示集中在「财务」，真实链路才对得上。

### 第 3 步：三个选择项

| 字段 | 选什么 | 为什么 |
|---|---|---|
| 时间范围 | 最近 5 年 | 财务趋势看 5 年才够看周期 |
| 标的池 | A股核心标的 + 港股对标 | 比亚迪 A+H，可比公司要覆盖 |
| 财务口径 | 合并报表（年报口径） | 跨公司比毛利率必须统一口径 |

### 第 4 步：取数方式选「大模型探针」

默认就是探针。演示时可以点一下「常规单次查询」再点回来，让评委看到这是有意识的选型。

### 第 5 步：补充说明（可粘贴）

```
比亚迪归母净利润取 2025 年三季报合并口径；营业收入口径与年报保持一致，差异超过 2% 需标注。
```

两个开关保持勾选：记住口径、生成「数据底稿说明」。

### 第 6 步：提交

右下角显示 **已选 2 个数据点 · 预计新增 12 条记录 · 约 1 分钟**。

## 三、提交出去的是什么

```json
{
  "action_type": "partial_refetch",
  "domains": ["financials"],
  "data_point_ids": ["F-01", "F-02"],
  "entities": ["比亚迪"],
  "probe_mode": "llm_dynamic",
  "query_hint": "补采 2 个数据点：比亚迪·营业收入(FY2025Q3)；比亚迪·归母净利润(FY2025Q3)；时间范围：最近 3 年；标的池：A股核心标的/港股对标；财务口径：合并报表（年报口径）",
  "calibration": { "time_range_years": 5, "universe": ["a_share", "hk"], "finance_basis": "consolidated" },
  "attach_worksheet": true
}
```

后端拿到后：`probe_mode=llm_dynamic` → 走 `run_dynamic_probe`，把 `entities + query_hint + reason` 喂给大模型探针，最多 4 轮自纠错。

## 七、注意（别被问住）

- 预览页里的金额/百分比是**示意数据**，不是真实财报数；真机应从 `source_records` 取值（这步还没接）。
- 探针每次最多 4 轮大模型调用，**贵**，所以默认只对点级清单开；日常全量取数仍走主链路。
- 若 `.env` 里没配 `LLM_API_KEY / LLM_MODEL`，探针会直接返回「未启用」，不会假装成功。
