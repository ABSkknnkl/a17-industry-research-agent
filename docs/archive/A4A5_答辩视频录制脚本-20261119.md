## 0.2 能不能按原顺序重放（关键）

两份任务都已走过你要拍的状态，**不能直接重演**：A4 停在 report_fusion / r8，A5 已 completed / r9。
平台支持版本回滚（`POST /runs/{run_id}/revisions/{revision}/restore`），以历史快照为基线创建**新修订版本**。三种做法：

| 方案 | 做法 | 适用 | 代价 |
| --- | --- | --- | --- |
| 1 真实重放（推荐） | A4 回滚到 **r6**，当场精修成新段；A5 回滚到 **r3**，重做全局修订→手工定稿→重新融合→签发 | 需要真实点击 | 版本号变成新号，不再是 r5/r8/r9；A5 重跑可能轻微漂移 |
| 2 只拍结果 | A5 不动，直接拍 r9 + PDF/CSV/ZIP；过程用「版本演化对比」的真实快照补 | 时间最紧 | 没有实时点击的过程 |
| 3 新建任务 | 用 `input_data.json` / `dataset.json` / `question_contract.json` 重跑整链 | 要一个干净任务 | 最慢，全部数字需重新验收 |

**决策规则：**
- 视频字幕**不写死 r5 / r8 / r9**，只写「保存定稿 / 重新融合 / 签发」；版本号让画面自己说话。
- 验收文档里的 r5 / r8 / r9 绑定原 run id，作为验收证据；录制 run 单独表述。
- 方案 1 的 A5 重放后必须复核：348 条证据、15 张图、25 页、标题/评级/摘要/指标卡。任何一项不符，停在核验，不签发。

## 2. 总原则与剪辑红线

**可以剪：** 模型等待、页面加载、PDF 生成、ZIP 打包。

**不能剪：** 点击动作本身、点击后的回执、版本号、修改前原文与修改后文字的前后关系。

**最低保留时长：**

| 内容 | 最短 |
| --- | --- |
| 点击前后 | 各 0.4 秒 |
| 版本号（r5 / r8 / r9） | 1.5 秒 |
| 修改前段落 | 1.5 秒 |
| 修改后段落 | 2 秒（A4 要求停 3 秒） |
| 核验通过 / 已签发徽标 | 1.5 秒 |

**字幕纪律：** 只写"已经发生的动作"和"画面已出现的状态"。
- 点击提交时写「提交修订」，**不写「正文已改」**——正文要等重跑后才变；
- 画面出现"质检通过，待人工核准"后才写「核验通过」；
- 画面出现"已签发/已完成"后才写「正式签发」。

## 7. 异常处置（不齐就不签）

**触发条件（任一成立）：**

- 指标数值、单位、变化率、期间与当前版本不一致；
- 摘要或标题在重跑后被改写，不是人工定稿文本；
- 证据记录与 CSV 对不上；
- 质检徽标不是「质检通过，待人工核准」。

**处置：**

1. 不点签发，画面停在「重新融合并核验」后的核验状态；
2. 字幕写「停留核验阶段」，不写「已签发」；
3. 重录该段，先修数据再签；**禁止用旧版 PDF 顶替**；
4. 若已误签，保留原任务不动，另开新任务重走完整链路（全局修订 → 定稿 → 重新融合 → 签发），旧任务作为失败案例存档。
