# 同花顺问财 —— 行业研究报告智能生成系统

> 面向：项目评审 / 课程答辩
> 定位：一个能自动生成行业研究报告、并且**每个数字都可追溯**的多智能体系统

---

## 一、这个项目做什么

用户输入一个研究问题，例如：

> 「动力电池行业现在景气度怎么样？」

系统自动完成**找数据 → 分析数据 → 画图表 → 写正文 → 排版出稿**这五件事，最终交出一份完整的行业研究报告，可直接导出 Markdown、网页和 PDF。

**全过程不需要人写一句话，但每一道工序都留给人审核的机会。**

---

## 二、核心思想：为什么不直接让 AI 写一份研报

如果直接问大模型"帮我写一份动力电池研报"，它能在 30 秒内写出很像样的一篇——但里面的数字可能是编的，年份可能对不上，结论可能来自过时的记忆。**研报的价值不在于像不像，而在于能不能信。**

所以这个项目做了一件事：**把"写研报"拆成五道工序，每道工序交给一个专门的智能体，并且给每个智能体立规矩——能查证的必须查证，查不到就说查不到，绝不允许编。**

打个比方，它不是"一个万能实习生"，而是**一个五人投研团队**：

```text
调研员 → 分析师 → 制图员 → 撰稿人 → 主编
  ①        ②        ③        ④       ⑤
  └─ 每做完一道工序，交给人签字，签字后才进入下一道 ─┘
```

---

## 三、五个智能体：谁负责什么

### ① 数据获取智能体 —— 团队里的「调研员」

| | |
|---|---|
| **拿到什么** | 用户的研究问题 |
| **负责什么** | 理解问题要查哪些指标，去同花顺数据平台把数据查回来，做清洗、去重、统一单位 |
| **交出什么** | 一份**证据包**——每条数据都带着来源、时间、单位、可信等级 |
| **硬规矩** | **只查数据，不发表任何观点。** 查不到就如实报告"这个指标没查到"，绝不猜测、绝不用别的数据顶替 |

**它的难点在于"听懂人话"**：用户问「光伏逆变器国内外厂商市占率」，它要能拆出"市占率"这个指标，并知道该去哪个数据库查。系统为此准备了一张**指标对照表**（几十个常见金融指标对应到相应的数据接口），用不上 AI 的地方就走固定规则，实在听不懂的长尾问题才让 AI 帮忙判断。

**它还有三层兜底**：首选数据源查不到 → 换同类数据源再查 → 仍查不到才去公开网络检索（并明确标注这是网络来源）。**三层全失败就报告缺口，绝不编造。**

---

### ② 数据解读智能体 —— 团队里的「分析师」

| | |
|---|---|
| **拿到什么** | 调研员交来的证据包 |
| **负责什么** | 看懂这些数据说明了什么：得出核心结论、判断五个维度（竞争格局/成长性/宏观政策/产业链/风险）、推演三种情景（乐观/中性/悲观）、列出风险点 |
| **交出什么** | 一套**结构化分析结论**，以及给下一道工序的图表建议 |
| **硬规矩** | **所有算术由系统固定公式计算，模型算的数字一律作废** |

**这是整套设计里最关键的一条**：财务比率（毛利率、现金流、资产负债率、杜邦分析等）全部由代码按公式算，AI 只负责解释和引用，**没有资格自己算数**。这样就从根上杜绝了"AI 心算错误"和"AI 编一个好看的比率"。

它还挂载了 7 套分析方法（行为金融、竞争格局、产业链、机构研究、财务报表、大宗商品、宏观周期），按研究主题自动选用——**用不上的方法不会加载**，既省资源又避免干扰。每套方法都被加了限制条款，比如产业链方法不许做星级评分，大宗商品方法不许给买卖建议。

**它还会主动说"我不知道"**：数据不足时不会硬凑结论，而是明确写"证据不足以支撑该结论"，并列出还缺什么。

---

### ③ 图表生成智能体 —— 团队里的「制图员」

| | |
|---|---|
| **拿到什么** | 分析师的分析结论 + 原始证据 |
| **负责什么** | 决定该配什么图（折线/柱状/饼图/雷达/产业链图），生成图表 |
| **交出什么** | 可直接渲染的图表，每张图都标注数据来源和统计口径 |
| **硬规矩** | **没有数据就不画图**；一个数据集只画一张图（用户主动要求多图除外） |

这一道工序**优先用固定规则而不是 AI**：什么数据适合什么图，有明确的工程规则。图上的每个点都能点回原始证据。

---

### ④ 章节撰写智能体 —— 团队里的「撰稿人」

| | |
|---|---|
| **拿到什么** | 分析结论 + 图表 + 证据 |
| **负责什么** | 按**固定 7 章 21 节**的结构撰写正文，每句话带数据来源 |
| **交出什么** | 报告正文，段落级可定位到具体证据 |
| **硬规矩** | **不许写没有数据支撑的话**；数据缺失的地方必须写成"数据待补充"，不许粉饰 |

固定章节结构保证了**每份报告的质量下限一致**，不会出现某份漏掉风险章节的情况。写完后还会过一道"通顺度与客观性检查"，把空话套话、自夸表述、内部术语泄漏这些问题挑出来重写。

---

### ⑤ 报告融合智能体 —— 团队里的「主编」

| | |
|---|---|
| **拿到什么** | 前四道工序的全部产物 |
| **负责什么** | 汇总排版、把内部数据编号翻译成人能看懂的中文来源标注、生成数据质量附录、渲染导出 |
| **交出什么** | Markdown / 单文件网页 / PDF 三种成品 + 一份文件校验清单 |
| **硬规矩** | 确定性编排，不改写任何结论；如实披露本份报告的数据缺口与质量状况 |

它还会生成一份**数据质量与研究边界附录**，坦白交代：这份报告哪些数据来自权威接口、哪些来自公开网络、哪些没查到、哪些存在冲突需要人工判断。

## 四、它们是怎么协同的

```text
用户提问
   │
   ▼
┌─────────────────────────────────────────────┐
│ ① 数据获取    →  证据包（带来源/时间/单位）      │
└─────────────────────────────────────────────┘
   │  ✋ 人工审核：数据范围对不对？要补查什么？
   ▼
┌─────────────────────────────────────────────┐
│ ② 数据解读    →  结论 + 情景 + 风险 + 图表建议    │
└─────────────────────────────────────────────┘
   │  ✋ 人工审核：结论靠不靠谱？
   ▼
┌─────────────────────────────────────────────┐
│ ③ 图表生成    →  图表（每张可溯源）              │
└─────────────────────────────────────────────┘
   │  ✋ 人工审核：图表取舍与摆放
   ▼
┌─────────────────────────────────────────────┐
│ ④ 章节撰写    →  7 章 21 节正文               │
└─────────────────────────────────────────────┘
   │  ✋ 人工审核：内容是否准确
   ▼
┌─────────────────────────────────────────────┐
│ ⑤ 融合导出    →  MD / 网页 / PDF + 质量附录      │
└─────────────────────────────────────────────┘
```

**交接靠标准化契约**：每道工序的产物格式都是约定好的，任何一道工序可以单独重跑——比如改了第三章，只需要重跑第四道工序，前面的数据不用重新查。**每次修改都会生成新版本，历史版本保留不覆盖。**

## 五、人在哪里参与

系统在五个阶段之间都设有**审核门**，人可以：

- **通过** → 进入下一阶段
- **打回修改** → 说明意见后重跑该阶段（例如让调研员补查某几个指标）
- **接受风险继续** → 系统提示数据有缺口，人确认知情后带警示继续
- **取消** → 终止任务

**关键设计**：审核意见以**结构化选项**（关键词、行业范围、时间范围、想补的指标）传回系统，而不是让系统去猜一句自然语言是什么意思。

## 六、三道保险：怎么保证不乱说

| 保险 | 做法 | 效果 |
|---|---|---|
| **① 每个数字都有身份证** | 每条数据带来源、抓取时间、原始内容校验值、可信等级；报告里每个数值段落都能点回原始证据 | 任何数字都能倒查到出处 |
| **② 能算的交给代码** | 财务比率全部由固定公式计算，AI 算的一律作废；单位不一致拒绝合并；分母为零直接报"无法计算" | 杜绝心算错误与编造比率 |
| **③ 缺口坦白，冲突保留** | 查不到就写"没查到"；同一指标出现不同数值时**全部保留**并标为冲突，交人工判断，绝不悄悄选一个 | 不掩盖问题，不假装确定 |

**一句话概括这套设计哲学：宁可少给，绝不给错。**

## 七、实际效果

系统已用真实数据源和真实大模型跑通全链路：

- 典型研究问题从提问到成稿，产出**完整 7 章 21 节**报告
- 最优案例中，正文里**每一个数值段落都带上了数据来源**（溯源率满分）
- 遇到数据缺失时，系统如实披露"未获取该数据"而不是硬凑——例如用户问主营业务构成但只有整体财务数据时，报告明确说明无法拆分，**不编造拆分比例**

## 八、一个值得单独讲的设计：录制回放

### 先说难点：AI 系统要怎么测试？

普通软件有个天然优势——**同样的输入，永远得到同样的输出**，所以测试可以反复跑、随时回归。

AI 系统没有这个优势，麻烦有三层：

1. **每次调用都要花钱**。数据接口按次计费，模型按字数计费，联网搜索按次计费。
2. **改一次代码就要回归一次**。这个系统有上百条评测用例，为了验证稳定性同一条还要跑多次——调用量是指数级放大的。
3. **不能把付费密钥发给每个测试同学**。这是安全红线，供应商的密钥一旦外泄就是真金白银的损失。

如果不解决这三个问题，项目就只能"跑一次看一次"，根本谈不上工程化。

### 解法：第一次真实调用，之后放「录像」

```text
录制模式（第一次，真实花钱）
    真实调用接口 / 模型  →  把返回内容按「请求指纹」存成本地文件
                                    ↓
回放模式（之后所有测试，零成本）
    同样的请求  →  直接读本地文件  →  零网络、零费用、零等待
```

**请求指纹 = 请求内容本身的哈希值**。这个设计很关键：只要请求里任何东西变了——模型换了、提示词改了、查询词不一样了——指纹就变，旧录像自动失效、重新录制。**所以它绝不会拿着过期的假录像糊弄测试。**

### 三条铁律，保证它不会"偷偷花钱"

| 铁律 | 说明 |
|---|---|
| **未命中绝不偷跑网络** | 找不到对应录像时直接报"快照缺失"并停止，**绝不静默去调真实接口**——否则省钱机制就形同虚设 |
| **额度用完自动熔断** | 一旦触发额度上限，整个批次立即停止，不再产生任何付费调用 |
| **三类来源分开存放** | 数据接口、模型、联网搜索各自独立归档，互不混淆，便于单独清理和核对 |

### 实际省了多少（可核验）

- 目前已固化 **902 份真实响应**（数据接口 725 份 + 模型 177 份）
- **一次全量回归，相当于省下约 900 次真实调用**
- **时间上更可观**：模型单次真实响应实测需要 170–260 秒，仅已录制的模型调用就相当于省下**约 8–13 小时的等待**；而回放是本地读文件，几乎瞬间完成
- **测试同学不需要拿到任何付费密钥**，拉下代码就能跑完整评测

### 附带收获：还能批量制造"故障场景"

录制的是正常响应，但回放时可以人为往里注入故障——模拟接口限流、响应超时、内容被截断、字段丢失、数据顺序被打乱，用来检验系统在这些异常下会不会崩溃、会不会编数据。

这些场景在真实环境里**几乎不可能稳定复现**（你没法让接口正好在你测试时挂掉），录制回放却把它们变成了可以反复验证的常规用例。

> 也正因为有这 900 多份真实响应在反复跑，前面说的"三道保险"才不是一句口号——**每一次回归测试，都在重新验证一遍「这个系统到底会不会编数据」。**

## 九、这个项目的特别之处

1. **不是提示词工程，是系统工程**。把研报生产拆成五道可独立验证、可单独重跑的工序，而不是靠一个"万能提示词"。

2. **把 AI 关进笼子里用**。AI 只做它需要做的事（理解语言、组织文字），不该它做的事（运算、选值、编造）被代码和规则剥夺了权力。

3. **可追溯优先于好看**。系统宁可交出一份"这里没查到"的报告，也不交出一份漂亮但数字可疑的报告。

4. **人始终在场**。五个审核门保证了 AI 是助手而不是替代品，最终判断权在人手里。

---

*技术栈：Vue 3 + FastAPI + LangGraph 多智能体工作流；数据源为同花顺问财数据接口，公开网络检索作为最后兜底。*
