# 联网搜索兜底方案调研与选型

- 日期：2026-09-04
- 目标：当用户问句在**同花顺技能（hithink-\*/news/report/announcement）查不到数据**时，自动触发联网检索，抓取整理后作为**补充**回答，而不是留一个空洞的"未查到"。
- 结论一句话：**双层兜底**——一级先用同花顺自家 `/v1/comprehensive/search` 扩通道（零新增 Key、零新增依赖），二级接**博查 Web Search API**（国内、中文、合规、3.6 元/千次）；涉海外主题时再用 Tavily 作第三级。

### 本文在整体方案中的位置（务必先读）

团队 2026-09-04 已交付 **`docs/plans/2026-09-04-doc-channel-fallback.md`**（文档通道降级链），它把取数链定为四级：

```
① 结构化技能（business/finance/industry…）
   ↓ 空返回 / 字段不符
② 文档通道降级：report_search / announcement_search   ← 已在做（不新增数据源）
   ↓ 仍无可用证据
③ 判为数据缺口，写进「研究边界」，绝不补造数值（现有行为，保持）
   ↓ 可选：用户显式要求，或纯定性缺口
④ 通用网页搜索兜底  ← 本文
```

**本文只负责第 ④ 级**，与 ② 不重叠、不替代。且 ② 的 ROI 显著更高（数据就在自家文档库里，零成本零合规风险），**建议先落地 ②，再评估 ④**。

术语与 ② 保持完全一致（不要另起一套）：

| 沿用字段 | 含义 |
|---|---|
| `evidence_tier` | `structured` > `document` > **`web_unverified`**（本文产物恒为 `web_unverified`，单向可降不可升） |
| `qualitative_only` | 本文产物**恒为 True**（见 §5.3 红线） |
| `source_locator` / `retrieved_at` / `source_org` | 必带，缺一不可 |
| `substitute_for` | 被替代的主任务指标名（第 ④ 级同样要带） |
- 本文所有方案政策均于 **2026-09-03/04 实测检索**核实，来源见 §9。

## 0. 先说结论（大白话版）

**现在的毛病**：用户问"某某公司最新的产能利用率"，同花顺技能返回空（或者接口报错），Agent 1 记一个 `DataGap` 就完事了，报告里这一块是空的。而这类"查不到"里，有相当一部分其实**公开网页上有**（新闻、研报摘要、公司公告转载、行业媒体），只是不在问财的结构化库里。

**要做的**：问财查不到 → 自动去网上搜一把 → 把搜到的内容整理成"补充材料"，**明确标注来源和"非同花顺结构化数据"**，塞进报告。

**推荐怎么接**：
1. **先问财自己再捞一次**（换更宽的通道），不花钱、不加依赖——很多问题到这步就解决了。
2. **还空 → 联网搜**（博查，国内中文源为主）。一次就够，不重试，超时就放弃，仍保留"数据缺口"记录。
3. 搜回来的内容**只当补充证据**，绝不当成金融指标填进表格——它是文本，不是口径一致的结构化数据。

**成本**：免费额度（博查 1000 次 / Tavily 1000 credits 每月）足够跑通和试用；正式上量后博查约 **3.6 元 / 1000 次**，一次报告就算触发 10 次兜底也才几分钱。

## 1. 项目现状：同花顺技能怎么调、查不到时长啥样

### 1.1 调用链路（代码位置）

```
Agent 1 Service
  └─ RetrievalExecutor.execute()            backend/app/agents/data_fetcher/executor.py:32
       └─ _execute_task(task)               executor.py:87
            └─ ToolGateway.execute(ToolCall)  backend/app/runtime/tool_gateway.py:140
                 └─ SkillHubClient.execute(skill_name, args)   integrations/skillhub/protocol.py
                      └─ 实际 HTTP：
                         · 12 个 hithink-*  → POST https://openapi.iwencai.com/v1/query2data
                         · news/report/announcement → POST https://openapi.iwencai.com/v1/comprehensive/search
```

技能注册表：`backend/app/integrations/skillhub/catalog.py:18-69`（15 个 SkillName，`endpoint` 分三类：`query2data` / `search` / `composite`）。
注册入口：`registry.py:23-38 create_skillhub_gateway()` —— 遍历 catalog，给每个技能建一个 `ToolDefinition`，**所有技能共用同一个 `SkillQueryArgs` 参数模型和同一个 client 协议**。

> 这条很关键：新增一个联网搜索能力，只要实现同一个 `SkillHubClient.execute()` 协议 + 在 catalog 加一行，就能被现有执行器、超时、预算、遥测完全接管，**不用改 executor 的并发/预算逻辑**。

### 1.2 参数与返回结构

- 请求（`SkillQueryArgs`，由 executor 构造，`executor.py:101-111`）：`{query, page, limit, call_type}`；`call_type` 为 `normal`/`retry`。
- 返回（`SkillPayload`，`schemas/acquisition.py:279-290`）：
  `skill_name / query / rows(list[dict], ≤5000) / total_count / page / trace_id / raw_sha256 / source_name / source_locator`
- 网关侧原始返回（`query2data`）：`{datas: [...], code_count, chunks_info}`；默认 10 条，`code_count > len(datas)` 时需翻页（SKILL.md §响应参数）。

### 1.3 "查不到数据"的四种具体表现

`executor.py:139` 把结果归成三种状态：`succeeded` / `empty` / `failed`，并在 `:155-168` 生成 `DataGap`。

| 现象 | 触发路径 | `status` | `DataGap.reason_code` | 是否可重试 |
|---|---|---|---|---|
| **① 空结果**：HTTP 200 但 `datas: []` | CLI 输出 `success:true` + `empty_data_tip`，`rows=0` | `empty` | `empty_result` | 否（问财侧已放宽重试 2 次） |
| **② 网关报错**：额度不足/次数超限/鉴权失败（响应里没有 `datas` 字段） | CLI 打印原始 JSON 并 `exit 1` → handler 异常 | `failed` | `tool_execution_failed` | 看网关返回 |
| **③ 超时/网络错误** | `tool_gateway.py:183` `asyncio.timeout` 触发 | `failed` | `tool_timeout` | **是**（`retryable=True`） |
| **④ 返回结构不合法** | `SkillPayload.model_validate` 失败 | `failed` | `invalid_tool_payload` | 否 |

补充：ToolGateway 还会产生 `tool_not_found` / `tool_arguments_invalid` / `tool_call_blocked`（被护栏拦截）/ `*_hook_failed`（`tool_gateway.py:152/159/171/184/188`）。

### 1.4 现有降级机制与缺口

- **已有**：`SkillQueryTask.fallback_queries`（最多 2 条放宽问句，`acquisition.py:88`），executor 会依次尝试 `executor.py:94-96`；分页 `max_pages ≤ 5`（`acquisition.py:89`）。
- **缺口**：所有兜底都在**问财域内**（同一个数据源、同一套索引）。问财库里没有的东西，放宽问句也还是没有。→ **缺一层"跨域/全网"兜底**。
- **最佳挂载点**：`executor.py:155-168` 生成 `DataGap` 之后 —— 这里已经知道"哪个任务、哪个技能、什么原因没查到"，天然是触发联网检索的位置，且不影响成功路径的任何行为。

## 2. 候选方案（4 个）

### 方案 A｜同花顺自有 `/v1/comprehensive/search` 扩通道（改造成本最低）

- **是什么**：项目里 3 个检索类技能已在用同一端点，差别只在 body 里的 `channels` 数组：`["news"]` / `["report"]` / `["announcement"]`（见各技能 `references/api.md:21`，标注为 *Fixed value*，但类型本身是 list）。
- **怎么用做兜底**：把已注册通道**组合查询**（例如一次请求传多通道），或向问财官方确认是否存在"网页/全网"通道值。
- 优点：**零新增 Key**（复用 `IWENCAI_API_KEY`）、零新增依赖、零采购流程、返回结构与现有 `SkillPayload` 天然一致、合规口径与报告主体同源。
- 局限：只覆盖问财已收录内容；是否有"全网网页"通道**待官方确认**（这是本方案的最大不确定性）。

### 方案 B｜博查 Web Search API（国内首选）

- 国内厂商，多模态混合搜索 + 语义排序，**面向 AI 应用设计**，返回 `snippet` + `summary`（可 `summary:true` 开启）。
- 关键参数：`query`、`count`、`freshness`（`oneDay`/`oneWeek`/`oneMonth`/`oneYear`/`noLimit`）、`summary`。
- 免费：新用户 **1000 次**调用资源包；付费约 **3.6 元/1000 次**（标准包 1000 次 ¥36 起的大包更便宜）。
- 数据在国内服务器处理，合规风险低；已作为插件接入 Coze / Dify 等平台。
- 来源：`https://open.bochaai.com/`（官方站点与 API 示例）。

### 方案 C｜Tavily Search API（海外/英文主题与生态首选）

- 面向 LLM Agent 的搜索 API，一次调用返回**排序结果 + AI 摘要**（`include_answer`），可选 `include_raw_content` 拿正文，`include_domains`/`exclude_domains` **可限定财经站点**（这点对本项目很有用）。
- 免费：**1000 credits/月，无需信用卡**；basic 搜索 1 credit / advanced 2 credits；超出后 $0.008/credit（约 ¥0.058/次）；约 10 req/s。
- 生态最好：LangChain / LlamaIndex / CrewAI 官方集成，本项目若后续引入 agent 框架几乎零适配。
- 局限：索引以英文/国际源为主，**中文财经覆盖弱于博查**；数据出境，面向国内客户交付时需评估合规。
- 来源：`https://docs.tavily.com/documentation/api-credits`、`https://tavily.com/`（2026-07 第三方复核一致）。

### 方案 D｜SearXNG 自托管（免 Key、无限流，但要自己养）

- 开源元搜索引擎，Docker 一键起，聚合 70+ 引擎，**无 API Key、无按次计费**。
- 需在 `settings.yml` 的 `search.formats` 里加 `json` 才开放 JSON API（默认关闭）；自带 limiter 会拦自动化请求，需 `limiter:false` 或配 `pass_ip`（对内网自用实例最简单）。
- 可按需 `keep_only` 白名单引擎，理论上能对中文/财经源做定制。
- 代价：要运维（容器、Redis、升级）；上游引擎反爬/验证码会导致**间歇性空结果**（生产 agent 跑一段时间必然遇到）；结果质量不如商业 API 稳定。
- 来源：SearXNG 官方 admin 文档 + 2026 年多篇自建实践（perlod.com、ssdnodes.com 等）。

### 顺带排除（2026 年现状，别踩坑）

| 方案 | 现状 | 结论 |
|---|---|---|
| **Deepseek 联网搜索（红狐中转）** | 团队 9-04 已评估否决：提交+轮询最坏 **5 分钟**（阻塞式）、只返回 AI 总结文本（无 url 时间戳/站点名/原始条目）、非官方第三方中转（redfox.hk）、无时间/域名/条数参数 | ❌ 不选（与 `doc-channel-fallback` 方案结论一致） |
| **Bing Web Search API** | 微软已于 **2025-08 在 Azure 上退役独立 Bing Search API**，转向 Azure AI Agent / Grounding with Bing，独立开发者成本大幅上升 | ❌ 不选 |
| **Brave Search API** | **2026-02 起新用户免费档下线**（旧 Data-for-Free 2000 次/月仅限存量），新用户为 $5/月额度、需绑卡、超额自动扣费 | ⚠️ 不作首选 |
| **Exa** | 免费档 2026-02 退役，改为一次性 $10 额度 | ⚠️ 特殊场景（相似语义检索）再考虑 |
| **Serper / SerpAPI** | Serper 2500 次免费、$1/1k，SERP 抓取型；但**只有 Google**、只有 snippet、中文财经覆盖差，且是抓取代理模式 | ➖ 备选，非金融场景可用 |

## 4. 首选推荐

**采用「L0 → L2 → L3」三层兜底**，而不是二选一：

| 层级 | 方案 | 什么时候触发 | 为什么 |
|---|---|---|---|
| **L0** | **文档通道降级**（`report_search`/`announcement_search`/`news_search`） | 结构化技能空返回时 | **已有方案在做**（`doc-channel-fallback`），零新增数据源、零采购、零合规风险，**优先落地它** |
| **L1** | 问财 `/v1/comprehensive/search` **多通道组合查询** | L0 之上 | ⚠️ 与 L0 高度重合——L0 落地后它只是一次请求传多个 `channels` 的小优化，**不单列为兜底层**，别重复建设 |
| **L2** | 博查 Web Search | L0 仍空、且为**中文/国内**主题 | 中文财经覆盖好、有摘要可直接用、单价最低、国内合规 |
| **L3** | Tavily | 主题明显涉海外/英文（如"美股 XX 公司""全球锂价"） | 国际源与 LLM 生态最好；可用 `include_domains` 锁财经站点 |

**SearXNG（D）建议先不做**：免 Key 的诱惑大，但它把"搜索质量的坑"换成"运维和反爬的坑"，生产上间歇性空结果比付费 API 更难排查。等日均兜底调用超过几千次、成本真正成为瓶颈时再评估。

**PoC 建议**：先用博查免费 1000 次 + Tavily 免费 1000 credits，两周内跑通链路并统计真实触发率，再决定采购量。

## 5. 降级触发与结果处理（重点）

### 5.1 什么时候算"空结果"、要不要触发

对 `executor.py` 里产生的四种状态区别对待，**不是所有失败都该去联网搜**：

| 状态 / `reason_code` | 处置 |
|---|---|
| `empty` / `empty_result` | ✅ **触发兜底**（真正的"库里没有"） |
| `failed` + `invalid_tool_payload`、`tool_arguments_invalid`、`tool_not_found` | ✅ 触发兜底，但要**记异常日志**（可能是接口变更，属故障信号） |
| `failed` + `tool_timeout` / `tool_execution_failed`（`retryable=True`） | ⚠️ **先重试问财 1 次**，仍失败才触发兜底（网络抖动不该烧额度） |
| `tool_call_blocked`（护栏拦截） | ❌ **不触发**（绕过护栏=安全事件） |

额外约束：
- **每个 task 最多 1 次联网调用**（不重试，避免额度翻倍与延迟叠加）。
- **单次运行总量上限**（建议 ≤ 20 次），超出后只记 DataGap，不再兜底——防止一次异常运行烧光月度额度。
- **硬超时 8 秒**（走 `ToolGateway` 的 `policy.tool_timeout_seconds`，复用现有机制）；超时即判兜底失败。

### 5.2 检索结果怎么进现有契约（别伪造 SkillPayload）

`SkillPayload` 里的 `trace_id`（问财网关 64 位追踪 ID）和 `raw_sha256`（网关原始响应摘要）**是问财网关的语义**，联网结果没有这些东西，**不要硬造假值去塞进 `SkillPayload`**（会让产物溯源失效，也会破坏 sha256 可复现性）。

建议新增一个平级结构（例如 `WebSearchHit` / `WebEvidence`），字段至少包含：

| 字段 | 说明 |
|---|---|
| `gap_id` | 关联到触发它的 `DataGap.gap_id`（`GAP-xxx`） |
| `task_id` / `skill_name` | 来自哪个任务和技能 |
| `provider` | `bocha` / `tavily` / `iwencai-web` |
| `query` | 实际送出去的检索问句（改写后） |
| `title` / `url` / `site_name` | 来源标识 |
| `snippet` / `summary` | 正文摘要（用于后续整理） |
| `published_at` | 发布时间（用于时效性判断与展示） |
| `retrieved_at` | 抓取时间 |
| `source_org` | 发布机构/站点主体（沿用 ② 的字段名） |
| `raw_sha256` | 对**本次响应原文**取摘要（保留可复现性） |
| `evidence_tier` | 恒为 `"web_unverified"`（与 ② 同一套枚举） |
| `qualitative_only` | 恒为 `True` |
| `substitute_for` | 被替代的主任务指标名（如"产能利用率"） |

### 5.3 来源标注（必须做，否则后患无穷）

- 证据层打标：`evidence_tier = "web_unverified"` + `qualitative_only = True`（与 ② 完全同一套字段，不新增第二套标签体系）；`source_org` 用站点/机构名，`source_locator` 用原文 URL，`retrieved_at` 必带。
- **层级低于 document**：排序为 `structured > document > web_unverified`，单向可降不可升——联网内容**永远不能**升级成结构化证据。
- **只补定性**：不得进入"指标表格的数值列"，不得作为 KPI 卡片数字（那是研报的门面，错了就是事故）。允许用途：佐证性描述、定性判断、事件时间线、补充说明、趋势方向。
- 报告呈现：在章节脚注或来源表加一行 **"补充来源（联网检索，非同花顺结构化数据）"**；HTML/PDF 里可加淡色标识块。
- 若后续要做引用编号，复用现有 `〔来源N〕` 体系，但样式上区分（例如加"网"字标）。

### 5.4 缓存策略

| 项 | 建议 |
|---|---|
| 缓存键 | `sha256(规范化query + provider + channel/freshness窗口)`；query 规范化：去空格/标点、繁简统一、实体别名归一（可复用 Agent 1 现有别名表） |
| TTL 分级 | 行情/新闻类 **30 分钟**；政策/公告类 **6 小时**；研报观点 **24 小时**；百科/静态资料 **7 天** |
| 命中即不计费 | 缓存命中不消耗 provider 额度，也不计入单次运行上限 |
| 存储 | 复用现有快照/产物目录风格（如 `eval/cache/...` 的内容寻址思路），落 JSON + 原始响应，便于回放与审计 |
| 负面缓存 | 某 query 明确无结果，也缓存 **10 分钟**，避免同一运行内重复烧额度 |

### 5.5 额度治理与熔断

- 记录每次调用到遥测（复用 P0-5 埋点体系），按日/月统计 provider 用量。
- 月度免费额度用掉 **80%** → 告警；**100%** → 自动降级为"仅 P0 任务可兜底"，其余只记 DataGap。
- 免费额度耗尽时的兜底顺序退化为：**A（问财）→ 无**，不允许静默失败也不允许超额扣费。

## 6. 接入步骤要点

**前置依赖**：`docs/plans/2026-09-04-doc-channel-fallback.md`（L0 文档通道降级）落地并测得"降级挽救率"之后再启动本文工作。理由：L0 若能把大部分缺口补上，第 ④ 级的触发率会很低，先做 L0 能避免为一个低触发场景付出采购与合规成本。**顺序建议：先四刀路由修复 → 再 L0 降级 → 最后评估 ④。**

**P0｜能力注册（1-2 天，纯新增不改存量）**
1. `schemas/acquisition.py`：`SkillName` 枚举新增 `WEB_SEARCH`（注意：`SkillPayload.skill_name` 是枚举类型，必须同步，否则校验不过）。
2. `integrations/skillhub/catalog.py`：加一行 `SkillSpec(..., endpoint="web_search")`（`endpoint` 的 Literal 需扩一位）。
3. 新增 `WebSearchClient`：实现 `SkillHubClient` 协议（`provider_mode` + `async execute(skill_name, args)`），内部按 `provider` 路由到博查/Tavily；**HTTP 复用现有客户端，不引入新依赖**（技能侧风格是标准库优先）。
4. `registry.py`：与现有技能一起注册进 `create_skillhub_gateway()` → 自动获得超时、预算、hooks、遥测。

**P1｜执行层挂载（2-3 天）**
5. `executor.py:_execute_task()`：在生成 `DataGap` 后、`return` 前插入兜底分支，严格按 §5.1 的状态白名单判定。
6. 契约：新增 `WebSearchHit`（或等价结构），关联 `gap_id`；**不动** `SkillPayload` 与 `DataGap` 的既有字段。
7. `DataGap.blocking` 保持 `False`（现状语义：单次失败不阻断整体）——联网补充同样不阻断。

**P2｜治理（1-2 天）**
8. 缓存层 + 额度计数器 + 硬超时（8s）+ 单次运行上限。
9. 遥测：`provider / 命中缓存 / 耗时 / 是否成功 / 触发 reason_code`。

**P3｜呈现（1 天，需与 Agent 5 报告层对齐）**
10. 证据与报告层：`source_type="web_supplement"` 的展示样式（脚注/来源表/淡色块），并确保**不进入指标数值列**。

## 8. 风险与待确认

| # | 事项 | 说明 |
|---|---|---|
| R1 | **问财是否有"网页/全网" channel** | 决定方案 A 的上限，需向问财官方确认（现有 `channels` 是 list 类型，multi-channel 组合查询可先试） |

| R4 | 延迟 | 联网 1-2s，串在兜底路径上；必须硬超时 + 单次 1 次，避免拖慢整条 pipeline |
| R5 | 额度 | 免费额度仅供 PoC；上量前确定采购与告警阈值 |
| R6 | 反爬与稳定性 | 商业 API 由厂商承担；若走 SearXNG 则风险自负（这也是不选 D 的主因） |
