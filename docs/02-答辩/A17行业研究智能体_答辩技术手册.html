00

先记住这六句话

答辩场上，先把结构讲对，再讲细节。

如果评委只给你三分钟，就按下面六句话讲。每一句后面都对应本手册的一章，被追问时再展开。

01
它是一台「研报产线」，不是五个聊天机器人

输入是一个行业和几个关注问题，输出是一份带证据目录、可导出 Markdown / HTML / PDF 的行业研究报告。五个智能体是五道工序，不是五个各聊各的助手。

02
工序之间只认「文件契约」

A1 产出 dataset.json，A2 只读它；A2 产出 interpretation_report.json，A3 只读它。每一份 JSON 都有 Pydantic 模型和跨字段校验，格式不对就进不了下一道工序。

03
每个数字都有「身份证」

从问财返回的每条记录开始就有 record_id；它一路穿过解读、图表、正文，最后进入交付证据目录。报告里任何一个数字，都能沿这条线回到原始记录。

04
模型只做三件事：理解、归纳、表达

算同比、判异常、查冲突、比单位、核数字，全部由确定性代码做。模型负责把问题拆成查询、把证据归纳成洞察、把洞察写成句子——它不被允许自己算数。

05
出错不靠「相信模型」，靠门禁

契约校验、风险清单、人工审批、版本回滚、2829 项测试，层层设卡。系统宁可交一份「零图 + 原因」的降级稿，也不交一份看起来完整、但数字对不上的稿子。

06
所以它是可复现、可追责的

每次执行在私有工作区，发布要过三重 CAS 校验；谁批的、批的哪一版、接受了哪些风险，都写进不可变的决策包。同一个输入重跑，数字一致，只有措辞可能不同。

三分钟口述稿（可直接背）

口述 我们这个系统解决的是「让大模型写一份能交付的行业研究报告」。难点不在写，而在三件事：数据从哪来、数字可不可信、出错怎么发现。 我们的做法是把一份研报拆成五道工序：取数、解读、画图、写作、融合交付，每道工序的输入输出都是强类型 JSON。 模型只在三道工序里做「理解、归纳、表达」，所有计算、校验、判定都由确定性代码完成。 每个数字从数据源开始就带唯一 ID，一路传到最终报告的脚注；任何一个环节引用了不存在的证据，契约校验会直接让这一阶段失败。 再往外还有一层编排：每个阶段可以停下来人工审，审批要带版本号和风险快照哈希，产物用「私有工作区 + 版本目录 + 原子指针」发布，改一次就多一个版本，历史永远可查。 所以它不是「让 AI 写得像真的」，而是「让每个数字都能回查、每个错误都能拦住」。

一张图看懂整个系统

先建立空间感：谁在调度、谁在执行、产物放在哪。

先看全图。左边是用户，中间是编排层，右边是五个智能体；上面一排是它们共享的外部能力，下面一排是产物与交付。

为什么这件事难：三个坑

数据坑

数据源是自然语言接口，同一指标多种叫法、多种单位、多个来源。问财一次问太多会截断，问太少又覆盖不全。

生成坑

大模型最擅长把不存在的数字写得像真的。研报里一个数量级错误，比整篇写得平淡严重得多。

交付坑

研报有格式、有引用、有口径要求；还要能停下来给人审、能回滚、能解释「这一版为什么可信」。

对应的三个设计答案

坑设计答案落在哪个智能体
数据坑分层取数 + 需求即验收：先把用户问题拆成一条条「可验收的指标需求」，再按「确权选股 → 实体财务 → 缺口补采」三层查询，每条需求逐字段核对是否真的被证据满足。A1 数据获取

02

用五层反演链读这个项目

把「我们做了什么」翻译成「系统被哪些规格约束着」。

这份手册的整理方法，来自随附文档《提示词逆向工程》。它把一个已经跑起来的 LLM 项目，从「成品」往回收敛成五层规格。用这套镜头看我们的系统，每个智能体都变得可解释、可验收。

为什么 L2 是价值中心

一个声称「能写研报」的系统，在编造数据时同样满足这句话。真正定义系统的，是它的拒绝面：什么输入会被拦、什么输出会被改写、什么情况下宁可交残缺稿也不交假稿。功能描述对生成式系统几乎没有约束力，约束才是语义。

这和类型系统是一个道理：函数的类型签名约束了它能接受什么、返回什么，比函数体里的注释信息量更大。反演里的约束层，就是给系统补一份「语义类型」。

本项目的三层约束，恰好就是文档里的三个真实事故

事故（文档编号）由此产生的规则 → 在本项目里的落点
「百万元」被当成「万元」，金额差 100 倍（P-01）以元为基准的完整单位倍率表，整词匹配；单位来源不明的金额不得参与比率计算。
落点：financial_semantics.py 的真值表；unit_provenance=unknown 的记录退出量化覆盖
写作环节自行计算比率，分母口径与上游不一致（P-10）比率只许引用上游已核验值；缺同口径分母时改写为固定缺口句，禁止自行相除。
落点：A4 的净现比守卫 net_cash_ratio.py；缺分母时整句改写为「无法计算」
输入检查通过，但编辑嵌图后终稿已变，仍按旧结论放行（S-05）交付判定必须针对最终导出对象复检；声明就绪但未进入终稿的图一律阻断。
落点：A5 交付审计 + 阶段契约「ready 必须有渲染体」+ 下载门禁按 built_at_revision 判代次
答辩时这么说 这三条不是我们「设计得很周到」，每一条背后都有一次真实翻车：单位错了 100 倍、比率自己算错、改完稿子忘了复检。我们把事故压成一句禁止条款，再把条款写成一条测试。没有事故来源的规则，我们只当建议，不进硬规格——否则复刻出来的系统会比原系统更保守，正常输出被误杀。

三个层次的名字，别混用

工程层：提示词逆向工程

从已交付产物反推「重新生成它需要哪些提示词与规格」。回答的是「怎么复刻」。

方法论层：规格反演

从可观察行为反推隐含遵守的规格。和传统的「规格挖掘」相比，我们反推的主体是约束，不是功能正确性。

知识层：默会知识显性化

专家「看一眼就知道不对」的判断，写成别人能照着执行的条文。业务岗是这类知识的唯一供给方。

L3：三段提示词，不是三段话

我们的五个 system prompt 都不短，最长的 A2 语义提示词有几千字。长不是目的，可判定才是：每一条都要么约束一个字段，要么约束一个动作，要么约束一句失败时该说的话。写不成「给定输入 → 必须出现的行为」的条款，会被降级成建议，甚至删掉。

L4：把约束变成门禁

本项目的门禁分两种。一种是阶段契约：每份主产物写出后，立刻用它自己的 Pydantic 模型重新解析，再跑跨字段检查（图表 ready 必须有渲染体、报告不能引用未登记证据）。另一种是测试：2547 个测试函数，按事故编号命名，改一条规则就必须有一条测试跟着改。

常见追问 「你们是不是先有代码，再补文档？」——不是。这份手册是事后反演，但代码里的约束本来就是从事故里长出来的：提示词里大量「实测反面案例」的注释就是证据。反演只是把散落在代码、注释、缺陷记录里的规格重新收集起来，让它能被别人读懂、被另一个执行体复刻。
03

一次研究是怎么跑完的

五道工序、一个状态机、一套版本协议。

这一章讲「一次研究任务从创建到交付，中间到底发生了什么」。先把流水线讲清楚，再讲编排层怎么保证它不出错。

每一阶段的输入、输出与门禁

阶段主要输入主产物这一阶段真正在解决的问题
A1 取数主题、关注问题、截止日、深度、技能选择dataset.json：七域记录、来源、冲突、需求覆盖矩阵把自然语言问题变成可验收的取数任务，并证明「每条需求到底满足了没有」
A2 解读dataset.json + 指标需求interpretation_report.json：指标、趋势、异常、跨源验证、洞察把「一堆记录」变成「可被引用的结论」，并且每条结论都挂证据
A3 图表A2 报告 + 数据集 + 图表策略chart_result.json + charts/把证据编译成图，并保证每个数据点都能回查
A4 写作A2 证据、A3 图表、7 章 21 节大纲chapter_result.json：章节、段落、组件、质量把证据写成有判断的正文，且每个数字都有出处
A5 交付A4 只读稿 + A2/A3 产物report_view.json + md/html/pdf + 一致性报告全局一致性、编辑审计、导出与交付门禁

编排层：状态机而不是脚本

用脚本串五个函数也能跑通，但脚本回答不了三个问题：现在跑到哪、为什么停、能不能从中间接着跑。状态机把每个阶段变成 StageResult，落盘到 workflow_state.json；服务重启后，编排层能从磁盘恢复到正确位置。

人工门禁的唯一开关是创建任务时的 review_stages。默认五个阶段都可审；传空数组就是全自动。关键设计是：自动通过也要写决策包，和人工审批共用同一套校验——所以「系统放行」同样留痕，同样能被硬阻塞拦住。

一次阶段执行的十二步

  1. 记下当前 revision 作为 CAS 基准，把阶段置为 running。
  2. 建私有工作区 .stage_workspaces/<stage>-<attempt>，把当前产物树整棵复制进去。
  3. 写 stage_input.json：输入版本、指针哈希、输入文件哈希、产物清单。
  4. 把工作区设为「当前可见产物目录」，此后 Agent 读写的都是副本。
  5. 调用适配器执行对应 Agent，写出主 JSON，立刻做契约校验。
  6. 图表阶段若提出补采需求，挂起发布，交给补采协调器。
  7. 进入 run 级互斥锁，重新读取最新状态。
  8. 三道丢弃守卫：状态没了 / 已取消 / revision 变了 → 丢弃本次结果。
  9. 生成决策包，评估阶段能否推进（硬阻塞？质量不过？）。
  10. 不能推进 → 标记 waiting_review 或 failed，丢弃工作区。
  11. 能推进 → 自动决策或等待人工；写状态，CAS 发布产物。
  12. 出锁，递归执行下一阶段（锁外递归，避免长任务一直占锁）。
为什么不能直接写 artifacts/ 读者会看到半成品；无法自证基于哪一版输入；并发的两个结果会互相覆盖；改一次就毁掉历史证据。私有工作区 + 版本目录 + 原子指针，把「发布」变成一次可验证的切换，而不是一次覆盖。

审核与风险：不是点一下「通过」

每次阶段结果写回状态前，都会生成一个不可变决策包，记录：run_id / stage / revision / decision_id / risk_snapshot_sha256 / blocking_risk_codes / acknowledgement_required_codes。审批请求必须携带当前 expected_revision、decision_id 与风险快照哈希；三者任一过期，返回冲突且不写决策。

风险类型含义能不能批
硬阻塞 blocking阶段硬失败、交付质量不过、数据为空不能。即使选「接受风险」也拒绝
需确认 acknowledgement已知限制，例如部分维度未覆盖可以，但必须用「接受风险」动作，且提交的风险码集合要完全一致
普通提示只是展示，不阻断正常批准即可

暂停、恢复、取消、回退

恢复不是「从断点重跑」

resume_run 会先校验上游产物的契约是否仍然成立，再检查上游有没有硬阻塞；文件在但内容无效，会前溯到更早的阶段重跑。

失效分两种粒度

直接编辑只把下游标成 pending 并保留旧内容（downstream_stale）；补采/重跑会清空下游数据和产物，并给 A5 打 exports_stale。

取消之后旧结果不能回写

提交段会检查状态是否已 cancelled；取消时也会 task.cancel() 并等待收尾，所以不会出现「取消了又被写回 running」。

版本回退不等于改历史

恢复历史版本会新开一棵版本树，旧版本字节仍在 artifact_revisions/ 里，随时可以再对比。

A1 数据获取：把问题变成可验收的取数任务

从一句人话，到一张带证据的需求覆盖矩阵。

如果只记一句A1 不是「搜数据的」，它是「把一句人话拆成一张验收单，再拿证据一条条打勾」。

三个真正决定质量的设计

1. 分层查询，不一次性问完

问财底层是自然语言解析器。一句话里塞七个领域、或者多家公司并列，结果不是「多返回几条」，而是词槽冲突、0 召回、只返 1 家。所以规划器被强制按层来：第一层「确权定界」——用最干净的语法锁定这个赛道到底有哪些公司、谁是龙头；第二层「实体锚定」——对已入池的公司逐一做估值和财务；第三层「缺口补采」——只针对验收没过的需求。

大白话先问「这个行业到底有谁」，再问「这几个人赚了多少钱」，最后才问「刚才漏掉的那项指标是多少」。顺序反了，问财会把你问糊涂。

2. 需求即验收：每条指标都带一张「验收单」

用户问「近三年市场规模」，模型要把它变成一条结构化需求：指标同义词、时间范围、最少记录数、是否必须有报告期。代码不判断「模型说得对不对」，只负责数数：逐条核对实体、期间、指标词、数值可解析、单位来源、是否在截止日之后、是否与另一来源冲突。全部通过才叫 passed。

这张验收单同时是「反喂」的燃料：没通过的需求、被拒证据的原因，会一起进入下一轮规划上下文。所以它不是事后打分，而是驱动下一轮取数。

3. 冲突保留，单位先归一

同一个指标两个来源数值不同，系统不替你选一个。它按「实体 + 指标 + 期间 + 单位/口径/币种」分组，财务冲突记录不能用于满足需求，冲突原值全部保留；只有价量类的 ±0.5% 才当噪声。金额统一折算到元，单位来源不明的记录直接退出量化覆盖——因为「百万元当成万元」这种错，会差 100 倍。

三个追问

LLM 会不会在 A1 里编数据？
不会。A1 里的模型只输出「任务清单」：选哪个技能、query 怎么写、依赖谁。提示词明写「绝对不能在输出中写入金融事实、数值或研究结论」，返回体里也没有数值字段可填。所有数字只能来自问财响应，经确定性融合代码入库。
怎么保证选出来的龙头是对的？
先把「谁是候选」和「谁是龙头」分开：候选来自主题选股与细分赛道选股；排序用总市值、营收、市场份额、行业排名等客观指标算 leader_score，取前 20。同时有 excluded_industries 排除跨界行业，避免「概念股」污染。产业链图的成员资格还有更严的一套（A3 章讲）。
数据源挂了怎么办？
分三种：单条任务失败只影响它自己；配额问题走全局冷却 + 多 key 轮换；全部 key 都不可用则整跑失败并写明原因。不会「降级成编造」。

A2 数据解读：算得对，才轮得到说得清

A2 不重新取数。它面对的是 A1 交来的一堆记录，要做的是三件事：把可计算的算出来（指标、趋势、异常、跨源一致性），把可归纳的归纳出来（洞察、知识事实、章节骨架），并且保证每一条结论都挂得住证据。

dataset.json

  • 指标需求（来自用户问题）
  • 研究截止日与主题
→
输出

  • 关键指标 / 趋势 / 异常 / 跨源验证

确定性引擎：五个可复算的分析

分析怎么算防的是什么
关键指标按「实体 + 可比口径 + 单位」分组，取最新一期和上一期；同名指标最多留 3 条，按重要度排序把不同口径的两个数放在一起比
同比 / 环比同月日且差 1 年 → 同比；同月日跨多年 → 同历史期；其余 → 相邻期变化。基期 ≤0 不给百分比，改标「扭亏 / 零基 / 非正基」负数基期算出 −300% 这种假增速
趋势同一口径至少 2 期；方向一致率 = max(升,降) / 非零变化数；<0.67 记「波动」，总变化 <2% 记「持平」两个点就敢说「持续增长」
异常横截面：样本 ≥5，用中位数 + MAD，修正 Z = 0.6745×(x−中位数)/MAD，|Z| ≥3.5 判离群；时序：≥4 期，对「相邻期变化量」再做一次 MAD均值/标准差被离群点带偏，漏掉真异常
跨源验证同实体、同指标、同期间、≥2 个不同来源；相对偏差 >1% 判 contradicted两个源差 30% 却当同一个数用

这四个数字（0.6745、3.5、2%、1%）不是拍脑袋：0.6745 是把 MAD 换算成与正态同尺度的系数，3.5 比 3σ 更保守，1% 是给四舍五入留的余量。答辩时如果被问「阈值怎么定的」，要能说出「保守 + 可解释 + 能被同一份数据复算」。

语义层：模型做什么、不做什么

模型做的

读用户关注点与数据形态，从 20 个方法论技能里选合适的；按技能做局部解读；把局部结果去重、保留冲突，写成 6–12 条洞察、3–6 条原子事实、一份章节骨架。

模型不做的

不算数、不补外部事实、不猜因果、不给投资建议、不掩盖上游冲突。它引用的 record_id 必须在本次输入里真实存在，否则整条丢弃。

证据索引怎么建、怎么用

每条记录进 A2 时会被包装成一个 EvidenceRef：record_id、实体、指标、值、单位、期间、口径、币种，以及「哪次查询、哪个技能、哪条 trace」。这个索引同时是：模型的输入、引用的白名单、下游 A3/A4/A5 的回查入口。

引用校验分三级：技能局部（只认本次发给它的证据）→ 全局融合（洞察与关联指标/趋势/异常都要在允许集合里）→ 文本重建（把实际用到的 ID 回填到句子上）。任何一级发现「引用了不存在的 ID」，轻则删条目，重则整条洞察不要。

没有模型还能跑吗

能。没有配置模型时，语义层标记 skipped，指标、趋势、异常、跨源验证、可比矩阵、质量评分全部保留，摘要退化成描述性叙述。缺的是原子事实、全局洞察和产业链拓扑。这是有意设计：确定性的部分永远可用，模型只是增强。

三个追问

两个来源数不一致，你们信谁？
不仲裁。同口径多值时，关键指标和趋势暂不发布，冲突进 conflicts 和附录，正文写「来源观测冲突，待核」。悄悄选一个等于制造假精度。
异常检测为什么用 MAD 而不是 3σ？
样本常只有 5–20 家，均值和标准差本身会被离群点污染。中位数 + MAD 更稳健，乘 0.6745 后与正态尺度可比，阈值 3.5 更保守。这是财务截面数据的常规做法。
技能是怎么选的？会不会漏？
三路并集：规则打分（关键词、数据命中、域命中）、模型自主选择（上限 7）、用户显式指定。合并上限 10，always 技能与用户指定项不会被裁掉。并集的好处是「模型没想到但规则认为该有」的会被补上，而且每个技能的来源会记录下来，能统计模型漏选率。

A3 图表生成：每张图都要能自证

模型选图，代码画图，契约拦图。

如果只记一句A3 的角色是「图表编译器」：模型选图，代码画图，契约拦图。

A3 不取数、不下结论。它把 A2 已经审定的证据压成同量纲的二维表，选一个合适的图形，编译成 ECharts 配置或 SVG，最后逐点回查「这个点到底是哪条记录」。

输入
interpretation_report.json
  • 证据索引、指标、趋势、可比矩阵
  • 产业链拓扑（若有）
  • 用户图表偏好与数量要求
→
输出
chart_result.json + charts/
  • 图表：option / SVG / 生成图
  • 每张图的点级证据与数据指纹
  • 被抑制的图表及原因、补采需求单

为什么「有数据」和「能画图」是两件事

一条记录进得了图，至少要满足：数值可解析、单位明确、口径一致、期间可比、有证据 ID。缺任何一项，配方阶段就直接放弃这张候选，而不是画一张「大概齐」的图。比如同一根轴上出现「元」和「%」，编译期直接报错，不允许双单位混画；比率类指标不允许进饼图，会自动降级成柱状。

零图是合法结果当数据不足时，A3 输出 0 张图、status=partial、quality.passed=false，并在 suppressed_charts 里逐条写原因。下游仍然可以写纯文字报告。我们宁可交一份「没有图但说清为什么」的稿子，也不交一张「看起来漂亮但点对不上」的图。

点级证据：A3 最硬的一层

很多系统只做到「整张图挂几个 evidence_id」，这挡不住「图是对的、某个点是编的」。A3 要求每个数据点都有 record_id，并把它写进 data_contract.points[]：系列、序号、类别、数值、单位、实体、指标、期间、口径、币种。发布前逐点回查，任何一点查不到记录，整张图不发布。

另外每张图有一个 data_fingerprint（图型 + option + 证据 ID 集合的 SHA-256），既做去重，也做「同一张图」的身份标识。

产业链图：模型只负责「是什么」，代码负责「画在哪」

产业链是 A3 的招牌，也是最容易出错的地方：企业串岗、环节重叠、概念股混入。做法是把「结构」和「版式」彻底分开：模型填的是 ChainGraphSpec（阶段、分组、节点、边），渲染器只管三列目录式布局。企业名要过三层：A1 证据白名单 → 只读知识底座四态裁决（匹配/不匹配/查不到/未知）→ 拓扑 8 条硬规则。只有明确判成「不匹配」才允许改名删名；「查不到」只留痕，不据此删人。

缺数据时：只开需求单，不自己取数

A3 发现自己缺时序、缺产业链、缺构成时，输出结构化的 data_demands（目标图型、实体、指标、领域、查询提示），由后端的补采协调器决定要不要补、补几条。协调器最多选 2 条、只补一轮，提交前要过四重 CAS 校验；一旦提交，A2 及下游立即失效并重跑。

三个追问

为什么不让模型直接给 ECharts option？
因为 option 看起来对、数值却可能是编的。我们的分工是模型选图型和章节，代码从证据重建数据和坐标轴，最后逐点回查。模型给错，最多图被拦掉，不会出现假数。
图里的公司名凭什么可信？
三层：A1 证据里真实出现过的实体白名单；只读知识库的四态裁决；产业链拓扑的 8 条硬规则（唯一性、环节不重叠、物料流方向等）。「查不到」不等于「错」，所以不会因为查不到就删企业。
没有数据时交白卷吗？
不交白卷，交「零图 + 原因」：status=partial、每张被抑制的图有 reason_code、正文照常写。这是显式降级，不是静默失败。

  • 已就绪的图表
  • 7 章 21 节大纲与用户问题
→
输出

  • 7 章结构化正文（段落/指标卡/对比表/提示框）

大纲为什么写死

7 章 21 节是 outline.py 里的常量，不是模型生成的：行业定义、市场规模与成长、产业链与利润分配、竞争格局、财务质量与估值、宏观政策与技术催化、情景与风险。每章恰好 3 节，由 Pydantic 锁死。用户的问题不会改变骨架，只会改变「检索什么」和「问题挂在哪一节」。

为什么不交给模型拟大纲研报的可比性来自稳定结构。今天 6 章、明天 8 章，读者没法比较，排版和质检也没法做。骨架稳定，模型才能把精力放在「这一节到底有没有判断」。

每个数字怎么被抓住

  1. 写前：上下文只给这一章相关的证据，提示词明令「严禁捏造事实和数字」。
  2. 写后绑定：段落里有数字但没绑证据时，系统按三种通道自动找：原值子串、量级变体（元 ↔ 亿元/万元、千分位、小数位）、指标名 + 实体同现。
  3. 绑上不算过：再交给 quantity_issues 复核实体、期间、指标族、口径、币种，容差是「半个末位」，不是百分比。
  4. 复核不过：删掉无依据的指标卡、裁剪句子，整段都不行就移除并写缺口句。

净现比是一个专门的例子：分子分母口径极易错（合并净利润 vs 归母净利润），所以 A4 只允许引用 A2 已核验的值；缺同口径分母时，整句改写成「缺少同口径归母净利润，净现比无法计算」。这条规则有独立开关，也是从真实事故来的。

质检到底查什么

层级检查项
单章章节 ID 与顺序；数字无证据；因果句无依据；数值语义不符；重复段落；单段 >1000 字；指标卡/对比表有数字无绑定；图表未就绪、错章、缺邻接解读
全篇必须 7 章 21 节；每张图全篇只出现一次；跨章总市值量级差 >3 倍判冲突；同键数值互斥只记录不阻断
汇总evidence_coverage = 至少绑一条证据的段落 / 有内容的段落；passed = 无任何 issue；status=completed 只在「无兜底章、无 issue」时成立

这里要诚实：代码里没有「字数下限」这种硬阈值。target_length 只是进提示词的风格参数，前端只做统计展示。质量分不看写得多不多，看「有没有据、齐不齐、图有没有重复」。

修不好怎么办

重写

整章带着上一轮错误重生成，最多 3 轮。

隔离

删掉缺绑定的指标卡、置空对比表；隔离比例 >50% 仍判不过，防「删光换通过」。

兜底

模型彻底不可用时，用已核验结论拼确定性章节；取不到就写「本节缺少可用于判断的直接证据」。

三个追问

7 章 21 节是 AI 定的吗？
不是，是代码里的手写常量，Pydantic 锁死每章 3 节。用户问题只影响检索和题面分配，不改骨架。
怎么保证模型不编数字？
写前只给证据上下文并强令禁编造；写后把数字绑到证据 ID，再用实体/期间/指标族/半末位容差复核。绑不上就删卡、裁句、写缺口句。宁可少写，不可乱写。
为什么每章并发、章内串行？
章与章之间没有依赖，并发能把 7 章的等待时间叠起来；章内审计要读整章状态，串行才不会互相踩。

A5 报告融合：只编辑，不创造

一致性、审计、出版，三道门禁决定能不能交付。

如果只记一句A5 是全篇唯一不生产事实的环节：它只编辑、只审计、只出版。

它改什么、不改什么

A4 的 chapter_result.json 物理上不会被修改：A5 读进来就做一份深拷贝，所有编辑都在副本上。模型能做的只有：写摘要和结论、连章节过渡句、极少量术语归一、个别段落微调。数字和证据 ID 必须是输入里已有的，否则整条编辑被拒并计数。

提示词里最硬的一句「严禁改动任何数字、严禁增加任何未在原文中出现的数字，包括股票代码、年份、列表序号；必须 100% 原样保留所有数字与精确字面值；必须完全复用原段落的 evidence_ids。」这句话不是靠模型自觉，后面还有代码白名单：输出里的每个数字都要在输入数字集合里，每个证据 ID 都要在白名单里。

全局一致性查什么

类别典型检查后果
输入完整性7 章 21 节；未知证据引用；未就绪图表；重复段落；A4 有兜底章阻断或 warning
跨章数值「万亿/亿」统一后与可比矩阵总市值差 10 倍；多个量级并存数量级冲突 warning + 基准对齐

全链路唯一允许「确定性改数字」的地方，是总市值基准对齐：当正文里的总市值与可比矩阵差 10 倍时，只在「总市值」语义子句内改写，并留下记录。其余任何数字，A5 只做「保留或剥离」，不做「修正」。

三种交付状态

ready 正式交付

无阻断、无标注、格式齐全。可以正式下载。

ready_scoped 有限覆盖

产业链覆盖有限、公告核验有限，但事实链完整。需在附录声明边界。

ready_with_limits 受限草稿

存在未消除的阻断或标注。只能以 mode=draft 下载，文件名带 draft 前缀，响应头写 draft_with_warnings。

导出：三种格式，一个源

Markdown 是纯文本拼装，引用写成「来源 N」，附录二是完整证据表（URL、文内定位、披露日、文档哈希）。HTML 用模板渲染，把 SVG 内联进去，所以单文件、可离线打开。PDF 用无头 Chromium 打印 A4，难点是目录页码：先出 PDF，读出锚点真实页码，回写目录再重排，最多 5 轮；不稳定就报错，宁可不出，也不出错误页码。

manifest.json 最后生成，生成前把每个产物重新读盘、按真实字节重算 SHA-256；发布到 run 目录后，再按新路径重算一次。这样「下载到的文件」和「清单里记录的文件」是同一份。

三个追问

A5 和「让大模型写报告」有什么区别？
模型在 A5 里没有事实写入权。它只能改措辞，输出里每个数字必须先在输入白名单里，每个证据 ID 必须在白名单里，否则整条被拒并计数。事实来自 A2/A3/A4，A5 只做审校与出版。
一致性报告只是提示吗？
不是。consistency.passed=false 会变成 hard_blocked，阶段只能停在待审核，正式下载被 409 拦掉，只允许走草稿通道。
「部分核验」是不是给自己放水？
有硬容量：最多 150 条、且不超过数值问题总数的 60%；优先级明确；每条必须写进 verification_warnings 并在附录展示。真正无据的数值和「国产化率」类断言，一条都不放。

可信度是怎么造出来的

四道防线，让错误在到达读者之前被拦住。

前面五章讲的是「每个智能体怎么做事」。这一章讲「它们凭什么可信」——不是某一个模型更聪明，而是四道防线叠起来，让错误在到达读者之前被拦住。

四道防线

① 数据层：先保证「进来的是干净的」

来源白名单（每条需求限定可接受的技能）、单位倍率表、口径/币种/期间校验、冲突保留不仲裁。单位来源不明直接退出量化覆盖。

② 生成层：再保证「写出来的有出处」

每个结论挂证据 ID；段落数字绑定 + 实体/期间/指标族复核；图表逐点回查；模型不许算数、不许补外部事实。

③ 交付层：最后保证「交出去的是终稿」

阶段契约、引用完整性、数值/附录/图表语义终审、三格式同源重渲染、交付状态机；不合格只能出受限草稿。

④ 运行层：全程保证「可追责、可复现」

私有工作区 + 版本目录 + CAS 发布；决策包记录谁批的、批的哪一版、接受了哪些风险；调用台账记录花了多少、打了几次。

如果评委挑刺，系统怎么接

可能的质问系统的实际回答
「模型编一个数字你怎么办？」写作时数字必须绑定证据；绑不上就删卡、裁句、整段隔离并写缺口句。A5 终审再按实体/指标族/期间/单位复核一次，过不去就剥离。
「来源之间数据打架呢？」不仲裁。冲突原值保留、进附录、标「待核」，并且这条记录不能用来满足需求，逼下一轮补采。
「图表是不是摆样子？」每个数据点有 record_id 和期间/单位/口径，A5 会把点值与 option 里的实际取值逐一对比。
「模型把结论改了，你怎么知道？」A4 的稿子只读；A5 的编辑逐条过白名单，改动以 editorial_changes 记录位置、类型、原因，正文不复制。
「产物被人手改了怎么办？」阶段在自己的工作区跑，发布时比对输入文件哈希与指针字节；执行期间被改就拒绝发布。
「两个人同时批准呢？」三层乐观锁：revision、decision_id、风险快照哈希。后到的那个一定冲突，不写决策。
「跑一半崩了怎么办？」状态落盘；重启后扫描未完成任务，默认不自动续跑，手动恢复时先校验上游产物契约与硬阻塞，必要时前溯重跑。

质量保障：让失败显形

2829 项测试、101 条评测、65 份真实基线，各管一段。

「你们怎么证明这不是 demo？」这是答辩最容易被问、也最容易答砸的问题。答案不是「我们跑通了」，而是「我们有一整套让失败显形的机制」。

四层各管什么

层规模回答的问题
单元测试301 个文件 / 2547 个函数 / 2829 项通过某个函数在边界上是否仍然正确：CAS、单位换算、指纹、契约字段、幂等
契约测试五阶段 schema、决策包、版本、下载门禁阶段之间交接的东西是否合法；人工审批是否真的不可绕过
评测集101 条用例（17 条负向）+ 6 种坏数据注入端到端行为对不对：该停的停对阶段、该交的产物齐、该报的错码对
人工验收65 份真实 run 基线 + 4 个门禁实操真实行业、真实数据下，人能不能用、敢不敢签

评测为什么不是「自嗨」

关键在两条：负向用例和坏数据注入。负向用例不是看系统跑通，而是看它在「信息不足」「口径冲突」「越界要求」时，是否停在正确的阶段、抛正确的错误码。比如「那个锂电龙头怎么样」这种指代不清的问题，必须停在取数阶段并返回「需要澄清」，而不是猜一个公司继续跑。

坏数据注入有六种：HTTP 超时、429、半包截断、字段缺单位、数据可见时间被改到未来、行序打乱。目标是存活率 ≥95%，且绝不允许静默错数——可以降级，不可以算错还显示成功。

pass@k 和 pass*k 是什么

pass@k：跑 k 次，至少一次通过的概率

用超几何无偏估计 1 − C(n−c,k)/C(n,k)，修小样本偏差。回答的是「这个能力稳不稳」。

pass*k：k 次必须全部通过

发版门禁用。回答的是「能不能保证每次都行」——交付一份报告，不能靠「多跑几次总有一次好」。

门禁按能力分组：意图路由、核心计算、拦截、工具规划各自有 PR 与发版阈值。比如核心计算要求发版 pass*5 = 1.0，一次都不许错。

要诚实说的三件事

答辩时的「不完美」清单（主动说，比被问出来好） ① 前端 E2E 目前 1 通过 / 4 失败，失败原因是弹窗展开前元素不可见、目标文本落在隐藏 tab，属于测试与 UI 的时序问题，不是业务逻辑错误；
② 代码格式检查在 9 个既有文件上未通过，与功能无关，尚未批量整改；
③ 评测里的「报告质量五维评分」在真实产物上必然 fail-closed，因为当前 A5 只输出一致性审计，没有 100 分制评分。我们宁可让它显示失败，也不让它静默通过。

三个追问

2829 个测试，维护得过来吗？
三层成本不一样：单元测试默认断网、秒级；契约测试跟 schema 绑定，改契约就必须改测试，是被迫同步；真正花钱的 live eval 用 marker 默认排除。维护靠三条纪律：默认断网、修 bug 必留回归测试（文件名带 bug 号）、每次全量记录 passed/skipped 数字。
测试多就等于质量好吗？
不等于，但没有测试一定不好。我们的测试主要不是「覆盖率」，而是「把每条事故变成一条断言」：单位错、比率自算、改稿后未复检，都有对应用例。测试是规格的可执行形态。
为什么不用真实数据天天跑？
贵且不稳定。真实 run 走人工验收与基线对照，日常回归用固定替身和录制回放。两条线分开，才不会因为外部接口抖动导致 CI 全红。

答辩问答 30 题

按「价值 → 细节 → 可靠性 → 尖锐问题」准备。

下面 30 个问题按「项目价值 → 五个智能体 → 工程可靠性 → 尖锐追问」分组。答案都写成可以直接说出口的短句；括号里是展开时用的细节。

A. 项目与价值（5 问）

一句话介绍这个项目。
它是一条把「一个行业 + 几个问题」变成「一份带证据目录、可导出 PDF 的行业研究报告」的多智能体产线。五个智能体分别负责取数、解读、画图、写作、融合交付，每个阶段都有输入输出契约和人工门禁。
如果对方追问「和 ChatGPT 写研报有什么区别」，接下一题。
它到底解决什么问题？
解决的不是「写不出来」，而是「写出来不敢用」。研报的难点是数据从哪来、数字可不可信、出错怎么发现。我们把这三件事变成可验收的工程问题：需求覆盖矩阵、证据 ID 闭环、交付门禁。
创新点是什么？
四点：① 把研报生成拆成五个带强契约的阶段，而不是一个 Agent 端到端；② 证据做到点级——每个图表数据点、每个段落数字都能回到原始记录；③ 计算与表达分离，模型不许算数；④ 交付级门禁与版本化审批，让报告可追责、可回滚。
不要只说「用了多智能体」，多智能体是手段，不是创新点。
和通用的 Agent 框架（AutoGPT、LangGraph 之类）是什么关系？
它们解决「怎么编排」，我们解决「编排出来的东西怎么验收」。框架不会告诉你一张图能不能发布、一个数字该不该采信、审批过期怎么办。这些是本项目自己长出来的领域约束。
商业价值在哪？
把「找数据、算指标、写初稿、排版」这些重复劳动交给机器，人只做判断与审校。更关键的是可审计：每个数字有出处、每次修改有记录、每个风险有人签字。这在券商、投研、咨询的合规场景里比速度更值钱。

B. 五个智能体（每个 2 问）

A1 为什么不用一个 Agent 一次问完？
问财是自然语言解析器，一句里塞多个领域或多家公司会被截断、词槽冲突。所以强制分层：先确权选股，再逐家做财务，最后按缺口补采。每一层还有确定性守卫兜底。
A1 怎么证明数据是全的？
它不声称「全」，它输出一张需求覆盖矩阵：每条需求是否通过、哪些证据支撑、哪些被拒、缺什么。全不全由用户的问题定义，不由系统自说自话。
A2 和直接把数据丢给大模型总结，区别在哪？
数字先由公式算好：指标、同比环比、趋势、MAD 异常、跨源一致性，全部可复算。模型只在这堆结果上做归纳，而且每条结论必须引用真实存在的 record_id。没有模型时，确定性部分照样出报告。
A2 的洞察会不会只是套话？
有可能，所以我们不把「写得好」当质量门槛，把「有据」当门槛：无证据的洞察会被丢弃，冲突会被保留并标注。质量分看覆盖率与一致性，不看辞藻。
A3 为什么强调「点级证据」？
只挂图级证据挡不住「图是真的、某个点是编的」。点级证据要求每个点都有 record_id、期间、单位、口径，发布前逐点回查。这是图表可信的最小单位。
A3 没有数据时怎么办？
零图 + 原因。每张被抑制的图有 reason_code，阶段状态是 partial、quality.passed=false。下游可以写纯文字报告。这是显式降级，不是静默失败。
A4 的 7 章 21 节是模型定的吗？
不是，是代码里的手写常量，Pydantic 锁死每章 3 节。用户问题只影响检索和题面分配，不改骨架。骨架稳定，报告才可比、可排版、可质检。
A4 怎么防止模型编数字？
写前只给证据上下文；写后把数字绑定到证据 ID，再用实体、期间、指标族、半末位容差复核。绑不上就删卡、裁句、写缺口句。净现比这类高风险比率，只允许引用上游核验值。
A5 是不是多余？A4 写完不就行了？
A4 是章节视角，A5 是全篇视角。跨章市值量级、图表重复挂载、术语不一致、附录数字对不上，只有看全篇才发现。而且 A5 是交付门禁所在：能不能正式下载，由它判定。
A5 会改内容吗？
只改措辞，不改事实。A4 的文件只读，A5 在副本上编辑；数字和证据 ID 必须是输入里已有的，改动只以「位置 + 类型 + 原因」记录，正文不复制。

C. 工程与可靠性（9 问）

为什么用状态机，不直接串五个函数？
串脚本回答不了「跑到哪、为什么停、能不能接着跑」。状态机把每阶段变成可持久化的状态，所以能暂停、恢复、取消、回退，也能追责。
审核卡住会不会死锁？
不会。waiting_review 是没有后台协程在跑的纯状态；锁只在请求处理期间短暂持有，等后台任务和递归下一阶段都在锁外。所谓「卡住」是门禁设计，不是进程阻塞。
产物被人手改了怎么办？
三道：阶段在自己的工作区跑，发布时比对输入文件哈希，执行期间被改就拒绝发布；契约校验会检查字段和跨字段关系；下载门禁按 built_at_revision 判代次，旧文件不能冒充新版本。
两个人同时点批准呢？
一个进锁成功、版本 +1；另一个的 expected_revision 已经落后，直接 409；就算伪造版本，decision_id 和风险快照哈希也对不上。三层乐观锁。
为什么发布要三重校验？
revision 防结果过期，指针字节防期间有人切了版本树，文件哈希防输入被就地改过。只校验一个都会漏。
为什么不用数据库事务？
产物是大 JSON 和二进制（SVG/PDF），塞进数据库事务不现实。我们用「目录树 + 指针 + 内容哈希」表达同一套语义：写完 staging 再原子替换、切指针，失败就回滚。跨文件崩溃的绝对原子性不在承诺范围内，但读者永远不会看到旧树被改。
失败/重启后怎么恢复？
启动扫描未完成任务，默认不自动续跑。手动恢复时先校验上游产物契约和硬阻塞，必要时前溯到更早阶段重跑；恢复会新开版本树，旧版本不覆盖。
成本怎么控制？
分层并发、上下文预算、模型只在必要环节调用、A3 图表数量分档、补采最多两条一轮。调用台账能统计每次 run 的真实请求数和重试次数。
外部依赖挂了怎么办？
单任务失败只影响自己；配额问题冷却 + 换 key；模型不可用时，A2 保留确定性分析、A3 走规则选型、A4 走兜底章、A5 走规则摘要。整条链路没有「必须依赖模型才能出东西」的死点。

D. 尖锐追问（6 问）

这是不是套壳？不就是写了几段 prompt？
如果只有 prompt，那确实。区别在于 prompt 之外的东西：五份强类型契约、逐点证据回查、交付门禁、版本化审批、2829 项测试。prompt 只是约束的一种载体，真正让系统可控的是代码里的拒绝面。
这是最容易被问的一题，建议主动展开「一个数字从问财到 PDF 要过几道关」。
数据源只有问财，是不是太单一？
主路径是问财，因为它是国内少有的、能同时给结构化指标和文本证据的接口；产业链另有公告、研报、新闻和可选的联网补漏。单一数据源是取舍，不是没意识到——多源会带来口径对齐成本，我们用冲突保留和来源分层来兜。
大模型的幻觉真的防住了吗？
不敢说 100%。我们做的是「让幻觉无法静默通过」：数字必须绑定证据、图表逐点回查、交付前数值审计、引用不存在的 ID 直接契约失败。剩下的漏网之鱼会以「标注 / 隔离 / 降级」的形式暴露，而不是伪装成正常结论。
评测是不是自己出题自己打分？
部分是。规则项是确定性的，模型评分只占 30%，双法官分差大就人工仲裁。而且负向用例和坏数据注入不是模型能「猜」到的。我们也在补真实 run 基线，用人工验收对照。
哪些地方还没做完？
三块：前端 E2E 有 4 条用例未过（时序问题）；报告质量的五维评分还没接进 A5，评测里是 fail-closed；产业链的完整结构还没有金标准验收，目前最高只到 partial，verified 必须人工认证。
主动说没做完的，比假装全做完可信。
你个人负责哪部分？
（按你的实际分工替换）我主要负责 X 模块：它原来的问题是 Y，我做了 Z——比如把「数字绑定证据」从图级下沉到点级，或者把人工审批从「点一下」改成带版本与风险哈希的决策包。
挑一个你真做过、能讲到代码级的模块。评委不怕你只做了一块，怕你说不清自己做了什么。
