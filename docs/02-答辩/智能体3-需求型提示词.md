# 智能体3 · 需求型提示词

上一版是“答案版”：把 16 种图型、单位规则、抑制原因、T01—T15 门禁全写死了。它适合复刻，不适合让 AI 帮你想方案。

这一版只做一件事：抛出一个核心痛点，要求 AI 先给三条路线、一个贯穿点、一个待验证假设，最后反问一个问题。方向对齐后，再进入实现。

## 可直接复制的提示词

你是我的产品架构顾问。先不要直接写代码，也不要给我完整系统提示词；先帮我把问题想清楚。

【背景】
我在做一套行业研报智能体：智能体2负责解读数据，智能体3负责把数据变成图表。现在最痛的一点不是“图不够多”，而是：

图表生成器在“图不够”和“图不可信”之间反复横跳——图少了，报告单薄；图多了，单位、口径、证据、重复全失控，读者既看不出重点，也不敢信。更糟的是，为了让图好看，它还会补没有证据的数、把零轴截断、把不同量纲硬塞进一张图。

【我要的结果】
智能体3要能做到：先判断这轮数据能画什么，再决定画什么，画完再检查“这张图能不能发布”。数据不够就不画，绝不凑数；每张图上的每个点都要有据。

【这次先不要给答案】
请按下面五步来：
1. 用大白话复述你理解的痛点，指出主要矛盾是“图少”“图假”“图乱”中的哪一个，为什么。
2. 给我 3 条不同的解决路线，不要只给一种。每条说清：核心思路、能解决什么、代价和风险、适合什么阶段。
3. 选一条你最推荐的，给我一个“贯穿点”（一句话原则），说明它怎么同时管住图少、图假、图乱。
4. 告诉我第一个要先验证的假设，以及最小验证动作。
5. 最后问我 1 个必须由我回答的问题；在我回答前，不要往下写实现。

先只给方案，不要直接写代码，也不要先列 16 种图型、阈值和门禁。等方向对齐后，再拆系统。

## 它应该怎么回

1. 先用一句话复述痛点，不能复述成“图表不够多”。
2. 给三条路线，不是三种图型；每条路线要能回答“它怎么防止假数、怎么防止图乱”。
3. 选一条，并给出一条贯穿点；贯穿点必须同时管住图少、图假、图乱，而不是只解决一个问题。
4. 给一个可验证的假设，以及一个最小验证动作；不要直接上全量实现。
5. 反问一个真正影响方向的问题，例如：上游数据能提供多期时序，还是只有单期截面？这决定路线选型。

## 为什么上一版不对

- 上一版是答案：它把架构、字段、阈值、门禁都写死了。AI 拿到它，只会照着建，不会替你想“还有没有更好的路线”。
- 这一版是需求：只给一个核心痛点和一个结果要求，让 AI 先发散、再收敛。它必须自己提出路线，并解释取舍。
- 上一版适合“复刻”；这一版适合“立项”。先立项，再复刻，顺序不能反。
