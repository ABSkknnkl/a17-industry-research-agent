## 1. 先把项目整体说清楚

这个项目不是 LangGraph、CrewAI、AutoGen、LangChain，也不是 PiAgent 运行时。它是**自研状态机 + 五段流水线 + 五个独立 Python 包**：

- 后端：FastAPI + Pydantic v2 + httpx；
- 前端：Vue 3 + TypeScript + Element Plus + ECharts；
- 编排：自研 `StateMachine` + `FiveAgentsAdapter`；
- 五个智能体是五个独立 Python 包，只通过 `data/runs` 里的落盘 JSON 交接，不靠内存互相调用；
- 大模型走 OpenAI 兼容接口，每个包内一个 `OpenAICompatibleLLM`，httpx 直接 POST `/chat/completions`。

五段主链路：

> 用户输入（行业/公司/五个问题/截止日/写作要求）
> → A1 数据获取：25 个技能，产出 `dataset.json` + `evidence_index`
> → A2 数据解读：确定性计算 + 模型解释，产出 `interpretation_report.json`
> → A3 图表生成：6 个技能、16 种图型，产出 `chart_result.json` + SVG
> → A4 章节撰写：7 章 21 节，产出 `chapter_result.json`
> → A5 报告融合：四维审计 + 三格式，产出 `report.md / .html / .pdf`
> → 人工审核门：`approve / revise / direct_edit`；A5 硬阻塞则只出受限草稿

**A4 的位置：Stage 4，编制环节。** 它不取数、不算指标、不画图，只负责把 A2 的“事实”和 A3 的“图”装配成章节文字；A5 再以整份报告为单位做复核和签发。

用一句答辩话讲：

> **A4 负责“从证据长出文字”，A5 负责“不让文字跑出证据”。**

## 2. A4 的输入、关键步骤、输出、协作

### 2.1 输入不是一句命题，是三份契约

A4 少一份 JSON 就直接报错，不硬编：

1. **A2 解读报告**：证据白名单、洞察、发现、财务比率、必答题覆盖表；
2. **A3 图表结果**：哪些图已就绪、每张图推荐哪一章、图内每个点对应哪些证据号；
3. **7 章 21 节标准大纲 + 人工反馈 + 写作选项**（模板、篇幅、风格、定向修改要求）。

每章另配一个**独立资料袋**：

- 最多 60 条证据、8 条洞察、25 条发现；
- 50 万字节上下文上限；
- 超限先丢可选背景，**证据白名单和必答题证据永不丢**；
- 仍丢不下就报错，不静默截断；
- 一张图只能进一个章节，防止同图跨章重复充数。

### 2.2 关键步骤

1. **载入大纲与契约**：`OUTLINE_VERSION=2026.1`，7 章 × 3 节 = 21 节；
   - CH-01 行业定义与研究基础
   - CH-02 市场规模与成长性
   - CH-03 产业链与利润分配
   - CH-04 竞争格局与壁垒
   - CH-05 财务质量与估值参照
   - CH-06 宏观、政策与技术催化
   - CH-07 情景、风险与研究结论
2. **逐章局部检索**：每章只拿自己的证据袋，避免把全库塞进一个提示词；
3. **7 章并发主生成**：`asyncio.Semaphore(7)` + `asyncio.gather`，每章一次主模型调用；**21 节是章内结构，不是 21 个并发任务**；
4. **逐段审计**：证据、数字语义、因果、重复、图号、指标卡、对比表、总市值锚点；
5. **生成—审计—修复**：整章重写或段落定点修复；每次修复先做 trial 审计，防止越修越错；
6. **图表嵌入与对齐**：图必须就绪、必须推荐给本章、必须单处挂接、正文必须真的讨论这张图；
7. **包级质检**：7 章 21 节、单图单处、未知证据、跨章量级冲突；
8. **落盘 JSON**：给 A5 和人工审核用。

### 2.3 输出不是一篇 Word，是结构化 JSON

核心产物：

- `chapter_result.json`：`status`、`chapters`、`quality`、`warnings`、`applied_skills`、`question_answers`、`model_name`；
- `chapters/CH-01.json … CH-07.json`：每章的结构化内容；
- `request.json`、`input_report.json`、`input_charts.json`：输入快照；
- `events.jsonl`：过程事件。

每章、每节、每段都有结构：

- 章节：`chapter_id / title / summary / sections / evidence_ids / chart_ids / used_fallback / content_audit`；
- 小节：`section_id / title / purpose / paragraphs / chart_ids / metric_cards / comparison_table / uncertainties / layout_hint`；
- 段落：`paragraph_id / kind / text / evidence_ids / assumption_note`；
- `kind` 是受控角色：`thesis / evidence / comparison / chart_readout / risk / methodology / transition / analysis / scenario`。

这就是 A5 能审计的前提：**如果 A4 交的是一篇散文，A5 没法逐段对证据；交的是 JSON，才能逐段查。**

### 2.4 协作关系

- A4 不直接调 A2/A3，只读它们落盘的 JSON；
- A5 不直接调 A4，只读 `interpretation_report.json`、`chart_result.json`、`chapter_result.json`，缺一份就报错；
- A4 跑完停在 `chapter_write / waiting_review`，人工审核通过后，状态机才派发 A5；
- 人工改了 A4 正文，状态机会把 A5 置 `pending`、打 `exports_stale`、删旧导出，必须重新融合；
- 所以“A4 写完”不等于“报告能发”，中间还有人审和 A5 门禁。

A4 内部模型情况也说清楚：

- 不是五个智能体用五个不同大模型，是同一套模型接入层 + 五套岗位契约；
- A4 默认代码是 `deepseek-chat`，实际 `.env` 是 `deepseek-v4-flash`，温度 0.2，`max_tokens=16384`；
- 10 份写作规范，不是 10 个子智能体；技能选择走章节策略，`model_planning_calls=0`；
- 这 10 份规范覆盖证据约束、章节质检、行业概览、产业链、竞争、财务、地缘风险、风险情景、科技基本面、投资逻辑跟踪；技能只提供结构和校验方法，事实仍只来自上游报告；
- 每章一次主生成，失败才加修复调用；不是每节都调一次模型。

## 3. 为什么 A4 最难

### 3.1 如果只选一个最难点：数字语义审计 + 修复闭环

A4 写的不是代码，是自然语言。自然语言里的数字最难查，因为：

- 同一个数可能属于不同公司、不同年份、不同指标；
- 一个数在证据库里存在，不代表它能用在这一段；
- `5 家`、`15`、`100%`、`352.1 万辆`这种派生数，证据库里不一定有现成值，必须能由分子分母复算；
- 模型还会用“综合测算”“假设说明”给事实数字找借口。

代码里的审计是 **fail-closed**：

> 找不到同实体、同指标、同期间、同单位、同口径的匹配，就判问题；光有一个真实证据 ID 不够。

而且不是“差不多就行”：

- 舍入容差是显示末位的一半，不是按百分比放水；
- 百分比必须说清是水平、同比、环比还是百分点差；
- 同比、复合增速、占比、百分点变化，必须在本段绑定全部原始操作数；
- 缺任一操作数，就改写为证据缺口，不许猜。

更麻烦的是：**修复本身也是生成，也会引入新错误。**

所以 A4 的修复不是“让模型再写一遍就信”，而是：

1. 先深拷贝一份 trial；
2. 替换段落；
3. 重新跑 `_audit_chapter`；
4. 只有“该段问题消失，且没有新增问题”才接受；
5. 修不好就只保留能逐句核对的从句，再补主语；
6. 还不行就整段隔离，绝不让错数字留在正文。

这就是 A4 最硬的一点：**它要同时对抗“模型写错”和“修复再写错”。**

### 3.2 四个配套难点

**第一，7 章并发，但一致性不能丢。**

- 7 章同时写，每章独立资料袋，防止长文本退化、章节串味；
- 代价是跨章一致性不能靠模型记忆，只能靠 `global_facts` 全局锚点 + 包级审计 + A5 印前复检；
- 代码里 `max_concurrency=7`，每章一个主调用；21 节不是并发单位。

**第二，证据边界必须硬。**

- A4 只能引用本章资料袋里的 `record_id`；
- 引了池外证据，过滤并留痕（`foreign_drops`），不触发整章作废；
- 不许引外部检索、不许自算新数、不许自编图号；
- 净现比只能引用 A2 已核验值，分母必须是归母净利润；没有就写“缺少同口径归母净利润，净现比无法计算”。

**第三，图表治理不是“把图塞进去”。**

- 图必须 `ready`，必须推荐给本章，必须只挂一个章节；
- 正文必须真的讨论这张图绘制的指标，不能只写“如图所示”；
- 图号不能充当数值或因果依据；
- 模板图点缺 `metric` 字段时，用图表标题、系列、类别推断指标族，再核对证据重叠；推不出来就不硬配。

**第四，失败要分级，不能一错就整篇崩。**

- 模型请求失败：退避重试；
- 单段失败：定点修复；
- 多段失败：整章重写；
- 整章仍失败：确定性兜底稿，打 `used_fallback`；
- 全篇有兜底或仍有问题：`status=partial`，如实上报；
- A4 不阻断流转，A5 再压成受限草稿；让问题可见，比悄悄停住更有价值。

### 4.1 一个最能讲的真实例子：图号重审

`chart_reference_reaudit.json` 里有一次很典型的修正：

- `P-02-01-01` 原本开头是“如图 [CHART-06-10DA732C] 所示，中国新能源汽车行业在 2021—2025 年实现规模跃升……”，但这段讲的是行业规模判断，不是这张图的解读，图号被撤掉；

- `P-02-01-06` 原本讲“销量、出口量、渗透率的年度/月度口径”，这段才真正需要渗透率图，于是补上了 `[CHART-02-BD119357]`；

## 5. 代码里到底怎么保证

### 5.1 审计清单

`_audit_chapter` 逐段查：

- 章节 ID、节顺序是否和大纲一致；
- 未知证据 ID 是否越界；越界过滤并写 `foreign_drops`；
- 有实质数字但没证据的段落；
- `quantity_issues` 数值语义：实体、指标、期间、单位、分子分母；
- `unsupported_causal_claim`：因果句有没有独立依据；
- 段内重复、段落过长（>1000 字）；
- 指标卡、对比表有没有证据绑定；
- 图是否就绪、是否推荐给本章、正文有没有实际解读；
- 总市值是否和 `global_facts` 一致。

`_audit_package` 再查：

- 是不是 7 章 21 节；
- 章节 ID 是否重复；
- 是否有未知证据引用；
- 图是否未就绪、是否串章、是否一图多挂；
- 每个图是否真的有正文解读；
- 跨章“万亿”值 max/min 是否超过 3 倍。

### 5.2 修复流程

`_generate_audited_chapter` 的循环：

1. 主生成；
2. `_audit_chapter`；
3. 不合格：
   - 第一次就大量段落失败、且整节都失败 → `chapter_redraft_requested`，整章重写；
   - 否则逐段 `paragraph_repair_started`；
4. 每段修复：
   - 深拷贝 trial；
   - 替换；
   - 重跑审计；
   - 只有“该段问题消失且不新增问题”才接受；
5. 模型修复仍失败：
   - `retain_supported_claims` 只保留能核对的从句；
   - `repair_prose_opening` 补主语；
   - 仍不过就隔离，`evidence_ids=[]`，写 `chapter_claim_repair`；
6. 整章仍失败 → `_fallback_chapter` 确定性兜底，`used_fallback=True`；
7. 最终 `status=partial`，`quality.issues` 和 `fallback_chapter_ids` 如实返回。

### 5.3 两个“不”原则

- **不靠模型自觉**：提示词只是第一道，真正兜底是代码审计；
- **不静默通过**：修不好就隔离、兜底、`partial`，让人看见问题，而不是把问题藏进正文。

## 6. 答辩口述稿

### 6.1 30 秒版

> 如果只能选一个，我选智能体4。A4 不是让模型自由写文章，是让它在 7 章并发、21 节按提纲落位，把每句话写成可审计的句子。我们实际踩过三类坑：图号乱挂、删句后主语丢了、同一章三个小节写重。解决不是靠提示词，是代码审计：图号按图点指标和证据重叠匹配，对不上就撤；删句只保留能核对的从句并补主语；重复段隔离。数字语义、因果、图表单挂、跨章量级都做确定性检查；修不好就整章重写，再不行段落隔离，最后确定性兜底，状态标 `partial`，绝不静默通过。

### 6.2 90 秒版

> 智能体4 是章节编制环节。它拿到的不是一句“写个新能源报告”，而是三份契约：A2 的证据白名单、洞察和财务比率；A3 的就绪图表、图表和证据的映射；以及 7 章 21 节的标准大纲和人工反馈。每章一个独立资料袋，最多 60 条证据、8 条洞察、25 条发现，一张图只能进一个章节。
>
> 它真正难的地方不是“写得漂不漂亮”，是“写得能不能被审计”。每一段都要挂证据号；每一个数字都要能同实体、同指标、同期间、同单位地复算；每一句因果都要有独立依据；每一个图号都要对得上图实际画的东西。A4 写完先自审，不合格就定点修，修完再审；修不好就整章重写，再不行段落隔离，最后确定性兜底，状态标 `partial`，不静默放过。
>
> 我们实际踩过的坑很具体：图号乱挂，段落写“如图所示”但没解读；事实核验删句后主语丢了，出现“同期经营现金流……”这种半句话；同一章三个小节写重。这些都不是靠提示词解决的，是靠代码里的图号对齐、证据保留、重复审计和 trial 复审。
>
> 这次 A4 专项验收跑出来是 7 章 21 节 52 段，47 段带证据，悬空引用 0，跨章完全重复 0；但仍有 43 条数值语义、2 条因果、5 条重复没过，所以状态是 `partial`。A4 不把问题藏起来，A5 再决定能不能签发。

### 6.3 2 分钟版（如果评委继续追问）

> 第一，为什么不是一个大模型一次写完七章？长文本会退化，章节之间会串味，token 也顶不住。我们是七章并发，每章一个独立资料袋，章节内按 21 节的结构落位；跨章一致性靠全局事实锚点和包级审计补，不靠模型记忆。
>
> 第二，为什么 A4 最难？因为它是五段里最密集地把“自然语言生成”和“机器审计”放在同一个环节的地方。A1 的难点在取数覆盖，A2 在计算口径，A3 在图和量纲，A5 在整份报告的复核和签发；A4 要把上游的事实写成文字，还要让每一句都能回到证据。写得好不等于写得对，写得对也不等于修得对。
>
> 第三，怎么保证不编数字？三层：提示词限定只能用本章资料袋；每段强制 `evidence_ids`；代码做数值语义审计，fail-closed，光有证据 ID 不够，要同实体、同指标、同期间、同单位。假设说明不能给事实数字豁免；指标卡和对比表也要绑证据。缺操作数就写缺口，不猜。
>
> 第四，修不好怎么办？先退避重试，再章内修复，再段落隔离，再确定性兜底，最后 `partial` 如实上报。A4 不阻断流转，是让问题可见；A5 再压成受限草稿。硬阻塞人工也绕不过去。我们宁可少写一段，也不猜一个单位。

## 7. 高频追问速答

**问：为什么不让一个模型一口气写完七章？**

> 长文本会退化、章节会串味、token 顶不住。七章并发、每章独立资料袋，控 token 又保证证据定位准；代价是跨章一致性要靠全局锚点和 A5 印前复检。

**问：七章并发怎么保证一致性？**

> 不靠模型记忆。靠 `global_facts` 统一总市值等全局数字，靠 `_audit_package` 查 7 章 21 节、单图单处、跨章量级冲突，最后 A5 再做整份报告的四维审计。

**问：A4 质检没过，为什么还能进 A5？**

> A4 不过不阻断，是设计选择：让问题可见，而不是悄悄停在 A4。A5 才是签发门，过不了就只出受限草稿；硬阻塞人工也绕不过去。

**问：怎么保证模型不编数字？**

> 提示词只是第一道。真正的兜底是代码：每段 `evidence_ids`、数值语义审计、假设说明不豁免、指标卡/对比表必须绑证据、未知证据过滤留痕。缺操作数就写缺口，不猜。

**问：修复会不会越修越错？**

> 会，所以每次修复先深拷贝 trial，重跑审计；只有该段问题消失且不新增问题才接受。候选润色新增问题就拒绝；不行就保留有据从句或隔离，最后确定性兜底。

**问：为什么图号不能当依据？**

> 图是证据的呈现，不是证据本身。图号只能定位；图里的点必须能回到原始证据、能复算。A4 正文引用图号，但数字必须绑原始 `record_id`。

**问：净现比为什么不能自己算？**

> 净现比是经营活动现金流 / 归母净利润，分母必须是归母净利润。A4 只允许引用 A2 已核验值；没有同口径值就写“缺少同口径归母净利润，净现比无法计算”，不许拿合并净利润重算。

**问：A4 和 A5 的边界？**

> A4 编制、自校、把问题标出来；A5 复核、签发、决定正式/受限/阻断。A4 可以是 `partial`，A5 才决定能不能发。

**问：A4 用的是什么框架？是 LangGraph 或 PiAgent 吗？**

> 不是。项目运行时是 FastAPI + 自研 `StateMachine` + `FiveAgentsAdapter`，A4 是独立 Python 包 `agents_core/chapter-writer`，只依赖 httpx、pydantic。PiAgent 更像开发时用的 coding agent，不是交付运行时。

**问：A4 用的是哪个模型？**

> 同一套 OpenAI 兼容接入层，不是五个不同大模型。A4 默认 `deepseek-chat`，实际 `.env` 是 `deepseek-v4-flash`，温度 0.2，`max_tokens=16384`；七章并发，每章一次主生成，失败才加修复调用。

**问：21 节是并发的吗？**

> 不是。代码是七章并发，每章一次主模型调用；21 节是章内结构，不是 21 个并发任务。按代码讲更稳。

## 8. 边界和数字口径

1. **A4 保证的是“有据、可查、可降级”，不是“文采好”。** 结构合规、证据合规之后，表达质量仍要人审；这次 8 段核心数字段盲评平均 0.5833，说明“能发”和“写得好”是两件事。
2. **A4 正常业务状态只有 `completed` / `partial`；`failed` 是适配层防御分支。** `partial` 不是崩溃，是审计发现了问题。
3. **A4 的 `quality.passed=False` 不等于“整份报告废了”。** 它表示有段落/章节没过审计；A5 会按严重级别决定正式、受限或阻断。
4. **不要把不同 run 的数字混着讲。** 这次 A4 专项验收是 7 章 21 节 52 段、47 段带证据、0 悬空、0 跨章完全重复；现场演示如果换另一份报告，数字以现场那份为准。机制不变。
5. **上游 A2 的已知缺陷不算 A4 的功劳，也不算 A4 的锅。** 金额缺单位、期间口径不齐，是 A2 数据层的问题；A4 的职责是不把不可比的数据写成确定结论，宁可写缺口。
6. **A4 的 `evidence_coverage` 是“被引用证据 / 全库证据”的全库覆盖率，不是“段落带证据比例”。** 对外讲“47/52 段带证据”更直观，不要把它和 `evidence_coverage` 混成一个数。
