## 一、这份文档记录什么

### 1.1 先说明一件事

本系统使用第三方大模型接口（火山方舟 DeepSeek-V4-Flash），**不训练模型权重**。因此本文所说的「训练」，指的是把通用大模型调教成能稳定产出可交付研报的全部工程工作，分三个层面：

| 层面 | 内容 | 本文对应章节 |
|---|---|---|
| 提示词层 | 11 个提示词模块的角色设定与约束条文 | 第二、三章 |
| 流程与协议层 | 智能体之间怎么交接、哪些事不交给模型做 | 第四章 |
| 接入参数层 | 模型选型、超时、并发、输出上限 | 第五章 |

### 1.2 为什么单独记录这一块

大模型在严肃投研场景里的问题不是「不会写」，而是三种更难处理的毛病：

1. **编造**——在没有数据支撑的地方写出看起来合理的数字；
2. **跑题**——把不在研究范围内的行业或公司混进来；
3. **失控**——同一个输入每次输出都不一样，无法复现。

本文记录的就是针对这三类问题的具体处置方式。**每一条约束条文背后都有一次实际碰壁**，不是凭空设计的。

## 二、提示词体系全景

全系统共 11 个提示词模块，分布在与五个处理阶段对应的智能体里：

| 阶段 | 提示词模块 | 承担职责 |
|---|---|---|
| 数据获取 | 需求理解 | 解析投研意图，推导相关/互斥行业大类，拆解细分环节，提取重点标的 |
| 数据获取 | 任务规划 | 编排数据查询任务，控制查询节奏 |
| 数据解读 | 技能规划 | 根据数据特征自主挑选方法论技能 |
| 数据解读 | 语义分析 | 从确定性计算结果中提炼洞察与事实 |
| 数据解读 | 技能执行 | 按技能方法论深挖单项分析 |
| 数据解读 | 多技能联合执行 | 多项技能联合分析的输出控制 |
| 图表生成 | 图表设计 | 图表选型、形态多样性与抑制判断 |
| 章节写作 | 章节撰写 | 按大纲逐节生成结构化正文 |
| 章节写作 | 写作技能规划 | 选择写作方法论技能 |
| 报告融合 | 总编审校 | 术语统一、跨章过渡、摘要提炼 |
| 报告融合 | 融合技能规划 | 选择审校方法论技能 |

**模块拆分的理由**：同一阶段内，需要模型判断的「决策」与需要模型执行的「产出」性质不同。把规划、分析、产出分开，每个提示词只需管好一件事，约束更容易写具体，出问题也更容易定位到是哪一环。

## 三、分阶段的关键约束与由来

### 3.1 数据获取：把「该怎么查」变成规则

**第一，先定界，再查数。** 需求理解模块要求模型先产出两组行业清单：相关行业大类与互斥行业大类。比如研究「新能源车」，互斥清单里明确列出通信、石油石化、房地产、建筑材料、食品饮料。这一步的价值在于：**把「哪些不该出现」在查询之前就写死**，而不是等数据回来再过滤。

**第二，拆细分环节，穿透宽泛概念。** 模块要求拆出 2~4 个代表性细分环节。以「宠物经济」为例拆为宠物食品、宠物用品、宠物医疗；「具身智能」拆为机器人减速器、伺服电机、人形机器人、灵巧手。原因很直接：**宽泛概念板块的检索结果里塞满了蹭概念的公司，只有落到细分环节才能查到真正的赛道标的。**

**第三，公司名与产业环节必须分开。** 提示词里专门写了一条规则：只提取用户明确提及的具体企业名称，不要把「减速器」「传感器」这类产业环节当成公司名。这是实际踩过的坑——早期版本会把环节名填进公司清单，导致后续查询方向跑偏。

**第四，查询必须分层递进，不许一次问完。** 任务规划模块里有一条强约束，原文是「严禁一次性盲目查询全部领域，必须实施分层查询，层层递进」。提示词还给了原因说明：数据接口底层是自然语言解析器，如果在单轮里倾泻七个领域的全部任务，或在单句里堆砌多重条件（例如「某行业 市盈率 市净率 涨跌幅 板块排名 A股 按总市值降序」），**极易造成词槽冲突、返回零结果，或因自愈降级而引入跨界巨头**。因此规划被强制拆成三轮：第一轮确权定界（锁定标的池与基准），第二轮锚定主体（针对龙头做点对点穿透），第三轮定向补齐（按缺口补采）。

**第五，规划模块不许写事实。** 提示词明确规定：只能选择给定技能并生成查询任务，**绝对不能在输出中写入金融事实、数值或研究结论**。这条约束的目的是保持职责单一——规划就是规划，事实必须来自真实数据源。

### 3.2 数据解读：把「只能说数据里有的」写成硬约束

**第一，唯一事实来源。** 语义分析模块的第一句就是：唯一事实来源是输入中的确定性计算结果与证据索引，**不得补充外部未经证明的事实，不得给出投资建议**。当证据不足时，明确写出「证据不足」，而不是绕过去。

**第二，计账币种单独列条。** 提示词里有一节叫「计账币种硬约束」：所有金额指标的计量单位以输入中的人民币为准，**未经实时汇率换算，严禁直接篡改计账币种符号**（严禁把人民币标注为港币或美元）。单列一条的原因是这个错误很隐蔽——数字没错，单位错了，读者看不出来。

**第三，区分赛道龙头与混业巨头。** 提示词要求：分析竞争格局时优先聚焦业务纯正度高的企业；**如果市值最大的企业属于混业跨界或外围概念标的，必须明确指出其主要业务来源，不得把它的整体财务波动等同于该细分赛道的核心现状**。这条是针对「市值大 ≠ 赛道核心」这个投研常识写的。

**第四，置信度必须标注。** 每条结论都要带置信度（低/中/高三档），不允许只给结论不给把握程度。

**第五，用代码兜住确定性计算。** 解读阶段的关键指标（增速、比率、集中度、估值分位、离群检测）由确定性计算引擎产出，模型拿到的输入已经算好的结果，它只负责归纳与表述。**模型不参与算术**，这是整套系统里最重要的一条分工。

### 3.3 图表生成：把「好看」和「合规」分开

**第一，多样性是硬指标。** 提示词明确写明「严禁整篇研报图表形态单一（严禁通篇只使用简单柱状图）」，要求一套图表至少涵盖四种以上形态，并逐类说明了适用场景：双轴组合图看规模与增速、四象限定位图看竞争分化、发散条形图看正负偏离、环形构成图看份额、多维雷达图看能力对比、产业链拓扑图看价值分布。

**第二，数据不足时必须抑制，并说明理由。** 提示词规定：若某类图表缺乏必要数据支撑（如没有连续时序却画折线、没有完整结构却画饼图、不同估值口径强行混画），**必须主动抑制，并说明专业原因**。这比「画不出来就报错」更符合业务实际——投研报告里，「因为数据不连续所以不做趋势图」本身就是一条有价值的判断。

**第三，图表要分散，不许堆在一章。** 提示词给出七章架构下各章的图表定位，并规定单章节图表数控制在 2~4 张以内，明确禁止把图表全部塞进某一章。

**第四，模型只做决策，配置由代码生成。** 这是图表层最重要的协议设计，详见第四章。

### 3.4 章节写作：约束最密集的一环

章节写作的提示词里列了九条严格约束，是全系统约束密度最高的模块。

**断言主旨驱动。** 每节先给 2~4 条可独立阅读的结论要点（25~80 字），结论前置、数字优先；章级摘要控制在 60~100 字，且明确「严禁跨章重复或与全篇宏观摘要雷同」。

**点名禁用套话。** 提示词里直接写出了禁止出现的表达：「已有资料显示」「当前资料未形成确定证据」等。规则是：**有证据就直接下判断，证据不全就明说缺口并归入不确定项**，不许用模糊表述糊过去。

**段落颗粒度受控。** 普通段落 120~260 字，一段只讲一个判断。段落类型必须从八种受控值里选：核心判断、数据论据、同业对标、图表解读、风险因素、口径方法、承上启下、情景推演。**用受控枚举代替自由发挥**，是让输出结构稳定的关键手段。

**图表引用必须显式。** 正文提到图表时必须写出完整占位符（如 `[CHART-xx]`），严禁只写「如图所示」；反过来，若本节没有挂接图表，就严禁插入任何占位符。这条规则同时管住了「引用了不存在的图」和「画了图却没人提」两种毛病。

**情景推演三要素。** 针对预测性章节，要求给出乐观、基准、悲观三档情景，每档必须包含：核心触发条件、经营与财务推演结果、可观测的前瞻跟踪阈值。此外必须附非外推声明，说明样本代表性的边界。

**全局事实必须锚定。** 提示词里给了一个很具体的反例：禁止在不同章节出现数量级矛盾（如 22.14 万亿与 2.21 万亿的十倍冲突）；企业的产业链环节归属也必须前后一致，**严禁同一标的上中下游反复横跳**。

**非宏观章节不许扯宏观套话。** 除宏观专章外，产业、竞争、财务章节不得重复展开与本节无关的宏观指标免责声明，保持对本行业真实财务与竞争态势的专注。

**输出必须是纯合法 JSON。** 禁止在开头加 Markdown 标题，禁止代码块外围文本，正文内引号使用中文引号。

### 3.5 报告融合：权限最小化

到总编审校这一环，模型的权限被压到最小。

**只能编辑，不能补充。** 提示词第一句就是：「只能编辑已有内容，不能补充外部事实、数字或来源。技能只提供编辑方法，绝不是事实来源。」

**默认禁止重写。** 段落微调映射「通常必须保持为空」；确实需要改动时，严禁大段重写，**严禁改动任何数字，包括股票代码、年份、列表序号，必须百分之百原样保留所有精确字面值**，且必须完全复用原段落的证据编号。

**术语映射严格限缩。** 术语归一表只用于极少数专业别名统一（如把「动力锂电池」归一为「动力电池」），并规定：严禁把专业术语或指标代码替换成长句解释，映射后的词不超过八个字、不得包含任何标点，不需要归一就留空。

这样设计的理由是：**正文的事实与数字在上一环已经过严格核对，总编阶段的职责是统一表述，不是重新创作。** 给它越小的改动权限，引入新错误的机会就越少。

## 四、流程与协议层的四个设计

### 4.1 图表生成协议：模型做决策，代码做配置

早期做法是让模型直接输出完整的图表配置。结果有三个问题：输出量大导致耗时长、JSON 括号极易出错、以及**金融图表的合规要求（如零轴不能截断）无法靠模型自觉遵守**。

优化后的协议是：模型只做语义决策——指定图表类型、X/Y 轴对应的指标、标题与解读重点；**具体配置由本地确定性编译器根据决策生成**，包括坐标轴、单位、零轴规则、图例与配色。这样做的收益是三重的：生成时间大幅缩短、格式错误不再出现、合规规则由代码强制保证，不依赖模型是否记得。

### 4.2 关键统计与模型的边界

增速、比率、集中度、估值分位、离群检测这些计算，全部由确定性引擎完成。模型看到的是算好的结果，它的任务是把结果讲清楚。

这条分工的实际意义在于：**模型算错的概率无法通过提示词消除，而算错之后表述往往依旧流畅**，这类错误在成稿里极难被发现。把算术剥离出去，数字的正确性就变成了可复算、可追责的代码问题。

### 4.3 事件抽取：模型判断 + 确定性规则兜底

公告与事件类数据的结构化抽取，采用模型判断与规则兜底的双轨：模型负责识别文本中的事件信号，当事件类型无法判定时，由十三条确定性关键词规则完成类型推断；字段缺失时只留痕、不造数。

**双轨设计的原因**：纯规则覆盖不全，纯模型判定不稳定。让模型做它擅长的语义识别，把兜底交给不会疲劳的规则。

### 4.4 智能体交接：契约化而不是自由对话

五个智能体之间不通过自然语言对话传递结果，而是通过结构化契约传递。每个阶段的输出有明确的字段定义，下一阶段只读取它需要的字段。

这样做带来两个直接好处：**一是可校验**（字段缺失或类型不符能在交接处立即发现），**二是可追溯**（每条数据从进入到成文，编号一路携带，中途不丢失）。

## 五、模型接入与参数配置

| 参数 | 取值 | 设置理由 |
|---|---|---|
| 模型基座 | DeepSeek-V4-Flash | 中文金融语料表现稳定，推理速度与成本的平衡点适合长流程多次调用 |
| 推理强度 | low | 本系统的分析深度由流程与提示词保证，不需要模型在单次调用里做长链推理 |
| 单次超时 | 180 秒 | 章节撰写是单次耗时最长的调用，留足余量的同时避免异常请求长时间挂起 |
| 单次输出上限 | 16384 tokens | 覆盖单章结构化的最大输出；超出会截断，因此章节拆到节级调用 |
| 数据技能并发 | 7 | 与数据服务的并发承受能力匹配；过高会触发限流 |
| 章节并发 | 7 | 章节之间无依赖，可并行；实际运行中七个章节接近同时完成 |

**并发参数的取值逻辑**：并发设得高不等于更快。数据服务的限流信号一旦触发，降级与重试反而拖慢整体；实测把并发控制在七路时，四十八个主题的批量运行全程未出现限流中断。

## 六、调优方法总结

**一、约束要具体到可以判定。** 「写得专业一点」是无法执行的；「章级摘要控制在 60~100 字」「段落 120~260 字」才可以。凡是能给出数字的约束，都给了数字。

**二、把不确定的事交给代码。** 算术、格式、坐标轴规则、字段校验——凡是有确定答案的，都不交给模型。留给模型的是真正需要判断的部分：意图理解、策略选择、语言组织。

**三、允许模型说「不知道」。** 提示词里反复出现「证据不足就明说」「数据不连续就不画趋势图」。**一个被允许承认缺口的模型，比一个被要求处处给出答案的模型更可靠**——前者留下的空白是可见的，后者留下的空白会被填满看起来合理的内容。

**四、给反例，不只给要求。** 提示词里保留了大量具体反例：「22.14 万亿与 2.21 万亿的十倍冲突」「同一标的上中下游横跳」「把减速器当成公司名」。抽象要求容易被遗忘，具体反例不容易。

**五、每一步的错都要在下一步之前被拦住。** 数据获取阶段定好互斥行业，解读阶段就不会混入跨界公司；解读阶段标好证据编号，写作阶段就无法引用不存在的证据；融合阶段只给编辑权限，成稿的数字就不会被改动。**整套体系的可靠性来自层层拦截，而不是某一环做得特别强。**
