## 1. 测量方法与可信度

数值不是目测，是从参考图里**程序化量出来的**（Pillow + numpy，`backend/.venv`）：

- **几何**：按亮度阈值扫暗像素求 bbox、逐行/逐列扫描找分隔线、按块分组找每个文字块的起止 x。
- **颜色**：区域内"最暗 8% 像素的中位数"作为墨色，避开 JPEG 过冲产生的假纯黑。
- **字号**：用墨迹高度反推（中文字面高 ≈ 0.86em），再用"整行宽度 ÷ 字数"交叉校验。

可信度分级：

| 类别 | 精度 | 说明 |
| --- | --- | --- |
| 分隔线 y / 按钮 bbox / 各文字块 x 起止 | ±2px | 直接量出 |
| 字号 | ±5% | 逐字字距 + 墨迹高度两法交叉 |
| 颜色 | ±2 色阶 | JPEG 有压缩噪声 |
| 插画子块坐标 | ±10px | 卡片带旋转，边界模糊 |

## 5. 逐区块实现规格

### 5.1 顶部导航（y 0–113）

- **布局**：`display:flex; align-items:center; height:113px`；左侧 Logo 组，右侧导航组；左右贴容器边（72 / 1470）。
- Logo 组：中文 + 英文，`gap: 6px`，英文基线对齐中文底部（`align-items: baseline` + 微调）。
- 导航组：`gap: 48px`；最后一项「个人」前有一个 **circle-user 图标**（描边风格，约 22px），图标与文字间距 8px。
- 底线：容器内 1px `#E2DAD0`，**不要通栏**。
- hover：文字转 `--hp-ink`；`focus-visible`：2px 金圈 + `outline-offset: 3px`。
- 导航映射建议：`首页 → /`、`我的任务 → /runs`、`研究能力 → #capability`、`帮助 → #help`（后两个先做页内锚点，避免造死链）。

### 5.2 Hero 左栏

- 整栏左边界 x=72（H1/按钮的墨迹会因字体侧边距落在 82 左右，属正常）。
- **垂直节奏**（导航底线 113 起算，全部按墨迹量）：
  - H1 第 1 行墨迹顶 **214** → 距导航底线 **101px**
  - H1 行距 **76px**（第 2 行墨迹 290–342）；H1 字号 55px → `line-height: 1.38`
  - H1 末行墨迹底 342 → 副文案第 1 行墨迹顶 382 → 间距 **40px**
  - 副文案行距 **39px**（第 2 行墨迹 421–441）→ `line-height: 1.70`
  - 副文案末行墨迹底 441 → 按钮顶 492 → 间距 **51px**
- H1 硬换行：`把产业研究，` / `从资料搜集推进到可审核报告`。**用 `<br>` 或 `white-space: pre-line` 固定**，不要靠宽度自然折行。
- 副文案硬换行：`5 个专业智能体协同完成数据采集、分析解读、图表生成、` / `每一步都保留证据、版本与人工审核入口。`
  ⚠️ 参考图第 1 行以顿号「、」收尾接管到第 2 行，读起来是断裂的（正常应为「，」或把「每一步…」并入同一句）。
  实现时建议改成 `5 个专业智能体协同完成数据采集、分析解读、图表生成、章节写作与报告融合，` /
  `每一步都保留证据、版本与人工审核入口。`——**换行位置不变，视觉一致，语义通顺**。是否采纳需你确认。
- CTA 按钮：`height:59px; padding:0 26px; border-radius:4px; background:#11365E;`，文字后跟一个 chevron（可用 `›` 字形或 12px SVG，间距 10px）。
  - hover：底色加深到 `#0D2B4C` + `translateY(-1px)` + 阴影；`active`：回弹到 0。
  - `focus-visible`：`0 0 0 3px rgba(176,143,82,.55)`。
- 「查看演示报告」：`<a>`，无下划线，hover 加金色下划线。跳转建议指向演示 run：`/runs/mock-amd-001`（`DEMO_RUN_ID`，见 `src/mock/fixtures/realBatteryData.ts:18`）。

### 5.3 特性区（y 746–892）

- 顶部 1px 线（x 67–1471），标题墨迹顶距线 **40px**。
- 3 列：`grid-template-columns: 1fr 1fr 1fr`，列 2/3 用 `border-left: 1px solid #E6DED2` + `padding-left: 62px`；列 1 `padding-left: 0`（内容单元再整体内缩 19px，使墨迹落在 91）。
  > 实测分隔线在 x=506 / x=1014，与"等分"不严格吻合（AI 生成图的不一致），**按等分实现即可**，diff 阶段校正。
- 竖线高度 ≈76px（约等于标题+描述的总高），用 `align-self: stretch` 或固定 `height:76px`。
- 列内：标题（衬线 33px）→ 距 20px → 描述（无衬线 18px），两者都左对齐、单行不换行。
- 移动端：3 列塌成 1 列，竖线改横线（`border-top`）。

### 5.4 底部 5 步流程（y 892–1024）

- 顶部 1px 线（x 70–1468）；序号墨迹顶距线 **39px**；底部留白 ≈59px。
- 结构：5 个等宽单元，节距 **294px**；单元内 = `序号(衬线 46px 金) → 8px → 标签(23px) → 20px → 双金线(94px)`；**最后一个单元不画线**。
- 双金线实现（二选一）：
  ```css
  /* 1) border 双线 */
  .dbl { height:5px; border-top:1px solid #B08F52; border-bottom:1px solid #B08F52; }
  /* 2) repeating-linear-gradient，更稳（避免 1px 亚像素抖动） */
  .dbl { height:5px; background: repeating-linear-gradient(
      to bottom, #B08F52 0 1px, transparent 1px 4px); }
  ```
- 移动端：5 步改纵向时间线（序号在左，标签在右，去掉连接线）。

## 6. 右侧插画重建方案（本页最花功夫的地方）

### 6.1 为什么不建议裁图

| 方案 | 优点 | 缺点 |

### 6.4 折线卡里的图

- 用 **内联 SVG 手绘 polyline**（`viewBox="0 0 260 120"`），**不要引 ECharts**——这里只是装饰插图，引入图表库会白拉 300KB。

## 8. 「开始制作研究报告」跳转与落地方案

目标 URL：`http://127.0.0.1:5173/`（= 现有 Vite 应用根，当前是创建任务表单 `HomeView.vue`）。

### 方案 A：独立页（推荐，1:1 最稳，零侵入）

- 落点：`frontend/public/home.html`（单文件，内联 CSS/SVG，不引构建依赖）→ 预览地址 `http://127.0.0.1:5173/home.html`。

- 好处：不碰 `router.ts` / `App.vue` / Element Plus 全局样式，样式 100% 可控，diff 干净。
- 代价：不在 SPA 路由内，导航项要用绝对地址；刷新不保留 SPA 状态（首页无所谓）。

### 方案 B：作为 SPA 新路由（产品化更正统）

- 新增 `src/views/LandingView.vue`；`router.ts` 加 `{ path: '/home', component: LandingView, meta: { bare: true } }`。
- ⚠️ **必改共享壳**：`App.vue` 现在的 `el-header` 品牌栏 + `el-main` 内边距是**所有路由共用**的，首页要 1:1 就必须按 `route.meta.bare` 条件隐藏（约 5 行改动，属最小改动但需团队 Review）。
- 若要让首页成为真正的"首页"（`/`），还要把现有表单 `HomeView` 挪到 `/create`，此时 CTA 应改为 `/create`，而不是 `/`。

> **建议**：先按 A 交付可验收的 1:1 页面（今天就能看到效果），视图代码写成分块 Component 友好结构，后续若要收进 SPA 直接搬到 B。
> **需要你拍板一件事**：首页最终是"独立页"还是"接管 `/`"？这决定 CTA 指向 `/` 还是 `/create`，以及动不动 `router.ts`。

## 10. 验收清单（截图 diff 迭代法）

**1:1 不是"一次写对"，而是"量-改-再量"。** 流程：

1. 起服务：`cd frontend && npm run dev`（5173）。
2. 用 Playwright（已装）把页面截成 **1536×1024、deviceScaleFactor=1** 的全图。
3. 与参考图做像素 diff：`backend/.venv/bin/python`（Pillow 12.3.0 已可用）输出差分图 + 锚点偏差表。
4. 只修偏差 >8px 的项，重复 2–3，直到下表全绿。
5. 收尾再跑一次 1280 / 768 / 375 宽的可用性检查（此时不看像素，看是否溢出/换行崩坏）。

## 11. 响应式策略

参考图只有 1536 一档，其余档位是按 1:1 稿**等比推导**（下表给系数，不是实测）：

| 断点 | 策略 | 关键换算 |
| --- | --- | --- |
| ≥1440 | 1:1 保真；容器 `width: min(1398px, 91vw)` | 尺寸不动，靠容器收边 |
| 1280–1439 | 整体等比 ×0.83–0.94（H1 63→52、插画 ×0.85 并右贴） | 用 `clamp()` 或 `--hp-scale` 变量统一缩放 |
| 768–1279 | 单列：左文案 → 插画（缩到 70%，居中）；特性 3→1 列；流程 5→纵向 | 导航保留 4 项、字号降到 16–18px |
| <768 | 移动：导航压成 Logo + 汉堡；H1 34–40px；副文案 16px；CTA 全宽 52px 高；插画缩到 60% 或换静态图；流程纵向时间线 | 触摸目标 ≥44×44px（现有按钮 59px 达标，导航项需补 padding） |

⚠️ 移动端不要试图保留插画的全部细节——按"主卡 + 流程条"两层呈现即可，否则小屏会糊成一团。
