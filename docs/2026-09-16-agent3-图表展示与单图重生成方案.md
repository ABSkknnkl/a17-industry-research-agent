# Agent 3 阶段图表展示与单图重生成 · 设计方案

> 2026-09-16 · 状态：待评审
> 目标：智能体 3（chart_generate）阶段从「只看候选表」升级为「看图 + 单图操作」，
> 卡片样式对齐参考图（标题 + 版本徽章 + 来源行 + 图表 + 操作），
> 并提供**重新生成单张**与**取消该图**两个动作。

---

## 一、现状盘点（实测结论）

### 1.1 现在用户看到什么

`StageDigest.vue` 的 chart_generate 区块（第 258–269 行）：

```
生成的图表（8 张）
┌──────────────┬──────────┬────────────────────┐
│ 图表编号      │ 图表类型  │ 标题               │
│ CHART-XXX…   │ bar      │ 新能源汽车销量…     │
└──────────────┴──────────┴────────────────────┘
对单张图表进行操作，请看右侧「图表」标签中的卡片菜单   ← 失效提示
```

**问题**：只有文字表格，没有图；提示里说的「右侧『图表』标签」**不存在**（ReviewView 没有图表 tab）。

### 1.2 已存在但没接线的资产（这是本次方案的地基）

| 资产 | 位置 | 状态 |
|---|---|---|
| 图表画廊组件 | `frontend/src/components/ChartGallery.vue` | ✅ 功能完整（ECharts 渲染 / SVG 内联 / 大图预览 dialog / dispose 管理），**但未被任何页面引用**（只有单测引用） |
| 单图操作菜单 | `frontend/src/components/review/ChartControlMenu.vue` | ✅ 按钮齐全：预览 / 重新生成 / 纳入报告 / 移出报告 / 删除 / 撤销删除 |
| Mock 单图重生成 | `mock/prototypeRun.ts:571` `regenerateChart()` | ✅ 已实现（running → unit_revision+1 → active） |
| 真实渲染数据 | 后端 `chart_generator/service.py:1250` `payload = generation.model_dump()` | ✅ `chart_specs[].option` 含完整 ECharts 配置（实测真实产物 17 张图可渲染） |
| 大图预览 dialog | ChartGallery 内置（780px） | ✅ |

**结论**：本次 Phase 1 的核心工作是「把已有的 ChartGallery 挂进 StageDigest + 补头部信息」，
不是从零造轮子。

### 1.3 真实模式的缺口（Phase 2）

| 缺口 | 现状 |
|---|---|
| 单图重生成 API | ❌ 不存在。真实模式只有阶段级 `POST /runs/{id}/reviews`（action=regenerate 整批重跑） |
| 单图删除/移出 | ❌ 同上。`customize` action 可带 `selected_chart_ids`，但那是「提交审核时勾选」，不是随时单图操作 |
| ChartSpec 的头部字段 | ❌ `chart.py:281` 的 ChartSpec 没有 `source_name` / `updated_at` / `unit_revision` 字段 |

## 二、设计决策（我定的，理由附后）

### 2.1 放在哪：StageDigest 内嵌图表卡片，删掉候选表

```
当前阶段：图表生成 [待复核]              r2
─────────────────────────────────────────────
生成的图表（8 张）          ← 标题保留
┌───────────────────────────────────┐
│ 新能源汽车销量及增长率趋势   [v2·最新] │  ← 卡片头：标题 + 徽章
│ 柱状图 · 来源：中汽协 · 2025-05-24  │  ← 副信息行
│ ┌───────────────────────────────┐ │
│ │      （ECharts 230px 高）      │ │  ← 图表本体，点击放大
│ └───────────────────────────────┘ │
│ [预览] [重新生成] [移出报告] [删除]  │  ← 操作行
└───────────────────────────────────┘
…（其余 7 张同构）
```

**决策理由**：

1. **不打断审核上下文** —— 用户看 Agent 3 产出就是为了逐张看图决定保留/重生成，跳到别的 tab 再跳回来是反模式
2. **组件已存在** —— ChartGallery 就是这个形态，挂载 + 增强即可
3. **删除失效提示** —— 「右侧『图表』标签」那句话一并删掉，消除误导

**不做的事**：不在 ReviewView 右侧新增「图表」tab。理由：ReviewView 主列已很满（步骤条 + 指标卡 + 摘要 + 操作面板），再切 tab 增加导航成本；卡片纵向流与现有证据审核/结论审核列表的视觉语言一致。

### 2.2 卡片结构（对齐参考图）

```
┌────────────────────────────────────────────┐
│ 标题（衬线、藏青、700）      [v3] [最新]     │  ← 头部行
│ 类型 · 来源 · 更新时间         [状态徽章]    │  ← 副信息行
│ ┌────────────────────────────────────────┐ │
│ │            图表本体 230px               │ │  ← 点击 → 大图预览
│ └────────────────────────────────────────┘ │
│ 分析目的：……（可选，insight_goal）           │
│ 注：纵轴未从 0 开始 …（footnotes，最多 2 条） │
│ [预览] [重新生成] [纳入/移出报告] [删除]     │  ← 操作行
└────────────────────────────────────────────┘
```

字段来源与降级策略：

| 卡片元素 | 数据来源 | mock | 真实 | 缺失时 |
|---|---|---|---|---|
| 标题 | `chart_specs[].title` | ✅ | ✅ | 「未命名图表」（ChartGallery 已有） |
| 版本徽章 `v3` | mock：`ChartItem.unit_revision`；真实：**没有该字段** | ✅ | ❌ | 不显示徽章 |
| 「最新」徽章 | 同一张图 unit_revision 最大者 | ✅ | ❌ | 不显示 |
| 类型 | `chartTypeLabel(chart_type)`（labels.ts 已有） | ✅ | ✅ | 原始值 |
| 来源 | mock：证据的 `source_name`；真实：**无字段** | ✅ | ❌ | 不显示该行 |
| 更新时间 | mock：`as_of_date`；真实：**无字段** | ✅ | ❌ | 不显示 |
| 图表本体 | `option` → ECharts；`generated_image` → img | ✅ | ✅ | 占位文案（已有） |
| 分析目的 | `insight_goal` | ✅ | ✅ | 不显示 |
| 脚注 | `footnotes`（质量提示） | ✅ | ✅ | 不显示 |
| 状态徽章 | 生成中/待复核/未纳入报告 | ✅ | ❌ | 不显示 |

> **设计原则：字段缺哪个就缺哪个，绝不用假数据填充。** 来源/更新时间/版本在真实模式的补齐列入 Phase 2 后端任务。

### 2.3 两个动作按钮

| 动作 | 语义 | 现有能力 | 本次处理 |
|---|---|---|---|
| **重新生成单张** | 只重跑这一张图的 builder | mock：`regenerateChart` ✅；真实：❌ 无 API | mock 直接可用；真实模式按钮**置灰 + tooltip「演示环境可用」**，Phase 2 补 API |
| **取消这张图表** | 用户不想让它进报告 | mock：删除（可撤销）+ 移出报告 ✅ | **复用，不新增按钮**。删除是软删（可撤销），移出报告是轻量动作，两级语义已足够 |

「取消」最终形态 = 卡片上的「移出报告」（轻）+「删除」（重，可撤销）。**不新增第三个按钮**——三个否定按钮只会让用户选恐。

## 三、视觉规范（严格对齐项目设计系统）

项目已有完整设计令牌（`frontend/src/style.css:1-45`），新样式全部走变量，不写死颜色。

| 元素 | 规范 | 令牌 |
|---|---|---|
| 卡片背景 | 暖白卡片底 | `var(--rp-card)` `#fffefb` |
| 卡片边框 | 1px 浅棕线，圆角 8px | `var(--rp-line)` `#e3ddcd` |
| 标题字体 | 衬线、加粗 | `var(--rp-serif)` + `font-weight: 700` + `color: var(--rp-navy)` |
| 版本徽章 | 描边 tag，藏青边 | `el-tag` `type="primary"` `effect="plain"` |
| 「最新」徽章 | 金铜底白字（项目里 warning 即金铜） | `el-tag` `type="warning"` |
| 副信息行 | 12px 次要文字 | `color: var(--rp-ink)` + opacity 0.65 |
| 主按钮（重新生成） | Element Plus small link，主色 | 默认（主色已被项目覆盖为藏青） |
| 危险按钮（删除） | `type="danger"` link | 默认 |
| 图表区 | 230px 高，米白底 | `background: var(--rp-paper)` |
| 操作行 | 与 ChartControlMenu 现有样式一致 | 复用 |

**与参考图的差异说明**：参考图是横版头部（标题在左、徽章在右、来源行在下）。
审核页主列宽约 700–900px，纵向卡片更适合滚动审阅，因此采用**纵版卡片**（标题区在上、图在下），
信息层级与参考图一致，只是排版方向随容器调整。

### 无障碍与交互底线

- **触摸目标**：按钮高度 ≥ 28px（Element small 标准）；卡片整体 hover 出放大光标
- **加载态**：「重新生成」点击后按钮变「生成中…」+ 禁用，卡片出 `生成中` tag（ChartControlMenu 已有）
- **错误态**：操作失败用 `ElMessage.error`，不清空用户已做的其他操作（项目既有模式）
- **动效**：ECharts 配置 `animation: false`（真实产物已内置），无眩晕问题
- **实例泄漏**：ChartGallery 已有 `disposeThumbs()` + `onBeforeUnmount` + ResizeObserver，挂载后逐卡验证

## 六、风险与边界

| 风险 | 应对 |
|---|---|
| ChartGallery 从未挂载过，可能有隐藏 bug | 挂载后先跑真实产物数据手测一遍（17 张图） |
| 5+ 张 ECharts 实例的性能 | ChartGallery 已做 ResizeObserver + dispose；若卡顿再引入懒渲染（IntersectionObserver） |
| 真实模式 SVG 产业链图 | `render_mode=generated_image` 且 `image_uri` 有值时正常；AI 图未内联时已有占位文案 |
| 用户误解「删除」为物理删除 | 确认框已写明「可撤销」（ChartControlMenu 现有） |
| Phase 2 改 ChartSpec 字段 | **先 grep 确认 `ChartGenerationResult.model_json_schema` 是否被用作 LLM 输出 schema**，是则只能阶段数据层注入（参照 contracts/README.md 的教训条目） |

## 七、一句话总结

**Phase 1 是把一个写好了但没接线的组件（ChartGallery）挂进 Agent 3 阶段，加上项目设计系统的卡片头；单图重生成 mock 立即可用，真实模式等 Phase 2 的对象级 API。**
