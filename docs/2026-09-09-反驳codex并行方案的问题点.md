# 反驳 codex《全异步跨阶段并行重构方案》的几个点

- 日期：2026-09-09
- 对象：`~/Downloads/2026-09-09-全异步跨阶段并行重构方案.md`（下称 codex 方案）
- 只列**codex 方案里不成立 / 被夸大 / 自相矛盾**的点，每条：codex 原话（带 §）→ 为什么不成立 → 证据。
- 说明：段内并行（Agent4 章节并发、Agent2 两段并发）本身不在此列——那部分我们认同；这里反驳的是 codex 的**跨阶段 DAG**叙事与几处技术前提。

---

## 反驳 1：那张"跨阶段性能表"与"保留每阶段人工审核"自相矛盾

- **codex 原话**：§3.1 给出"总时长快 55–75%、首条可用内容 20–45s"；同时 §11 声称保留人工审核、§7 红线要保审核语义。
- **为什么不成立**：要兑现这张表，必须让下游消费**还没过审的上游 provisional 产物**——codex 自己在 §6 把审核对象从 stage 级改成 artifact 级（evidence/claim/chart/chapter）来做到这件事。但赛题的硬要求是"**每阶段**人工审核"，我们商定的做法也是"**前端仍是阶段级流水线审核，并行只在后端**"。一旦坚持阶段级整体过审才放行下游，链路 `1→2(审)→3→4` 就**串行锁死**（Agent4 要 Agent3 的真实图表、Agent3 要已过审的 Agent2），那张跨阶段表**拿不到**，只剩段内并行的 ~35–50%。
- **证据**：codex §3.1 / §6 / §11 内部张力；v3.1 已证 `1→2(审)→3→4` 串行锁死（`docs/2026-09-07-流水线式并行重构-方向与思路.md` §4.5）。
- **一句话**：codex 的激进收益是**建立在悄悄把审核粒度降到 artifact 级**之上的，它没把这个代价与"保留阶段审核"的冲突讲透。二者只能选一个。

## 反驳 2：Agent2 按证据域分片 + 确定性 reducer，会让研报深度倒退

- **codex 原话**：§4.2 / §5.3——`analysis_worker` 按 finance/growth/competition/policy/risk 等证据域并行产 claim，"每个 shard 只接收相关 evidence"，最后由**确定性 reducer**（"不依赖 LLM 决定合并顺序"）合并。
- **为什么不成立**：真实复合查询是**因果耦合**，不是维度并列；而且最终产物有**硬 schema**要求跨维联合。分片后每个 shard 只看到自己那份证据、reducer 又是确定性的 → **跨维因果 claim 和跨维校验卡都产不出来**。
- **证据**：
  - `eval/cases/intent_golden.json` 复合用例：I-C01/I-C15「市占率**及海外政策影响**」=竞争↔政策（政策是市占率的因）；I-C02「毛利率…**并梳理主营业务结构**」=财务↔业务（业务结构解释毛利率）；I-C12「**增发方案**和最新**财务情况**」=事件↔财务（增发摊薄财务）。
  - `openai_compatible.py:98,103-116`：`AnalysisCoreDraft.dimensions` **恰好 5 维**、`validation_cards` **恰好 3 张跨维校验卡**（口径可比性/财务质量/估值预期）——本质是跨维联合判断，单维 shard 产不出、确定性 reducer 合不出。
- **一句话**：compound 用例是用户主力输入、也是赛题最看重的深度；codex 的分片合并会把它们做浅。

## 反驳 3："全局结论摘要只读快照"是个循环缺口——没人产它

- **codex 原话**：§5.5——章节 prompt 注入"全局术语表 / 结论摘要只读快照"来控一致性。
- **为什么不成立**：这份**跨维结论摘要由谁生成？** 在 codex 的分片架构里，没有任何一个 worker 看得到全维证据，reducer 又是确定性的——**没有生产者**。codex 把一个"被分片删掉的跨维 synthesis 步骤"当成了既有输入来用。
- **证据**：codex §5.3（shard 只吃相关 evidence + 确定性 reducer）与 §5.5（需要全局结论摘要）互相打架。
- **一句话**：只读快照是**一致性补丁，不是深度补丁**；而且它预设了一个方案里根本不存在的 synthesis 环节。

## 反驳 4：chart_worker"早产图"的前提与现状矛盾

- **codex 原话**：§5.4——chart 从"等完整 AnalysisResult"改为消费"verified metric series"，"只要一组时间序列稳定即可出图"。
- **为什么不成立**：现状里 `chart_candidates` **产自 Agent2 的第二段 supplement（末段）**，core 段根本没有图表字段。要"越早出图"，得先改 Agent2 的**输出契约**（把 chart_candidate 的产生从 supplement 拆出来、且能按域独立产出），这不是 codex 说的"消费一组稳定时间序列"那么轻。
- **证据**：`openai_compatible.py:120-134`(supplement 含 chart_candidates) vs `:92-117`(core 无图表字段)。
- **一句话**：codex 低估了 chart 早产所需的 Agent2 契约改造。

## 反驳 5："7 章按维度天然独立、可跨阶段提前写"被夸大

- **codex 原话**：§4.2——`chapter_worker` 7 章并行、按维度提前启动对应章。
- **为什么不成立**：章节↔维度映射只覆盖 CH-02/03/04/06/07；**CH-01 用全部 claims、CH-05 用"估值 claims 否则全部 claims"**，且每章还要吃 supplement 的 `data_quality_issues` 等全局字段。所谓"维度闭包"在代码里**只是 prompt 过滤规则，不是可调度的依赖契约**——所以"某维度分析完就提前写对应章"（跨阶段）不成立。
- **证据**：`chapter_writer/prompt_adapter.py:9-15,34-37,64-70`。
- **注意**：这不否定**段内** 7 章并发（在 Agent2/Agent3 全部完成、图表就绪后，7 章拿各自 prompt 切片同时写）——那个成立；被夸大的是"**跨阶段**按维度提前启动章节"。

---

## 汇总：codex 方案里真正站不住的，就这 5 点

1. 跨阶段性能表 ⇄ 保留阶段审核，**二者互斥**，codex 靠降审核粒度兑现收益却没讲代价。
2. Agent2 按域分片 + 确定性 reducer **做浅 compound 研报**（因果耦合 + 5维/3卡硬 schema）。
3. "全局结论摘要快照"**没有生产者**，是循环缺口。
4. chart 早产图**与"chart_candidates 在 supplement 末段"矛盾**，低估了 Agent2 契约改造。
5. "章节按维度天然独立"**被夸大**，维度映射只是 prompt 过滤非依赖契约（段内并发不受影响，跨阶段提前写不成立）。

> 其余部分（先修 Agent1 取数=0、异步 202+SSE 改善体感、SQLite 并发写要上单写者/WAL 或迁 PG、并发上限自适应防 429、可观测性是上线前置）codex 说得对，不在反驳之列。
