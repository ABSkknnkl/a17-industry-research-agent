01 / POSITION

一页看懂：A4 在流水线的什么位置

A4 不取数、不算指标、不画图。它只做一件事：把 A2 的事实和 A3 的图，装配成 7 章 21 节的可审计章节。A5 再以整份报告为单位复核、签发。

→
A4 章节撰写 chapter_result.json
7 章 21 节
→
A5 报告融合 report.md / .html / .pdf
四维审计 + 签发
大白话：A4 像装配工。零件必须来自仓库（A2/A3），每个零件有编号（evidence_id），图纸是 7 章 21 节；装错不能自己造一个，只能退回、隔离或标缺口。

输入：三份契约

A2 的证据白名单、洞察、发现、财务比率、必答题覆盖；A3 的 ready 图、图表和证据映射；7 章 21 节大纲、人工反馈和写作选项。

  • 少一份 JSON 直接报错，不硬编
  • 每章一个独立资料袋：≤60 条证据、8 条洞察、25 条发现
  • 一张图只能进一个章节

处理：生成—审计—修复

7 章并发主生成；逐段查数字语义、证据 ID、因果、重复、图号、指标卡、对比表、总市值锚点；不合格就修，修不好就隔离或兜底。

  • 每章一次主生成，失败才加修复调用
  • 10 份写作规范，技能选择走章节策略
  • 21 节是章内结构，不是 21 个并发任务

输出：结构化 JSON

chapter_result.json、每章 JSON、events.jsonl。A5 不读 A4 的“文章”，只读这些落盘文件，才能逐段对证据。

  • 段落：paragraph_id、kind、text、evidence_ids
  • 小节：chart_ids、metric_cards、comparison_table、uncertainties
  • 质量：passed、evidence_coverage、issues、fallback_chapter_ids
框架一句话：不是 LangGraph、CrewAI、AutoGen，也不是 PiAgent 运行时。项目是 FastAPI + 自研 StateMachine + FiveAgentsAdapter；五个智能体是五个独立 Python 包，只通过 data/runs 里的落盘 JSON 交接。A4 包在 agents_core/chapter-writer，默认 max_concurrency=7；实际模型走 OpenAI 兼容接口，A4 生产配置为 deepseek-v4-flash、温度 0.2、max_tokens 16384。

03 / HARDEST

最难的一块：不是写，是判得准、修得稳

如果只能选一个智能体，我选 A4。不是因为它代码最多，而是因为文档 3.3 的三条判定链，正好卡在 A4 和 A5 之间：段落连同证据索引进来，出去的是三态判定和裁后文本。

直接回答：如果只能选一个，是 A4；A4 内部最难的是文档 3.3 的三条判定链——断言分型核验、精度裁定、幂等裁剪与修复同源。写作本身不是最难的，难的是写完之后还能被判对、修稳、降级。
为什么是 A4：A2 难在算得准，A3 难在画得对；A4 难在把前两段的结论写成可判的句子。上游的错会在这里变成“看起来专业”的成稿，所以 A4 是章节阶段的语义闸门。

“三者分别回答断言是否成立、两个数是否相等、修复结果是否稳定，串起来构成一条可审计的判定链。”

《最终版-算法质量重写版》3.3

01
文档 3.3.1

断言分型核验

数值、方向、因果、排名、预测、情景，六类断言各有证据标准；判不了就 fail-closed，按 ⊥U 拦截，不靠模型“像不像真的”。

39 条标注集：应拦 21、应留 18；拦截 17/21（81.0%），漏放 4/21，进稿风险 19.0%；误判 1/18（5.6%）。因果、排名各 6/6。
代码落点

financial_semantics.py 的 quantity_issues；A4 的 _audit_chapter 把数值语义、方向、因果问题逐段落成 issues。

02
文档 3.3.2

精度裁定

不用固定百分比容差。从原始披露串反推小数步长，把精细侧按粗侧步长舍入再比；精度不可确认就判 ⊥U，不做猜测。

“精度应视为数据属性，而非可随意设定的参数。” 16.17 与 16.2 判等价；1.2 亿元与 12000 万元同步步长后等价。
代码落点

quantity_issues 的舍入容差按显示末位半单位；A4 的数字复算与 A5 的数值闭环审计共用同一口径。

03
文档 3.3.3

幂等裁剪与修复同源

裁剪只删除、不新增、不跨句拼接；T(T(x))=T(x)。校验和修复共用同一批判据，修完再用同一判据复验；修不好回退，不把错稿交付。

文档的产业链修复七条约束是同一思路：报错集必须落在可修集里；修不好时“回退扁平结构属于合法结果，不是失败”。
代码落点

A4 用 retain_supported_claims 保序保留有据从句，再 repair_prose_opening 补主语；trial 审计通过才接受修复，失败就隔离或兜底。

落地边界：A4 直接跑的是段落级数值、方向、因果审计；排名、预测、情景还要靠写作约束和 A5 终审收口。六类断言是系统级判定链，不要讲成 A4 一个包全包了。
精度裁定 · 等价
16.17 = 16.2 16.17 是 2 位小数，16.2 是 1 位；按 0.1 步长舍入，16.17 → 16.2，判为同一个数。
精度裁定 · 冲突
16.17 ≠ 16.25 两者都是 2 位小数；差 0.08，大于半个末位 0.005，判冲突，不能放行。
跨单位 · 同步步长
1.2 亿元 = 12000 万元 元、万元、亿元按倍率换算；非金额按单位分桶，百分比与倍数不跨桶。

04 / INNOVATION

创新点：文档表 2.2 的五项，A4 用在哪

文档把创新分成功能和技术两类。五项里，三项直接长在 A4 上；另外两项是 A4 的上游和章节支撑。不是新模型，是契约、判定链、门禁和证据链。

01 · 产业链全景图谱

表 2.2 / 2.3.2 / 3.3.3
“三列全景图 + 七条结构约束，环节可追溯到披露证据。”

固定使用三列全景 SVG，上游、中游、下游分层；节点编号唯一、阶段枚举合法、有且仅有一个核心节点、同一企业只出现在一个环节、实物流方向合规、节点度数不超上限、证据编号真实存在。

A4 用在哪：CH-03 产业链章节。图由 A3 提供，A4 只写解读，不自己画图、不自己编图号；章节里的每个图点仍要能回到 A2 证据。

02 · 数值勾稽与精度裁定

表 2.2 / 2.3.3 / 3.3.2
“按披露精度判等，16.17 与 16.2 不误判。”

财务指标由确定性算子计算，模型只在算好的结果上做解释；判等从原始披露串反推小数步长，不用固定百分比容差。

A4 用在哪：数字审计不靠“看起来差不多”；先复算，再判精度；判不了就写缺口。A4 不自己算新数，净现比也只能引用 A2 已核验值。

03 · 智能取数探针

表 2.2 / 2.3.2 / 3.6
“静态精确查询 + 规程化动态补采，按点下单。”

静态侧解析宏观、行式、宽表序列、分组年度四类 schema；动态侧限定白名单技能，最多 4 次改写，只返回 JSON，按实体、指标、期间、数值四要素校验命中。

A4 用在哪：A1 的上游能力。补到的证据才进 A4 的资料袋；A4 不自己查数、不自己补数，补不到就写缺口。

04 · 五阶段分级复核台

表 2.2 / 2.3.2
“段落级精修只更新当前段落及其引用关系，不重跑整章。”

五个阶段各有一张面向原对象的编辑台。A4 这一站，研究员可以在段落上直接改，不需要通过聊天框描述“哪里不对”。

A4 用在哪：CH-05 / SEC-05-03 改一段，保存后重开仍在；只更新该段及引用关系，不重跑整章。演示里 P-05-03-02 从“分位极低”改成带基准日、PB 口径的句子。

05 · 证据穿透与底稿溯源

表 2.2 / 2.3.3 / 3.3.1
“唯一编号贯通记录、结论、图表与正文。”

每条关键记录生成唯一编号，携带来源、期间、单位、口径与取数时点；结论、图表与正文都引用这个编号。正文按数值、方向、因果、排名、预测、情景六类断言配置不同证据标准。

A4 用在哪：每段 evidence_ids；A5 只收录真被引用的记录，生成证据目录和 CSV，排版时才变成读者看到的 [1][2]。

7 章并发 + 独立资料袋

不是 21 节并发。每章一个资料袋，控 token，也避免章节串味。

单图单处

一张图只能进一个章节、一个小节；包级再查串章和一图多挂。

trial 修复

每次修复先深拷贝，重跑同一套审计；不新增问题才接受。

段落级精修

改一段，只更新该段及引用；保存后重开可复现，不重跑整章。

创新不是“换了个更大的模型”。 文档里的五项创新，加上 3.3 的三条判定机制，解决的是同一件事：让模型写出来的自然语言，能被代码逐段判定、逐段修复、逐段降级。模型只是写手，判据、证据、门禁都在代码里。

06 / DEFENSE

答辩怎么讲

先讲结论，再讲一个真实坑，最后讲边界。不要一上来讲代码。

30 秒版

如果只能选一个，我选智能体4。A4 不是让模型自由写文章，是让它在 7 章并发、21 节按提纲落位的前提下，把每句话写成可审计的句子。文档 3.3 的三件事最硬：断言分型、精度裁定、幂等修复。我们踩过的坑也很具体：图号乱挂、删句主语丢、同章重复。解决不是靠提示词，是代码审计和 trial 复审；修不好就 partial，绝不静默通过。

适合开场，控制在 45 秒内。

90 秒版

智能体4 是章节编制环节。它拿到的是三份契约：A2 的证据白名单、洞察和财务比率；A3 的就绪图表和图表证据映射；7 章 21 节的标准大纲和人工反馈。每章一个独立资料袋，最多 60 条证据、8 条洞察、25 条发现，一张图只能进一个章节。

它真正难的不是写得漂不漂亮，是写得能不能被审计。每一段要挂证据号；每一个数字要能同实体、同指标、同期间、同单位地复算；每一句因果要有独立依据；每一个图号要对得上图实际画的东西。文档 3.3.2 的精度裁定最能说明这一点：16.17 和 16.2 按披露步长判等价，不是按固定百分比容差放水。A4 写完先自审，不合格就定点修，修完再审；修不好就整章重写，再不行段落隔离，最后确定性兜底，状态标 partial。

适合评委追问“到底难在哪”时展开。
为什么不让一个大模型一口气写完七章？

长文本会退化、章节会串味、token 顶不住。七章并发、每章独立资料袋，控 token 又保证证据定位准；代价是跨章一致性要靠 global_facts 和 A5 印前复检。

七章并发怎么保证一致性？

不靠模型记忆。靠 global_facts 统一总市值等全局数字，靠 _audit_package 查 7 章 21 节、单图单处、跨章量级冲突，最后 A5 再做整份报告的四维审计。

A4 质检没过，为什么还能进 A5？

A4 不过不阻断，是让问题可见；A5 才是签发门。A5 过不了就只出受限草稿；硬阻塞人工也绕不过去。让问题可见，比悄悄停在 A4 更有价值。

修复会不会越修越错？

会，所以每次修复先深拷贝 trial，重跑同一套审计；只有该段问题消失且不新增问题才接受。候选润色新增问题就拒绝；不行就保留有据从句或隔离，最后确定性兜底。

A4 用的是什么框架？是 LangGraph 或 PiAgent 吗？

不是。项目运行时是 FastAPI + 自研 StateMachine + FiveAgentsAdapter，A4 是独立 Python 包 agents_core/chapter-writer，只依赖 httpx、pydantic。PiAgent 更像开发时用的 coding agent，不是交付运行时。

21 节是并发的吗？

不是。代码是 7 章并发，每章一次主模型调用；21 节是章内结构，不是 21 个并发任务。按代码讲更稳。

创新点是不是包装？

不是新模型。文档表 2.2 的五项创新，加上 3.3.1—3.3.3 的三条判定机制，解决的是“自然语言能不能被代码逐段判定、逐段修复、逐段降级”。每一项都能落到代码、验收数字或界面动作。

答辩时别说的四句话

  • 别说“21 节并发”——代码是 7 章并发，21 节是章内结构。
  • 别说“A5 就是排版”——A5 是复核与签发，排版只是最后一步。
  • 别说“A4 保证文采”——A4 保证的是有据、可查、可降级。
  • 别说“测试全过”——A4 真实验收是 partial，问题被如实标出来。
