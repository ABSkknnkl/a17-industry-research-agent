# A17 答辩串讲词 · 4 分钟版

> 配套图册：`index.html`；图在 `png/`。每段前面的时间是大致节奏，不必卡死。

## 0:00–0:40｜图 00：先回答框架问题

评委老师好，我先用一句话回答“这个项目用了什么框架”：

**我们没有用 LangGraph、CrewAI、AutoGen 这类现成 Agent 框架。前端是 Vue 3，后端是 FastAPI，核心是自研的 StateMachine 加 FiveAgentsAdapter。**

五个智能体是五个独立 Python 包，不互相直接调用，只通过 `data/runs` 里的产物文件交接。这样做不是因为想造轮子，而是金融研报要求四件事：阶段能停、版本能回、失败能重跑、每个数字能对账。通用框架的隐藏状态和自动重试，反而让这四件事不好控。

## 0:40–1:40｜图 01：总体框架

这张是总图，从上往下看：

- 最上面是**人**：发起任务、逐段审核、定稿签发。
- 中间是**前端和 FastAPI**：所有请求统一进状态机；状态机管五段状态和 revision，适配器把五个独立包接进来。
- 五段是**数据、解读、图表、写作、融合**；相邻两段只通过产物文件交接，产物都落在 `data/runs`。
- 下面两层是**共享引擎和外部能力**：产业链、口径、技能路由这些五个工位共用；问财 SkillHub 提供数据。
- 紫色虚线是 **A3 缺数 → A1 补采 → A2 重算** 的闭环。

一句话：这是一条**有状态、可回滚、每段可审核**的流水线，不是五个脚本串行。

## 1:40–2:30｜图 02 + 图 03：数据怎么来、怎么算

**A1 数据获取**：它像采购员，先开采购清单，再去市场买；买不到就写“缺货”，不拿假货凑数。

- 先把问题拆成 7 大领域和验收指标；
- 再生成 SkillTask 清单，去问财并发取数；
- 取回来做单位/报告期统一、多来源冲突检测、交易所公告重述对账；
- 最后用验收矩阵逐项打勾，缺的写进 `data_gap_notice`，可自动补采也可人工补；
- 每条记录都有 `record_id`、来源、报告期和哈希。

**A2 数据解读**：它像分析师，先用 Excel 把数算死，再让 AI 写人话。

- 确定性引擎算 CAGR、杜邦 ROE、三表勾稽、可比公司矩阵、异常检测、三情景敏感性；
- 这些都不依赖模型；
- 然后才让模型输出 insights，但每条结论必须绑 `evidence_record_ids`，语义校验不过就删。

一句话：**算得对和讲得通分开，模型只负责解释，不负责造数。**

## 2:30–3:20｜图 04 + 图 05：图怎么出、文怎么写

**A3 图表生成**：它像制图师，先验收数据点，再选图。

- 先看每个候选图的数据点够不够：期间齐不齐、单位同不同、有没有证据 ID；
- 够了才进图表规划，按业务语义选图型，生成 ECharts option 和离线 SVG；
- 中间有量纲守卫：万元/亿元不混轴，金额轴和比率轴物理隔离；
- 最后做图表质检，不合格的图降级或剔除；
- 缺关键期间就发 `data_demands`，回 A1 补采、A2 重算，再回来重画。

**A4 章节撰写**：它像写手团队，7 个人同时写 7 章，但每章都有提纲和证据夹。

- 按 7 章 21 节写，结构不能改；
- 每节先定 purpose，再做局部检索，只取相关事实、证据和 ready 图；
- 最多 7 章并发；
- 每章走“生成-审计-修复”：数字能不能复算、引用 ID 是否存在，不支持就改写或删除；
- 正文只放 `chart_id` 占位，不自己编图号；
- 人可以对单章提反馈，只重跑那一章。

## 3:20–4:00｜图 06：怎么合、怎么签发

**A5 报告融合**：它像出版社总编，合稿、校对、印刷；发现硬伤就锁正式下载。

- 先合稿：封面、目录、执行摘要、7 章正文、4 类附录；
- 再做四维一致性审计：结构是不是 7 章 21 节、引用有没有悬空、摘要/正文/图数字是否一致、规划图是否全部嵌入；
- 有问题最多修 8 轮，修不好就标受限；
- 最后用 Playwright 渲染 HTML/PDF，给产物清单和哈希；
- 全通过才给正式下载 **200**；有硬缺口只给受限草稿 **409**；
- 人工改正文以后，旧质检和旧 PDF 立即作废，必须重新融合。

## 4:00–4:30｜收尾：三条主线

评委记不住五个智能体的所有细节，但能记住三句话：

1. **状态机 → 可控**：五段状态、revision、CAS 版本校验、单任务锁；人工改了数据，后台旧结果不会覆盖新版本。
2. **record_id → 可信**：从 A1 取数到 PDF 角标，每个数字都有唯一 ID、来源、报告期和哈希；悬空引用不进交付稿。
3. **人审门禁 → 可签发**：每段可停、可改、可重跑；四维审计通过才正式下载，有硬伤只给受限草稿，签发权在人。

# 追问速答

**Q：为什么不用 LangGraph / CrewAI？**
A：金融研报要求阶段级审核、版本回滚、局部重算和并发锁。自研状态机把这些做成显式代码，出问题能定位；通用框架的隐藏状态反而增加调试成本。

**Q：五个智能体怎么通信？**
A：不直接调用，只通过 `data/runs` 里的产物文件交接。接口契约用 Pydantic 模型固定，下一段只读上一段的产物。

**Q：模型编数字怎么办？**
A：数字必须绑 `evidence_record_id`；A4 做复算与引用校验，A5 再做四维一致性审计。证据不支持就改写或删除，悬空引用不进交付稿。

**Q：人改完会被后台覆盖吗？**
A：不会。阶段开始前记 `input_revision`，提交时 CAS 比对；版本不一致就丢弃后台旧结果。审核、取消、重跑都走同一把任务锁。

**Q：为什么有时只能下载“受限草稿”？**
A：交付门禁：有硬缺口、兜底章、图表契约不过，就锁正式下载（409），只给带警告的草稿。不伪造“完美通过”。

**Q：最大的创新点是什么？**
A：不是“多智能体”四个字，而是把五个智能体做成一条可停、可回滚、可对账的流水线；再用 `record_id` 把每个数字穿透到原始证据。
