## 1.5 编写思路（三条方法论）

**思路一：判据层测试 ≠ 用例层执行**
任务书里的用例是「用户语句 → 预期结果」形式，执行它们必须真实模型（本轮不做）。
因此把判据**下沉到产物层**：直接对历史 run 的产物做断言。好处：零外呼、确定性、可重复、
失败可精确定位到产物字段（附 JSON 指针）。与用例层执行互补。

**思路二：把"不可直接观测的判据"翻译成可判事实**（三条后来都抓到真缺陷）

| 原始判据 | 翻译成的可判事实 |
|---|---|
| 无数据不绘图 | ① 已出图必须带非空 `evidence_ids`；② 被抑制候选须带 `reason_code` + 证据；③ **以"缺连续时间点"抑制时序图时，数据里该实体的时间点必须确实稀疏** |
| 不伪造不补数 | 全部引用（章节/图表/结论）⊆ A1 证据池（顺带验证 **A2 ⊆ A1、A3 ⊆ A1** 单写者不变量） |
| 失败降级正确 | 中断样本的下游产物**必须不存在**（而非"存在但为空"） |

**思路三：基准必须来自生产定义或真实产物，禁止自造**
- 章节数基准从 `DEFAULT_OUTLINE` **推导**（不写死 7/21）；
- 交叉验证 `status` 枚举**从 Pydantic 模型动态读取**（曾自造白名单导致误判）；
- 基准值从黄金样本**回填**（`eval/tools/backfill_baselines.py`），**禁止编数**。

| # | 原则 | 为什么 |

**结论：修复优先级应落在数据层（D-05），而不是图表选型算法。**

### D-01 · 存储层 run_id 路径穿越（阻断级）

**改动点**：`backend/app/core/storage.py`

```python
_RUN_ID_RE    = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$")   # 白名单
_FILE_NAME_RE = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$")

def _safe_run_dir(self, run_id: str) -> Path:
    """校验 run_id 并返回 base_dir 内的目标目录（未创建）。
    Raises:
        ValueError: 非法字符 / `.` `..` / 解析后越出 base_dir
    """
    if not isinstance(run_id, str) or run_id in {".", ".."} or not self._RUN_ID_RE.match(run_id):
        raise ValueError(f"非法 run_id: {run_id!r}")
    base, target = self.base_dir.resolve(), (self.base_dir / run_id).resolve()
    if target == base or not target.is_relative_to(base):
        raise ValueError(f"run_id 越界: {run_id!r}")
    return target
```

**接线**：`get_run_dir` / `delete_run` / `save_artifact_file` 统一走校验入口。

**验证**：`test_adapter.py` 3 条失败用例全部转绿（24 passed）；既有后端测试 13 passed（无回归）。
**兼容性**：合法 `run_id`（`run-20260923094843-353`）行为不变；非法 `run_id` 由"静默逃逸"改为抛 `ValueError`。

| `entities` + `time_range` | `ResearchRequest.industry` + `as_of` + 证据 `period_end` 区间 |
| `requires_clarification` | **模糊主体不得幻觉**：须落 `blocked`/`partial`（`planner_blocked`）→ 转 `waiting_review` |
| `parser_mode=fallback`（规则回退） | **改为失败语义判据**：LLM 不可用时必须 `failed` + `stop_reason` 明确（本项目**无规则回退路径**） |
| T 类的 `RetrievalPlan` 7 字段 | `dataset.json.sources`（`skill_id`/`query`/`trace_id`）+ `max_skill_calls` 上限 |
