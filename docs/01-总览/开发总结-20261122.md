# 智研天工 · 开发总结（2026-11-22 结项版）

> 本文是三件事的唯一事实源：项目做到哪、怎么做到的、还剩什么没做。答辩、交接、后续迭代都以本文为基线。
> 关键数字均可在仓库中找到对应实现或产物；无法核验的推断不写入本文。

## 0. 一句话结论

项目已打通"输入主题 → 五阶段生成 → 人工审核 → 三格式交付 → 归档"的完整链路，交付过可核验的新能源汽车研报（7 章 21 节、15 张图、348 条证据、25 页 PDF）；核心价值不在写作速度，而在**每条数字可回查、每类错误有门禁、每一步可重跑**。

---

## 1. 项目目标

### 1.1 命题要求（六项能力）

赛题要求基于同花顺问财 SkillHub 完成六件事：多源投研数据获取、数据解读、图表生成、分章写作、报告融合、人机协同。项目用五个智能体 + 一个编排层承接，报告按行业交付范式组织为七章二十一节，输出 Markdown / HTML / PDF 三种格式。

### 1.2 产品定位与边界

定位是"投研报告的初稿与底稿生成器"，不是投资决策工具：不输出投资建议、不设目标价与买卖评级；研究范围、样本取舍、异常解释、结论强度由研究员决定；系统负责取数、计算、制图、写作、校验与留痕。

### 1.3 验收对象

一次完整任务要能交出四件套：报告正文、图表、证据目录、修订记录；质量指标三个：关键数字证据覆盖率、指标错配率、返工次数。

## 2. 已完成功能

### 2.1 五阶段流水线

| 阶段 | 输入 | 产物 | 关键约束 |
|---|---|---|---|
| Agent1 取数 | 主题、样本、截止日、研究问题 | dataset.json：原始记录、来源、覆盖矩阵、冲突与缺口 | 无合格证据包不进入解读 |
| Agent2 解读 | 数据集、指标需求 | interpretation_report.json：指标、趋势、洞察、风险、证据索引 | 算归代码、说归模型，无证据不结论 |
| Agent3 制图 | 结论、证据、图表策略 | 图表配置、图表文件、点级证据 | 图型白名单，无点级证据退回，缺数不出图 |
| Agent4 写作 | 结论、图表、证据、七章提纲 | chapter_result.json：章节、摘要、组件、质检 | JSON 契约，节后六项检查 |
| Agent5 融合 | 已审稿、图表、证据 | 报告视图、证据目录、审计与清单 | 只编辑不补事实，门禁不过不发布 |

### 2.2 工作台与人工审核

- 任务工作台：建任务、看五阶段进度、看证据与待办、异常恢复。
- 五阶段分级复核台：16 个前端组件，数据点、图表、段落、指标卡上就地修改，不通过聊天框描述问题。
- 审核能力：八种动作（通过、采纳建议、修改后重跑、带参重跑、重新生成、就地编辑、接受风险继续、取消），段落级修改不重跑整章。
- 状态机：八状态（待执行、执行中、等待审核、已通过、已驳回、已完成、失败、已取消），事件驱动、迁移表白名单，等待审核是显式阻断态，不因超时自动越过。

### 2.3 交付与归档

- 发布判断四类出口：正式报告、带提示交付、受限草稿、阻断交付，由质量门禁 + 终审结论决定。
- 三格式同源渲染：Markdown / HTML / PDF；归档清单记录 kind、uri、sha256、size_bytes。
- 实测样例 r18：7 章 21 节、15 张图、348 条证据、25 页 PDF、3 种格式、2 份配套 JSON。
- 五问轻量版实测归档：端到端 180 秒、19 次问财请求、375 条观测、33 次模型调用、24 页 PDF。

### 2.4 局部补采（点级重采）

按"主体 + 指标 + 报告期 + 来源"检查覆盖缺口，允许指定指标定向补采；补采前给成本、补采后复核覆盖；最多一轮、每轮最多两项，带 probe_id 留痕，不挤占主流程额度。

### 2.5 三种深度模式

概览（3—4 章、图表上限 8 张）、标准（七章二十一节）、深度（多期对比、来源交叉验证、更细口径说明）。模式只改执行范围与校验强度，不改证据绑定与可追溯要求。

## 3. 关键实现

### 3.1 四层架构

L1 交互层（工作台、审核、预览）→ L2 编排层（FastAPI、状态机、run_id 与 revision）→ L3 智能体层（五个智能体）→ L4 能力层（问财 SkillHub、模型、文件与证据）。层间协议四件：参数约束、阶段产物、证据链接、审核决定。

### 3.2 产物契约（schema 校验）

阶段之间只交接结构化 JSON，字段名、枚举、取值域、嵌套结构写进 schema；模型不能增删字段；交接前校验，不合格不发布给下游；失败分可重试与不可重试，重跑生成新修订号，不覆盖失败记录。

### 3.3 并发与幂等保护

修订号是任务级递增整数，提交修改必须携带读取时的修订号，服务端版本更高即拒绝（CAS）；每次执行用独立工作区，产物先写临时文件刷盘、再原子改名，写入前算校验值；取消的旧执行结果隔离，不写回当前状态；审核动作生成不可变决策包（run_id / stage / revision / action / actor / risk_snapshot_sha256 / timestamp）。

### 3.4 证据链（贯穿五阶段）

record_id（取数）→ evidence_record_ids（解读）→ point_evidence_ids（图点）→ evidence_ids / chart_ids（章节）→ evidence_catalog（报告目录）。报告中的引用编号可反查原始披露；融合阶段专查引用悬空，落不到的引用直接阻断正式发布。

### 3.5 四个判定算法

| 算法 | 解决什么 | 实现要点 | 边界 |
|---|---|---|---|
| DPE 精度判等 | 同一数字不同披露精度被误判冲突 | 从披露串反推步长 s=10⁻ᵈ，精细侧按粗侧舍入再比，Decimal 四舍五入，三态输出 | 不纠事实错误；精度不可确认即拦截 |
| 稳健 Z | 错数不报错、混入成稿 | 按同域同指标同期间分组，中位数 + MAD，阈值 3.5，只标注不删数 | 教科书方法；样本 <5 或 MAD=0 跳过 |
| CLA 断言核验 | 句子专业但依据是编的 | 切子句 → 六类断言 → 分类配证据标准 → 三态 → 保序幂等裁剪 | 分型含模型成分；因果只认直引或标假设 |
| RPD 拓扑修复 | 图画乱、查出错却修不好 | 七条硬约束校验 + 按关系权重贪心删边（回收<服务<技术<实物）+ 同源判据 + 修不好回退 | 贪心非最优；保证报错集 ⊆ 可修集 |

评测口径：39 条六类断言标注集（应拦 21、应留 18）拦截 17/21（81.0%），误删 1/18（5.6%），漏放 4/21；关闭核验时 21 条无据断言 100% 进稿。

### 3.6 发布门禁（G1—G4）

G1 至少一条核心结论有有效证据；G2 无悬空引用；G3 无未消解的高严重度冲突被写成事实；G4 无安全问题/契约失败、三格式与清单齐全。任一失败即 blocked；质量分只用于比较修订，不豁免硬条件。

### 3.7 技能路由与取数治理

技能路由取四路并集（强制 / 用户指定 / 模型规划 / 规则），融合上限 10、模型规划上限 7；66 个技能按五阶段分域（25/20/6/10/5）；四道确定性归一工序（时点对齐、实体与指标归一、量纲归一、编号去重）不调模型；一次采集通常三到五条查询组合。

### 3.8 提示词工程

87 份资产、约 21 万字符（21 条主提示词 32,713 字符 + 66 份 SKILL.md 约 17.8 万字符）。装配四步：固定基座 + 条件片段 + 技能文本 + 上下文预算（默认 500KB，超限只裁可选段，必答证据不动）。章节写作提示词最硬五条：只用输入证据、断言主旨驱动、图表占位符必须显式、global_facts 强制锚点、严格 JSON。

### 3.9 前端接线（已按 P0/P1/P2 分级落地）

P0 修审核有效性与数据丢失问题；P1 修展示错位与空态；P2 清理误接线风险。统一状态与交互规范、异常文案、mock 联调与问题数据注入，全部五阶段审核门可走通。

## 4. 遗留问题

### 4.1 已登记缺陷（来源：金融公式审查清单，2026-11-12）

高优先级 5 条：P-01"百万元"换算差 100 倍（当前 DPE 与单位表已覆盖该场景，需回归确认关闭）；P-02 market_cap_billion 字段名与量纲不符；P-03 CR3/CR5 生产缺失、判据与产物不一致；P-04 杜邦 ROE 名实不符；P-05 周转率/产能利用率声明未实现。
中优先级 11 条：P-06—P-16，集中在组内均值口径、研发费用率两套量纲、同比负基数两套规则、净现比分母口径、来源冲突零容差、重述容差、环形图 total≤0、轴单位两套规则、中位数定义、百分比与倍数混用。
低优先级 4 条：P-17—P-20（PEG 名实不符、IQR 参数、空单位、前缀单位未换算）。
**纪律**：以上为审查日状态，关闭前必须逐条回归；未关闭的不得在答辩中声称已解决。

### 4.2 评测缺口

- 无整报告级盲评与"裸模型 vs 系统"基线对比，现有评测为机制级（39 条断言集、512 条用例、8 组 60 条判据）。
- 无系统性多模型横向评测，只有提示词层离线 A/B。
- 异常检测未单独统计误报率/漏报率，目前依据"只标注不删数"控制代价。

### 4.3 行业规则与规模化

行业画像是人工写的配置，五个行业固定；换一个新行业要人写画像（环节、代表企业、指标口径、检索词、章节骨架）。这是上线四步里最难的一步。

### 4.4 版本与平台化

提示词无集中注册表、无任务级全局版本号，只有 industry_chain、chain_research 等局部 PROMPT_VERSION；修改走代码评审与回归，平台化程度不足。

### 4.5 能力边界

- 因果断言只认原文直引或显式假设，偏保守，存在误删（5.6%）与漏放（4/21）。
- RPD 为加权贪心，不保证全局最优。
- 非 A 股/未上市企业无结构化数据，只能降信任层（industry_common），不能带强证据。
- 不覆盖持续更新：新资料发布后需人工判断影响范围，尚无增量重算。

### 4.6 上线缺口

多用户与鉴权、数据商用授权、私有化部署、正式 SLA 均未做；单份机器成本按公开刊例价为几元到十几元，证据上下文是 token 大头。

## 5. 后续建议

### P0（结项后立刻做，1—2 周）

1. **关闭高优先级缺陷并回归**：P-01—P-05 逐条确认，更新缺陷台账状态，纳入 512 条用例回归。
2. **建整报告级评测基线**：固定 20 题验收集，跑"裸模型 vs 系统"盲评，固化三指标（证据覆盖率、错配率、返工次数）。
3. **多模型横评与分阶段选型**：用同一批用例跑 3 个模型，按阶段定选型（取数规划用快模型、写作与解读用强模型），形成选型表。

### P1（1—2 个月）

4. **断言分型置信度化**：强模型输出"类型 + 置信度"，低置信度直接判不可判定；规则继续兜底；漏放目标从 4/21 降到 ≤2/21，误删率不升。
5. **行业画像 AI 起草 + 人审**：从公告、招股书、行业标准抽取画像草稿，把"人写配置"变成"AI 起草、人审"；验收看新行业上线工时。
6. **提示词注册表与版本号**：集中登记 87 份资产，任务记录绑定提示词版本，规则变更必须同步回归。
7. **增量更新**：沿 evidence_catalog 建"证据→产物"依赖图，新公告发布后只重算受影响图表、段落与摘要，并出差异对比。

### P2（3—6 个月）

8. **因果断言多跳证据**：跨公告、研报、新闻组合证据，每跳带 record_id，保持可判定。
9. **RPD 约束求解**：规模上来后用带度数上限的最大权子图替代贪心，删边总权重下降，可修率保持 100%。
10. **报告问答**：对着成稿提问，答案必须带证据编号，复用幻觉拦截机制。
11. **上线准备**：多用户与鉴权、数据商用授权、私有化部署。
