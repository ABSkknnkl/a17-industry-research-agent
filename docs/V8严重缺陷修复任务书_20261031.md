## 3 S-01 阶段阻塞与失败不能被批准覆盖

### 已确认路径

`backend/app/agents/adapters.py:407`，`FiveAgentsAdapter.run_data_fetcher` 在特定空数据条件下设置 stage_error；返回的 StageResult 仍是 waiting_review。随后 `backend/app/engine/state_machine.py:985` 的 `WorkflowEngine._execute_stage` 只按 review_stages 决定状态：在审核列表就重写 waiting_review，否则重写 approved/completed 并继续下游。

隔离适配器分别返回以下两种结果，当前状态机都执行了解读、制图、写作、融合，最终 run=completed、data_fetch=approved，原 error 仍是 empty_dataset：

```text
StageResult(status="waiting_review", error="empty_dataset",
            data={"agent_status":"blocked", "record_count":0,
                  "blocking_issues":["empty_dataset"]})
StageResult(status="failed", error="empty_dataset", ...)
```

`handle_review` 的 approve 分支同样未先检查阻塞，隔离运行确认它会派发一次下游。这比“只在 review_stages=[] 时失效”的旧描述更完整：人工批准路径也缺硬约束。

### 最小修改范围

主责是 `_execute_stage`、`handle_review` 和 `run_data_fetcher` 的状态契约；不要仅修改提示词。

1. 在重写审核状态前识别终止性失败与硬阻塞。阶段 error、结构化阻塞原因和上游原生状态必须有明确一致的语义；不要把所有 warnings 一律当硬阻塞，也不要靠中文关键词猜测状态。
2. 所有入口遵守同一规则，包括自动流转、默认人工审核、指定审核列表、approve/accept_recommendation/accept_with_risks、resume。硬阻塞不得被风险接受绕过；允许展示研究边界的草稿与正式量化交付分开。
3. 空数据判断结合研究模式。只有事件或有证据支持的产业链断言时，不应因七个数值域为空就机械判定全空；能否做定性研究与能否写量化结论分别判定。保留当前 chain_bundle.supported_assertions 路径的语义。
4. A4 增加最后一道量化护栏：关键量化结论须有有效证据绑定，证据为空时不得补写百分比、营收、增长率、目标值。不能用禁止所有数字的正则代替证据校验，年份、章节号不属于财务事实。
5. 当前 StageStatus 没有 blocked。若用 failed/waiting_review 加结构化阻塞字段表达，需统一 API/UI；若新增枚举，同步 schema、前端类型和恢复路径。失败原因须可追溯，不能将其覆盖成“已完成”。

## 5 S-03 图表按系列统一单位后再转换

### 已确认路径与最小复现

`chart_generator/data_formulation.py:653`，`DataFormulator._formulate_time_series` 按点调用 normalize_financial_value，每个点自行选择目标单位，最后用末点的 final_unit 标记整个系列。`metric_guard.py:388` 的转换器对万元金额在 10000 阈值处切换单位，因此即使源数据单位齐全也会错。

本轮经过公开 `DataFormulator.formulate` → `EChartsCompiler.compile`，没有绕开宽表选择逻辑：

| 同一实体的营收 | 输入 | 当前 option | 正确含义 |
|---|---|---|---|
| 2024-12-31 | 9999 万元 | 9999 亿元 | 0.9999 亿元 |
| 2025-12-31 | 10000 万元 | 1 亿元 | 1 亿元 |

轴单位实际为亿元，series 实际为 `[9999.0, 1.0]`。这是确定的图配置错误；本轮未声称两份指定真实 PDF 恰好含此阈值样本。

```python
records = [
    EvidenceRef(record_id="a", domain="financials", metric="revenue", entity="甲公司",
                value=9999, unit="万元", period=date(2024, 12, 31)),
    EvidenceRef(record_id="b", domain="financials", metric="revenue", entity="甲公司",
                value=10000, unit="万元", period=date(2025, 12, 31)),
]
report = InterpretationReport(report_id="r", subject="单位核验", as_of=date(2026, 10, 31),
                             status="completed", evidence_index={r.record_id:r for r in records})
table = DataFormulator.formulate(["a", "b"], report, "line")
option = EChartsCompiler.compile(table, "line", "营收趋势")
# 修复后：同系列所有值共享一个单位；不能是当前的 [9999, 1] 亿元。
```

上例补 `from datetime import date` 与 chart_generator.models、data_formulation、compiler 对应 import 后即可运行；不需要外部 API。

### 最小修改范围

1. 先收集同系列原始单位与金额，再选择一次目标单位；逐点传入同一个 target_unit。`_try_formulate_combo` 的时序和跨实体分支也有逐点归一再用末点单位的相同写法，必须覆盖；共享轴的多个系列还须统一轴单位或明确分轴。
2. 选择万元可保留 `[9999,10000]`；选择亿元则保留足够精度表达 `[0.9999,1]`，避免 round(...,2) 提前把两点都变成 1。计算和事实数据保持精度，显示层再按量级格式化。
3. 原始单位缺失或冲突时，先用来源字段、技能契约等确定；无法确定就标记不可比或抑制，不能根据“值看起来像多少”推断元/万元，也不能给所有空 unit 填“亿元”。比例小于 1 亦不得仅据大小猜它是小数还是百分数。
4. 保持点级 evidence_id、period 与数值位置对应，不更改源记录来适配显示。前端预览、SVG、PDF 使用同一归一化结果。
5. 本包只修单位一致性。图数量上限、所有行业口径映射、通用图形美化暂不扩展。

### 必须新增的失败断言

建议：`agents_core/chart-generator/tests/test_series_unit_consistency_v8.py`。

- 上述 9999→10000 万元经 formulate→compile 后语义仍为小幅增长；转换回同一基础单位逐点核对，不能只断言 axis_unit 非空。
- 9999/10000 元阈值、元/万元/亿元混合输入、负值和真实 0；共享轴多个系列、combo 左右轴分别校验。

- SVG 文本/tooltip 的单位与 option 一致；不能只修 yAxis.name 而保留错数。
