## 3. Bug 明细（现象 → 复现 → 根因 → 影响 → 修复方向）

### BUG-1（静默误判，一票否决项）：「行业出口占比」被公司口径别名误路由

- **现象**：`行业出口占比数据`（2.18）→ 锁定 `hithink_business_query`，指标被归一为「海外收入占比」，静默取**公司级**数据，无澄清、无低置信标记。
- **复现**：L1 直跑即现；L2 探针 G 中即使语义层显式给出 `reject_reason="行业口径出口占比≠公司海外收入占比"`，BUSINESS 锁定仍存活。
- **根因**：第三刀词表给 `overseas_revenue_share` 补了别名「出口占比/外销占比」（方案 §2 第三刀改动点 1 原文如此）。该指标是**公司财报口径**，但 `deterministic_intent_parser._segment_skills` 的子串匹配不区分公司/行业上下文——行业问句命中同一别名后被锁进公司技能。
- **影响**：行业外贸结构问题会拿回若干公司的海外收入占比数据并被当作行业结论，属于「取错数且静默」，直接击穿 §3 一票否决项。
- **修复方向**（未实施，待授权）：
  1. 口径护栏：公司口径别名（外销占比/出口占比/海外收入占比）仅在存在公司实体时锁定；行业问句命中 → 转澄清/unsupported 披露；
  2. 词表回退：从 `overseas_revenue_share` 移除「出口占比」，仅保留「外销占比」（公司语境更强），行业出口数据登记为研究边界词表。

### BUG-2（缺口掩盖）：「产业链…良率」被关键词锁掩盖真实缺口

- **现象**：`产业链各环节良率分别是多少`（2.10）→ 锁定 `industry_chain_analysis`，`metrics=[]`，无澄清。用户要的「良率」是未注册指标（真缺口），但因句中含「产业链」（`CHAIN_KEYWORDS`）被整体路由走，缺口不再披露。
- **根因**：`_segment_skills` 的关键词锁（产业链/竞争格局/行业规模…）与问句的**指标诉求脱钩**——只要关键词在场就锁技能，不管诉求指标是否已注册。后续 `_unsupported_fragments_by_question` 只统计「无技能碎片」，该碎片有技能（关键词锁来的），缺口检测被绕过。
- **影响**：真缺口拦截率 16/17；同类风险覆盖所有「关键词在场 + 诉求指标未注册」的组合（良率/产销率/自给率 + 产业链/竞争格局句式）。
- **修复方向**：关键词锁产出时检查同碎片是否存在已注册指标；「纯关键词锁、无指标」的碎片追加 `unresolved_metric` 标记，进入缺口披露通道（保留关键词查询，但不声称满足诉求）。

### BUG-3（仲裁缺陷，最重）：R3 交叉污染，L2 正确路由被整单丢弃

- **现象**：`动力电池竞争格局怎么样？`（6.2）。L2 人工拆解给出 `STOCK_SELECTOR + 市场份额`（金标准 R-F02 期望）。实测合并后计划被 `validate_intent_plan` 判 block：
  ```
  blockers=['skill_capability_mismatch:SUB-01:hithink_industry_query']
  ```
  随后整单回退确定性重建，最终只剩 `hithink_industry_query`，**L2 的正确补充被完全丢弃**（探针 A 证据：uncalibrated 含双技能 → verdict block → final fallback）。
- **根因链**：
  1. 「竞争格局」∈ `INDUSTRY_KEYWORDS` → 确定性锁定 INDUSTRY（L1 强行硬选）；
  2. L2 碎片与确定性碎片文本相同 → 走**严格匹配路径**合入同一子需求（该路径无能力校验，放宽路径的护栏 2 不覆盖严格路径）；
  3. 合并后子需求 `source=hybrid`，R3 对 hybrid 子需求的**全部**候选技能做能力校验：INDUSTRY 服务不了 `market_share` 指标类型 → `skill_capability_mismatch`；
  4. block → 回退确定性计划 → L2 成果清零，且用户无感知。
- **影响**：所有「关键词锁技能 ≠ L2 路由技能」的组合（竞争格局→选股、行业规模→宏观…）都会触发，语义层的补充能力被系统性废止。这是方案 §0 所说「确定性锁定永远生效、LLM 只能补充不能否决」的遗留病灶在新形态下的复发。
- **修复方向**：
  1. 严格匹配路径补能力护栏（与放宽路径护栏 2 对齐）：目标碎片既有技能无法服务合并后指标类型时**不合入**，L2 碎片独立成子需求——锁定技能继续独立执行，L2 补充并行存在，两不相害；
  2. 或 R3 对「确定性锁定技能」豁免能力校验并拆分混合子需求。推荐 1（改合并，不改门禁语义）。

### BUG-4（仲裁缺陷）：R4 把被否决的关键词锁复活，否决通道被绕过

- **现象**：`产业链各环节良率分别是多少`（2.10）的 L2 探针 E：语义层显式否决（`reject_reason="良率无对应技能"`）。合并层正确触发否决（uncalibrated：`notes=['产业链各环节良率分别是多少']`、碎片移除），但：
  ```
  verdict: block  blockers=['locked_skill_not_routed:industry_chain_analysis']
  final: skills=['industry_chain_analysis'] mode=fallback notes=[]
  ```
  否决成果（analysis_notes、碎片移除）在 fallback 中全部丢失，关键词锁借 R4 复活。
- **根因链**：
  1. 第一刀改动点 1/2 只处理了「被否决碎片携带的指标锁」，未处理**关键词锁**：`industry_chain_analysis` 锁不是被否决碎片携带的候选技能，而是 `parse.locked_skills`（R4 的守护对象）；
  2. 否决清空了唯一路由该锁的碎片 → R4 `locked_skill_not_routed` → block → 确定性重建 → 锁复活、notes 丢失；
  3. 与 BUG-2 同源：关键词锁与指标诉求脱钩后，R4 的「锁定必须被路由」不变式把错误的锁保护到底。
- **影响**：对含关键词锁的判断题/派生诉求，L2 否决通道形同虚设；`analysis_notes` 透传链在这类问句上断裂（直接影响 Agent 2 的否决线索接收）。
- **修复方向**：区分「指标锁」（来自已注册指标命中）与「关键词锁」（纯关键词表）；否决清空计划时，关键词锁不触发 R4 复活，降级为「披露型查询」或随澄清门处理。与 BUG-2 的 `unresolved_metric` 标记可合并为同一次修复。

## 6. 结论与建议

1. **四刀的确定性层成果经得起压测**：否定表、口径三分族、澄清门、否决通道（指标锁场景）全部按设计工作。
2. **剩余 4 个 bug 集中在同一病灶的两个面**：关键词锁与指标诉求脱钩（BUG-2/4）+ 严格合并路径无能力护栏（BUG-3）+ 公司口径别名无上下文（BUG-1）。建议按「BUG-3 → BUG-1 → BUG-2+4 合并修」的顺序立项，每刀沿用独立 feature flag + 本文 61 条做回归基线。
3. 修复前**建议先冻结本 61 条为 `eval/cases/` 金标准**（方案 §4.3 的固化工作），并把本文 §2.2 的门禁口径纳入 PR 一票否决。
4. 词库补充走外置双轨（`metric_aliases.yaml`），研究边界词表另立文件，避免把「查不到」的指标混进可路由词表。
