## 1. 口径声明（务必先读）

**本项目不存在任何模型微调（fine-tuning）。**

赛题附件未对"训练"作定义（"A类企业命题初赛统一评分标准"不在赛题手册内），为避免与"模型训练"产生歧义，
本文件对本项目语境下的"**训练记录**"作如下**与代码事实一致**的口径声明：

> **"训练" = ①提示词工程（系统提示词、结构化输出契约、修复轮次）＋ ②技能库调优（64 个 `SKILL.md` 的编写、触发元数据与适配说明）＋ ③评测迭代（判据定义、缺陷发现与收敛记录）。**

具体证据：

| 环节 | 实际形态 | 代码/产物位置 |
|---|---|---|
| 提示词工程 | 每个智能体包内的 `SYSTEM_PROMPT` 常量 + 结构化 JSON 输出契约 + `max_repairs` 有界修复轮 | `agents_core/*/<pkg>/agent.py`、`prompt_adapter.py` |
| 技能库调优 | 64 个技能包，每个含 `SKILL.md`（frontmatter: `name`/`description`）+ `_meta.json`（`domains`/`keywords`/`requires_signal`/`source`/`adaptation`） | `agents_core/data-fetcher/data_fetcher/skills/`（25）、`data-analysis/data_interpreter/skills/`（20）、`chart_generator/skills/`（4）、`chapter_writer/skills/`（10）、`report_fusion/skills/`（5） |
| 评测迭代 | `eval/` 评测层（L0 自检 + 判据分派器）+ `backend/tests/l1/` 判据测试 + 逐轮快照与台账 | `eval/`、`backend/tests/l1/`、`docs/测试执行台账.md` |

**模型底座**：统一通过 OpenAI 兼容协议调用外部模型服务（LLM 基座 `deepseek-v4-flash`），
**没有本地权重、没有训练/微调产物**。因此本文件不包含 loss 曲线、epoch、checkpoint 等训练类内容——
写出来即是失实。

### 3.2 提示词与输出契约的迭代方式

- **有界修复**：每章生成最多 `max_repairs + 1` 次尝试，每次尝试后由 `_audit_chapter` 审计
  （章节 ID/节序一致性、证据白名单、数值一致性修复、段落重复检测），全部失败则降级为确定性兜底稿；
- **降级可观测**：降级章进入 `quality.fallback_chapter_ids`，并在 `warnings` 中写明原因
  （本轮 K 系列即靠此机制发现哨兵夹具的"段落重复"问题）；
- **一致性修复**：对已知口径错误（如市值"22.14 万亿/2.21 万亿"量级错位）做正则级修复，
  修复动作在 `_audit_chapter` 内完成并留痕。

### 3.4 本轮暴露的"方法论级"结论（可直接用于后续修复排序）

1. **"图表类型恒为 bar"的根因在数据层，不在图表算法**：
   判据"以 `insufficient_time_points` 抑制折线图时数据事实必须支持该理由"**通过** ——
   数据集中 (实体,指标) 组合的时间点中位数 < 3。因果链为
   **D-05（时间元数据缺失）→ A2 看不到连续时间点 → A3 合规抑制时序图 → 只剩横截面 bar**。
2. **单位元数据缺失使"单位归一"形同虚设**：顶层 `unit` 0/807 → 下游 `peer_comps` 退化为无序数比较，
   与 D-03 的 comps 覆盖面问题互为因果。
3. **"字段声称的能力与实际不符"是本项目的高频模式**：本轮新增两例——
   `point_evidence_ids`（6/6 恒空）与 `delivery_status`（硬编码 `"ready"`，吞掉 `ready_with_limits`）；
   加上既有的 `required_domains`、`intent_routing`、`decision=="stop"`、`data_demands`，该模式累计已 6 例。
   **建议在代码评审清单中加入一条**："新增判断类字段时，必须同时给出产出路径与消费方"。
4. **合并（大范围覆盖）会静默退化实现**：D-04 即"以 A 线覆盖 B 线"造成三处退化
   （`delivery_status` 硬编码、大纲基准写死 7/21、`security_types` 默认值）。
   **护栏做法**：对"必须推导而非硬编码"的约束写**源码级断言**（本轮已落 `test_d04_*` 两条）。

**流程特征（与外包/数字化研发流程的对应）**：
① 需求可追溯（赛题要求 ↔ 模块 ↔ 判据三层对账）；
