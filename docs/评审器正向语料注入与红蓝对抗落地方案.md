**关键代码位（注入点）**——LLM 评审器 system prompt 现状（`openai_compatible.py:875-882`）：

```python
system_prompt = (
    "你是行业研究报告的可读性评审器。只依据给定段落文本判断其是否通顺、俗通、连贯、客观。"
    "返回ReadabilityReport JSON：score为0到1的可读性软分（1为完全可读）；"
    "findings列出具体问题，dimension取值通顺度/俗通度/连贯性/客观性，"
    "severity取值must_fix/suggest，每条包含reason（哪里读不懂）与rewrite_hint（修改方向）；"
    "paragraph_id固定为空字符串；findings为空表示可读。"
    "不得评价段落之外的内容，不得引入新事实、数值或结论。"
)
```

**没有任何样例、没有 0.9/0.6/0.3 的分数语义锚**。这是"正例注入"的第一落点。

Linter 十条规则（`readability_linter.py`）：

| 规则  | 判据                                                 | 维度      | 严重度       |
| --- | -------------------------------------------------- | ------- | --------- |

### 🔴 头号发现：R2 句长判断口径错误——应按标点切分，而非按整句数字数

最初把 401 条真实研报句喂给 Linter，按「句号到句号」数整句字数，误伤 147 条（36.7%），全部由 R2 命中。例如：

> "受益于全球电网升级改造和AI数据中心建设浪潮，海外高压设备需求旺盛，尤其是变压器等产品供给紧张，交货周期长达数年。"（整句 56 字，被判 R2）

**但这句话内部有 3 个逗号，每个小句都 ≤19 字，读起来毫不费力。** 问题根源：句长判断看错了单位——**「句号到句号」不是句长，两个标点之间才是**。一个标点（。！？；，、：）就是一个句子的边界。

按「一个标点=一个句子」口径重新标定（791 条真实研报句 → 4624 个小句）：

| 小句长度   | 累计占比  |
| ------ | ----- |
| ≤ 20 字 | 78.0% |
| ≤ 30 字 | 87.2% |

**87% 的真实研报小句 ≤30 字，30 字是「一口气读完」的自然拐点。** 故 R2 改为：按全部标点切分，超过 30 字的无标点片段才报 suggest。

## 4. 注入方案（把语料"给到"评审器，四处落点）

### 落点 1（✅ 已落地，零 LLM 成本）：扩展红队样本回归集

`redteam_readability_samples.py`：`POSITIVE_SAMPLES` 3 → 19 条（16 条 PDF 正例）、`NEGATIVE_SAMPLES` 5 → 16 条（6 条坏报告负例 + 5 条 AI 味负例）。防误杀 + 确定性抓取双重回归。

### 落点 2（⏳ 待做）：few-shot + 评分锚注入 system prompt

在 `openai_compatible.py:875` 的 `system_prompt` 末尾追加（每个维度 1 正 1 负 + 分数语义锚）：

```
评分语义锚：0.9=专业且通顺（可直接入报告）；0.6=勉强可读但需改写；0.3=读不通。
正例（score≈0.9）：
- 「从技术路线看，磷酸铁锂电池已确立绝对主导地位。」
- 「储能，即能量储存，是指通过特定技术和装置将暂时不用的能量储存起来，在需要时再释放利用的过程。」
负例（score≤0.3）：
- 「该行业受到政策影响使其产能出现下降，而其产能利用率又受到需求影响从而出现波动。」（双主语）
- 「行业规模保持增长。样本覆盖范围有限。政策导向保持稳定。」（语义断裂）
长句不是减分项：主谓清晰、标点充分、逻辑连贯的专业长句（即使整句 50~60 字）应给 0.85 以上。
```

⚠️ **一票否决提醒（运营方案 §6）**：few-shot 用的例句**不得**与校准集标注样本重复（数据泄漏作废）。

| 指标                 | 门禁                                      |

## 7. 未解决的上游根因（评审器兜不住，需另开）

真实坏报告暴露的两个**上游 bug**，R6/R7 只能"拦下转人工"，不能"修数据"：

1. **A2 数据解读层字段清洗缺失**：`宏观@值为X未提供`、`证据编号相关证据` 等原始 KV/占位符直接进 claims 文本，未转成自然语言。
