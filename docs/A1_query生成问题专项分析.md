> **问题一句话**：**智能体 1 的意图识别没问题，问题出在"把识别结果写成 query"这一步。**

## 3. 根因：**提示词把"结构化字段"塞进了 query 字符串**（核心）

**根因在 `PLANNER_SYSTEM_PROMPT`（`agent.py` L56–L83）** —— 它明确要求 LLM 把"字段名 / 指标清单 / 时间跨度 / 排序规则"**写进 `query`**：

| 提示词原文（节选） | 行号 | **直接导致的 query 形态** |
|---|---|---|
| `expected_fields 必须包含："证券代码"、"证券简称"、"总市值"、"营业收入"、"所属行业"、"所属概念"` | L68 | → **"字段名当检索词"**（query #2/#3/#4） |
| `query 必须包含多年度连续时序（例如"近3~5年及最新报告期"或"2021年至2025年"）` | L77 | → **年份夹在中间**（query #5–#8） |
| `财务查询必须完整覆盖…营业收入、归母净利润、销售毛利率、销售净利率、ROE、资产负债率、经营活动产生的现金流量净额、研发费用及其同比增速` | L78 | → **一条塞 9 个指标**（query #5–#8） |
| `query 必须显式包含按总市值从大到小排序，覆盖样本量取前 20~30 家行业龙头企业（例如："按A股总市值从大到小排序取前25~30家核心龙头企业"）` | L64 | → **40 字长串**（query #1 类） |
| `query 必须指定明确的多期时间跨度（如"近3~5年GDP当季同比及工业增加值季度趋势"）` | L81 | → 宏观 query 冗余（query #9/#14） |
| `严禁将多家核心公司合并在同一条 query 中`（L75，**这条是对的** ✓） | L75 | 已被遵守（#10/#11 拆成单公司） |

**根因表述**：
> **提示词混淆了"检索条件"与"返回要求"** ——
> 「要返回哪些字段（`expected_fields`）」「要覆盖哪些指标」「要什么时间跨度」「怎么排序」
> 这些**都应该放在结构化字段里**（`expected_fields` / `arguments.time_range` / `limit`），
> 但提示词写成了"**query 必须包含…**"，于是 LLM 把它们**全部拼进 query 字符串**，
> 形成 50–60 字的长串，破坏问财的分词与匹配。

**佐证**：同一份提示词里**唯一正确的一条**是 L75（"严禁多公司合并进同一 query"）——
因为它约束的是**反例**而非要求"query 要包含什么"；而该条确实被遵守（#10/#11 已拆分)。

| query | 结构 | 命中 |
|---|---|---|
| `海水淡化` | 纯行业名 | 10 |

| `伟明环保(603568.SH) 2021年至2025年 营业收入 归母净利润 …`（60 字） | **有空格的长串** | **1–10** ✅ |

### 4.3 结论（**一次重要的自我修正**）

| 假设 | 结论 |
|---|---|
| "长 query 一定归零" | ❌ **不成立**（60 字有空格的长串仍能命中 1–10 条） |
| **"无空格连写 → 归零"** | ✅ **成立且稳定**（`海水淡化2025年吨水成本` 重复测 2 次均为 0） |
| "改写短一点就有帮助" | ❌ **不成立**（当原串已有空格时，改写无提升：4→2、8→8、1→1） |

> **精确结论**：**致命的是「无空格连写」，不是「长」。**
> A1 生成的 query 里，"字段堆砌 + 有空格"的**能出数但命中偏少（1–4 条）**；
> "无空格连写"的**直接归零**。

## 5. 影响面

| 影响 | 说明 |
|---|---|
| **覆盖度偏低** | 命中 1–4 条的 query 会留下数据缺口 → A2 可分析维度减少 → 图表被抑制（如产业链图需 ≥2 期数据） |
| **完全归零** | 无空格连写的 query → 该任务 0 条 → 若关键域（如财务、行业）落在此类 → 阶段覆盖度不足 |
| **静默化** | 上述失败**不产生任何 error/warning**（`blocking_issues=[]`）→ 上游不知情，问题被推迟到"报告内容空洞"才暴露 |
| **任务量浪费** | 16 个 query 中 14 个结构冗余，占用配额与耗时（单份报告约 13.5 分钟，图表/解读阶段被拖长） |

## 6. 修复建议（**针对提示词，可直接落地**）

### 6.1 核心修改：把"返回要求"从 query 里剥离

| # | 措施 | 具体改法 |
|---|---|---|
| **1** | **明确 query 的定位** | 在 `PLANNER_SYSTEM_PROMPT` 增加：<br>「`query` **只写检索用的实体与主题词（≤20 字，词间用空格分隔）**；<br>**严禁**写入返回字段名、指标清单、排序规则、时间跨度或说明性文字」 |
| **2** | **字段名归位** | 把 L68 的 `expected_fields 必须包含…` 改为：<br>「字段名**只能写入 `expected_fields` 数组**，**不得出现在 `query` 中**」 |
| **3** | **指标清单归位** | 把 L78 的 9 个指标名从"query 必须覆盖"改为：<br>「指标清单写入 `expected_fields`；如需一次查全，**拆成 ≤3 个指标/条**的多条任务」 |
| **4** | **时间跨度归位** | 把 L77/L81 的"query 必须包含多年度"改为：<br>「时间跨度写入 `arguments.time_range`；query 中**年份放末尾或省略**，严禁插在实体与指标之间」 |
| **5** | **排序规则归位** | 把 L64 的"query 必须显式包含按总市值排序取前 25~30 家"改为：<br>「排序写入 `arguments.sort_by` / `limit=30`；query 只写『行业 + 核心环节词 + 龙头』」 |
| **6** | **禁止自然语言整句** | 「query 中不得出现标点（，。、；）、『重点关注/用于评估/包括…等/时间范围』等说明性文字」 |
| **7** | **失败显式上报** | query 命中 0 条时，写入 `TaskResult.error` 或 `blocking_issues`（与主报告 §1.5.2b 一致） |

| 场景 | 现状（A1 生成） | 建议（修复后） |
|---|---|---|
