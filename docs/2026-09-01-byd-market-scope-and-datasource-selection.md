## 4. 选型结论

### 一句话

**结构化主数据用 iFinD（同源、口径一致、且 `search_stocks` 正好补 P0-3 泛称实体落地）；NeoData 作为跨品类与文档兜底的第二源；妙想只在资讯时效性场景作为第三层。若只能立刻用起来一个 —— 目前只有 NeoData 是开箱可用的。**

### 4.1 首选：iFinD（同花顺）

三条硬理由，全部命中本项目当下痛点：

1. **口径同源**。项目目录本身就是同花顺生态，现有 `hithink_*` 技能走的是问财。混合异源数据是投研报告最危险的事——同一个"营业收入"在两个源可能差一个合并口径。iFinD 与现有链路同源，可省掉一整层口径对齐。
2. **`search_stocks` 直接解决 P0 遗留的结构性短板**。P0-3 现在的泛称解析是"任务内自举"（从 brief + 意图抽取里捞已知公司名），换个 brief 里没有公司名的新任务就会解析失败走澄清门。而 `search_stocks("光伏组件行业市值前5的股票")` 是**真正的外源实体落地**，语义上等价于方案 §3 P0-3 原本设计的"调 `hithink_sector_selector` 取板块成分"，且是现成接口。
3. **EDB 宏观/行业指标最全**。`search_edb` 先搜指标再取数，正好覆盖 P0 里那个"产业级有数据、公司级没数据"的尴尬地带（如光伏组件行业产量/产能利用率是行业口径，公司口径查不到）。

代价：需申请密钥；免费版 2 并发/秒，多 Agent 并行取数会成为瓶颈 → 需要在 Agent 1 侧加串行化队列或申请个人/企业版。

### 4.2 第二源：NeoData（补位 + 兜底）

- 唯一**结构化与文档在同一次召回内返回**的源，直接对应方案 P1 要做的「fallback 链」：主选技能空调用 → 自动落备选。
- 唯一能对治 **P0-6 / 成因 D「静默降级为行情数据」** 的补位源：问财查"隆基绿能出货量"会静默返回行情列（最新价/涨跌幅），这类"行数 > 0 但字段不对"的错误，靠**文档召回给研报口径的定性数据** + 后续字段相关性校验才能拦住。
- 跨市场、跨品类（债券/期货/期权/外汇/大宗）覆盖最宽，报告涉及港股/美股对标或宏观对冲时不用再接新源。

代价：异源，必须做口径标注（证据分级里标 source），不能与 iFinD 数字混算。

### 4.3 第三层（可选）：妙想

只在"要最新研报/公告/政策解读原文"时接。它不做结构化数字，接进 Agent 1 只会污染证据池；更适合 Agent 2 的分析素材通道。当前未授权，优先级最低。

### 4.4 接入顺序建议

```
1. 配好 iFinD 密钥 → 作为 hithink_* 之外的「实体落地 + 行业指标」专用技能，先接 search_stocks 与 edb 两个工具
2. NeoData 作为 P1 fallback 链的备选位（主选空调用时自动落），所有召回证据强制打 source 标记
3. 妙想暂不接；等 P1 澄清门分级文案要做"按失败类型给不同下一步"时再评估
```

## 5. 附：为什么 P0 修完了、bug 还会复现（回应"我不是已经改好了吗"）

手上只有方案与验收报告两份文档，没有你这次复现的具体报错，所以下面是**基于文档的归因推断**，不是对本次 bug 的定性。五条可疑点，按可能性排序：

### 5.0 先更正：P0-6 已经改了，且已接线（已核实代码）

- `normalizer.py:565` 定义 `_field_relevance_check`，`normalizer.py:264` 在清洗出口调用
- `backend/tests/agents/data_fetcher/test_p06_field_relevance.py` 有 7 个用例
- `app/schemas/evidence.py` 加口径标签、`acquisition.py` 加 `market_quote_fallback` 标记

所以 8-31 验收报告里只有 P0-1~P0-5 是**时序问题**：P0-6 是 9-01 才补进方案的，晚于验收报告。

推论：**"P0 验收通过"只覆盖了 6 项中的 5 项，P0-6 至今没跑过真 LLM + 真 SkillHub 的端到端验收**。若你看到的复现现象是"数据看着有、但字段不对/口径不对"，先查 P0-6 是否真被调用、`market_quote_fallback` 有没有落到证据上。

### 5.1 头号嫌疑（已核实代码）：P0 修的是「层内」，「层间仲裁」三处没动

今天 61 条问句测试的核心结论：**34 条问题里 32 条根因在层间仲裁，不在层内**。对应三处代码，本次已逐行核实现状：

| # | 位置 | 现状 | 后果 |
|---|---|---|---|
| ① | `intent_merger.py:368` `if not valid_skills: continue` | **原样未改** | LLM 输出空 candidate_skills 时被直接跳过 → LLM 只能补充、**没有否决权** |
| ② | `intent_merger.py:477-485` `locked_skill_missing_after_merge` | **原样未改** | 确定性 locked 技能强制补回 `subs[0]` → 关键词误锁压过 LLM 判断 |
| ③ | `plan_validator` 打 `clarification_should_be_advisory` 但 service 层未据此放行 | `service.py` 已有 `advisory_clarifications` 通道，需确认是否覆盖 W2 场景 | 23 条过度阻塞 |

而对应的修复方案 `docs/plans/2026-09-01-agent1-arbitration-fix.md` 状态是**待评审授权、未动生产代码**。

⇒ **这就是"改好了还复现"最可能的解释**：P0 把拆解、合并、泛称、词表、埋点、字段校验这些"层内"问题都修了，但"层间谁说了算"没修。命中层内成因的那批 bug 消失了，命中层间仲裁成因的（静默误判 9 条 + 关键词误锁 2 条 + 过度阻塞 23 条）**原样复现**——它们从来就没被 P0 覆盖过。

### 5.2 验收是「单次跑通快照」，且回归入口已被删除

验收结论建立在 `run_id=run-p0-acceptance-pv` 这一次探针运行上，探针脚本 `probe_p0_e2e.py` 已按方案要求删除。

`test_p0_routing_fix.py` 的 25 个用例是**构造输入下的断言**（喂固定的那几句问句），它证明的是"这 5 个已知 case 修好了"，不是"线上任意 query 都不会再犯"。**缺少一个可复跑的端到端回归入口**，新 query 走新分支照样漏。

### 5.3 遥测数据本身就暴露了覆盖盲区

验收表格里：`route_decision = 5`，且**全部 `layer=deterministic`**。

含义是：本次验收中 **L2 语义路由层一条都没被触发/观测到**。P0-1 的 prompt 规则 5/6、`_is_analysis_directive` 的正则兜底主要在确定性层生效。而线上真实 query 一旦走语义层（LLM 拆解），就是**未被这次验收覆盖的路径**。

同时 `decomposition=14` 对 `skill_call=84` —— 拆解层样本量极小，模型行为的分布根本没被采样到。

### 5.4 三处修复的触发条件都很窄

- **P0-1** 只在 `not candidate_skills and entities and not metrics` 时继承。若拆解器产出的是"有实体 + 一个 metric 但类型 unknown"（例如"组件出货量"被切成"组件"），继承不触发。
- **P0-4** 别名表是**闭集**：出货量/销量/销售量/发货量。用户说"交付量""排产""开工"照样 miss → 回落成"暂无对应查询技能"或静默降级。
- **P0-3** 泛称解析优先用"已知公司池"（brief + 意图抽取），本质是任务内自举。光伏任务恰好池里有三家，所以过；换一个 brief 里没公司名的任务，必然解析失败走澄清门。**这一条建议直接改用 iFinD `search_stocks` 做外源解析（见 §4.1）。**

### 5.5 环境差异

验收用 `deepseek-v4-flash`。线上若换模型，`_DECOMPOSER_SYSTEM_PROMPT` 的规则 5/6 是**概率性约束**（prompt 不是契约），拆解结果分布会变，裸实体碎片会重现——这正是方案自己写下的"只改 prompt 是概率修复"的注脚。

### 建议动作

```
A. 把复现的具体问句 + 运行详情贴出来（子需求/候选技能/证据字段名），先判定属于层内还是层间成因 —— 层间成因 P0 本来就没覆盖，不是回归
B. 若属层间成因：评审并落地 docs/plans/2026-09-01-agent1-arbitration-fix.md 三处改动（LLM 显式否决权 / locked 不强制补回 / advisory 真放行），这是 32/34 的根因
C. 给 P0-6 补一次真 LLM + 真 SkillHub 的端到端验收（它的 7 个用例是单测，没跑过真实静默降级样本）
D. 恢复可复跑的端到端回归入口（probe 脚本改 pytest e2e + nightly 标记），别再靠单次探针快照下结论
E. 用 iFinD search_stocks 替换 P0-3 的任务内自举解析，做真正的外源实体落地（见 §4.1）
F. 补语义层遥测样本：目前 route_decision 5 条全 deterministic，样本量不足以支撑任何 P1 立项判断
```
