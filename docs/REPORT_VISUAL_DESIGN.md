# 报告视觉设计方案 — 让最终报告变好看

日期: 2026-08-19
目标: 解决"什么时候用表格、什么时候放图、放在哪里、怎么排版"四个核心问题。
约束: 7章21节结构不可变；图表上限30张（推荐8张）；证据链必须完整；不构成投资建议。

---

## 一、核心决策规则：表格 vs 图表 vs 纯文字

### 1.1 什么时候用图表

| 数据特征 | 用图 | 图表类型 |
|----------|:----:|----------|
| 时间序列（≥3期） | ✓ | line / area |
| 分类对比（≤8类） | ✓ | bar (vertical/horizontal) |
| 占比结构（≤6项） | ✓ | pie |
| 多维能力对比（3-6维） | ✓ | radar |
| 产业链环节关系 | ✓ | industry_chain |
| 双轴异量纲（价格+量） | ✓ | combo |
| 分布/离散度 | ✓ | boxplot |
| 两变量相关性 | ✓ | scatter |

**不用图的情况**：
- 数据点 < 3（样本不足，图无意义）
- 纯定性描述（政策、新闻、事件）
- 精确数值查询（用户要"查一个数"而非"看趋势"）
- 证据被隔离或为空（G5规则：无数据不绘图）

### 1.2 什么时候用表格

| 数据特征 | 用表 | 说明 |
|----------|:----:|------|
| 精确数值（用户需要抄录/引用） | ✓ | 表格是精确值的载体 |
| 多属性对比（≥4列） | ✓ | 图无法承载多维属性 |
| 财务预测/假设条件 | ✓ | 需要精确到小数点 |
| 成本拆分/费用率明细 | ✓ | 分组表比饼图更清晰 |
| 数据质量问题清单 | ✓ | 结构化信息用表 |
| 来源/证据索引 | ✓ | 已有模板实现 |
| 排名/排序结果（>8项） | ✓ | 条形图超过8项可读性下降 |

**不用表的情况**：
- 只有1-2个数值（直接写在正文里）
- 趋势展示（用折线图更直观）
- 定性分析（用文字段落）

### 1.3 什么时候用纯文字

- 因果推理、逻辑论证
- 政策/事件解读
- 风险提示、不确定性说明
- 过渡段、章节摘要
- 方法论说明

### 1.4 图和表同时存在时

规则：**图先概括，表后展开**。

```
正文段落（提出观点）
  ↓
图表（可视化概括趋势/结构）
  ↓
表格（展开精确数值）
  ↓
正文段落（解读数据含义）
```

## 二、放在哪里：7章21节的视觉分配策略

### 2.1 总体原则

```
每个节（SEC-XX-XX）的内部结构：
  段落（观点）→ 图表/表格（证据）→ 段落（解读）→ [不确定性提示]
```

图表通过 `placement_section_id` 绑定到具体节。规则：
1. **图表必须放在首次解释它的段落之后**（紧跟原则）
2. **一个节最多2张图**（超过则拆分到相邻节或降级为表格）
3. **结论段和对应图表必须同页**（print CSS: `break-inside:avoid`）
4. **产业链图独占一整节**（不与其他图混排）

### 2.2 各章视觉策略

| 章 | 典型内容 | 视觉策略 | 图表类型 |
|----|----------|----------|----------|
| CH-01 行业概览 | 市场规模、增速、阶段 | 1张趋势图 + 1张规模表 | line + 表格 |
| CH-02 竞争格局 | 市占率、CR5、玩家对比 | 1张份额图 + 对比表 | bar/pie + 表格 |
| CH-03 财务分析 | 营收、利润、费用率 | 趋势图 + 财务明细表 | line/bar + 表格 |
| CH-04 产业链 | 上中下游、盈利分配 | 产业链图（独占） | industry_chain |
| CH-05 驱动与风险 | 政策、技术、风险因素 | 文字为主，可选1张图 | bar/radar（可选） |
| CH-06 预测与情景 | 基准/乐观/悲观 | 情景表 + 预测图 | line(虚线) + 表格 |
| CH-07 结论与建议 | 核心结论、边界 | 纯文字 + 结论表 | 表格（可选） |

### 2.3 执行摘要的视觉

执行摘要是第一屏，必须**一眼看到答案**：

```
┌─────────────────────────────────────────┐
│  核心判断（1句话，加粗，21px）            │
├─────────────────────────────────────────┤
│  结论1 │ 结论2 │ 结论3                  │  ← 卡片式，每个带置信度标签
│  [来源chips]                             │
├─────────────────────────────────────────┤
│  三种情景（乐观/基准/悲观）              │  ← 列表
├─────────────────────────────────────────┤
│  核心风险 + 研究边界                     │  ← 列表
└─────────────────────────────────────────┘
```

不放图表。执行摘要是纯文字+结构化卡片。

### 2.4 附录的视觉

| 附录 | 内容 | 形式 |
|------|------|------|
| 数据质量附录 | 问题清单、一致性检查、维度覆盖 | 表格（已实现） |
| 来源索引 | 证据目录 | 表格（已实现） |
| 未放置图表 | 超出节绑定的图 | 图+figcaption（已实现） |
| 未解决问题 | 草稿模式下的风险 | 列表（已实现） |

## 三、排版布局系统

### 3.1 页面结构（A4）

```
┌──────────────────────────────────────┐
│  页眉：报告标题（左）· 页码（右）      │  ← 9pt, #64748b
├──────────────────────────────────────┤
│                                      │
│  正文区（单栏，max-width: 1040px）    │
│  左右边距: 64px (屏幕) / 12mm (打印)  │
│                                      │
│  [段落]                              │
│  [图表卡片]  ← 带边框圆角容器         │
│  [段落]                              │
│  [表格]                              │
│  [段落]                              │
│                                      │
├──────────────────────────────────────┤
│  页脚：免责声明（固定）               │  ← 9pt
└──────────────────────────────────────┘
```

### 3.2 字体层级

| 元素 | 字号 | 字重 | 颜色 |
|------|------|------|------|
| 封面标题 | 44px / 32pt(print) | 700 | #0f172a |
| 章标题 (h2) | 28px | 700 | #0f172a |
| 节标题 (h3) | 20px | 600 | #162b4d |
| 正文 | 15px / 13.5px(print) | 400 | #0f172a |
| 章摘要 | 16px | 400 | #334155 |
| 图注/来源 | 12px | 400 | #64748b |
| 表格内容 | 13px | 400 | #0f172a |
| 表头 | 13px | 600 | #0f172a |

### 3.3 颜色系统

```css
--ink: #0f172a;       /* 正文 */
--muted: #64748b;     /* 辅助文字、图注 */
--line: #dbe4ef;      /* 边框、分隔线 */
--blue: #1d4ed8;      /* 品牌色：标题装饰、链接、关键数据 */
--paper: #fff;        /* 背景 */
--soft: #f4f7fb;      /* 卡片背景、表头背景 */
```

**用色规则**：
- 品牌蓝只用于：封面顶线、h2底线、引用链接、结论左边框、eyebrow
- 红绿只表示涨跌/正负，且必须同时用符号（↑↓）
- 单页有效颜色 ≤ 6种
- 不用渐变、玻璃效果、强阴影

### 3.4 间距节奏

| 元素 | 上间距 | 下间距 |
|------|--------|--------|
| h2 (章标题) | 48px | 20px |
| h3 (节标题) | 30px | 12px |
| 段落 p | 10px | 10px |
| 图表卡片 | 22px | 28px |
| 表格 | 16px | 22px |
| 不确定性提示 | 14px | 14px |
| 章摘要 | 0 | 16px |

### 3.5 分页规则

| 规则 | 实现 |
|------|------|
| 每章起始新页 | `.chapter { page-break-before: always; }` |
| 标题不孤留页尾 | `h2, h3 { page-break-after: avoid; }` |
| 图表不跨页 | `.chart { break-inside: avoid; }` |
| 不确定性提示不跨页 | `.uncertainty { page-break-inside: avoid; }` |
| 表格可跨页（加"续表"标注） | 允许，但表头重复 |
| 封面独占一页 | `.cover { page-break-after: always; }` |

## 四、图表卡片规范

### 4.1 图表容器

每张图是一个带边框的卡片（已实现 `.chart` 类）：

```
┌─────────────────────────────────────┐
│  [SVG 图表区域]                      │
│                                     │
├─────────────────────────────────────┤
│  图X-Y · 标题 · 图表类型            │  ← figcaption 第一行
│  数据来源：[来源1] [来源2]           │  ← 可点击跳转
│  分析目的：...                       │  ← insight_goal（可选）
│  数据说明：...                       │  ← footnotes（可选）
└─────────────────────────────────────┘
```

### 4.2 图表编号

格式：`图{章号}-{节内序号}`，如"图3-1"表示第3章第1张图。
- 全文连续编号
- 图表编号与表格编号独立（表格用"表X-Y"）

### 4.3 图表尺寸

| 类型 | 宽度 | 高度 |
|------|------|------|
| line / bar / area | 100% | 自动（SVG viewBox） |
| pie / radar | 60% 居中 | 自动 |
| industry_chain | 100% | 自动（可能很大） |
| scatter / bubble | 80% 居中 | 自动 |
| heatmap / treemap | 100% | 自动 |

打印时 SVG 最大高度 78mm（已实现 `.chart svg { max-height:78mm; }`）。

## 五、表格规范

### 5.1 表格样式

采用**三线表**风格（学术规范）：

```css
.data-table {
  width: 100%;
  border-collapse: collapse;
  font-size: 13px;
}
.data-table thead tr {
  border-top: 2px solid var(--ink);    /* 顶线 */
  border-bottom: 1px solid var(--ink); /* 表头分隔线 */
}
.data-table tbody tr:last-child {
  border-bottom: 2px solid var(--ink); /* 底线 */
}
.data-table th, .data-table td {
  padding: 8px 12px;
  text-align: left;
  vertical-align: top;
}
.data-table th {
  font-weight: 600;
  background: var(--soft);
}
```

- 无竖线
- 无多余横线
- 表头背景 `--soft`
- 数值列右对齐，文字列左对齐

### 5.2 表格标题与来源

```
表X-Y 表格名称                    ← 表格上方，加粗
┌─────────────────────────────┐
│  表格内容                    │
└─────────────────────────────┘
数据来源：同花顺iFinD；报告期：2023-2025  ← 表格下方，12px灰色
```

### 5.3 表格放置位置

- **紧跟首次提及该数据的段落之后**
- 不跨章节放置
- 大表格（>10行）可独占一个节的下半部分
- 小型补充表格（≤5行）嵌入段落之间

## 七、Agent 5（Report Fusion）的视觉决策输出

Agent 5 在组装 `ReportViewModel` 时，应输出以下视觉决策元数据（供渲染层使用）：

```json
{
  "visual_shell": "analysis_note",
  "chart_density": "medium",
  "table_priority": "high",
  "per_chapter_strategy": {
    "CH-01": {"charts": 1, "tables": 1, "dominant": "line"},
    "CH-02": {"charts": 1, "tables": 1, "dominant": "bar"},
    "CH-03": {"charts": 1, "tables": 2, "dominant": "line"},
    "CH-04": {"charts": 1, "tables": 0, "dominant": "industry_chain"},
    "CH-05": {"charts": 0, "tables": 0, "dominant": "text"},
    "CH-06": {"charts": 1, "tables": 1, "dominant": "line"},
    "CH-07": {"charts": 0, "tables": 1, "dominant": "text"}
  }
}
```

### 视觉外壳选择规则（3种，不是16种）

| 外壳 | 触发条件 | 特征 |
|------|----------|------|
| **数据手册型** | 表格数 > 图表数 × 2 | 表格主导，图只提炼趋势 |
| **分析笔记型**（默认） | 图表数 ≈ 表格数 | 图文均衡，图紧跟结论 |
| **深度研究型** | 定性段落占比 > 60% | 章节叙事，图穿插点缀 |

本项目大多数报告是**分析笔记型**（行业研报 = 数据+分析均衡）。

## 附：一句话总结

**图回答"什么趋势/什么结构"，表回答"具体是多少"，文字回答"为什么/意味着什么"。图紧跟首次解释它的段落，表紧跟需要精确值的段落，每节最多2图，产业链图独占一节。美观来自秩序（统一的字体、颜色、间距、编号），不来自装饰。**
