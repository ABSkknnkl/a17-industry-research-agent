## 2. 先补离线逐站演练

### 2.1 固定单次运行控制

真实验收使用一个独立进程和独立验收目录，复用 `WorkflowEngine.create_run`、`handle_review` 及生产阶段适配器。由同一个常驻进程持有工作流与事件循环，等待每次审查放行。建立请求时显式设置：

```json
{
  "review_stages": ["data_fetch", "data_interpret", "chart_generate", "chapter_write"]
}
```

进入下一站只批准当前已审阶段，传最新 `expected_revision`。A4 停在 `chapter_write / waiting_review`。现有批准逻辑会调度下一阶段，因此验收控制入口在调用审核 API 前就应拒绝对 A4 的任何批准动作。A5 调用计数为 0，A5 阶段状态应为 `pending`。 [任务创建与阶段派发](../../backend/app/engine/state_machine.py#L585) · [审核批准与推进](../../backend/app/engine/state_machine.py#L1366) · [阶段暂停](../../backend/app/engine/state_machine.py#L2133)

**上线前必须覆盖 A3 的自动补采分支。** 当前 A3 返回 `data_demands` 时，状态机在提交阶段结果与进入待审核前尝试补采，补采提交后会重新进入 A2。仅配置审核停点无法保证本次的阶段次数。推荐在验收入口的隔离进程中使用局部的 `WorkflowEngine` 验收包装器，针对该次运行拦住 `_run_chart_supplement`。将原始需求及原因写入验收诊断，返回现有的 `"none"` 状态，使 A3 产物进入正常审查。使用现有实现的返回契约，保留需求本身。所有离线与真实验收共用这套控制。 [补采路径](../../backend/app/engine/state_machine.py#L425) · [补采提交后回到 A2](../../backend/app/engine/state_machine.py#L2066)

建议新增小型验收入口 `scripts/run_agent4_p3_acceptance.py` 和覆盖该入口的 `backend/tests/test_agent4_p3_acceptance.py`，先验证这两个建议路径在当前分支尚未已有实现。验收入口应提供创建一次运行、读取状态与快照、接受 A1–A3 放行、结案四项操作。A1–A4 各阶段以首次开始事件计数，第二次派发应在适配器入口前拦截。台账在创建任务前取得验收批次的独占记录，创建后保存真实 `run_id`。进程中断后先核对台账和工作流状态。无法确认是否已发起模型调用时，按名额可能已经使用处理。

## 3. 执行唯一一次真实验收

1. **冻结配置。** 原方案第 09 节四题合并为一个请求，保留题号。确认实际 A4 配置为 apply、四个审核停点有效、自动补采受控、A4 审核锁有效。冻结提交、问题输入哈希、模型、证据截止日和调用预算。核实凭据及额度可用时避免预先消耗真实 LLM 调用。收到执行本阶段的指令且前置门槛齐备后创建一次真实运行。
2. **A1 自查。** 核查 2021—2025 年销量、渗透率、出口量的年份、单位、来源及统计口径。渗透率分子分母同范围。逐项标记三家整车企业 27 个财务单元及动力电池分组所需数据，区分集团与分部。原始数据、修订数据和证据引用可核对后放行 A2。
3. **A2 自查。** 用最终 A1 数据复算关键指标和趋势。核对分组、研发强度定义、利润率和现金流口径、产业链关系与归因边界。记录错误及依赖项，只做已登记内容的确定性修正。证据可回指、口径可比后放行 A3。
4. **A3 自查。** 对照最终 A1/A2 检查表格值、图表点、年份、单位、证据索引和产业链节点及关系。审查被记录的补采需求，将有据材料、明确缺口及需阻塞的问题分开。依赖无法局部修正就结案为阻塞。确认 A2/A3 实际输入版本后放行 A4。
5. **A4 停止与验收。** 只接收本次生成的章节稿。按四题检查有据作答、明确披露缺口或遗漏，复核关键数字解读、引用、重复展开及表图文一致性。保存最终状态与阶段计数。正文交付包含表格内容、图表引用和证据索引。

逐站审查由 AI 完成。每条问题记录 `issue_id`、阶段、版本、位置或 `record_id`、原值、来源及口径、受影响的结论/图表、修订前后、复核结果。确认修订依赖已同步后再放行。无据内容以缺口记录，合成夹具单独标注。发生失败、超时或必须重跑的情况时保留现场，关闭后续派发，以阻塞或未通过结束本次真实验收。

## 4. G3 验收单独结论

**当前没有同一真实输入和证据的可比旧稿。** 评估器会检查 `source_report_id`、主题、大纲版本及小节集合。合成 off 稿与真实 A4 稿无法组成可比对照。已有的 53 → 30 是自动候选数。候选确认列表为空且未完成复核时，脚本显示的 100% 降幅没有验收意义。 [评估器的可比性检查和门槛](../../scripts/evaluate_agent4_refactor.py#L190)

按以下方式收尾：

1. **合成回归。** 复核 off/apply 的候选重复位置，补齐两版实际答题状态和各至少 6 段评分后再使用 `--gate`。结果只代表合成对照。保留原标注文件，另存审核后的版本。未确认的重复列表标为待审，已经逐项复核且确认无重复才写空列表。
2. **真实稿绝对评价。** A4 产出后逐题核查证据和遗漏，抽查至少 6 段核心数字正文。每段按可复核比较、业务含义、判断边界记 0/1 分，另列跨章真重复、错误因果和行业特例残留。位置用 `chapter_id/section_id/paragraph_id`，每分附理由及证据 ID。AI 先提交自查与待复核清单。正式盲评保留独立复核记录。
3. **相对改善结论。** 只有已有同问题、同证据的真实旧稿才做盲评对照，按原定 30% 降幅门槛核对。两版按同一论点和口径配对，即使段落位置变动也不能把未配对的段落默认成基线零分。无可比旧稿则把 G3 降幅记为「缺可比基线，未验收」，保留真实稿绝对评价。单次验收期间不为补旧稿追加真实模型运行。

若后续自动化必须依赖 `--gate` 出具相对改善结论，再另开最小评估器修补：标注不全时不计算可发布降幅，段落比较要求明确配对，增加对应回归。当前可以先用人工标注和绝对评分完成 P3 的实际交付记录。
