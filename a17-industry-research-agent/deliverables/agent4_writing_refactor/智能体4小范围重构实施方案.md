# 智能体 4 小范围重构实施方案

实施规格 V2.1 · 2026-11-09

核查基线 fa9a6a6，供 AI 工程师实施与验收人员复核。

执行本方案时，按 T0 → P0 → P1 → P2 → P3 完成实施、离线回归和验收交付。P3 在重构完成后执行一次真实工作流。第 09 节规定唯一的真实试跑范围、逐站放行和完成条件。

## 01 重构目标与范围

| 目标 | 完成标准 |
| --- | --- |
| G1 清理行业特例 | 非航天合成样本中，旧航天示例和替换规则引入的表述为零。未知行业仍可计算市值、样本数和估值锚点。有效航空航天证据仍可用于正文。 |
| G2 明确问题的主答位置 | 可确定归属的必答需求有唯一主答小节。可用证据的必答项都有有据作答，缺数据的必答项明确说明缺口。基线已答项无退化。 |
| G3 改善内容密度 | 重复明显的冻结样稿中，人工确认的跨章重复展开率相对下降至少 30%。关键数字段落更能解释变化、业务含义及证据边界。 |
| G4 保护交付 | 证据引用与图表可追溯，事实核验、修订版本、正式与受限交付通过既有回归。 |

核心改动位于 `agents_core/chapter-writer/chapter_writer/`。允许新增内部归属模块、针对性测试和离线评估脚本。优先由现有检索器同时服务整篇写作和单章重写。若复现两条入口拿到不同有效大纲，允许在后端单章重写入口做最小接线，并保留原版本保护。

沿用 7 章 21 节、章节目编号、公开请求与结果、Python/Pydantic、现有模型客户端与事实核验。A1/A2/A3/A5 通过现有契约接入。最终图注与三格式导出使用离线夹具做兼容性回归。真实验收范围为 A1 至 A4 的数据、分析、图表与章节稿。

## 03 目标架构与技术选型

A2 解读与需求矩阵 / A3 图表 / 有效大纲 → 确定性分配 → 现有证据检索与装包 → A4 写作和事实核验。A5 成品兼容性由离线回归验证。

新增 `chapter_writer/assignment.py`，用标准库数据类与纯函数，从现有 Pydantic 输入生成不可变分配表。由 `DynamicEvidenceRetriever.__init__` 按实际大纲计算一次。整篇和单章重写均使用该入口。现有文本相关性检索用于材料排序及兼容回退。

### 内部数据契约

| 字段 | 约束 |
| --- | --- |
| `requirement_id`、`label`、`hard` | 从需求矩阵读取。每个原始 ID 独立建项。内容完全相同的重复行可去重，同 ID 冲突行回退并记诊断。 |
| `owner_section_id` | 有效大纲中的唯一小节 ID，歧义时为 `None`。所属章从小节关系派生。 |
| `coverage_state` | `covered` 要求上游通过且有有效证据。`missing_data` 表示上游明确未满足。缺失或不可判读为 `unknown`。 |
| `evidence_record_ids`、`reason_code` | 只保留本次索引中的原始 ID，按 ID 稳定排序。记录 `metric_family`、`domain`、`ambiguous`、`unknown_kind`、`custom_outline` 或 `conflicting_rows`。 |

### 首版分配与检索规则

1. 有效大纲取 `request.outline or DEFAULT_OUTLINE`。默认大纲映射只用于小节编号及语义一致的情况。自定义大纲出现不匹配时沿用旧检索并记录诊断。
2. 将显式 `metric_families` 通过现有 `metric_family()` 规范化，按领域和指标族匹配。匹配唯一才分配。混合行指向多节时记录歧义，保留原需求和证据。缺结构化指标时，仅使用已确认能唯一确定位置的领域规则。
3. 默认先覆盖 `SEC-02-01` 的行业指标 `pv_new_capacity`、`nev_sales`、`nev_penetration`，`SEC-05-01` 的财务指标 `revenue`、`parent_net_profit`、`gross_margin`、`rd_expense`、`rd_investment`，以及 `SEC-05-02` 的财务指标 `operating_cash_flow`、`cash_to_net_profit`。事件规则指向 `SEC-06-03`，接入前用生产形态夹具确认实际领域值。未识别的需求沿用旧逻辑。
4. 每章先保全现有必需证据、图表绑定证据和需求行，再对可选论点排序。主答负责完整展开，其它章可使用相同证据支撑新的判断或简短回顾。图表推荐、证据相关性与章节目职责共同约束解读。

**模式**使用单个内部开关 `A4_ASSIGNMENT_MODE=off|observe|apply`。缺省或非法值用 off，非法值记诊断。observe 生成内部评估信息，模型正文输入与 off 等价。apply 加入本章主答列表，以必答、有效证据、ID 顺序排序。新增提示软预算 2048 UTF-8 字节/章，优先压缩可选摘要和指导，保留原需求与证据保护规则。超限沿现有异常及兜底路径处理。

采用既有异步生成、技能路由、`quantity_issues`、章节重写预算和审计。新增规划和去重模型调用数为零。评估记录由直跑 A4 的 emit 或评估器保存，生产入口无需暴露新的响应字段。

## 04 分阶段实施、风险和回滚

### T0 · 冻结输入与建立基线 · 开工前置

1. 执行附录基线命令。保存提交、工作树状态、Python 版本、退出码、失败和跳过用例的 node ID。既有用户变更保持原样，比较在同一环境进行。
2. 冻结两份可重放的 A2/A3 包。A 为正文重复明显的报告，B 为证据稀疏的非航天报告。另做一份航天证据夹具。只有 PDF 留档时，从现有用例生成合成包并单独标识，真实对照留待有效产物。
3. 为每份样本记录原始问题、可答的需求、数据缺口、`report_id`、图表 ID、模型配置和输入 SHA-256。先标注基线重复段落和关键数字段，再开始改代码。

**门槛**为测试基线与样稿可复跑。**风险**是把旧 PDF 当成可重放输入或把模拟结果当真实能力。**回滚**为撤销无效基线，修订输入清单后对基线和候选共同重跑。

### P0 · 行业特例清理 · 最高优先级

1. 先在 `test_aerospace_chapter_defects.py` 与 `test_dynamic_segment_and_scale_consistency.py` 写三组红测：非航天触发旧替换、合法航天事实、未知行业通用锚点。单独标记依赖历史硬编码修辞的断言。
2. 在 `agent.py` 删除航天提示示例及三条公司名硬替换。用本次证据说明样本和期间边界。历史具体市值示例从提示移除，现有通用数值计算与审计保持回归覆盖。
3. 让固定公司字典退出事实锚点。角色提示只接收能回指本次证据的 A2 关系。核对同一条依据是否实际支持该公司、环节和范围，单有代表公司名单及段级证据 ID 时只能按来源描述样本，归属待核。现有证据约束、章节结构和修复预算照常校验。
4. 更新锁定旧硬替换的断言，用可追溯的关系与缺证据反例替代。保留公司、期次、金额与既有结论的核验强度。

**门槛**为 G1 和事实回归通过。**风险**是旧航天稿曾依赖人工替换。**回滚**按 P0 的独立提交执行，恢复上一可用版本后重新核查行业样稿。恢复旧版的报告标注旧规则风险。

### P1 · 真实需求主答分配 · 核心实施

1. 建立 `assignment.py` 和 `test_writing_assignment.py`。测试唯一映射、混合指标、同 ID 冲突、输入重排、自定义大纲、无矩阵、坏引用及合成跨行业用例。
2. 在 `retriever.py` 接入共享分配。先验证 observe/off 的正文输入等价，再加入 apply 的本章主答提示和可选项排序。已存在的必需证据保护、硬需求和图表绑定条件先通过原回归。
3. 在 `agent.py` 接入装包优先级和写作指导。优先压缩附加提示，按现有方式报出仍超限。已有局部解读、事实审计和回退逻辑复用。
4. 对整篇生成和人工单章重写传入相同 A2/A3 与大纲，断言责任、证据集合和降级行为一致。若后端旧重写入口只能取默认大纲，先复现自定义大纲路径，再决定是否做最小透传。历史数据不足时保留基线行为。

**门槛**为路由稳定、旧契约兼容、没有新增必需证据或图表缺失。**风险**是错误认领和提示挤占证据空间。**回滚**将开关切回 off，按现有审核流程重写受影响章节并重建下游。

### P2 · 重复与可读性诊断 · 先观察

1. 新增 `scripts/evaluate_agent4_refactor.py` 及测试。按章、小节、段落 ID 生成跨章重复候选。先检测归一化后完全相同的正文，再对同一需求或同口径观测用字符三元组 Jaccard 筛近似候选，0.85 作为初始送审阈值。
2. 归一化移除空白、图表占位符和引用标记，保留主体、数值、年份、单位及否定。排除必要摘要回顾和图表说明。按人工标注确认同一结论的重复展开，同一证据支持不同分析判断时允许复用。
3. 比较冻结样稿的 off/observe 与 apply 结果，记录命中位置、人工判断及证据影响。先验收写前分配能否改善问题。跨章自动返修的立项以已确认的重复仍高为前提。

**门槛**为脚本可运行、结果可回查、G2/G3 有成品对照。**风险**是相似度误把不同期间、比较对象或观点当重复。**回滚**为撤销误判规则或修订阈值后重算候选，保留原样稿与人工标注。

### P3 · 离线集成回归与单次真实验收

1. 使用离线夹具完成 T07，复验现有导出、图表挂接、版本失效和事实审计。先离线证明 A1、A2、A3 产出后能分别暂停，能放行修订后的输入，且 A4 产出后工作流停止。
2. 完成重构和离线验收后，以 apply 模式按第 09 节执行唯一一次真实工作流，记录代码版本、模型配置、预算和运行编号。每站由 AI 自查和登记问题。A3 放行后只生成一次 A4 章节稿。
3. 依据 T08 和第 09 节对章节稿逐题验收，收拢原始快照、修订材料和证据。按实际结果标记通过、带缺口通过、未通过或阻塞。PDF、A5 编辑效果和正式报告交付状态归入后续独立验收。

**门槛**为离线兼容性检查通过，真实验收达到 A4 并有逐站审查、最终输入版本及逐题结论。**风险**是工作流自动推进、上游修订与下游引用错版，或一次运行内无法修正关键问题。**处置**为保留原始产物并阻塞放行。必要时关闭 apply，恢复日常环境配置。真实运行名额用完后，本次验收以已有产物结案。

## 05 数据与接口兼容性

| 场景 | 实施约束 |
| --- | --- |
| 旧产物缺少需求矩阵 | 空分配并复用原检索。现有 ChapterWritingRequest、ChapterDraft、ChapterWritingResult 和成品结构兼容旧数据。 |

### 发布门槛

- **必答完整性**以 T0 标注的真实必答问题为分母，逐项记录“有据作答、明确缺口、遗漏”。保全基线已答项。有证据的必答项遗漏为零，缺数据项说明缺口。证据相交只作为定位线索。
- **重复率**为人工确认的重复展开段落数除以可比正文段落数。每个冗余段落只计一次，必要引用、摘要和不同视角的合法证据复用排除。高重复样本相对下降 ≥30%，低重复样本逐项对照，零重复基线无新增。
- **信息密度**每份样稿至少抽查 6 段关键数字段，比较、含义、边界各 0/1 分。隐藏版本标识并保存逐段理由。候选平均分不下降，高重复样本至少两段改善。必要时复核归因原始材料。
- **事实与导出**分别记录生成错误、审计隔离和产物残留。新增错误数字、主体、单位、期间、悬空引用及错绑版本为零。已能完成的离线案例无新增兜底。以新增失败用例 ID 判回归，既有失败保留记录。
- **预算与耗时**上下文超限无新增，新增规划和去重模型调用为零。记录真实运行各阶段的输入字节、调用数和耗时。只有条件可比的历史记录可用于耗时对照，单次结果仅报告本次实测。

前后对照使用既有历史稿或离线样稿。真实运行固定模型配置、技能和章节预算，仅生成候选章节稿。同输入、同证据的历史稿可用于前后对照。其余历史稿仅作观察参照，以本次验收规则给出绝对评价。合成、真实模型、实际 Chromium 与导出 stub 各自记录。

## 09 单次真实 LLM 验收 · 新能源汽车行业

### 研究输入

以下四题合为同一个研究请求。第一题定义报告主线，其余三题作为必须逐项验收的子问题。保留题号作为审查和交付索引。数据表、趋势图、产业链结构和证据来源在 A1–A4 产物中交付。

1. **总题。** 2021—2025 年中国新能源汽车销量及市场渗透率如何变化？比较比亚迪、长安汽车和赛力斯在 2023—2025 年的营业收入、毛利率及经营现金流。分析整车与动力电池产业链的主要关系，提供数据表、趋势图、产业链结构和证据来源。
2. **市场与口径。** 2021—2025 年中国新能源汽车销量、渗透率及出口量如何变化？汽车总量、乘用车等不同统计口径会怎样影响结论？
3. **整车企业。** 比亚迪、长安汽车、赛力斯 2023—2025 年的营收、毛利率及经营现金流如何分化？整车业务能否单独比较？
4. **电池与整车分组。** 宁德时代、亿纬锂能与整车企业在研发强度、利润率及现金流方面有何差异？为什么应按动力电池与整车环节分组分析？与第三题使用可比期间，存在期间或口径差异时分列。

已知历史试跑停在章节审核，未形成 PDF。本次沿用该停点验收章节稿。历史记录只能说明此前到达了该停点，具体质量以本次产物为准。

### 开跑前检查与运行边界

1. 先完成 T0、P0、P1、P2 的实施、文档与离线回归，再完成 P3 的离线集成验证。使用模拟模型演练各站暂停、审查、修订产物生效和停止边界。若现有运行入口不能同时满足这些条件，先在离线环境配置或验证控制路径，实际可控后再消耗真实运行名额。
2. 冻结四题、代码提交、环境配置摘要、模型、技能、预算、证据截止日和输出目录。核对阶段放行能够传入审查后的版本。开跑前缺凭据、额度或暂停能力时，记录阻塞，保留运行名额。
3. 真实验收只创建一个 `run_id`。顺序固定为 A1 → 自查和放行 → A2 → 自查和放行 → A3 → 自查和放行 → A4 → 章节稿验收和停止。各阶段只触发一次，阶段内部既有的模型调用和修复预算计入这次工作流并如实登记。自查、局部修订和验收用已有证据、脚本复算及人工可复核检查完成，避免额外真实模型调用。
4. A4 产出后停在章节审核或等效状态。关闭自动放行，A5 调度次数为零。以工作流状态和调用记录验证边界。各阶段失败、超时或无法局部修订时保留现场，以阻塞或未通过结案。禁止重新创建运行、重启阶段或用替代真实样稿充当本次结果。

### 问题登记与局部优化

- 每个问题分配唯一 `issue_id`。记录阶段、输入或产物版本、具体位置、原值与口径、预期值与依据、`record_id` 或来源、影响的分析句和图表点、修订前后、复核结果与状态。发现影响正文的遗漏也列入清单。保留原始产物供复核。

### A4 章节稿验收

使用最终放行的 A1、A2、A3 版本生成章节稿。验收时逐题标注「有据作答」「明确披露缺口」或「遗漏」，记录章节目、段落、图表 ID 和证据。保留完整章节稿，执行以下检查。

- **问题覆盖**。市场趋势、口径差异、三家车企财务分化、集团与分部可比性、动力电池与整车分组、产业链结构均能定位到正文。可用证据的必答内容不得遗漏。
- **专业解读**。按第 06 节抽查至少六段核心数字段，分别核对比较、业务含义和判断边界。数据口径、角色和因果有明确支撑。具体指出无法单列的分部或需补充的证据。
- **事实与图文一致**。核对引用均在最终证据索引中，正文和表图使用同一修订版本，数值、范围、单位和年份一致。缺数不得以零或推测值填充。
- **重构效果**。检查同一结论是否跨章重复展开、关键数字是否只罗列未解读、旧行业特例是否污染本次正文。有可比历史稿时直接对照。历史稿不可比时按本节给出本次评价，并标明无法量化的改进项。
