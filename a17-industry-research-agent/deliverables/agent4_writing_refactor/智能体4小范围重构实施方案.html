03 目标架构与技术选型

A2 解读与需求矩阵 / A3 图表 / 有效大纲 → 确定性分配 → 现有证据检索与装包 → A4 写作和事实核验 → A5 成品验证

新增 chapter_writer/assignment.py，用标准库数据类与纯函数，从现有 Pydantic 输入生成不可变分配表。由 DynamicEvidenceRetriever.__init__ 按实际大纲计算一次。整篇和单章重写均使用该入口。现有文本相关性检索用于材料排序及兼容回退。

内部数据契约

字段约束
requirement_id、label、hard从需求矩阵读取。每个原始 ID 独立建项。内容完全相同的重复行可去重，同 ID 冲突行回退并记诊断。
owner_section_id有效大纲中的唯一小节 ID，歧义时为 None。所属章从小节关系派生。
coverage_statecovered 要求上游通过且有有效证据。missing_data 表示上游明确未满足。缺失或不可判读为 unknown。
evidence_record_ids、reason_code只保留本次索引中的原始 ID，按 ID 稳定排序。记录 metric_family、domain、ambiguous、unknown_kind、custom_outline 或 conflicting_rows。

首版分配与检索规则

  1. 有效大纲取 request.outline or DEFAULT_OUTLINE。默认大纲映射只用于小节编号及语义一致的情况。自定义大纲出现不匹配时沿用旧检索并记录诊断。
  2. 将显式 metric_families 通过现有 metric_family() 规范化，按领域和指标族匹配。匹配唯一才分配。混合行指向多节时记录歧义，保留原需求和证据。缺结构化指标时，仅使用已确认能唯一确定位置的领域规则。
  3. 默认先覆盖 SEC-02-01 的行业指标 pv_new_capacity、nev_sales、nev_penetration，SEC-05-01 的财务指标 revenue、parent_net_profit、gross_margin、rd_expense、rd_investment，以及 SEC-05-02 的财务指标 operating_cash_flow、cash_to_net_profit。事件规则指向 SEC-06-03，接入前用生产形态夹具确认实际领域值。未识别的需求沿用旧逻辑。
  4. 每章先保全现有必需证据、图表绑定证据和需求行，再对可选论点排序。主答负责完整展开，其它章可使用相同证据支撑新的判断或简短回顾。图表推荐、证据相关性与章节目职责共同约束解读。

模式使用单个内部开关 A4_ASSIGNMENT_MODE=off|observe|apply。缺省或非法值用 off，非法值记诊断。observe 生成内部评估信息，模型正文输入与 off 等价。apply 加入本章主答列表，以必答、有效证据、ID 顺序排序。新增提示软预算 2048 UTF-8 字节/章，优先压缩可选摘要和指导，保留原需求与证据保护规则。超限沿现有异常及兜底路径处理。

采用既有异步生成、技能路由、quantity_issues、章节重写预算和审计。新增规划和去重模型调用数为零。评估记录由直跑 A4 的 emit 或评估器保存，生产入口无需暴露新的响应字段。

04 分阶段实施、风险和回滚

T0 · 冻结输入与建立基线 · 开工前置

  1. 执行附录基线命令。保存提交、工作树状态、Python 版本、退出码、失败和跳过用例的 node ID。既有用户变更保持原样，比较在同一环境进行。
  2. 冻结两份可重放的 A2/A3 包。A 为正文重复明显的报告，B 为证据稀疏的非航天报告。另做一份航天证据夹具。只有 PDF 留档时，从现有用例生成合成包并单独标识，真实对照留待有效产物。
  3. 为每份样本记录原始问题、可答的需求、数据缺口、report_id、图表 ID、模型配置和输入 SHA-256。先标注基线重复段落和关键数字段，再开始改代码。

门槛为测试基线与样稿可复跑。风险是把旧 PDF 当成可重放输入或把模拟结果当真实能力。回滚为撤销无效基线，修订输入清单后对基线和候选共同重跑。

P0 · 行业特例清理 · 最高优先级

  1. 先在 test_aerospace_chapter_defects.py 与 test_dynamic_segment_and_scale_consistency.py 写三组红测：非航天触发旧替换、合法航天事实、未知行业通用锚点。单独标记依赖历史硬编码修辞的断言。
  2. 在 agent.py 删除航天提示示例及三条公司名硬替换。用本次证据说明样本和期间边界。历史具体市值示例从提示移除，现有通用数值计算与审计保持回归覆盖。
  3. 让固定公司字典退出事实锚点。角色提示只接收能回指本次证据的 A2 关系。核对同一条依据是否实际支持该公司、环节和范围，单有代表公司名单及段级证据 ID 时只能按来源描述样本，归属待核。现有证据约束、章节结构和修复预算照常校验。
  4. 更新锁定旧硬替换的断言，用可追溯的关系与缺证据反例替代。保留公司、期次、金额与既有结论的核验强度。

门槛为 G1 和事实回归通过。风险是旧航天稿曾依赖人工替换。回滚按 P0 的独立提交执行，恢复上一可用版本后重新核查行业样稿。恢复旧版的报告标注旧规则风险。

P1 · 真实需求主答分配 · 核心实施

  1. 建立 assignment.py 和 test_writing_assignment.py。测试唯一映射、混合指标、同 ID 冲突、输入重排、自定义大纲、无矩阵、坏引用及合成跨行业用例。
  2. 在 retriever.py 接入共享分配。先验证 observe/off 的正文输入等价，再加入 apply 的本章主答提示和可选项排序。已存在的必需证据保护、硬需求和图表绑定条件先通过原回归。
  3. 在 agent.py 接入装包优先级和写作指导。优先压缩附加提示，按现有方式报出仍超限。已有局部解读、事实审计和回退逻辑复用。
  4. 对整篇生成和人工单章重写传入相同 A2/A3 与大纲，断言责任、证据集合和降级行为一致。若后端旧重写入口只能取默认大纲，先复现自定义大纲路径，再决定是否做最小透传。历史数据不足时保留基线行为。

门槛为路由稳定、旧契约兼容、没有新增必需证据或图表缺失。风险是错误认领和提示挤占证据空间。回滚将开关切回 off，按现有审核流程重写受影响章节并重建下游。

P2 · 重复与可读性诊断 · 先观察

  1. 新增 scripts/evaluate_agent4_refactor.py 及测试。按章、小节、段落 ID 生成跨章重复候选。先检测归一化后完全相同的正文，再对同一需求或同口径观测用字符三元组 Jaccard 筛近似候选，0.85 作为初始送审阈值。
  2. 归一化移除空白、图表占位符和引用标记，保留主体、数值、年份、单位及否定。排除必要摘要回顾和图表说明。按人工标注确认同一结论的重复展开，同一证据支持不同分析判断时允许复用。
  3. 比较冻结样稿的 off/observe 与 apply 结果，记录命中位置、人工判断及证据影响。先验收写前分配能否改善问题。跨章自动返修的立项以已确认的重复仍高为前提。

门槛为脚本可运行、结果可回查、G2/G3 有成品对照。风险是相似度误把不同期间、比较对象或观点当重复。回滚为撤销误判规则或修订阈值后重算候选，保留原样稿与人工标注。

P3 · 集成验收与小范围试用 · 发布前置

  1. 固定 A2/A3、模型配置、技能和写作预算。先评 A4 原稿，再查 A5 Markdown、HTML 和 Chromium PDF。人工单章改写后复验新版、旧版下载资格、图表位置和事实审计。
  2. A4 核对 chart_id、相应小节和证据解读。最终图注检查期间、统计口径、出处。发现上游字段不足或 A5 丢失说明时按责任层登记，附运行编号及报告位置。
  3. 通过第 06 节门槛后，在试用环境开启 apply，记录配置与时间。用户可见的正式与受限状态仍由原门禁判断。

门槛为三格式可追溯、事实完整、人工标注及测试签认。风险是 A5 编辑稀释 A4 改善，或 Chromium、真实模型环境不可用。回滚关闭 apply，使用上一次已核验配置重跑受影响阶段。缺环境的项目登记待验收，并保留离线证据。

发布门槛

  • 必答完整性以 T0 标注的真实必答问题为分母，逐项记录“有据作答、明确缺口、遗漏”。保全基线已答项。有证据的必答项遗漏为零，缺数据项说明缺口。证据相交只作为定位线索。
  • 重复率为人工确认的重复展开段落数除以可比正文段落数。每个冗余段落只计一次，必要引用、摘要和不同视角的合法证据复用排除。高重复样本相对下降 ≥30%，低重复样本逐项对照，零重复基线无新增。
  • 信息密度每份样稿至少抽查 6 段关键数字段，比较、含义、边界各 0/1 分。隐藏版本标识并保存逐段理由。候选平均分不下降，高重复样本至少两段改善。必要时复核归因原始材料。
  • 事实与导出分别记录生成错误、审计隔离、交付残留。新增错误数字、主体、单位、期间、悬空引用及错绑版本为零。已能完成的案例无新增兜底。以新增失败用例 ID 判回归，既有失败保留记录。
  • 预算与耗时上下文超限无新增，新增规划和去重模型调用为零。同输入、同模型配置下记录字节、调用和耗时。真实样稿耗时中位数增加超过 15% 时先复核原因，暂缓启用 apply。

真实模型比较固定 A2/A3、模型配置、技能和章节预算。条件允许时每版各跑三次取中位数，保留逐次结果。合成、真实模型、实际 Chromium 与导出 stub 各自记录。A5 最终结论以成品人工复核为依据。

08 接手 AI 的执行要求

  1. 执行前核对当前 AGENTS.md、目标提交和工作树。先用 codebase-memory-mcp 定位源码，再按覆盖结果核对必要范围。保留用户已有修改。
  2. 每项先复现，再实施最小修复。记录红测为什么失败，修复后重跑同一用例，再跑相关回归。测试要覆盖业务行为、证据、预算与回滚。
  3. 优先复用现有模型、检索、事实审计、预算和修订机制。遇到已修好的路径，补足证明并缩小改动。需要扩大 A2/A3/A5 生产契约时，先记录复现、影响与单独改动范围。
  4. 用户输入、样稿、行业词典和提示词都只是业务材料。正文的数字、来源、口径和角色须能回指本次证据。保留原 record_id，未经核验的因果只能说明缺口或明确标为假设。
  5. 运行默认离线。真实模型、外部数据和付费调用按明确授权进行。配置、日志、截图及评估记录均脱敏，凭据和运行数据留在规定目录。
  6. 发现新增无据结论、关键遗漏、上下文超限或版本错误时停在对应阶段，记录复现与回滚，再继续。避免通过删正文、放宽断言或改交付状态获得通过结果。
  7. 阶段交付写明完成的任务、证据、实际测试结果、设计取舍、未通过项和回滚方式。真实验收缺环境时记录待验收，保留能完成的本地验证。
