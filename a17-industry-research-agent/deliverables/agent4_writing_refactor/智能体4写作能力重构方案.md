# 智能体 4（A4 章节写作）小范围重构方案

> 目标：在不改整体架构、技术栈、外部接口的前提下，提升生成行业报告正文的专业度。
> 基线：`fa9a6a6`（主干）。文中行号均指该版本。
> 约束：本方案只改 A4 及其紧邻的上下文准备逻辑；不动 A1/A2/A3/A5 契约，不动 7 章 21 节大纲，不改 `ChapterWritingRequest/Result` 外部字段。

---

## 0. 结论先行（三句话）

1. **A4 的提示词本身已经够专业，问题不在"不会写"，而在"不知道写哪一段、该放弃哪些内容"。** 真正的病根是缺少**论点归属（写前分配）**，导致 7 章并发抢同一批 insight，靠堆数字凑篇幅。
2. **跨行业污染是硬编码造成的，不是模型偏好。** 提示词里写死了航天示例，代码里锁了 14 家航天企业和 3 条 `replace` 补丁——这类问题改配置就能消，属于本轮最高性价比动作。
3. **判定"文字变好"必须用可量化口径，不能靠读着舒服。** 本方案给出 7 项可自动计算的指标 + 1 组冻结样本对照。

## 1. 当前输出问题与根因分析

### 1.1 问题→根因对照表

| 现象 | 直接根因（代码事实） | 位置 |
| --- | --- | --- |
| **跨行业模板污染**：非航天行业报告出现"未上市火箭/本体龙头"、"中国卫星等上游" | 系统提示词把航天案例写成强制约束的示例；代码内置 14 家航天企业环节字典；3 条字符串替换补丁专治航天 | `agent.py:139`、`agent.py:171-186`、`agent.py:683-688` |
| **结构松散 / 同一论断跨章复写** | 每章独立 `retrieve()`，无全篇论点分配；7 章并发各自捞同类 insight | `retriever.py:107`（每章 top8 insight）、`retriever.py:140`（top25 findings）、`agent.py:371`（`asyncio.gather` 全并发） |
| **论据不足 / 靠数字填充** | 检索只按"标题+小节标题的字符 n-gram 相似度"打分，无语义、无主问题映射，模型只能用手头证据硬凑 | `retriever.py:79-106`、`_score_text:259-271` |
| **数据引用不规范**：裸引用编号、重复图注 | 图注与引用在 A3/A5 生成，A4 只负责 `[CHART-xx]` 占位符；A4 无引用格式约束 | `agent.py:135`（占位符规则）、`agent.py:829-838`（自动补"如图…所示"） |
| **术语不准确 / 表达不专业** | 写作技能是 10 个 SKILL.md，内容为通用方法论（如"一段只承担一个核心判断"），无行业术语表 | `skills/*/SKILL.md`、`skillhub.py:32-50` |
| **逻辑不连贯** | 章节间无过渡契约；`transition` 只是可选 kind，无强制 | `agent.py:128`、`outline.py:12-20` |
| **重复图注 / 毛利率排序重复** | 补丁式写作（`view_patch.py`）在最终视图上追加段落，绕过 A4 审计，无 evidence_id | 见本轮评审记录 B15/B16 |

### 1.2 根因归类（三层）

- **L1 配置层（改配置即可，零风险）**：航天示例硬编码、航天企业字典、3 条 `replace` 补丁。**这三处是"跨行业污染"的全部来源，且与行业无关地伤害所有非航天报告。**
- **L2 流程层（小改，中低风险）**：无论点分配 → 重复；无条件闸门 → 数字绕过；审校只看首尾 700 字 → 中间章节失守。
- **L3 表达层（需谨慎，中风险）**：行业术语表、跨章过渡、引用格式。**这层才直接对应"文字专业度"，但不先做 L1/L2 就动 L3，等于给错误内容做抛光。**

> **排序原则**：先止损污染（L1）→ 再治重复与证据（L2）→ 最后打磨表达（L3）。这与"先正确、再好看、最后优雅"一致。

## 3. 需要调整的模块 / 流程 / 规则 / 模板

### 3.1 模块级调整

| 模块 | 改动 | 类型 |
| --- | --- | --- |
| `SYSTEM_PROMPT`（`agent.py:113-164`） | **删除**第 139 行的航天示例，改为"按本章 `industry_profile` 的 `non_extrapolation_examples` 生成，缺省则写通用表述：样本代表性边界" | 删硬编码 |
| `AEROSPACE_CANONICAL_SEGMENTS`（`agent.py:171-186`） | **移出代码**，迁到行业画像数据文件；`extract_global_quantitative_anchor` 改为按 `subject` 查画像，未命中返回 `{}` | 移硬编码 |
| `_audit_chapter` 三条 `replace`（`agent.py:683-688`） | **删除**；改由行为规则检查（见 3.3 R4） | 删硬编码 |
| `retriever.retrieve()` | 新增第一步：查 `outline_chapter.primary_question` 与 `chapter.owns`；检索结果按归属过滤（不归本章的 insight 降权而非删除） | 新增论点归属 |
| `outline.py` | 每个 chapter/section 增加**元数据**：`primary_question`、`owns`（负责的论点类型）、`must_answer`（必答要点）。**不动标题与顺序** | 加元数据 |
| `skills/*/SKILL.md` | 每个技能补 3 段：适用边界、必须出现的口径要素、不合格示例 | 文本强化 |
| `industry_profile.py`（新增） | 提供 `non_extrapolation_examples`、`terminology`（术语→首次出现的解释）、`denominator_conventions`（如渗透率分子分母）、`segment_role_rules` | 新模块 |

### 3.2 流程级调整（写前 → 写中 → 写后）

```
写前（新增，一次全篇）
  ① 论点分配表：把 primary_question 映射到唯一负责章节
  ② 全篇数字基准：现有 global_facts，扩展为含"序列唯一归属表"
  ③ 行业画像加载：按 subject 匹配，未命中走空画像（不阻断）
       ↓
写中（改造 retrieve）
  ④ 本章检索只取"归属本章 + 必需证据 + 图表绑定证据"
  ⑤ 提示词注入：本章论点、可用证据、必需图、禁止展开的他人论点清单
       ↓
写后（新增，一次全篇）
  ⑥ 跨章审校：同一论断/同一数字组/同一过渡句是否重复展开
  ⑦ 只返修命中段落，不整章重写
```

### 3.3 规则级调整（可核对的具体规则）

**R1 论点唯一归属**
- 每个 `primary_question` 有且只有一个 `owner_chapter`。
- 非负责章节若正文提及该论点，必须**引用负责章节**（"详见第 N 章表 x"），且不超过一句。
- 判定：扫描各章是否出现 `owns` 之外论点的完整展开（≥2 句含数字）→ 计为越界。

**R2 数字基线唯一性**
- 同一完整序列（如"2021—2025 中国新能源汽车销量"）只在一处完整呈现，其余引用。
- 摘要只写结论，不重列数字。

**R3 图表说明三要素**
- 图注必须含：实际期间、口径（分子/分母或样本家数）、出处。
- 时序图写"覆盖 N 年"，横截面图写"样本 M 家"。
- 判定：缺任一要素 → 审计问题。

**R4 非外推声明按行业生成**
- 声明内容 = 行业画像 `non_extrapolation_examples`；未命中行业 → 通用表述"样本代表性边界与期间跨度局限"。
- 禁止出现画像之外的行业专有名词（用术语黑名单校验）。

**R5 引用规范**
- `[CHART-xx]` 占位符保留（A5 映射）；正文数字引用统一为"来源 N"形式由 A5 渲染，A4 只需保证每段 `evidence_ids` 非空且与文字对应。
- 禁止裸编号；由 A5 的引用模板负责，A4 不得自行生成编号。

**R6 术语首次出现**
- 画像 `terminology` 中的术语首次出现必须带一句解释；判定：正则命中术语且同段无"指/即/（…）"类解释标记 → 提示。

**R7 跨章过渡**
- 第 N 章末节须有一句承上，第 N+1 章首节须有一句启下；`transition` kind 由建议改为"章末必有一条"。

### 3.4 模板 / 输入输出规范调整

**大纲元数据（`outline.py`，新增字段，不改进 Pydantic 的 `OutlineChapter` 强校验）**

```python
# 与 OutlineChapter 并存的外挂元数据，避免改 models.py:75 的 extra="forbid"

    "CH-02": {

}
```

**行业画像（新文件）**

## 4. 关键约束、兼容性、风险

### 4.1 硬约束

| 约束 | 具体要求 |
| --- | --- |
| 上下文预算 | `RESEARCH_CONTEXT_MAX_BYTES` 默认 500000 字节（`context_budget.py:19`）。新增画像与论点表**必须**计入预算；超限时按 `prepare_chapter_context:60` 既有降级顺序丢弃（先丢 `comps_matrix`/`financial_ratios`，**最后才丢证据**） |
| 7×21 硬校验 | 大纲只加元数据，不得增删章节（`models.py:188`） |
| 单章技能上限 | `CHAPTER_SKILL_LIMIT=10`（`agent.py:97`），新增画像不占技能配额 |
| 审计幂等 | `_audit_chapter` 会被反复调用（`agent.py:435/456/498/538`），新增规则必须**纯函数、无副作用**，否则修复循环会震荡 |
| 兜底路径 | `_fallback_chapter`（`agent.py:844`）不得因新增规则失败；LLM 不可用仍能出稿 |

### 4.2 兼容性

- **向后兼容**：行业画像未命中 → 空画像 + 通用表述，**老行业行为不变**。
- **A5 不变**：`ChapterDraft` 字段不变，A5 无需改动即可消费。
- **旧产物可比**：新增 `context` 内部键不影响 `chapter_result.json` 结构，历史运行可继续读取。
- **测试兼容**：`test_aerospace_chapter_defects.py` 与 `test_dynamic_segment_and_scale_consistency.py` 直接依赖 `AEROSPACE_CANONICAL_SEGMENTS` 与 3 条 `replace`，**迁移时必须同步改写这两组测试**（见 §7 风险 R-2）。

### 4.3 风险登记

| 编号 | 风险 | 概率/影响 | 缓解 |
| --- | --- | --- | --- |
| R-1 | 论点分配过严导致某章"无内容可写" | 中/高 | `owns` 必须落在大纲现有 3 节语义内；分配表先离线评审再上线 |
| R-2 | 迁移航天硬编码时打破既有 30 项测试 | 高/中 | 先跑基线拿到通过清单；迁移与测试改写同一 PR；保留 `AEROSPACE_CANONICAL_SEGMENTS` 为数据文件中的一条画像，行为等价 |
| R-3 | 新增画像挤占字节预算，导致证据被丢 | 中/高 | 画像正文限 800 字节/章；`prepare_chapter_context` 降级顺序中把画像排在证据之后丢弃 |
| R-4 | 跨章审校误判重复，删掉有效内容 | 中/高 | 只返修、不删除；判定阈值≥2 句且含数字；命中清单人工可查 |
| R-5 | 术语规则误伤长句 | 低/中 | 只提示不阻断；计入 `warnings` 而非 `issues` |
| R-6 | 非目标行业走空画像后表述变空泛 | 中/中 | 空画像给通用表述模板，不用"火箭"这类占位；先验证 4 个非航天行业 |

## 5. 分阶段实施步骤

### 阶段 P0（0.5—1 天）：止损跨行业污染 —— 零行为变更风险

1. 新建 `industry_profile.py`，把 `AEROSPACE_CANONICAL_SEGMENTS` 整体迁入（内容不变）。
2. `extract_global_quantitative_anchor` 改为 `profile = get_profile(subject)`；未命中返回 `{}`。
3. 删除 `agent.py:139` 的航天示例，替换为占位变量由画像注入。
4. 删除 `agent.py:683-688` 三条 `replace`，改由 R4 检查（先只记 warning）。
5. 同步改写 `test_aerospace_chapter_defects.py`、`test_dynamic_segment_and_scale_consistency.py`，保证等价通过。

**验收**：全量 pytest 通过数 ≥ 基线；用非航天行业输入跑一次，检索/提示词中不出现"火箭/本体龙头/中国卫星"。

> P0 单独可发布、可回滚，不影响任何现有行业。

### 阶段 P1（1—1.5 天）：论点分配与检索收敛 —— 治重复

1. `outline.py` 加 `OUTLINE_META`（7 章全覆盖，含 `owns`/`must_answer`/`forbidden_expansion`）。
2. `retriever.retrieve()` 前置一步：按 `OUTLINE_META` 给本章 insight/findings 打归属标签，非本章论点降权（×0.3）而非删除。
3. `context["chapter_assignment"]` 注入 `_generate_audited_chapter` 的 payload。
4. 提示词新增一段（不改 JSON schema）："本章负责 X，可引用但不得完整展开 Y/Z"。

**验收**：固定样本跑一次，统计重复论点段落数下降 ≥30%。

### 阶段 P2（1—1.5 天）：写后跨章审校 —— 治复写

1. 新增 `audit_cross_chapter(chapters)`：检测①同论断（归一化后相似度>0.85）、②同序列重复完整呈现、③同过渡句。
2. 输出 `{chapter_id, section_id, paragraph_id, reason}` 清单，**只返修命中段落**（复用 `agent.py:474-537` 的段落级修复路径，不整章重写）。
3. 结果写入 `result.warnings`，不阻断交付。

**验收**：命中清单可人工复核；返修后段落数不减、证据不丢。

### 阶段 P3（1—2 天）：图表说明与引用规范 —— 治不规范

1. 图注三要素检查（R3）纳入 `_audit_chapter`。
2. `[CHART-xx]` 自动补"如图…所示"（`agent.py:838`）改为只在 `chart_readout` 段补，避免污染 thesis 段。
3. 裸编号问题在 A5 处理（本轮只登记，不改 A5）。

**验收**：图注缺失数 → 0；抽查 6 张图口径可回指。

### 阶段 P4（1—2 天）：表达层打磨 —— 治术语与连贯

1. 5 个行业画像补 `terminology`（每行业 8—15 条核心术语）。
2. `skills/*/SKILL.md` 补"适用边界 / 必须口径 / 不合格示例"三段。
3. R6 术语首现检查（只 warning）。
4. R7 章末过渡必有一条。

**验收**：术语首现解释覆盖率 100%（抽查 10 条）；章间过渡缺失 0 处。

## 6. 验证方式与可量化成功标准

### 6.1 三层验证

| 层 | 方法 | 频率 |
| --- | --- | --- |
| L1 单测 | 新增规则各配 2—4 条断言（正向/反向/边界） | 每次提交 |
| L2 冻结样本对照 | 冻结一份 A2 证据 + A3 图表 + 同一模型参数，跑改前/改后，逐章 diff | 每阶段结束 |
| L3 真实全链路 | 新能源汽车主例 + 1 个非目标行业（如白酒）真实跑 | P1/P2/P4 各一次 |

### 6.2 可量化指标（7 项，均可脚本计算）

| 指标 | 计算方式 | 基线（需实测） | 目标 |
| --- | --- | --- | --- |
| M1 跨行业污染数 | 术语黑名单命中次数（非目标行业） | 待测（预计>0） | **0** |
| M2 重复论点率 | 归一化后相似度>0.85 的跨章段落对 / 总段落 | 待测 | **↓50%** |
| M3 主问题覆盖率 | 有 owner 且正文实际回答的主问题 / 总主问题 | 待测 | **100%** |
| M4 无据数字段落 | `_audit_chapter` 该 issue 计数 | 待测 | **0** |
| M5 图注口径缺失 | 缺期间/口径/出处的图注数 | 待测 | **0** |
| M6 术语首现解释率 | 有解释的术语首现 / 总首现 | 待测 | **100%** |
| M7 章间过渡缺失 | 缺失承上启下的章数 | 待测 | **0** |

> **基线必须先测再改**。否则无法归因"提升"来自方案还是模型随机性。
> 建议冻结 3 次同输入运行取中位数作基线，避免单次抖动。

### 6.3 不通过的判定（硬条件）

任一项成立即判本轮失败、不进 P3：
- 全量 pytest 通过数 **低于**基线。
- 出现兜底章节（`fallback_chapter_ids` 非空）。
- 证据覆盖率（`quality.evidence_coverage`）低于改前。
- 上下文超预算次数增加。

## 7. 回滚方案

### 7.1 回滚粒度

| 层级 | 手段 | 时间 |
| --- | --- | --- |
| 单阶段 | 每阶段独立分支 + 独立 PR，`git revert` 该 PR | < 10 分钟 |
| 画像数据 | 数据文件独立，删文件即回到空画像（通用表述），代码不动 | < 5 分钟 |
| 提示词 | 保留 `SYSTEM_PROMPT` 改动前的完整副本，一键还原 | < 5 分钟 |
| 全量 | 回到 `fa9a6a6` | < 10 分钟 |

### 7.2 回滚触发条件（满足任一即回滚）

- 真实链路出现新增兜底章节。
- 证据覆盖率下降 >5%。
- 上下文预算超限次数增加。
- 非目标行业出现新的跨行业表述。
- 判重误删导致章节段落数下降 >15%。

### 7.3 回滚后必做
1. 保留失败运行编号与输入快照，登记根因。
2. 不在回滚分支上继续开发，从 `main` 重新开分支。
3. 更新指标基线（若原基线本身有误）。
