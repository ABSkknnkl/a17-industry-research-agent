## 产品界面 UX 三问题审计（只读静态分析，未改代码）

用户给出三张界面截图，要求逐个分析并给可落地改进方案。

### 定位到的关键文件
- `frontend/src/components/StageDigest.vue` L287-326：阶段一「研究问题与数据匹配情况」表格
- `frontend/src/components/InterpretationDigest.vue` L292-311（凭证溯源）、L446-454（风险卡片）
- `frontend/src/api/labels.ts`：`skillLabel` / `dimensionLabel` 映射表
- `backend/app/agents/adapters.py` L382-390（risks 构造）、L937-946（阶段五 evidence_catalog）
- `agents_core/data-analysis/data_interpreter/engine.py`：AnomalyFinding 生成（explanation 为 kind 级固定模板句）

### 三个根因（重要，后续复用）
1. **阶段一英文透出**：后端 `intent_routing.plans` 的 key 是 `{domain} 核心数据`（如 `companies 核心数据`），
   `sub_requirements[].candidate_skills` 下发的是**分析领域 domain 名**（companies/financials/macro/
   industry_chain/reports/news），而前端 `SKILL_LABELS` 是按 SkillName（hithink_*）+ EvidenceCategory
   （company/industry/tech/opinion）建的 → 查不到 → 英文原样透出。
   ⚠️ 隐藏 bug：`industry` 碰巧命中 EvidenceCategory 的 `industry: '行业资料'`，属**误译**（本该是"行业概况/行业数据"）。
   另 `sub.description`（采集X核心数据相关指标）只是复述 key，零信息量。

2. **凭证溯源**：展示的是 `insight.evidence_record_ids` = 内部主键 `R-{18位hex}`，用户零信息量。
   可读信息全在 `evidence_index`（502 条，字段 record_id/domain/entity/metric/value/unit/period/
   skill_id/trace_id），但该字段**只存在于 interpretation_report.json artifact，未下发前端**
   （adapters.py L392-404 的 data 字典没有它）。
   ⚠️ 隐藏 bug：`view-evidence` 事件**无任何父组件监听**（StageDigest.vue L367-371 未绑定 `@view-evidence`），
   `EvidenceDrawer.vue` 是空占位 `<div style="display:none">` → 标签是"假按钮"，点了无反应。

3. **风险提示**：所谓"风险"实为 `anomalies`，是**数据质量/统计异常检测结果**，非投资风险。
   75 条 = 38 cross_sectional_outlier + 31 data_quality + 6 time_series_spike。
   `ano.explanation` 是 engine.py 里按 kind 写死的模板句 → 同 kind 文案完全相同。
   ⚠️ 后端已下发差异化的 `title`（`离群异常: {metric}`）与 `level`，**前端 L451 只渲染 description**，
   完全丢弃了 title/level → 用户看到"75 条几乎一样"。
   可差异化字段（AnomalyFinding 全有）：entity/metric/period/observed_value/expected_range/score/severity/kind。

### 已给出的建议方向
- 问题1：翻译+精简（不删表），前端补 domain 映射，根治靠后端直接下发中文
- 问题2：后端按 insight 引用裁剪下发 `evidence_digest`（entity·metric），前端渲染可读标签；
  并修复 `@view-evidence` 绑定 + 实现证据抽屉
- 问题3：区块标题改「数据异常检测」，文案去 Z 分数/MAD 术语，用 anomaly 明细字段做差异化，
  按 kind 分组、按 severity 分色

用户协作边界为只读分析。**本轮未修改任何业务代码**，仅输出方案。
