- 诊断日期：2026-11-16
- 对比基线：`同花顺赛题-T3交接/a17-industry-research-agent`（Git HEAD `2cc962a`，2026-11-15 15:41，工作区代码未改动）

- 验证方式：真实 LLM + 真实问财数据，按你 11-14 新能源那一轮的同一份输入跑完五阶段（未使用 mock）

## 一、一句话结论

**交接版能跑完、能出完整的 PDF/HTML/Markdown，但复现不了你 11-15 那版新能源报告。**

它不是在你的主线上做小修补，而是**换了一条代码分支**：新加了一套五阶段引擎（约 2600 行），同时把 A3 图表、A5 融合和共享指标语义退回到你 11-15 之前的版本。结果是“格式还在、核心内容和图表没了”。

### 4）根因：共享指标语义表换了分支，NEV 指标认不出来

`agents_core/financial_semantics.py`：

- 你的版本 1416 行 / 70 KB；交接版 2368 行 / 123 KB（内容更多，但**不是你的那份**）。
- 交接版少了 16 条新能源汽车指标别名，包括：
  - `新能源汽车:销量:累计值`、`新能源汽车:销量:年度值`
  - `国内零售渗透率:新能源汽车:当月值`、`国内零售渗透率:新能源汽车:年度值`
  - `新能源汽车:出口量`、`新能源汽车:出口量:中汽协口径`、`中国新能源汽车:出口量`
  - `新能源汽车:渗透率:当月`、`新能源汽车:渗透率:年度`
- 还缺 `_NEV_METRICS`、`_YEAR_RANGE`、`_COUNT_UNITS` 这组 NEV 专用辅助常量。

问财返回的指标名就是带冒号的字符串。交接版的 `metric_family()` 只认“新能源汽车销量”“市场渗透率”这类短名，认不出 `新能源汽车:销量:累计值`，于是：
**数据明明采到了，需求覆盖却判 0 条证据 → 报告写“数据缺失” → A3 抑制时序图 → A4/A5 继续按缺口写。**

### 5）环境与交付变化

- 交接副本没有 `.env`、没有 `.venv`、前端没有 `node_modules`；`启动.command` 直接引用 `.venv/bin/python`，`start.sh` 第一道检查就是 `.env`，所以**开箱即跑不了**。
- `.env.example` 把搜索源改成 `bocha` 并写明“豆包 provider 已彻底移除”；而你的 `.env` 是 `SEARCH_PROVIDER=doubao`。交接版会静默禁用产业链联网补漏（不报错，只是不补）。
- 删除 47 个你仓库里的文件：A3 的 4 个模块、A5 的 `export_view.py`、15 个评估脚本、`docs/superpowers` 等；新增 183 个（引擎模块 + 30 个 backend 测试 + 前端补采 UI）。

## 四、责任链（为什么会这样）

```
financial_semantics 缺 16 条冒号别名
        ↓
A1 需求覆盖把已采到的 NEV 销量/渗透率/出口判成 0 证据（15 项硬缺口）
        ↓
A2 指标卡被估值快照占据（PE/市值/股价），产业指标边缘化
        ↓
A3 旧版没有 _annual_volume_combos / publication / selection
        ↓
出口、渗透率、同比、分组图被抑制；重复生成 8 张估值图（4 张同主题重复）
        ↓
A4 新门禁把“数值语义未通过”的段落整段删除（不是标注保留）
        ↓
正文出现空洞，A5 又缺逐题年表/净现比复算
        ↓
61 页“受限草稿”，核心结论回不来
```

补充：A3 旧版会把产业域里的全部公司当成图表样本（本次 20 家电力设备公司），且没有发布前的重复图/样本口径校验，所以出现“正文 5 家、图表 20 家”的自相矛盾。

## 五、我的判断

1. **你的仓库没有被这次交接改坏**：Git HEAD 仍是 `2cc962a`，A3/A5/`financial_semantics` 的新能源逻辑都在，backend 能正常 import；11-15 的成品报告文件也还在。
2. **交接版不是“改错”，是“另一条线”**：它带来了可用的引擎能力（阶段契约、版本化产物、决策包、自动补救），但把智能体层换成了对方更早的版本。整目录覆盖必然丢你的新能源修复。
3. **“报告都跑不了”分两层**：
   - 开箱层：交接副本缺 `.env`、`.venv`、`node_modules`，启动脚本第一步就退出；
   - 内容层：即使补齐环境跑完，核心数据/图表/结论也回不到 11-15 的水平。
4. 另外提醒：你仓库里 `deliverables/a5_nev_20261116/report.md`（11-16 09:48）也是受限草稿，营收/现金流大量“—”。这说明**自动链路的 A1 取数与需求覆盖本身也不稳定**，不只是交接版的问题；这版报告不能当作“之前的报告”基线。

## 六、建议（按优先级）

### P0：先恢复“能复现”的主线
- 以你的仓库 `2cc962a` 为基线，不要用交接副本整目录覆盖。
- 用你原来的 `.env` + `.venv` 跑；交接副本仅作为引擎能力参考。
- 如果要跑自动链路，先把 A1 的 NEV 需求覆盖修到 63/63（或至少 0 硬缺口），再谈 A5 门禁。

### P1：如果一定要用交接版，必须补回三块（不能只改配置）
1. **共享语义**：把 `financial_semantics.py` 里 16 条冒号别名 + `_NEV_METRICS/_YEAR_RANGE/_COUNT_UNITS` 补回（这是“数据在、判缺失”的总开关）。

3. **A5/A4**：补回 `_annual_cash_ratios`、`_financial_question_tables`、`export_view.py`；A4 的段落门禁从“整段删除”改回“标注 + 隔离”，否则正文永远有洞。

### P2：环境与配置
- 交接副本补 `.env`（从你的仓库复制）、`.venv`（`pip install -r requirements.txt`）、`frontend/npm install`。
